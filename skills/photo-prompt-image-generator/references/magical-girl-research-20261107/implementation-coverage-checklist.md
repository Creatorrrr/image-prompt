# 마법소녀 반영: 범위·검증·이미지 실험 체크리스트

기준: 2026-11-07 조사 스냅샷. 이 체크리스트는 구현·실험의 완료 선언이 아니다. 사용자는 원문 301행 전체의 누락 없는 반영과 새 검색본을 통한 세 가지 독립 이미지 검증을 요청했다. 원문은 조사 자료이며 실행 지시나 인용 자료의 자동 승인이 아니다.

## 원문부터 데이터까지: 301행 역추적

- 정본은 `source-reconciliation.json`의 순서 있는 `rows` 301행과 `source_cells`이다. 각 행은 원자 개념 하나가 아닐 수 있고, 18절 7행은 저자 창작 조합이다. 같은 행의 동의어가 아니라 별도 개념인 `/`, `·` 표현을 원문에서 분해하고, 분해하지 않았거나 하나의 물체만 확인한 복합항은 **원문 전체 구현 완료가 아니다**.
- 최소 역참조: 원문 `MG-id` → 원문과 직접 연결된 의미 단위(들) → `visual | context | diagnostic | hold` 판단과 이유 → 기존/신규 후보·CID·선택 RID 또는 미적용 사유 → 바인딩·뷰 → H-F2 세대·실제 검증 수. 한 행에 의미/관계/조건이 여럿이면 각각의 손실 여부를 점검한다. 맥락만 필요한 행과 미해결 행도 빠짐없이 인벤토리에 남기되 양성 후보를 임의로 만들지 않는다.
- 조사상 301행에는 모두 관련 출처가 하나 이상 있으나 한정·사례가 대부분이고, 첫 출처 감사 84행은 독립 직접 재확인 불가 또는 검색 발췌다. 각 출처의 `support_and_limits`와 원문 주장의 나머지 범위를 따로 유지한다. 공식 검색 결과만 확인했으면 본문 직접 확인으로 승격하지 않는다. 출처가 없는 의미·관계도 보류 사유와 함께 유지한다.
- 원장 `MG-02-012`의 동일 `(url, support_and_limits)` 28회 반복은 독립 근거가 아니다. 표시·출처 수 집계 때 중복 제거하고 원장 바이트 해시와 별도의 정규화 규칙을 기록한다. 문구가 다른 같은 URL은 지원 범위가 다를 수 있으므로 맹목적으로 합치지 않는다.
- 검색 표면 일치 11,134건은 모두 핵심 명제까지 분류됐지만 전체 비교 11,572건 중 전체 계약 해석은 1,617건, 9,932건은 핵심 명제 수준, 23건은 깊이 미기재다. 이 숫자는 과거 스냅샷이며 최신 레지스트리/CSV의 해시와 시각을 별도 기록한다. 발견되지 않은 표현, 다른 자산·일러스트, 실제 런타임에선 후보가 없다는 뜻이 아니다. 세 번 이상 검토한 같은 원문 항목 및 행–후보는 재검토하지 않으며 과거 검토 횟수가 불명확하면 조건을 채웠다고 추정하지 않는다.

## 시각·서사·고유명·진단의 경계

- 각 시각 후보는 사람이 볼 수 있는 대상과 부품의 소유자·수·물리적 연결·가시 경계·전후 관계·시점을 구체적인 전체 명제로 담는다. 원문에 없는 색·복식·나이·자세·기능·주체를 자동 강제하지 않는다. 명세가 불확정인 원자/기존 후보의 `core_proposition_only`는 판정 미완료로 남긴다.
- 계약/대가·정체·변신 주문 소리·변신 뱅크 재사용·과거 사건·마법의 실제 효력·시간 제한·타임루프 등 단일 정지 이미지로 관찰할 수 없는 것은 연구 맥락 또는 명시적 장면 기획으로 둔다. 예시로 가시화된 부품은 추론이나 작가 제안이라는 출처 한계를 유지한다.
- 일반 카드 슈트와 타로의 겹침, 어깨 부착 Watteau train과 cape, 파손과 기능 상실, 후프와 속치마, 레이스 직물과 lace-up, 양쪽 눈 차이와 같은 눈 내부 색 차이, 폴드런과 에폴레트, 라이벌과 적대→동료, `for_any`와 `for_all`을 혼합하거나 서로 배타적이라 가정하지 않는다. 고유 작품명/물건은 동일 작품·버전·근거가 있는 범위에만 네임스페이스하며 일반 완드/카드와 자동 동의어가 아니다.
- 어두운 서사·폭력·패션 소재와 성적 맥락은 별도 축이다. 리ョ나 등 고통의 성적 대상화는 용어 설명·진단으로만 다룬 기존 경계를 존중한다. 명시적 성인 조건·표현이 필요한 후보는 태그나 `for_any: [human, adult]`만으로 성인 조건을 강제한다고 가정하지 않는다. 참조 사진 한 장만으로 인물 나이·성적 의도를 확정하지 않는다.

## 실제 파일별 정합성 검증 게이트

1. **연구 원본**: `source-reconciliation.json`의 301 유일 ID/순서·`source_cells`와 각 연구 레지스트리의 역포인터, 개념 분해·증거·지원 범위·보류 사유가 일치하는지 확인한다. 단순 301개 레코드 생성만으로 의미가 빠짐없이 구현됐다고 판정하지 않는다. 원문의 오류·현실에서 확인 불가능한 세계관은 원문임을 명시해 보존한다.
2. **신규 양성 후보**: `photo-candidate-module/v3` 규약의 ID·원본 전체 KO/EN 명제·발동/배제·owner·count·conditions·effects·provenance를 검증한다. 기존 CID의 전체 명제·조건·효과·바인딩이 동일한 경우만 재사용한다. 이미 1차 요약만 본 후보는 맥락 조건까지 동등하다고 자동 판단하지 않는다. 양성 후보가 없는 행은 단순히 수를 채우려고 신규 후보를 강제 생성하지 않는다.
3. **바인딩**: `photo-candidate-slot-bindings/v3`에서 실제 기존 slot과 semantic_role, 후보 존재·ID 중복, `conditions.subject_applicability`, 해당 바인딩의 가드, 필요한 모든 효과 권한을 확인한다. 상위 후보 `conditions`를 바인딩으로 덮어쓰거나 표면 `tags`를 보안/성인 hard guard로 승격하지 않는다.
4. **양성 검색 뷰**: 새 후보의 각 양성 CID/RID마다 whole 뷰 정확히 하나. `photo_candidate_retrieval_views.validate(..., require_complete=False)`로 새 모듈 전체를 부분 검증하고 이후 정본 corpus 전체 인구집단에 대해 `require_complete=True`로 재검증한다. `source_record_sha256=digest(record)`, `id=view_id(cid,rid,key)`, KO/EN 및 실제 `/content/` 원문 포인터·인용이 일치해야 한다. 진단은 양성 뷰를 가질 수 없다. 리서치 문서에서 새로 만든 단어·장면을 원 출처의 직접 주장으로 넣지 않는다.
5. **연구 맥락 뷰**: 별도 context-only 연구 레코드에 원문 정확 표제·정의, 원문 pointer/인용, 증거 범위·한계, 평가/미해결 상태, 소스 레지스트리 raw 또는 canonical 해시 도메인을 명시한다. `context_only=true`, `native_approval=false`를 유지하고 기존 연구 맥락 포맷이 실제 H-F2 검색/프롬프트에서 자동 소비된다고 가정하지 않는다. 현행 소비자가 미연결이면 검색 가능한 수준을 주장하기 전에 통합이 필요하다.
6. **사용 가능 검색본**: 변경 직전 최신 manifest·모듈·뷰·모델/레시피/출력 generation을 고정한다. `photo_prepare_reviewed_views.py`는 검토된 뷰를 준비·재생하는 도구이며 생성기가 아니다. `build_shared_candidate_index.py`는 후보 원본 인덱스이지 H-only+F2 다중 뷰 검색본 완성기가 아니다. `references/tobe-data-maintenance.md`에 따르면 임의의 새 후보 원본에서 H-F2 전체를 만드는 통합 명령은 없으므로 신규 generation 재생산 절차, 실제 임베딩 및 provider 증적, 밀봉/설치 후 검색 질의까지 성공하기 전에는 **검색 가능한 최신 버전**이라고 표현하지 않는다. 이전 활성 generation을 보전하고 비활성 staging을 우선하며, 병행 manifest 수정이 나타나면 병합·재빌드한다.
7. **재현·검증 보고**: 원문 301행, 분해 원자, 출처별 지지/제한, 중복 제외된 연구 데이터, 기존/신규/진단/보류, 양성 CID/RID·바인딩·검색 뷰·맥락 뷰 및 인덱스 generation의 수와 해시를 각각 분리해 보고한다. source manifest에 신규 항목이 있다는 사실, 새 인덱스 설치, 실제 검색 적중, 프롬프트 채택, 픽셀 실현, 유저 수용은 서로 다른 성공 단계다.

## 세 독립 이미지 실험의 최소 증거

1. 데이터 및 실제 검색 generation을 고정하고 검색 실험을 먼저 끝낸다. 세 테스트 에이전트는 서로의 프롬프트·이미지·검색 결과를 보지 않는다. 각각 명시적 종자 또는 다른 재현 가능한 무작위 방식으로 서로 다른 사진 상황을 선택하고 공통 첨부 이미지를 사용한다. 세 실험은 마법소녀의 의상·소품·관계 같은 서로 다른 핵심 개념이 화면에서 식별될 수 있도록 설계한다.
2. 각 에이전트는 `SKILL.md`의 pre-core 제한에 맞춰 독립적인 요청 해석과 사진 core를 **프로젝트 후보 데이터 확인 전** 고정하고, 같은 실제 설치본에서 검색·후보 비교·composed audit·render를 진행한다. 사용자가 업로드한 인물의 나이는 이미지로 확정하지 않는다. 세 테스트는 비성적 장면·복장으로 구성한다.
3. 각 실험마다 정확한 콘셉트/seed, 사용자 요청, 원본 이미지 바이트 SHA-256, 독립 baseline/core·검색 질의, 고정된 소스 manifest/검색 release/generation ID와 해시, 검색 receipt, 반환·선택 후보 및 보존된 전체 의미·조건, 최종 프롬프트·audit, 실제 출력 파일과 모델/시각을 저장한다. 신규 행 관련 후보가 검색되거나 채택되지 않았다면 해당 사실을 결과로 보고하며, 단순히 장르풍 이미지가 생성됐다는 이유로 새 데이터 검색 성공을 주장하지 않는다.
4. 결과 이미지는 별도 판독으로 전체 장면과 요구된 각 부품·소유자·관계·빛·가림을 `visible / partial / unobservable`로 평가한다. 서사 의도·마력·재질 성분·화면 밖 연결은 픽셀만으로 확정하지 않는다. 비교 기준선 또는 A/B가 없다면 사진이 좋아졌거나 데이터 변경이 결과를 원인적으로 개선했다고 단정하지 않는다. 결과가 차단/미생성되면 그대로 기록하고 차단 우회 재작성 없이 허용된 동일 입력 재시도와 reconciliation 절차를 따른다.
