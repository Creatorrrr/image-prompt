# Shared candidate and lazy search maintenance

The [genre-fusion extension](genre-fusion-visual-semantics.md) documents 84
complete optional visual realizations and 12 nonvisual context records for
Dying Earth / New Weird / Cozy Fantasy / Cosmic Horror. Its owner graphs and
150 keyword routes are review metadata, not native qualification or hard
activation. Search and saved-pixel evidence remain separately qualified.

Local EmbeddingGemma installation, separate rebuilds, qualification and Gemini rollback are documented in [local embeddings](local-embeddings.md). The active manifest declares its model space; local document/query evidence is validated separately from Gemini HTTP evidence.

The authored source is `assets/photo_candidate_corpus_manifest.json`. Each `cand_<uuid>` has exactly one payload owner. Managed slots are presentation tags. A candidate may have zero or many persistent `bind_<uuid>` relations. New request-local role proposals can present compatible untagged or differently tagged records without modifying source tags. Preserve intrinsic effects, provenance, binding conditions, owner/carrier relations, conditional obligations and bundle requirements.

The V3 native corpus owns intrinsic conditions and effects once per candidate. Bindings own only role applicability and distinguish direct properties from contextual interpretations; they cannot override candidate guards or carry a second effect payload. Intrinsic source eligibility is evaluated before any role binding. An exact frozen-action record can remain discoverable; its optional presentation still checks every canonical effect against frozen dimensions and property locks. Discovery does not authorize adoption. A declared role's failed condition cannot be bypassed by making an unbound proposal for that same role. A different role is evaluated under its own conditions without inheriting unrelated role policy.

Conditional effects use an explicit `realizations` contract with one complete alternative or a base plus an optional declared-context branch. Only the selected branch supplies member references, component units and effects. Branch guards are ANDed with intrinsic guards. Conditional bundles expose individually verified complete choices; composition requires an explicit presented `realization_id`. They never union mutually exclusive garment owners or colors. Previous V2 corpus and V9 packs are rejected.

Semantic catalog definitions include bilingual scope, owners, property paths, evidence terms, inclusion/exclusion boundaries, neighbor roles, frozen-core focus fields and presentation priority. Dimension overlap, tag membership and a lexical match alone do not establish role approval. Specific owned properties and corroborating meaning support eligibility; uncertain evidence remains review-required. V2 independent queries bind the complete semantic specification; previous query contexts are rejected. V10 packs retain canonical source conditions, role conditions and semantic fit separately.

Neutral freeze can carry an explicit `existing_member_scope` inventory using `photo-frozen-existing-member-scope/v1`. It is a request-local address for a complete, known-present, nonempty, flat list of independently declared existing owners, with exact request/envelope/input hashes, ordered reviewed input IDs, and each member's active membership spans/input provenance and atomic presence witness. It never creates an owner, a body inventory, a count, an inferred descendant or a permission. Canonical aliases are duplicate members; `part_of` stays distinct. The old result has no added empty key when no such assertion exists. Bounds remain 64 total assertions and 32 owners, with at most 8 scopes, 32 members and 65,536 UTF-8 inventory bytes; 32 separate owners plus 32 presence rows plus a scope exceed the row cap and fail. A frozen inventory alone does not qualify a source; adoption requires the explicit source and request contracts below.

`photo_native_owner_resolution.resolve_selected_contracts` is the pure B1 foundation for a source-checked selected projection. It keeps fixed-point contexts separate from exact core-bound point/member scopes, expands every actual P/PR/context/E and all receivers, and returns one joint assignment ledger with canonical and raw-order permission footprints. The result grants no admission or qualification. Native B2 consumers now share this one source-qualified resolved view across admission, guard evaluation, permission checks and a full composition audit. A source opts in with owner-bindings/v4 and an existing each-member/all-receiver selector; request owner-selections/v2 binds the exact core, graph, member table, source qualification and actual selected closure. Missing choices remain discovery-only and cannot become final authority. Every member independently witnesses prerequisites and preservation, and all actual targets and receivers retain whole effect locks. An equal-value effect is still a mutation. Root cache reuse rechecks actual selected edges/RIDs; only a real descendant of the exact active root may use a descendant choice subset. Partial discovery contexts never authorize strict reuse.

Source-guards/v3 supports an explicit `for_each_member` over one selected existing scope and one atomic predicate using its lexically bound member. Each member executes the actual predicate and carries its own source and witness provenance. No nested quantifier, implicit point-to-set lifting, new member, count or anatomical inventory is inferred. Preservation checks include the complete chosen union, including other independent roots, using the shared permission view. Guard-role-support/v1 rejects quantified v3 guard evidence; it needs a separate versioned extension before such a guard can support a role. Immutable packs retain unresolved descriptors; composed selections and freshly revalidated runtime resolution bind the actual choice. These engine and isolated transport checks do not approve any actual corpus candidate or instrument application.

The exact named source fields `phrase_en` and `phrase_ko` participate in automatic native whole-field coverage and in non-profile global retrieval labels. These are actual authored phrases, not aliases or tag metadata. Nonblank phrase-bearing documents use `photo-global-visual-phrase-text/v1`; other document and profile projection recipes stay unchanged. A changed recipe requires a freshly qualified vector even when label deduplication happens to retain identical text bytes. Manual ordinary or one-hop reference units still need the same exact selected-RID anchors. Named phrase coverage neither resolves translation differences nor grants role approval. Selected realization rendering still derives its own phrases from its selected en/ko projection.

Native source facts need their own exact field-local positive anchors. A full typed value cannot borrow a missing qualifier from a short paraphrase or gate. An explicit `semantic_reference` source unit may instead retain a partial restatement, selected-output constraint or same-owner reference to canonical facts already directly supported by ordinary `semantic` units in the same CID and actual RID. Its exact fields are the ordinary `realization_id`, `pointer`, complete `quote`, `fact_refs`, `disposition`, plus `reference_relation` and a nonblank `retained_constraint_rationale`. The relation is one of `partial_restatement`, `selected_output_constraint`, or `same_selected_owner`; its meaning requires direct review. Both endpoints must be actual positive primary fields, with different pointers. No reference chain, metadata anchor, foreign candidate or sibling-RID witness is allowed. Each field can have one ordinary semantic unit and one reference unit for different local clauses; duplicate units or a contradictory nonsemantic disposition fail. References cover the local field without supplying a new fact, role, effect, prerequisite or permission. All facts still need direct semantic anchors, and all substantive local conditions, profile/render obligations and effect locks remain independently enforced. References share the existing unit budget and are bound by the complete proof fingerprint before compact sealing. This feature does not convert or approve an older source or proof.

`photo_candidate_search.json` is the only operating index manifest. It references complete global BM25F statistics, compact source applicability metadata, quantized routing certificates, ordinal/float64 TF posting pages, payload shards and seekable exact float64 vector extents. DF and field-length statistics cover every positive source record. Slot tags never partition the search space or add ranking votes. Each active or explicitly requested slot receives its own candidate-free query, BM25F lane, actual query embedding, exact cosine ranks and RRF before presentation budgets. `keyword_only` is an explicit diagnostic, with no implicit hybrid fallback.

Readers verify declared source/index identities, keep payload/posting/vector bodies lazy, use a 64MiB content cache and at most 64 vector descriptors, and read only required extent bytes. A physical pack may contain many independently checked leaf shards. Source context guards can prune ineligible records; remaining vector areas are skipped only with certified score bounds. Weak bounds cause more exact reads, including bounded full streaming. Query contexts bind slot, language, specification, frozen core, controls, exact text, recipe, model/space and execution/vector hashes.

```bash
.venv/bin/python skills/photo-prompt-image-generator/scripts/validate_photo_prompt_dictionary.py

.venv/bin/python skills/photo-prompt-image-generator/scripts/build_shared_candidate_index.py --env-file .env --publish
```

The build explicitly materializes all vectors offline. It reuses the current verified native layout only when ID, full text hash, text recipe, provider/model/dimensions and vector integrity match. It does not import a legacy index, seed adapter, old query format or ownership tree. Missing/changed text invokes the durable embedding provider; failed or unknown attempts remain inspectable. Source edits during the build block activation. Full source, statistics, payload/vector coverage, extent closure and routing residual bounds verify before the active manifest moves.

The build declares a `source_update` revision and completes it on success. `--publish` then seals an independently copied, fully verified V3 generation. Retrieval never rebuilds or bootstraps a generation; an unpublished or incomplete revision remains blocked. Request acquisition uses sealed filesystem identities and on-read SHA verification. Publication and explicit maintenance perform the complete verification. V10 packs, V3 generations/current pointers and V3 issued receipts are the only operating contracts. Receipt replay uses its stored exact per-slot contexts and never re-embeds a query to manufacture matching ranks.

The full-scan oracle and vector-map materialization are offline build/evaluation tools. They are not retrieval, audit, compose, view or preflight fallbacks. Historical evidence remains archived outside operating manifests. Old pack/query/receipt contracts are rejected; create a new native run instead of rewriting an old result as new success. Cleanup must list and hash exact unreferenced generated members, protect the active manifest closure, authored modules, fixtures and other work, and preserve recoverable history.

Search/index/source integrity does not prove role-specific semantic precision or saved-image quality. Frozen requester meaning and owner/property restrictions retain authority. Unknown effects require review, optional suggestions can all be declined, and required visual meaning must still pass independently.

The exact named positive field `content.application_contract` requires complete source-unit disposition for every actual realization, with the same local quotation and direct normal-fact rules as other positive fields. It may use a valid one-hop semantic reference when the whole application clause and its remaining constraints have been reviewed. Unknown or nested fields are not admitted by this explicit addition. Application instructions do not add BM25F labels, embedding text or ranking votes. The 46 research input fields remain review inputs; this coverage rule does not approve their meanings or change operating source qualifications.

An explicitly opted-in `guard_supports` proof can use a directly quoted, exact own common/selected-branch source guard relation as prerequisite-only role evidence. Bind the actual CID/RID, condition and rule hashes, source schema/index, endpoints, complete slot specification and ordinary positive source unit. It creates no scalar fact, effect, preservation value or permission. Eligibility requires a fresh, verified execution receipt for that exact independent-core predicate; an `allowed` flag alone is insufficient. V1 raw relation values and V2 canonical equivalence retain their separate semantics. Compact seals bind the support locator and projection; selected child namespaces cannot borrow an unselected role. Manual relation-to-role meaning still needs direct review. Absent support metadata adds no new proof/receipt keys and independent source-unit validation needs no new review/CID fields. Guard supports remain separate from scalar fact views; guard_supports/v1 cannot qualify quantified guards.

`photo_semantic_role_views` binds an explicitly reviewed role view of the same canonical fact to the full spec, original fact/mode, ordinary positive unit, exact facet occurrence inside its canonical quote, all original endpoint positions and complete obligation/closure hashes. Native proofs opt in with nonempty `manual_role_views` and exact role `view_refs`. Full native validation runs before compilation; generated compact `manual_role_view_bindings` never become their own authority. The proposal/fit/qualification path requires independent full source data and rebuilds the expected binding from its exact validated record. Lazy lookup loads the existing hash-verified payload for opted-in records; ordinary records add no view metadata or authority payload reads. Public-pack authored records, Python classes and recomputed local hashes cannot supply expected authority. Views retain the actual canonical property, value, mode, operation, target, all receivers and requirements. They create no projected effect or permission; context-to-direct promotion and preservation-sentinel trait invention are rejected. Guard admission, selected dependencies/profile obligations, per-member P/PR and whole effect locks remain cumulative. Exact structural binding does not establish natural-language truth; every authored view still requires direct semantic review.

The entry-level typed-human filter honors a catalog's explicit `allow_domains_override_subject_categories` only when the actual request domains intersect that catalog's `allow_domains`. This exception does not remove an explicit actor owner, source/binding conditions, subject/domain denials, adult restrictions or `no_people`. Candidate routing tags cannot create a catalog exception.

A scoped149 migration uses `photo_scoped_slot_adoption.py` with an exact authored catalog and per-binding decisions. It does not relax the separate full-native review tool or qualify a source from tags. `_slot_binding_review` records inherited/relationship-reviewed/deferred status separately from native evidence. Deferred bindings keep their original IDs and bytes for dependency references, but role enumeration, proposal replay and explicit bound entry reject them; the source remains in the common search pool and unrelated roles keep their own guards. A reviewed tag without native source evidence remains `review_required`. Never turn a deferred relation into an unbound presentation of that same role.

## Verify the installed recorder before maintenance

Run `python3 skills/photo-prompt-image-generator/scripts/photo_installed_h_f2.py
--check-runtime` from the repository root. This read-only check resolves the
selected sealed release and its bound Python, imports NumPy and that release's
actual recorder, and verifies v10 new-write support and actual-pack version
derivation. For a staged release supply both `--source-store STORE` and
`--generation-id ID`. It performs no image calls or source writes. Use the
reported `runtime_python` for standalone NumPy maintenance helpers; an arbitrary
`.venv` may lack the dependency. A working-source fix does not update installed
code: stage a reviewed member allowlist, qualify it, install without activation,
and activate only after verification. Preserve data, CURRENT and old run history.

The composer may copy an omitted disabled (`intensity: 0`) appeal-axis metadata
entry from the frozen pack. It never fills positive-intensity evidence, changes
a supplied value, writes prompt text, or supplies a reviewer/requester judgment.
Missing positive axes and conflicting values still fail the existing audit.
