### 4.1 의미 카드

각 분해된 개념에 안정적인 `term_id`, 원문 섹션·순번·표기, 한국어/영어 이름과 한정적 별칭, 정의, 동음이의, 상위·하위·부분 관계, 출처 URL과 출처가 입증한 범위, 구별·관찰 한계, 검토 상태를 둔다. `material=latex`와 `finish=high-gloss`, `wet_surface=true`는 같은 필드가 아니다. 실제 코드가 읽는 필드와 연구 메타데이터를 분리하며 새 스키마를 기존 엔진의 동작처럼 가정하지 않는다.

- 실크는 섬유, 새틴은 직조, 레이스는 구조, 페이턴트는 마감된 가죽, wetlook은 외관이다. `glossy`는 각 소재의 완전 동의어가 아니다.
- corset과 bustier는 컵·길이·지지 구조를 비교하고 보이는 채널과 숨겨진 보닝을 별도 기록한다. 바스크·롱라인 브라와의 유통명 중첩은 출처별 차이를 남긴다.
- stockings/tights/pantyhose/hold-ups/thigh-high는 다리 분리, 허리 연결, 길이, 고정 방식을 직교 축으로 둔다. 사진에서 클립이 가려지면 `unknown`, 빠진 것으로 판단하지 않는다.
- 신발은 높이(shaft), 굽(stiletto), 앞창(platform), 앞코(pointed), 여밈(lace-up), 뱀프를 따로 다룬다. 파츠 하나로 다른 파츠가 자동 생성되지 않게 한다.

### 4.3 맥락 뷰와 검색 뷰

- 연구용 `context_only` 뷰는 원문 포인터·정의·출처·구분을 담고 이미지 선택이나 후보의 권한을 주지 않는다. 관심, 심리, 재료 구성, 보이지 않는 구조, 시대와 문화의 설명은 여기에 둘 수 있다.

## 6. 빠짐없는 반영을 위한 실행 계획

1. **원문 고정과 분해:** 이 문서의 전체 대조표를 기준으로 `section/row/concept` 안정 ID, 원문 표기·정의·별칭·분류·제외 이유를 갖는 inventory를 만든다. 하나의 행이 `latex/rubber`처럼 복수 개념이면 별도 개념으로 분리한다. 처리 상태는 `included_visual`, `context_only`, `needs_evidence`, `excluded_bdsm` 등으로 남긴다. 합계가 원문 표의 행 및 분리 개념과 맞는지 자동 점검한다.
2. **개념별 직접 출처 대조:** 범주별 출처를 각 행에 일괄 상속하지 않는다. 각 중요한 구별 명제에 직접 근거를 연결하고, 위 출처가 확인하지 않는 세부 항목은 `needs_evidence`로 둔다. 보류 항목은 담당·필요 근거·검색어를 남긴다.
3. **기존 소스 실사:** 전체 candidate 및 realization별 정의·조건·효과·소유자 관계·기존 views·바인딩을 읽어 `exact`, `partial`, `conflicting`, `absent`, `unresolved`로 대조한다. CID와 근거 필드, 검색어, 수동 검토 근거를 기록한다. 단순 어휘 출현을 완전 대응으로 간주하지 않는다. 의도치 않은 BDSM 전용 연상과 중복 옵션도 확인한다.
4. **의미/후보/뷰 제작:** 원문 개념과 근거를 의미 카드에, 사진에서 검증 가능한 선택지를 후보에, 비가시적 정의는 context view에, 검토된 검색 표현만 retrieval view에 둔다. 신규 후보는 변형과 역방향 혼동 사례를 포함하되 소유자·대상·접촉·부분·개수·가림 상태를 보존한다. 구조·식별자 충돌, provenance 해시, dangling bindings, `native_approval`과 진단/positive 분리를 검사한다.
5. **고정 평가셋:** 작성자가 보지 않은 다국어 보류 질의와 기존 비교 질의를 포함한다. 최소 범주별로 직접 요청, 한국어·영어 별칭, 유사어 대조, 조합, 부정/제외, 비시각 맥락, 가려진 파츠, 명시된 재료/미상, 다중 인물 owner를 포함한다. 같은 정답 한 개만 강제하지 말고 적합 후보 집합과 부적합 이유를 먼저 동결한다. `bodystocking/body stocking`, `wetlook/wet look`, `latex/PVC`, `back seam/lacing`, `thigh-high/hold-up`, `three-quarter pose/length`를 필수 쌍으로 둔다.
6. **실험과 회귀:** 변경 전후 동일 전체 코퍼스·검색 설정·모델·고정 질의·seed·샘플 정책으로 비교하고 BM25F, dense, 결합 결과와 노출 샘플을 각각 기록한다. Recall@K, MRR 또는 nDCG, 혼동 오탐, 제외 위반, 지연·인덱스 크기를 함께 보고, 추가된 후보가 다른 기존 영역의 품질을 해치지 않는지 점검한다. 구축자가 만든 개발 질의와 독립 보류 질의를 분리한다. 전역 F2 검색의 실제 조건을 유지하며 랭킹/샘플을 편의상 바꾸지 않는다.
7. **빌드·설치:** 새 모듈과 현 manifest를 충돌 없이 결합하고 전체 소스 구조 검사 → 봉인된 후보 스냅샷 → 색인·벡터 빌드 → 동일 release 검증 → 비활성 설치 및 명시적 generation 테스트를 거친다. 활성 포인터를 바꾸기 전 현재 동시 변경과 체크섬을 재확인한다. 설치만으로 native 자격, 요청 적합성, 프롬프트 채택, 이미지 품질이 증명되지 않는다. 이전 릴리스와 기존 실행 기록을 보존한다.
8. **이미지 평가와 수용:** 별도로 선택된 성인 비-BDSM 사례에서 동일 요청·설정으로 전후 결과를 비교하고, 각 파츠·관계의 보임/가려짐/오류를 독립 판정한다. 소수 생성이나 호출 성공은 개선의 증거가 아니다. 모델·시드·선택 편향·정책 거절을 기록하며 필요한 반복 수와 사전 정의된 판정 기준을 두고 최종 사용자 수용을 별도로 기록한다.

### 완료 조건과 미해결

완료란 모든 원문 행이 포함·보류·제외 중 하나로 설명되고, 포함된 각 개념에 근거 범위·기존 후보 대조·데이터 연결이 있으며, 전체 회귀와 독립 보류 평가에서 실패가 해소되거나 명시적으로 남은 상태다. 현재는 **원문 범위 대조와 일부 범주 출처 조사만 완료**했다. 개별 개념별 독립 근거, 전체 후보 의미 대조, 새 데이터·인덱스·검색 평가·이미지 비교는 아직 수행하지 않았다. 이 문서의 예시 수나 정규식 수치를 완성도나 개선율로 해석해서는 안 된다.
