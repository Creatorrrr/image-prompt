# Global retrieval contract

Freeze and validate the requester envelope, v3 authorial core, creative controls and embodiment review before reading candidates. The default public CLI searches every positive native record compatible with its independently frozen subject/context/exclusions. Slot tags describe roles; they are neither storage parents nor an admission filter.

One global record contributes one BM25F document and one vector. Each slot independently fuses exact cosine and global lexical ranks under `photo-slot-retrieval/v2`. The public `photo-candidate-pack/v9` stores each retrieved payload once in `candidate_pool`; role and optional presentation views use native references. It admits at most 64 unique candidates with role caps 4/2 after the slot searches. Untagged records are discoverable. Inspect the complete authored record and source constraints before adoption; a rank or tag grants no permission.

A private `photo-runtime-receipt/v3` pins source, binding, catalog, shared layout, per-slot query vectors and algorithm to one immutable V3 generation. The auditor independently reconstructs allowed IDs, exact lexical/cosine scores, allocation and full-tree pruning proofs from those recorded vectors using the needed shards. Complete source/index verification belongs to publication and explicit offline maintenance. Missing query execution fails `hybrid_required`. Diagnostic `keyword_only` records embedding as not_requested. Neither lane absence nor a zero-hit executed lane is reported as the other.

Exact requester-defined profile meanings and complete opt-in contracts remain distinct from approximate discovery. Candidate retrieval cannot invent people, change owner/topology/direction, supply protected effects or turn an optional match into a hard obligation. All optional candidates may be rejected while retaining the independently authored baseline.

## Independent slots and lazy shared search

The operating path is `photo_slot_queries` → `photo_slot_retrieval` → `photo_sharded_search` with `SearchReader`. Every requested/active slot searches the entire context-eligible positive common pool. Persistent bindings are guarded source relations, not lookup partitions; request-local role proposals preserve original conditions/effects and add no source tags. Global BM25F DF/length normalization stays identical across shards. Exact cosine uses original float64 values. Quantized coordinates supply outward residual bounds only; they do not replace exact ranking vectors.

Both lanes and RRF execute independently for each slot before the global unique 64 and core/support 4/2 display limits. A slot excluded from display by budget still has a completed search trace. Missing provider evidence is an error, rather than an automatic keyword fallback. Corpus, catalog, binding, layout, per-slot context, ranks, role proposals and pruning proofs bind the V9 pack/V3 receipt. The native view dereferences each candidate payload once with presentation-specific eligibility; optional source meaning never changes because it was presented in another role.

Compact metadata is eagerly available; payload, posting and exact vector bodies are loaded on demand. A requested vector leaf can be a checksummed extent inside a physical pack. Only that byte range is read. Cache and descriptor limits are bounded, and unsafe pruning is rejected by independent proof/rank audits. The separate offline evaluator reads the full source and all vectors to produce the qualification oracle. See [maintenance](maintenance.md) for publication and exact closure verification.
