# 후보 회수 개선 계획 — 검색 lane 분리와 제한된 대조

2026-10-18 · Claude 2회 논의·재검토 반영 · 구현·운영 반영 전

## 목적과 유지할 조건

창작 소재 탐색에서 적합한 후보를 더 잘 회수한다. 부적합 후보 수나 precision은
주요 실패 기준으로 삼지 않는다. 공통 positive 풀 18,180 CID / 18,182 actual
RID 전체를 검색하고, 슬롯당 BM25F 1회·로컬 embedding/cosine 1회를 유지한다.
한 슬롯의 두 lane에는 동일한 단일 검색어를 쓴다. RRF10, CID 중복 제거,
top8, F2 가중치·길이 정규화, 로컬 모델과 prefix도 이번 라운드에서 고정한다.

Gemini, 원격 fallback, reranker, 추가 검색어·검색 lane, 슬롯 태그 사전 제한,
전수 의미 검토와 전수 데이터 보강은 수행하지 않는다. 기존 96건 원문 검토와
41건 보강, 671건 판정 및 126개 명시적 적합 연결을 재사용한다.

## 확인한 사실과 채택하지 않을 추론

설치 A는 55/126·28/40, 두 lane에 보강을 넣은 C는 55/126·29/40이다.
검토 문서가 바뀐 30개 적합 연결에서는 17→20, 나머지 96개에서는 38→35였다.
이는 층화 기술 통계이며 무작위 실험의 처치 효과나 전수 보강 효과 추정치는 아니다.
전수 보강하면 순위 손실이 없어지거나 특정 점수에 도달한다고 외삽하지 않는다.

저장 점수를 독립 결합한 D1(C의 BM25F+A의 dense)은 56/126·29/40,
보강 대상에서는 21/30이다. D2(A의 BM25F+C의 dense)는 55/126·29/40이다.
D1은 기존보다 1건 더 회수하므로 가장 저렴한 다음 대조로 삼는다.
이는 사후 점수 결합이며 구현·새 세대 검증·품질 통과를 의미하지 않는다.

A의 lane별 top8 적합 연결은 BM25F 51, dense 34, 합집합 66, 최종 RRF 55다.
합집합 안의 적합 연결 12건이 최종에서 빠지고, 합집합 밖의 1건이 최종에 들어왔다.
합집합은 최대 16 CID이므로 66을 달성 가능한 실제 Recall@8로 보고하지 않는다.

Claude의 RRF k/일부 quota 재계산은 현행보다 나은 결과를 찾지 못했다.
이 결과로 모든 융합 정책에 가능성이 없다고 단정하지 않으며, 이번 라운드의
예산을 문서·검색어 분리에 집중하기 위해 융합 변경은 제외한다.

기존 적합 후보가 top8에서 빠지면 대체 후보의 판정 여부와 무관하게 알려진
적합 연결 손실로 센다. 미판정 대체 후보는 unknown이며 negative로 세지 않는다.
서로 다른 두 사실을 섞어 손실을 삭제하지 않는다.

## 1단계 — 기준선과 진단 증거 고정

현재 설치 세대와 코드·모델 binding, query, 원문, 리뷰, 판정의 hash를 고정한다.
A/C/D1/D2 전체 순위와 목표별·슬롯별·보강 노출별 손익을 저장 점수에서 재현한다.
A에서 적합 0건인 12개 목표와 각 positive의 양 lane 순위를 기록한다.
Q1 작성에 사용할 원 요청·장면 의도·슬롯 목표의 실제 출처도 확보하고 봉인한다.
확보하지 못한 뜻을 후보/판정에서 역으로 복원하지 않는다.
한 lane 상위권/양쪽 심층은 실패 위치에 대한 관측으로만 분류한다.
그것만으로 질의 또는 데이터가 원인이라고 확정하지 않는다.

- 새 검색·모델·판정 0회. 새 진단 스크립트와 입력 manifest만 추가한다.
- 진행 조건: A 55/28, C 55/29, D1 56/29, D2 55/29와 전체 순위가 정확히 재현됨.
- 불일치 시 구현 실험으로 넘어가지 않고 원인을 규명한다.
- 오래된 EVALUATION.json의 RRF30 설명은 역사 자료로 보존하고,
  이번 실행 계약에는 실제 설치 H-only/F2/RRF10을 명시한다.
- 검증 후 커밋한다. 이미 알려진 D1 결과를 사전 예측 성공으로 세지 않는다.

## 2단계 — sparse와 dense의 독립 투영 계약

원문 정본·실제 RID·조건·효과·binding은 그대로 보존한다. 검색 파생물만 분리한다.

- sparse: 기존 F2 단서와 필드 소유권을 보존하고 승인된 설명·alias만 추가한다.
- dense: D1에서는 기존 D와 벡터를 정확히 유지한다. 후속 대조에서만 검토 요약을
  넣으며, sparse alias를 자동 복사하지 않는다.
- lane별 레시피 ID, 텍스트/필드 hash, 리뷰 hash, 원문 pointer, 실제 RID와
  source hash, 임베딩 입력·벡터 실행 증거를 독립 결속한다.
- 서로 다른 lane의 token Counter가 같아야 한다는 규칙을 제거하되,
  sparse 내부의 단서 누락·중복 소유권 검증은 유지한다.

대체 불변식은 다음과 같이 명시한다.

1. sparse의 모든 값은 기존 native part 또는 승인된 review summary/alias에서만
   유래한다. 값별 source pointer 또는 review hash를 결속하고 허용 집합 밖 값은 거절한다.
2. dense는 D1에서 기존 expected D와 정확히 같고, D1b에서 expected D와
   선언된 review summary 연결로 정확히 재구성돼야 한다. 임의 문자열은 거절한다.
3. 같은 CID/RID/source hash에 승인 리뷰를 sidecar로 결속한다. native corpus의
   조건·효과·binding에 새 의미나 권한을 기록하지 않는다.

현재 설치 포맷은 문서와 F2 파일을 따로 저장하지만 generation builder는
양자의 token 일치와 기존 원문에서의 필드 재구성을 강제한다.
따라서 컴파일러 한 파일만 바꿔 끝내지 않는다. `photo_candidate_documents.py`와
새 builder/검증기/manifest 계약·실행 코드 binding까지 함께 정비한다.
설치 cache의 봉인된 코드는 직접 편집하지 않고 새 Git 소유 구현과 세대를 만든다.
기존 receipt는 원래 봉인된 세대에서 계속 재생한다.

검증: RID 교차, source/review 변조, 근거 없는 추가, sparse 단서 삭제,
벡터 proof 불일치를 거절한다. 기존 관련 72개 회귀 검사와 필요한 계약 검사를
통과한 뒤 커밋한다. CURRENT와 설치 선택 파일은 변경하지 않는다.
정확성 검증을 통과한 독립 투영 계약과 builder는 이후 품질 HOLD와 무관하게
미활성 자산으로 보존한다. 품질 미달을 이유로 검증된 출처 계약까지 되돌리지 않는다.

## 3단계 — D1을 실제 전체 풀 경로로 검증

보강 41건을 sparse에만 반영하고 dense는 A를 유지한다. 새 로컬 임베딩과
새 의미 판정은 없다. 별도 시험 세대에서 각 슬롯 1+1 검색을 실제 실행한다.
원본 query/후보 집합/정규화 통계/벡터 binding을 고정한다.

진행 조건은 사후 재결합 D1과 **전체 순위·top8·점수·56/29가 일치**하고,
dense 벡터가 A와 같으며 원문/조건/효과가 바뀌지 않는 것이다.
이는 정확성 확인이며 운영 품질 PASS가 아니다. 검증 후 커밋한다.
56/126이 62/126에 못 미치는 것은 이미 알려진 상태이며, 이 단계에서 기준을 바꾸지 않는다.

## 4단계 — D1b: 요약만 dense에 넣는 단일 대조

D1의 sparse를 그대로 두고 dense에는 검토된 English summary만 추가한다.
alias는 넣지 않는다. 기존 41건의 검토만 사용하고 새 원문 보강은 하지 않는다.
검토 요약이 여러 문장이면 임의로 첫 문장만 잘라 관계·조건을 없애지 않는다.
변경 입력은 최대 41건, 새 레시피 1개, arm 1개로 제한한다.

전체 풀에서 H와 RRF/F2를 고정해 D1 대비 dense 추가의 효과만 비교한다.
선택 순서는 전체 FIT@8, 목표 Hit@8이며 동률이면 더 단순한 D1을 선택한다.
전체 FIT이 D1 미만이거나 목표 Hit이 A 미만이면 D1b를 폐기한다.
cosine 순위 하락 수는 진단으로 기록하며 임의의 2건 제한을 품질 gate로 쓰지 않는다.
실패 후 요약 길이·alias·가중치 변형을 추가 탐색하지 않는다. 검증 후 커밋한다.

## 5단계 — 필요 시 Q1: 0건 목표의 검색어만 한 번 개선

앞선 대조가 기존 운영 기준 62/126·목표 최소 28/40에 못 미친 경우에만 실행한다.
1단계에서 고정한 12개 0건 목표의 원 요청·장면 의도·슬롯 표현 목표를 바탕으로
직접 단일 검색어를 작성한다. 작성 입력에는 목표 CID, 정답 목록, 후보 원문,
순위를 제공하지 않는다. 과거 판정을 이미 접한 한계는 기록한다.

한 목표의 검색어에는 표현하려는 대상·행동·관계·필요 조건을 담되,
관련 없는 장면 디테일은 덜어낸다. 새 query는 최대 12개이며 두 lane이 같은
query를 한 번씩 검색한다. 다른 목표는 기존 H를 유지한다.
대상은 **A 기준 12개 전부**로 고정한다. D1/D1b에서 이미 회수된 목표도
제외하거나 교체하지 않고 별도 손익을 보고한다. 새 query 로컬 임베딩은
최대 12건이며 문서 벡터는 이 단계에서 바뀌지 않는다.
4단계에서 선택한 문서/융합을 고정해 query 효과만 비교한다.
검색어를 결과를 보고 다시 고치지 않는다.

`QUERY-PROVENANCE.json`에 절별 원 요청/의도/목표 pointer·원문 quote와
바꿔 쓴 의미의 대응을 기록하고 점수 전에 봉인한다. 검색어를 원문의 문자 그대로로
제한하거나, 드문 단어라는 이유로 금지하지 않는다. 후보/정답에서 가져온 표현을
원 요청의 뜻으로 둔갑시키지 않는지를 감사한다. 원 뜻을 확정할 출처가 없으면
해당 query를 추측해 작성하지 않고 Q1을 보류한다.

Q1은 특정 목표 ID나 CID에 붙이는 운영 예외가 아닌 일반 검색어 작성 규칙이다.
새 요청 6개 목표에도 같은 규칙을 적용한다. 실험 arm을 비교해도 운영에서는
승자 query 하나만 쓰며 기존 H와 Q1의 두 결과를 합치지 않는다.
회수된 후보의 기존 순위 깊이와 변화는 기록하되, 얕은/깊은 이동만으로 의미 개선이나
원인을 단정하거나 별도 성공 기준을 만들지 않는다.

이번 계획의 구현 후보는 **D1, D1b, Q1 최대 3개 arm**이다.
기존 A/C와 사후 교차 점수 진단은 새 정책 탐색 횟수로 둔갑시키지 않는다.
최종 선택은 전체 FIT, 목표 Hit, 단순성 순서로 고정하며, 기준 미달이면
이번 라운드를 HOLD로 끝낸다. 검증 후 커밋한다.

## 6단계 — 승자 1개를 새 요청으로 확인

개발 기준을 통과한 승자 1개만 A와 비교한다. 새 요청 3개·목표 6개를
후보·정답·검색 결과를 제시하지 않은 입력에서 작성하고 query까지 먼저 동결한다.
결과를 본 후 요청·목표·query를 바꾸지 않는다. 생성한 검증 요청임을 밝히며
사용자 실요청의 대규모 평가라고 주장하지 않는다.
슬롯 배분은 결과를 보기 전에 composition 2, lighting 2, action 1,
body_pose 1로 고정한다. 반복 사용한 기존 실패와 같은 표현을 복제하지 않는다.
실제 작성 입력과 봉인 시점을 남긴다. A와 승자에 query가 다르면 서로 다른
벡터는 최대 12건이며, 같으면 같은 증거를 재사용한다.

양 arm의 top8 합집합을 CID/RID 기준으로 중복 제거해 **새 목표별 판정 최대 96건**만
진행한다. arm·점수·순위를 가린 뒤 원문과 적용 조건을 대조하여
‘이 목표에 유용한 창작 소재인가’를 판정한다. native 권한 판정으로 바꾸지 않는다.
애매한 연결은 unknown으로 남기고, 어느 arm에 유리하게 FIT으로 올리지 않는다.
판정자는 새 요청 작성/정책 선택의 점수 정보와 분리된 입력을 사용한다.
목표별 유용 소재 수(0–8), 소재 1개 이상인 목표 수, unknown 수를 모두 기록한다.

주 확인 지표는 유용한 소재를 1건 이상 찾은 목표 수이며 A 이상이어야 한다.
각 arm의 알려진 유용 연결 수도 함께 기록하고 A 미만이면 채택하지 않는다.
신규 판정은 이 확인 집합에만 사용하고 기존 126개 분모를 바꾸지 않는다.
A가 6/6이면 그 결과는 유지 확인이며 추가 개선의 증거로 해석하지 않는다.
결과를 보고 요청이나 후보 판정을 더 늘리지 않는다. 검증 후 커밋한다.
일부 목표가 회귀해도 전체 목표 수와 연결 수 기준으로 판단하며 목표별 완벽 무회귀를
요구하지 않는다. 동점은 추가 개선 증거로 주장하지 않고 더 단순한 구성을 우선한다.

## 7단계 — 최종 품질 gate와 중단 조건

운영 전환을 위해 모두 충족해야 한다.

1. 기존 126개 적합 연결에서 최소 **62/126**, 지원 목표 최소 **28/40**.
2. 새 요청의 유용 소재 목표 수와 확인된 유용 연결 수가 A 이상.
3. 전체 후보/RID/원문/조건/효과/기존 binding 무결성과 lane별 출처·벡터 증거 통과.
4. 관련 회귀 검사, 슬롯당 실제 검색 1+1, 오프라인 실행 및 재개·receipt 검증 통과.

보강 노출군 성능은 설명 자료이며 전체 품질 gate를 대체하지 않는다.
부적합 개수, precision, 모든 목표의 개별 무회귀는 조건으로 추가하지 않는다.
기준 미달이면 기존 H-only+F2를 유지하고 추가 arm·전수 보강으로 확대하지 않는다.
구현 정확성 PASS, 탐색적 품질 결과, 운영 승격을 별도 기록하고 커밋한다.

## 8단계 — 통과한 새 세대의 설치와 실제 스킬 검증

gate를 통과한 경우에만 검증한 코드·원문·lane별 문서/통계·벡터·proof를
포함하는 self-contained H-F2 세대를 설치한다. native CURRENT는 유지한다.
기존 세대는 receipt 재생과 복구용으로 보존한다.

연구 checkout과 원래 build cache 접근·네트워크를 차단한 상태에서 평범한
`photo_workflow.py retrieve --run RUN` 진입점, view, compose-audit, deliver를
검증한다. 필요 시 설치 선택 manifest만 새 검증 세대로 갱신한다.
기본 경로의 실제 실행과 검색 횟수·receipt·source 효과를 다시 확인하고,
실패하면 선택 manifest를 복구한다. 완료 후 커밋한다. push는 별도 요청 범위다.
전환 전에 선택 manifest 복구를 실제로 시험하고, 전환 후 기존 run 1건의
receipt가 원래 세대에서 재생되는지 확인한다.

현재 요청에서는 위 계획과 Claude 검토만 작성한다. 구현·검색 기본 경로·CURRENT는
변경하지 않는다.
