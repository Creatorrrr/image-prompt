# 사진 스킬 운영·재현 보존 및 실험·산출물 정리 계획

2026-10-19 · 계획 작성 완료 · 정리 실행 전

## 목적과 고정 조건

현재 설치된 H 단독+F2의 동작과 과거 실행 재현을 유지하면서, 비활성 실험·평가를
운영 개발 경로에서 분리하고 참조 없는 생성 산출물을 정리한다. 검색 품질 개선이나
새 구조의 운영 승격은 이 계획의 목적이 아니다.

- 공통 positive 풀 전체, 슬롯당 BM25F 1회·로컬 임베딩/cosine 검색 1회,
  동일한 단일 query, F2·RRF10·top8·CID 중복 제거를 유지한다.
- 모든 기존 CURRENT와 설치 선택 파일 `retrieval-runtime.json`을 유지한다.
  설치된 세대의 코드·데이터·모델·receipt를 편집하거나 재봉인하지 않는다.
- 기존 modified·staged·untracked 작업 파일의 경로·내용·Git 상태를 보존한다.
  별도 작업 트리도 보호한다. stash/reset/clean 및 작업 트리 제거는 하지 않는다.
- 기존 미추적 파일은 작업 여부가 불명확하면 보호한다. ignored라는 사실이나
  오래된 날짜, 파일명에 test/legacy/v1이 있다는 이유로 삭제하지 않는다.
- Gemini, 원격 fallback, 새 의미 판정, 전수 의미 검토, 후보 보강은 실행하지 않는다.
  검증은 기존 질의·벡터·판정·점수와 소수의 오프라인 실행을 재사용한다.
- 참조가 불명확하거나 보호 대상과 겹친 항목은 보류한다. 정리 완료를 위해
  보호 조건이나 과거 재현 범위를 축소하지 않는다.

## 현재 확인한 기준과 범위

계획 작성 시 main HEAD는 `45b60bb08`이며 기존 변경은 modified 176개,
untracked 7,875개다. 이는 조사 시점의 수치이고 실행 직전에 다시 수집한다.

설치 선택은 H 세대 `663038595155d8d48bfa20339bbe7a5c3128eea4ce504900c9a8fdadd34c152b`,
native 세대 `9649504ffbcd1ebe7d9aedf9eab821fc18aa0300a8f70b65dbdd145b435ec1da`,
코드 집합 hash `493f1830db1f564c8acfe0218a24c8445990aa3ec968b948e80d187cfa9f7f90`다.
경로는 환경 변수 override와 run별 binding까지 포함해 실행 시 확정한다.

main의 Python 원본 83개와 설치된 94개는 같은 소스 집합이 아니다. 공통 파일
중 25개가 다르고 설치본의 21개는 main에 없다. 확인한 핵심 H-F2 모듈은
`codex/slot-search-relevance` 작업 트리의 추적 파일과 설치본이 동일하다.
main 전체를 최신 운영 소스라고 간주하거나 다른 작업 트리를 통째로 머지하지 않는다.

최근 D1·D1b·Q1은 품질 HOLD로 비활성이며 H 단독+F2가 운영 기준이다.
native fallback은 이미 pack이 있는 기존 native run에 사용되고, H-F2 자체도
native 구성·권한 감사에 의존한다. 이전 검색 방식과 현재 공통 감사 코드를 구분한다.

정리 범위는 사진 스킬, 관련 테스트·연구 증거, 이들이 참조하는 생성 store다.
다른 스킬, 사용자 이미지·최종 프롬프트, 실행 ledger, 모델 설치와 다른 작업 트리는
자동 정리 대상에 포함하지 않는다.

## 1단계 — 보호 목록과 작업 기준선 고정

원본·설치·실행·연구 경로를 읽기 전용으로 조사하고 다음을 기록한다.

- main과 관련 작업 트리의 HEAD, index, staged/unstaged/untracked 경로와 내용 hash.
- CURRENT, 설치 선택 파일, 실제 선택된 H/native 세대, 모든 issued run의
  store/generation binding, receipt·receipt index, 로컬 모델·Python 환경 연결.
- 후보 원문·카탈로그·binding, authoring 정본, 고유 리뷰·판정, 고정 평가 입력,
  코드·데이터 manifest, frozen 코드 및 hash 참조.
- 정리 후보의 경로·종류·파일 수·논리 크기·Git 추적 상태·symlink/hardlink 관계.
  실행 중인 프로세스와 열린 파일도 확인한다.

운영·과거 재현·유지보수·기존 작업을 포함하는 `PROTECTED.json`, Git 기준선,
산출물 목록을 별도 정리 증거 디렉터리에 저장한다. 이 단계에서는 후보를 이동하지 않는다.

**통과 기준:** 각 활성 pointer의 전체 참조 집합과 조사 가능한 모든 issued run의
binding을 확보한다. 외부 store나 실행 기록을 확인하지 못한 경우 관련 항목을 보류한다.
보호 목록과 겹치는 항목은 삭제 allowlist에 들어갈 수 없다.

## 2단계 — 운영 소스의 소유·재설치 기준 확보

설치된 94개 Python 파일과 대응하는 Git commit/path/hash를 대조한다.
운영 코드의 기준을 main·연구 checkout·설치 cache 중 어느 파일이 우연히 최신인지에
의존하지 않도록 고정한다.

현재 코드는 설치 세대에서 그대로 실행한다. main에 새 운영 구현을 덮어쓰는 대신,
Git으로 관리하는 불변 소스 묶음과 `SOURCE-LOCK.json`을 마련한다. 이 묶음은
선택된 코드 집합을 정확히 재구성하는 보관물이며 새로운 실행 진입점이 아니다.
추적된 원 commit에서 필요한 파일만 결정적으로 추출하고 설치본과 비교한다.
기존 main의 생성기·감사기 미커밋 변경은 덮어쓰지 않는다.

lock에는 파일별 hash, 원 commit/path, 설치 세대, Python·모델 lock,
데이터 manifest와 확보된 배포 입력을 연결한다. 운영 소스 묶음은 필요한 코드를
한 곳에 보존하며, 여러 날짜별 폴더에 같은 원본을 다시 복사하지 않는다.

설치 세대에 포함된 `test_photo_recall_first.py`도 현재 코드 봉인의 일부이므로
그대로 보존한다. 향후 배포 패키징에서 테스트를 제외하는 일은 별도 배포 변경이며
이번 정리를 위해 설치된 세대를 바꾸지 않는다.

**통과 기준:** 다른 작업 트리와 build cache를 읽지 않는 임시 환경에서 코드 묶음을
복원해 94개 전체 hash와 코드 집합 hash가 같다. 현재 설치 선택과 세대가 그대로이며,
기존 self-contained release 복사·검증 경로와 그 데이터 의존성을 설명할 수 있다.
원본 Git 출처나 재설치 입력을 확보하지 못하면 관련 경로의 정리는 진행하지 않는다.

## 3단계 — 파일 단위 참조 그래프와 정리 목록 확정

정적 import 외에 동적 import, subprocess CLI, runpy/spec loader, 문서의 실행
명령, manifest member, 고정 hash, 원문 pointer, receipt·run 경로를 함께 추적한다.
보존하는 실험의 재현 의존성도 조사한다. Python import가 없다는 사실만으로
미참조라고 판정하지 않는다.

각 경로를 다음 중 하나로 분류하고 이유와 역참조를 기록한다.

| 분류 | 처리 |
|---|---|
| KEEP_RUNTIME | 현재 운영 코드·데이터·모델·검색·감사·전달 경로 보존 |
| KEEP_REPLAY | 과거 issued run 재현에 필요한 코드·세대·벡터·receipt 보존 |
| KEEP_MAINTENANCE | 설치·검증·정본 관리에 필요한 도구 보존 |
| ARCHIVE_EXPERIMENT | 비활성 구현·평가와 재현 입력을 함께 보관한 뒤 개발 경로에서 분리 |
| GC_DERIVED | 고유 원본이 없고 참조 없는 생성물만 격리 검증 후 제거 |
| DEFER | 변경 중이거나 참조·출처·복원 가능성이 불확실해 원래 위치에 유지 |

`ACTION-LIST.json`에는 정확한 경로·hash·처리 이유·보호 충돌·재현/복원 방법을
남긴다. glob만으로 삭제 범위를 표현하지 않는다. 사용 중인 파일과 기존 미커밋
작업은 별도 작업이 끝날 때까지 보류한다.

**통과 기준:** 각 처리 대상에 보존/이동/제거의 근거가 있으며 모든 보호 대상과
충돌하지 않는다. 13개 shard 중 현재 manifest가 선택하지 않은 12개도 이 조사 전에는
제거 가능 항목으로 확정하지 않는다.

## 4단계 — 비활성 실험·평가를 재현 묶음으로 분리

우선 대상은 후보 보강 A/B/C, 독립 lane D1/D1b/Q1, 과거 순위·reranker·dual-query
실험과 날짜별 일회성 평가 드라이버다. 다른 작업 트리의 prototype은 현황과 관계를
기록하되 그 작업 트리 자체를 이동·삭제하지 않는다.

- `photo_candidate_authoring/review/documents/evaluation/lane_documents/lane_generation`
  계열은 파일별 역할을 확인하고 비활성 부분을 실험 영역으로 옮긴다.
- 구 documents 모듈의 tokenizer·field_index처럼 다음 실험이 사용하는 공통 기능은
  의존성 단위로 함께 보관한다. 단순히 v1이라는 이유로 구 compiler를 삭제하지 않는다.
- `candidate-authoring/v1`의 정본과 원문, 96건 검토·41건 보강, 671건 기존 판정,
  기존 평가의 질의·벡터·점수·기준·결과는 보존한다. 유일한 원본은 생성물이 아니다.
- 참조가 연결된 여러 실험은 하나의 재현 집합으로 묶거나 공유 보관물을 명시한다.

해시로 고정된 과거 파일은 내용을 수정하지 않는다. 원래 상대 경로, 필요한 원본
코드·입력과 의존성 lock을 보관물 안에 유지한다. 새 복원 도구는 임시 루트에서 그
트리를 복원하고 실행하며 기존 파일을 덮어쓰지 않는다. 과거 FREEZE를 새 경로의
hash로 다시 써서 과거 결과가 처음부터 같았던 것처럼 만들지 않는다.

기존 경로를 외부 실행 기록이나 보호된 파일이 계속 참조한다면 해당 경로는 유지한다.
현재 작업 때문에 변경 중인 연구 파일도 원래 위치에 남기고 보류 목록에 넣는다.
보관물의 목록·요약·결과·복원 명령은 저장소에서 바로 찾을 수 있게 유지한다.

**통과 기준:** 복원한 최신 보존 평가를 네트워크와 원래 연구 checkout 없이 실행해
저장 순위·Recall 집계·HOLD 판단을 재현한다. 최신 재현 입력의 전수 해시를 검증하고,
분리한 과거 실험별 고유 계약 검사를 실행한다. 대규모 검색이나 새 의미 판정은 하지 않는다.
각 묶음의 복원 검증이 끝난 뒤에만 원래 개발 경로의 깨끗한 파일을 제거한다.

## 5단계 — 운영 회귀 검사와 실험 평가 분리

테스트를 파일 나이가 아니라 보호하는 동작에 따라 분류한다.

- 기본 회귀 검사: 설치 선택, 봉인·변조 거부, 공통 풀·CID/RID, 실제 1+1 검색,
  F2·RRF·동률 순서, 로컬 임베딩 binding, precore 격리, native 조건·효과·권한,
  compose/view/deliver, 기존 receipt 재생을 유지한다.
- 과거 실험의 고정 arm·임계값·특정 집계만 검사하는 테스트는 해당 재현 묶음으로 옮긴다.
- 한 테스트 파일에 공통 계약과 실험 기준이 섞여 있다면 책임을 분리한다.
  테스트에서 공유하는 fixture를 옮길 때에는 일반 helper로 분리하고 참조를 검증한다.
- full-scan oracle과 vector-map 검증은 유지보수/검사 전용으로 보존한다.
  운영 검색의 fallback으로 연결하지 않는다.

실행 명령은 `운영 H-F2 회귀`, `기존 native/replay 회귀`, `선택한 archive 재현`으로
구분한다. main 소스만 검사하고 설치된 H-F2도 검사했다고 보고하지 않는다.
과거 RRF30 oracle이나 임의 정책 unit test를 현행 RRF10에 억지로 맞추지 않는다.

**통과 기준:** 실제 설치 코드 대상 H-F2 검사와 기존 native/replay 검사가 각각 통과하고,
실험 제외 후에도 원래 보호하던 운영 계약이 빠지지 않는다. 검사 목록·건수와 실행한
코드/세대 hash를 기록한다. 아카이브에서 옮긴 테스트도 독립 실행 가능해야 한다.

## 6단계 — 증명된 미사용 로직만 좁게 제거

이 단계는 비활성 코드 분리 후 남은 실제 미사용 부분만 대상으로 한다.

- `legacy_camera_clauses`처럼 소스·테스트 호출이 없는 함수는 동적 호출·외부 진입점과
  과거 재현 참조를 확인한 뒤 작업 소스에서 제거할 수 있다.
- Gemini 신규 호출·과거 전환/rollback 지원은 현재 유지보수 의존성이 없을 때 정리한다.
  과거 receipt의 provider 증거를 읽는 검증기는 신규 원격 호출 코드와 구분한다.
- keyword-only 진단, 기존 native run 분기, 옛 계약을 거절하는 검사, precore bridge,
  native 감사·권한 코드는 이름이 오래되었다는 이유로 제거하지 않는다.
- 원본 모듈 전체에 운영·유지보수·연구 기능이 섞여 있으면 필요한 공통 함수부터
  분리하되, 보호된 미커밋 파일이나 설치 봉인을 건드려야 한다면 해당 변경은 보류한다.

**통과 기준:** 제거 목록의 역참조가 없고 관련 회귀 검사·기존 실행 재현이 통과한다.
공유 소스 fingerprint 때문에 기존 경로가 막히면 변경을 되돌리거나 보류한다.
이를 해결하기 위해 CURRENT나 설치 세대를 전환하지 않는다.

## 7단계 — 미참조 생성물을 격리·검증한 뒤 정리

후보는 날짜별 runtime-store/source-data의 반복 복사본, 구 shard 세대,
불필요한 중간 출력과 계산 캐시다. 기존 사용자 실행 산출물·이미지·ledger·고유 판정은
이 범주의 자동 제거 대상이 아니다.

제거하려면 다음 조건을 모두 충족해야 한다.

1. 활성 manifest, 모든 보호된 CURRENT, 설치 선택 및 issued run/receipt가 참조하지 않는다.
2. 정본·고유 리뷰·판정·frozen 입력·필수 archive 재현 파일이 아니다.
3. 기존 미커밋 작업, 다른 작업 트리, 열린 파일·실행 중 작업과 겹치지 않는다.
4. 생성 출처가 확인되고, 필요한 복원 수단이 검증되었거나 검증된 동일 복사본이 있다.
   크기·파일명만으로 중복을 판정하지 않는다.
5. symlink 대상과 hardlink 공유 관계까지 확인했으며 보호 파일에 영향을 주지 않는다.

실행 직전에 hash·pointer·작업 상태·열린 파일을 다시 확인한다. 검증으로 확정한 정확한
경로 목록만 같은 파일시스템의 임시 격리 위치로 rename하고, 원래 위치에서 파일이
없는 상태로 운영 검사·기존 replay·선택 archive 재현을 실행한다.
실패하면 즉시 원래 경로로 복구하고 해당 묶음을 보류한다. 충돌 경로는 덮어쓰지 않는다.

통과한 묶음만 격리본을 제거한다. 설치된 불변 세대를 파일 단위로 잘라 정리하지 않는다.
새로 생성된 임시 검사 파일도 이번 실행 소유가 확인된 것만 정리한다.

**통과 기준:** 원래 경로 부재 상태에서 관련 검사가 통과하고 보호 hash가 유지된다.
제거 경로·hash·논리 크기·복원 수단을 기록한다. 관측한 전체 점유량을 곧바로
확보 가능한 공간으로 보고하지 않는다.

## 8단계 — 실제 경로 확인과 결과 문서화

기존 질의와 벡터를 사용해 소수의 고정 사례를 임시 run/store에서 검사한다.
현재 설치된 H-F2의 실제 진입·검색·view·구성 감사·deliver와 기존 native/H-F2
receipt 재생을 분리해 확인한다. 원본 issued run과 운영 store에는 새 결과를 쓰지 않는다.
선택된 세대와 원본 입력을 읽기 전용으로 사용하고 새 출력은 검사 소유 경로에 둔다.

최종 완료 조건은 다음과 같다.

- H/native 설치 선택, 모든 기존 CURRENT와 설치 세대의 보호 파일 hash가 동일하다.
- 고정 query/벡터에 대한 전체 풀·1+1 호출·점수·top8·CID/RID가 정리 전과 같다.
- 기존 run의 receipt·원래 코드/세대를 이용한 감사 결과가 같다.
- 실험 재현은 보관물과 문서화된 오프라인 복원 명령으로 가능하다.
- 기존 미커밋 작업의 경로·내용·staged 상태가 유지된다.
- 운영 경로에 연구 checkout·실험 evaluator·임시 저장 위치 의존성이 새로 생기지 않는다.
- 다른 스킬·worktree·사용자 결과물에는 변경이 없다.

동시 작업으로 보호 파일이 달라지면 자동으로 원복하지 않는다. 정리 실행이 바꾼 항목만
복구하고 관련 정리를 중단한다. 새 기준선으로 덮어써서 통과 처리하지 않는다.

최종 리포트에는 보존·아카이브·실제 제거·보류를 나누어 기록한다. 경로별 처리 내역,
실행한 검사, 미실행 범위, 논리 용량과 실제 공간 변화, 복원 명령을 포함한다.
판별이 끝나지 않은 항목이 남으면 명시적으로 보류 완료로 보고한다.

## 실행·변경 관리

순서는 1→2→3→4→5→6→7→8이며, 보존·복원 검증에 실패한 대상은 후속 제거에
포함하지 않는다. 운영 변경을 동반하는 범위 확대나 품질 실험은 별도 작업으로 남긴다.

실행을 시작하면 단계별 검증 결과와 좁은 변경 목록을 남긴다. 커밋할 때는 이번 변경만
명시적으로 stage하고 기존 index와 미커밋 작업을 보존한다. 기존 staged 변경이 있으면
별도 index 등으로 분리하며 `git add -A`로 섞지 않는다. 생성물 제거는 Git 커밋만으로
복구되지 않을 수 있으므로 검증된 보관물·복원 도구를 먼저 확보한다.

현재 요청에서는 이 계획 문서만 작성한다. 파일 이동·삭제, 운영 코드 변경, 설치·publish,
CURRENT 전환, commit/push는 실행하지 않는다.
