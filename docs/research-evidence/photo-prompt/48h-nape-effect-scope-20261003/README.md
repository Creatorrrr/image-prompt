# H15/H16 목덜미 영향 속성 보완

새 48시간 작업의 첫 DATA 수정이다. **기존 개념 2개의 기록 4개**(일반 후보 2, 시각 프로필 2)를 보완했다. 새 장면·키워드·프로필은 추가하지 않았다. 기준 소스는 `8a0fb5b8`, 적용 직전 main은 문서만 추가된 `6fb87682`다.

## 변경과 원문 근거

- `sca_h15`: 원문은 정수리·얼굴 주변의 짧은 층과 더 긴 목덜미 층을 함께 설명한다. 기존 `hair.style.layers.crown_nape_length`를 보존하면서 `hair.style.nape.layer_length`를 추가했다
- `sca_h16`: 원문은 옆머리 **또는** 목덜미의 짧은 언더컷을 허용한다. 기존 옆머리 효과를 보존하면서 `hair.style.nape.undercut_length`를 추가했다
- 일반 후보와 대응 시각 프로필의 네 `affected_properties` 배열만 확장했다. 원문 의미·별칭·활성화 조건·근거·렌더 게이트는 그대로다
- 목덜미 경로는 기존 점 표기 관례에 맞춰 새로 선언한 형제 경로다. 유한한 정식 어휘집에 원래 있던 항목이라고 주장하지 않는다
- 원래 유지보수 기록은 수정하지 않고, [새 연결 기록](../extension-maintenance/48h-nape-effect-scope-20261003.json)에 이전 기록과 현재 확장의 해시를 연결했다

원문은 기존 `subculture-appearance-20261003/term-specs.psv`의 H15/H16과 `subculture-appearance-integration-20261003/NEW-RELATION-ALTERNATIVES.psv`에 있다. 기존 소비자는 점 경로의 겹침을 검사하지만 설명문의 “nape”를 별도로 해석하지 않는다. 따라서 기존 합성 경로·옆머리 경로만으로는 `hair.style.nape` 잠금을 보호하지 못했다.

## 전후 검증

같은 런타임과 변경하지 않은 입력으로 분리된 전후 실행을 했다. 입력은 소스 기반 회귀 검증용 합성 사례이며 독립 자연어 일반화 실험이 아니다.

- 최종 제안의 실제 후보 생성 CLI **8/8** 성공: 4개 사례 × 전후 2개 상태
- 기본 프롬프트를 그대로 보존하고 선택형 후보를 모두 거부한 전체 구성 감사 **8/8** 통과. 사례별 기존 경고 3개 또는 4개는 그대로이며, 안전한 새 후보 채택이나 이미지 품질을 검증한 것이 아니다
- 실제 체크아웃 적용 후 CLI **4/4** 재실행. 결과 파일은 자격 검증한 after 상태와 바이트 단위로 같다
- 코어·네거티브·신체 검토는 전후 동일하다
- 완전 개방, 옆머리 보호, 무관한 홍채 보호 사례의 후보 ID/적합성 및 창의 보강 후보 ID는 전후 같다
- 목덜미 보호 사례에서는 일반 H16 후보가 제거된다. H16만 고친 첫 시도에서 대신 등장했던 H15도 최종안에서는 들어오지 않는다
- 통제된 직접 소비자 검사는 두 ID × 9개 조건 × 전후의 36개 상태를 확인했다. 시각 프로필의 목덜미 차단은 이 검사 근거이며, public CLI의 시각 후보가 전후로 바뀐 사례라고 부풀리지 않는다
- 신규 회귀 테스트: 기존 DATA에서 예상한 실패 6개 하위 검사, 수정 후 5개 테스트 메서드 모두 통과
- 최종 관련 **60개 테스트 통과**, 사전 메타데이터 검증 통과. 전체 저장소 테스트 재실행이나 CI 성공을 뜻하지 않는다

실제 실행 seed는 모든 전후·V1/V2 실행에서 **1003**이다. 입력 작성자가 남긴 명령 템플릿의 90716을 그대로 실행했다고 주장하지 않는다. 20개 동결 입력 파일은 바꾸지 않았다.

## 보수적 손실과 부수 변화

이것은 의미 검색 순위나 이미지 품질 향상을 증명하는 변경이 아니라, 두 기록의 영향 범위 선언을 원문에 맞춘 수정이다.

- 하나의 후보가 여러 영역을 제안하므로, 목덜미가 잠겨 있으면 실제로는 안전한 옆머리만의 실현도 선택형 후보에서 제외될 수 있다. 이 보수적 손실을 인정하며 좁은 변형 후보로 분리하는 설계는 이번 범위가 아니다. 요청된 기본 프롬프트 자체는 유지된다
- 목덜미 사례에서 공유 후보 예산의 빈 자리로 화장 후보 `faded_lip_center_wear`가 추가 노출된다. 이 행은 이미 **ineligible**이고, 선택하려는 대조는 `candidate_applicability`로 거부된다
- 같은 사례의 창의 보강 허용 풀은 50→49로 줄고 seed 기반 표본도 달라진다. 기존 실루엣·귀 근처 머리 들어올리기 대신 의복 목둘레 및 얼굴 주변 프레이밍 후보가 포함된다. 변경을 숨기거나 다른 후보가 전부 바이트 동일하다고 주장하지 않는다
- H15의 옆머리 관련 경로, 기존 `two_block_disconnected_cut`, 자유로운 속성 명명·영역 온톨로지의 일반 문제는 해결하지 않았다. 머리 전체/목덜미 전체 범주의 보호를 보장하지 않는다

## 임베딩·지출·재현

**새 API 호출 0회**. 시각 인덱스 1,622개와 일반 인덱스 9,876개 항목의 텍스트·벡터·BM25F, exact lookup은 그대로다. 사전·레지스트리 해시가 바뀌어 기존 캐시만으로 인덱스 연결 정보를 다시 만들었다. 일반 샤드 16개의 내용 바이트는 종전과 같다. 최종 인덱스에는 실제 재구축 시각을 기록했고, 이후 실제 CLI 출력 동일성도 확인했다.

`diagnostic-evidence.tar.gz`는 원본 H16-only 시도, 최종 H15+H16 제안, 독립 검토, 고정 입력, 실제 전후 출력, 실패 이력, 최종 테스트 로그를 포함한다. 첫 구성 검사 도구의 선택 필드 가정 오류 및 다른 상태의 인덱스를 사용한 검사 오류도 남겼다. 그것들은 도구 준비 오류이며 DATA의 전후 실패로 계산하지 않았다. 최종 비교는 각 상태의 자체 소스·인덱스로 실행했다.

내부 실행 경로를 치환했으며 `export-manifest.json`에 원본 및 내보낸 파일 해시를 따로 기록한다. 전체 실행용 인덱스 복제본은 넣지 않았고, 기준 커밋과 캐시 재사용 스크립트로 재구성한다. 새로운 이미지 생성이나 픽셀 검증은 하지 않았다.
