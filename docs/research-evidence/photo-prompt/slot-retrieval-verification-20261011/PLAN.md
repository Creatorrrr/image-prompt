# 슬롯 후보 조회 검증 계획

작성일: 2026-10-11 (Asia/Seoul)

## 목적과 대상

현재 작업 폴더의 `photo-prompt-image-generator`가 실제 authored 데이터에 등록된 각 슬롯과 후보를 적재하고, 해당 의미를 가진 입력에서 실제 조회 결과와 V6 후보팩으로 노출하는지 확인한다. 시작 시점 HEAD는 `218e339320f0e3c27aac3f2a48a9299812b16935`이며 작업 폴더에는 기존 변경이 있다. HEAD 버전만이 아니라 이 작업 폴더의 현재 바이트를 검증한다.

초기 로더 인벤토리는 114개 슬롯, 12,043개 후보다. 수치는 이후 소스 대조와 runtime snapshot에서 다시 확인한다. 이 작업은 스킬 유지보수 검증이며 사진 제작 요청이 아니다. 데이터 기반 테스트 입력과 기존 테스트 fixture를 사용할 수 있으며, 그 결과를 독립적인 사진 창작이나 이미지 품질의 증거로 사용하지 않는다.

## 검증 단계

1. **원본 → 적재 → 인덱스**: source manifest에 등록된 원본 후보를 슬롯/ID 단위로 수집한다. 병합 로더가 누락하거나 중복한 후보, 소유 차원이 없는 슬롯, semantic index와 slot BM25F index의 누락/잉여를 확인한다. source와 code 해시, checkout 상태를 보관한다.
2. **전 후보의 검색 가능성**: 전체 후보의 실제 영어/한국어 표기와 명시된 alias를 사용해 동일 슬롯 BM25F 조회를 실행한다. 실제 결과에 기대 ID가 있는지, 순위와 같은 슬롯 중복 표현을 기록한다. 정확 문자열 조회는 데이터의 기계적 검색 가능성만 검증하며 자연어 의미 정확도의 증거와 분리한다.
3. **슬롯별 실제 조회 경로**: 모든 슬롯에 대해 source 기반 probe를 만들고 실제 `retrieve_core_slots`를 전체 현재 corpus에 실행한다. 슬롯 소유 차원, focus 근거, 후보 eligibility, whole-scene/focus 검색, cap 적용, 최종 노출 ID를 기록한다. 표본은 원본의 위치가 다른 후보를 사용한다. 기대 ID 미노출을 검색 실패, 필터 제외, focus 부재, 순위/공유 cap 문제로 구분한다.
4. **독립적인 장면 입력과 공개 CLI**: 후보 문구를 복사하지 않은 한국어/영어 사진 장면을 먼저 고정한 후 현재 runtime snapshot과 공개 `generate_photo_prompt.py`로 V6 pack을 생성한다. 기대 슬롯과 후보의 실제 의미 적합성을 검토하고 composer view의 ID 보존을 확인한다. 실제 실행 모드와 receipt를 저장한다.
5. **경계와 재계산**: 사람 없는 장면, 비인간 주체, 명시 제외, 필수 context, 카메라 소유, lexical hit 부재, 후보 cap과 변조 검출을 관련 기존 회귀 테스트 및 실제 source 사례로 확인한다. 테스트에서 provider/네트워크가 사용되는지는 별도 기록한다.
6. **보고 및 보존 확인**: 슬롯별 데이터 수, 검색 적중률, 실제 노출, 미검증/실패 원인과 재현 입력을 표로 제공한다. source/code 해시를 다시 비교하고 변경은 검증 artifact에만 한정됐는지 확인한다.

## 판정 기준

- 등록 후보가 로더와 인덱스에서 동일한 슬롯/ID로 존재해야 한다. 허용된 compiler 보강은 원본 출처와 함께 구분한다.
- exact 조회의 top 1 / top 2 또는 4 / top 24 / 전체 적중을 각각 보고한다. 동형 표현의 다른 후보가 앞선 경우를 일괄 누락으로 처리하지 않는다.
- 슬롯 probe의 실제 노출은 해당 slot의 source 후보여야 하고, eligibility 및 source hash binding을 만족해야 한다. 소유 차원 없음, 유효 context 없음, focus 없음은 조회 성공으로 계산하지 않는다.
- 한 장면에서 모든 슬롯이 켜질 필요는 없다. 전체 cap 64, core slot cap 4, support slot cap 2와 정상 필터링은 누락 오류와 분리한다.
- 공개 CLI pack 생성과 composer view 변환 성공은 별도 결과다. 기본 함수만 통과하고 공개 CLI가 막히면 운영 경로 통과라고 보고하지 않는다.
- 새 이미지 생성, 유료 embedding 호출, 최종 후보 채택, 이미지 픽셀 품질은 이 검증 범위에 포함되지 않는다.
