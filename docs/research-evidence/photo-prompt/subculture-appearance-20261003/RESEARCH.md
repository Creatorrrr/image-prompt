# 서브컬처 외형 의미 데이터 보강 리서치

작성일: 2026-10-03 · 범위: 조사와 반영 계획 · 기준본: `900848816f88a494e5bf16ea475a25074d584911`

## 결론

원 대화의 **171개 용어와 37개 사례를 모두 추적**했다. 보강의 중심은 용어 수 증가보다 **부품의 기점, 신체/의복/소품 소유자, 가림 경계, 비율 비교점, 표면 특성**을 명시하는 것이다. 원 용어별 선택한 해석 171개에 혼동을 풀기 위한 구조 분리안 16개를 더해 **187개 의미 단위와 187개 후보 초안**을 작성했다. 이는 운영 데이터가 아니라 owner·property·scope 검토를 거쳐 옮길 연구 데이터다.

넓은 복식 계열은 하나의 보편적 필수 부품 집합으로 만들면 안 된다. ‘메카’, ‘동물 귀’, ‘고딕’, ‘풍만’, ‘바이저’, ‘SD’처럼 여러 구조나 의미가 섞이는 말은 요청에서 선택한 해석을 먼저 확정해야 한다. 정확한 단어가 등장해도 부정·인용·장식·다른 소유자 문맥이면 신체 의무로 승격하지 않는다.

반영은 기존 owner의 동등한 문맥 보강 → 작은 신규 관계 배치 → 파생 인덱스 재생성 → 고정 core에서 후보팩 비교 → 실제 이미지의 관계 검증 순서로 제안한다. 상세 작업표는 [반영 계획](IMPLEMENTATION-PLAN.md)에 있다.

## 조사 범위와 근거의 등급

연결 대화는 `read_thread`로 읽었으나 응답 본문이 20,000자로 제한돼 뒤쪽이 잘렸다. 브라우저의 실제 대화 DOM에서 14개 절과 13개 표를 확인해 누락된 표를 복원했다. 1–4절은 사례 37개, 5–12절은 재사용 용어 171개, 13절은 모호성 질문 8개다. 14절의 세 예시는 조사 범위 확인에 사용했다. 전체 원시 대화의 완전한 로컬 백업을 만들었다고 주장하지 않는다. [원 대화 정규화 자료](SOURCE-CONVERSATION.json)와 [범위 영수증](source-tail.json)에 이 차이를 기록했다.

외부 출처 57개를 출처 원장에 기록했다. 공식 제작자·제조사·게임사·패션 브랜드·박물관·사전·작화 도구 자료를 우선했으며, 커뮤니티 용례는 용례라는 등급을 유지했다. 검색 요약만 확인한 출처, 본문을 읽은 출처, JS 접근 제한, 버전 불일치를 구분했다. **모든 용어의 정의가 공식 표준으로 확인됐다는 뜻은 아니다.** 출처가 직접 뒷받침하는 사실과 연구자가 설계한 관찰 기준은 각 레코드에서 분리했다. [전체 출처와 한계](SOURCES.md).

이번에 공식 디자인 이미지의 실제 픽셀까지 직접 관찰한 것은 **미쿠 초기 의상과 테토 Synthesizer V 삼면도 두 장**이다. 다른 사례는 본문·제품 구성 확인 또는 원 대화 가설이며 사례집에 확인 상태를 남겼다. 새 이미지 생성이나 네이티브 생성물 품질 검증은 수행하지 않았다.

## 1. 머리카락: 형태와 장식을 분리

머리 후보는 색·성격·의상 세트를 함께 묶기보다 `묶음의 수 → 위치 → 각 다발의 구조 → 길이 단계 → 색 영역`으로 분리한다. 아호게 한 가닥과 안테나형 머리 두 가닥은 개수와 기점이 다르다. 두 양갈래는 두 기점만으로 성립하지만 트윈 드릴은 각 머리 다발이 반복 나선을 형성해야 한다. 포니드릴은 하나의 뒤 묶음에서 하나의 나선이 내려온다. 테드의 포니드릴 명칭은 [공식 소개](https://kasaneteto.jp/about/)에서 확인했다.

[테토 Synthesizer V 삼면도](https://kasaneteto.jp/assets/download/illust-logo/teto_sv_3views.jpg)를 직접 보면 붉은 나선 머리 바깥에 흰 띠가 감겨 있다. 이 흰 부분을 염색으로 인덱싱하면 ‘좌우 분할 염색’이나 ‘두 색의 나선 머리’가 잘못 활성화될 수 있다. `H05`의 머리 나선과 `X10`의 별도 리본 감김을 분리했다. 테토의 군복풍 상하의·벨트·오선보 장식은 머리 구조의 필수 요소가 아니다.

히메컷은 기존 `hime_cut_structural` owner를 우선한다. 짧은 좌우 얼굴 옆 패널과 긴 뒤 머리의 길이 단차가 핵심이며, 뱅·검정색·완전한 직모는 요청이 따로 선택할 요소다. [실무 스타일 자료](https://www.hair.com/hime-cut.html)는 이 길이 구성의 출처로 활용하되 역사적 기원이나 계급을 외형 규칙으로 가져오지 않았다.

‘한쪽 눈 가림’과 ‘양눈 가림’은 `occluded_eye_regions`가 다르다. 메카쿠레 같은 커뮤니티 상위 말은 한쪽/양쪽 가림의 모든 용법이 확인됐다고 가정하지 않고, 여기서는 **양눈 앞머리 가림이라는 선택된 해석**에 한정했다. 안대·양눈 천 띠·바이저는 다른 소유자와 재료를 가진 별도 단위다.

**우선 후보:** H01–H06, H13–H14, H19, X10. **대표 검증:** R01–R07. 한 가닥 부족, 묶음 기점 합침, 리본을 염색으로 대체하는 결과는 선택한 구조의 실패다.

## 2. 눈·얼굴: 인상보다 영역과 좌표

츠리메/타레메는 눈꼬리 방향이다. 사전의 [吊り目](https://kotobank.jp/word/%E5%90%8A%E3%82%8A%E7%9B%AE-572877), [垂れ目](https://kotobank.jp/word/%E5%9E%82%E3%82%8C%E7%9B%AE-563456) 정의를 바탕으로, 머리 roll을 고려한 안쪽·바깥쪽 모서리의 상대 높이로 연구 기준을 정했다. 화난 눈썹·졸린 눈꺼풀·착함·사나움과 같은 효과를 함께 넣지 않는다. 지토메의 특정 인상은 반쯤 덮인 눈꺼풀과 응시 방향 등 선택한 요소로 표현하되 모든 half-lidded 눈을 같은 팬 용어의 정확한 동의어로 추가하지 않는다.

삼백안은 공막이 드러나는 **위치**를 기록해야 한다. `F04`는 아래와 양옆이 보이는 해석으로 범위를 정했고 위쪽 노출형·사백안·단순 위쪽 시선을 반례로 두었다. [아이센터 설명](https://www.fkmc.or.jp/data/2683/eyecenter_yomoyamadtl/)에서 세 방향과 네 방향 노출의 구분을 확인했다. 눈 모양에서 성격·건강·공격성·운명을 추론하는 규칙은 만들지 않는다.

홍채, 동공, 공막, 표면 반사를 별개 영역으로 유지한다. 하트/별 모양 동공은 기호형 하이라이트와 다르다. ‘별 모양 눈’만으로는 영역이 모호하므로 `F08`은 동공/홍채 그래픽/반사 중 선택이 필요하다. [눈 구조 자료](https://my.clevelandclinic.org/health/body/21823-eyes)는 영역 분할의 근거이며, 가상 디자인을 의학적으로 진단하는 용도가 아니다.

오드아이는 좌우 홍채 전체의 색 차이와 한 홍채의 부분·중앙 고리 색 차이를 분리한다. [이색 홍채 자료](https://my.clevelandclinic.org/health/symptoms/25112-heterochromia)의 구분을 이용하되 렌즈·조명·원인은 외형만으로 확정하지 않는다. `eye_detail.subtle_heterochromia`가 있으므로 광범위한 새 alias를 넣기 전 기존 의미를 비교한다.

야에바는 **단순 송곳니의 뾰족함과 같은 말이 아니다.** [사전 원문](https://kotobank.jp/word/%E5%85%AB%E9%87%8D%E6%AD%AF-143407)은 치열 밖으로 겹쳐 난 치아를 설명한다. `F13`은 치아 배열 변화를, 길고 뾰족한 작화 치아는 별도 형태를 나타내도록 교정했다. 상어형 치아는 여러 치아의 삼각 윤곽이고 상어 후드의 톱니 트림은 의복에 속한다.

하이라이트 없는 눈·ω형 입은 매체 조건을 보존한다. 일러스트 기호를 물리적으로 비반사적인 눈이나 실제 고양이 주둥이로 바꾸면 의미가 달라진다. **우선 후보:** F01–F09, F13–F14, X03–X04. **대표 검증:** R08–R15.

## 3. 체형: 독립된 축과 실제 기준점

체형은 `stature`, `torso/leg ratio`, `shoulder/hip breadth`, `waist breadth/depth`, `regional muscle volume`, `surface definition`, `regional soft-tissue volume`으로 나눈다. 슬렌더=작은 키, 다부짐=짧은 키, 큰 근육=선명한 근육, 큰 가슴=큰 복부/골반이라는 연결을 만들지 않는다.

현재 기준본에 `bm_stocky_build`, `bm_torso_limb_ratio`, `bm_shoulder_width`, `bm_hip_width`, `bm_muscle_volume`, `bm_breast_projection`, `bm_thigh_volume` 등이 있다. 신규 전신 라벨을 대량 생성하기 전에 이 owner를 사용하는 편이 중복·잠금 우회를 줄인다. 다만 ‘장신·장지형’과 ‘lean athletic’은 여러 축을 묶은 말이므로 하나의 문맥 확장만으로 동등하다고 판단하지 않는다.

긴 다리는 골반부터 발까지와 어깨부터 골반까지를 같은 인물에서 비교한다. 하이웨이스트 바지·긴 외투·투시 왜곡은 몸 비율의 증거가 아니다. 큰 손발도 실제 손발 경계를 봐야 하며 건틀릿·장화의 외곽 크기와 분리한다. 모래시계형은 몸의 세 폭 관계이고 코르셋이 만든 외곽과 구분한다.

중성적 실루엣은 원하는 어깨·허리·골반 비례를 설명하는 보조 라벨로 남긴다. 정체성 판정으로 사용하지 않는다. 치비는 [작화 가이드](https://www.clipstudio.net/how-to-draw/archives/155423)의 비례 관습을 참고한 스타일 효과다. **치비의 SD와 [Super Dollfie 제품군 SD](https://dollfie.volks.co.jp/sd/)는 분리**한다. 머리가 크다고 나이를 바꾸지 않는다.

**우선 재사용:** B03–B07, B09–B11, A01–A04. **대표 검증:** R16–R20, Q03·Q06. 신규 exact 라벨보다 기존 부위 owner와 실제 property binding을 먼저 보강한다.

## 4. 인외·동물성: 기점, 개수, 대체, 접촉

동물 귀는 **기관**, **머리띠 장식**, **귀 달린 모자**를 분리한다. 생물 귀의 기점은 머리 표면이고 머리띠 귀의 기점은 띠이다. 사람 귀도 함께 남는지 여부는 요청이 결정한다. 고양이·여우·토끼라는 단어만으로 네 귀·꼬리·털 몸을 자동으로 추가하지 않는다. Dejiko 사례는 귀 달린 모자와 신체 귀를 혼동하는 반례로 유용하다.

뿔은 가지 없는 원뿔/말린 축, 가지뿔은 분기하는 주된 축과 끝가지, 투구 장식은 투구 껍질에 붙는 다른 owner다. 겉모양이 비슷해도 root topology가 다르다. 다중 꼬리는 개별 꼬리의 기점과 개수가 있어야 하며 한 꼬리의 리본·분기된 끝을 개별 꼬리로 세지 않는다.

지행형은 뒤로 꺾인 사람 무릎으로 구현하지 않는다. [digitigrade 사전](https://www.collinsdictionary.com/us/dictionary/english/digitigrade)의 발가락 지지 정의를 토대로 뒤꿈치·발목/비절·무릎·접촉면을 별개로 추적한다. 사진에서 옷이나 장화가 가리면 숨겨진 관절 구조를 PASS로 추정하지 않는다.

하피는 **팔이 날개로 이어지는 구성**과 **보통 팔 외에 등 날개가 더 있는 구성**을 구분한다. 라미아는 다리 쌍을 대신하는 연속된 뱀 하체이고 별도 뱀이 사람 다리를 감는 장면과 다르다. 켄타우로스는 하나의 연결된 몸이고 승마는 두 subject의 관계다. 아라크네·다완·다안은 count와 각 기관의 기점이 있어야 한다. 촉수·케이블·리본도 가까이 있는 것만으로 같은 부속지가 되지 않는다.

구체관절 인형은 공과 대응 소켓 사이의 interface를 보아야 한다. [인형 제작 구조 소개](https://dolk.jp/en/portal/generic/new)를 참고했고 둥근 마킹만 있는 결과는 제외했다. 사이보그는 착용 장갑·인공 신체·잔존 사지의 소켓 의지·별도 탑승체로 분리했다. 현재 `bm_prosthetic_connection`은 그중 소켓 연결의 특정 의미를 이미 소유한다.

**우선 구조 분리:** N01–N02·N05·N08·N11–N12·N16–N19·N22–N26, X01–X09·X11·X13. 종/subject/body를 동시에 바꾸는 초안은 현재 하나의 슬롯에 넣지 않고 보류했다. **대표 검증:** R21–R29.

## 5. 복식 계열: 스타일 이름은 선택 맥락

메이드·마녀·마법소녀·Lolita 하위 스타일·오우지·군복·닌자·발키리는 용어만으로 모든 부품을 강제하지 않는다. 각 레시피는 `몸판/하의 구성`, `목선`, `소매`, `레이어`, `실루엣 지지`, `트림 위치`, `여밈`, `부착 장비`의 선택지로 풀었다. 색·나이·성별·국적·역할·성적 톤은 외형 라벨에서 자동 상속하지 않는다.

고딕/스위트/클래식 로리타는 한 브랜드 상품의 색이나 패니에를 전체 스타일의 필수 조건으로 삼지 않는다. [Metamorphose 제품 분류](https://metamorphose.gr.jp/product_category/10), [BODYLINE 지침](https://bodylinetokyo.co.jp/en-int/blogs/news/lolita-petticoat-guide), [BABY/AATP 제품](https://store.babyssb.co.jp/en/products/p21sk502)을 참고해 ‘선택한 치마 모양을 별도 속층이 받친다’는 관찰 가능한 관계를 추출했다. 특정 시대·하위 스타일·길이에는 변형이 있으므로 broad label의 hard gate로 쓰지 않는다.

무녀풍 분리 소매는 [라이선스 Reimu 의상](https://dollfie.volks.co.jp/dd/special/touhou-project/product/mdd_reimu.html)의 별도 부착 소매와 추가 프릴에서 부품 관계를 확인했다. 이것이 역사적 무녀복 전체의 정의는 아니다. [Marisa 제품](https://dollfie.volks.co.jp/dd/special/touhou-project/product/mdd_marisa.html)은 모자·블라우스·베스트·앞치마·속치마가 별도 부품이라는 자료로 썼다.

메카무스메는 기존 사람+장착 장비, 인공 몸, 키트 소체 관절, 탑승 외골격을 섞지 않아야 한다. [ASRA NINJA 제품](https://www.megamidevice.com/megami/asra_ninja/)은 장착 가능한 무장 목록과 소체의 구분을 제공한다. 제작·팬 커스텀·행사 활동을 다루던 기존 `subculture_extension` 전체를 외형 사전으로 덮어쓰는 방식은 피한다.

**데이터 제안:** 복식 계열 19개는 구성 선택 맥락, 그 아래 재사용 단위는 기존 `garment_detail`, `wearable_accessory`, `surface_material`, `silhouette_proportion` owner에 각각 연결. 색·무기·머리·몸을 한 거대 costume candidate로 묶지 않는다.

## 6. 의상 부품·재질: 실제 구조와 보이는 효과

[미쿠 초기 의상](https://piapro.net/intl/images/official_cos_miku.jpg)에서 별도 소매와 몸판 사이의 빈 간격을 직접 관찰했다. 분리 소매는 길이·플레어·재료와 다른 부착 관계다. 모에소데는 소매 끝이 손을 덮는 길이/coverage 관계이고 오페라 글러브는 손을 감싸는 별도 장갑이다. 겉보기 긴 팔 천이라는 이유로 같은 owner가 되지 않는다.

페티코트/현대 패니에는 바깥 치마의 선택한 부피를 받치는 속층이다. 역사적 옆 후프·방사형 크리놀린·뒷 버슬은 부피 방향과 구조가 다르다. [V&A 설명](https://www.vam.ac.uk/articles/corsets-crinolines-and-bustles-fashionable-victorian-underwear)의 구분을 참고하되 현대 패션 제품명에 역사 구조를 강제하지 않는다.

건틀릿은 손을 덮는 갑주이고 팔뚝만 덮는 부품과 구분한다. 손가락 분절판 또는 한 덩어리 장갑형 중 하나를 모든 건틀릿에 필수로 넣지 않는다. [박물관 물체 기록](https://www.metmuseum.org/art/collection/search/23276)은 손 갑주라는 물체 범주의 근거다. 폴드런·그리브도 위치가 핵심이며 실제 어깨·정강이 크기를 바꾸는 효과와 분리한다.

레이스업은 줄의 교차만 아니라 양쪽 eyelet/부착점과 연결되어야 한다. 파이핑은 옷 경계를 따라가는 좁은 띠이고 큰 색면·그림자·발광 외곽과 다르다. 망사는 실제 열린 셀과 아래층 투시를, 시스루는 연속된 직물 층의 투과와 불투명 경계·아래층을 검증한다. 다이아몬드 인쇄무늬는 열린 망사를 대신할 수 없다.

라텍스·에나멜/코팅은 화학적 재료와 광학적 마감을 분리한다. [라텍스 시트 제조사](https://radicalrubber.co.uk/)를 재료 출처로 참고하되 광택만 보고 라텍스임을 확정하지 않는다. 가죽·PVC·라텍스를 같은 동의어로 검색하거나 모든 라텍스를 반짝이는 표면으로 강제하지 않는다. 털 트림과 깃털 트림도 작은 가장자리 구조를 분리하며 몸 털·생물 날개로 확대하지 않는다.

**우선 후보:** G01·G04·G08·G14·G18·G20–G24. **대표 검증:** R30–R33.

## 7. 성인 체형·노출 복식: 몸과 의복은 다른 소유 범위

원 대화의 성인 체형·노출·페티시 복식 항목을 연구에서 누락하지 않았다. 다만 몸의 체적과 옷의 노출 경계는 다른 속성이다. 큰 가슴/작은 가슴/평평한 앞면/굵은 허벅지는 부위별 body_geometry, 플런지·키홀·언더붑·사이드붑·백리스·하이레그는 garment coverage/개구부 관계다. 몸을 바꿀 수 있는 상황이어도 잠긴 옷의 경계를 바꿀 수는 없다.

플런지는 위쪽으로 열린 neckline 경로, 키홀은 위쪽 천 연결부가 남는 닫힌 구멍이다. 언더붑은 top 아래 가장자리와 하부 가슴, 사이드붑은 측면 가장자리와 외측 가슴이다. 서로 비슷한 노출 분위기를 주어도 실제 경계가 다르다. 기존 `pfe_lower_chest`, `pfe_lateral_chest`, `clothing_ct037_v2`를 우선 대조했다.

가터 벨트는 허리/골반 지지부-끈-스타킹 윗단의 연결이다. 독립 허벅지 밴드는 그 관계를 충족하지 않는다. 절대영역은 짧은 밑단과 긴 스타킹 윗단 사이의 같은 다리 피부 띠이며, 두 허벅지 사이의 배경 공간과는 다른 단위다. 기존 `pfe_garter_path`와 `pfe_thigh_skin_band`에 맞는 문맥이면 재사용한다.

버니 수트의 귀는 보통 선택한 장식 부착으로 분석하며 생물 귀·꼬리를 자동 추가하지 않는다. 하네스·본디지풍 하드웨어의 모양은 실제 immobilization 행동과 별도다. ‘동정을 죽이는 스웨터’는 인터넷 별칭의 변형군이며 이름의 과장된 의미나 성적 이력을 데이터 효과로 넣지 않는다. 치치부쿠로는 [커뮤니티 작화 용례](https://ja.wikipedia.org/wiki/%E4%B9%B3%E8%A2%8B)로 다루고 옷감의 그림 선·장력 표현을 실제 옷 종류나 큰 가슴의 동의어로 만들지 않는다.

**우선 관계:** A02·A07–A12·A17·A19–A23. **대표 검증:** R34–R36, Q03–Q04·Q07. 명시된 성인·의복·매체 맥락과 core 잠금을 보존한다.

## 8. 소품·메카·공포·손상: 조립과 실제 노출 경계

큰 무기는 손잡이-날/총신의 상대 크기, 건블레이드는 한 조립체의 결합, 열쇠형 무기는 고리-축-이빨 관계, 사슬 무기는 두 끝점과 연결 경로를 기록한다. 소품을 커다랗게 만드는 효과를 사람의 body scale 슬롯으로 우회하지 않는다. 현재 `prop` 슬롯의 dimension 범위가 비어 있으므로 자동 bundle 채택은 보류한다.

부유 유닛은 몸에서 떨어진 간격, 기계 날개는 등 mount와 관절/판, 헤일로는 머리와의 간격·위치·별도 발광 선택이다. ‘기계’라는 재료 인상만으로 기관·장비·부유체·탑승체를 합치지 않는다. 표시 얼굴은 가면/바이저 판 위 도안인지 몸체 자체의 인공 얼굴인지 구분하고, 햇빛 가리개인 sun visor와도 나눈다.

봉합 신체는 신체 구간 사이의 실밥, 패치워크 옷은 천 패널의 이음선이다. 노출 배선은 같은 인공 몸체의 내부를 열어 보여야 하며 겉에 드리운 케이블로 대체할 수 없다. 다안·다구는 기관 수·위치·기점이고 셔츠의 눈무늬는 다른 owner다. 가면 아래 빈 얼굴은 **구멍을 통해 내부가 실제 보일 때**만 평가하며 온전한 가면의 가림은 UNOBSERVABLE이다.

배틀 대미지는 금속의 긁힘/찌그러짐과 천의 찢김/올풀림을 구분한다. 붉은 액체 같은 무늬의 위치·형상은 기록하되 임의 사건·원인·대상을 추가하지 않는다. 현재 `aftermath_trace`도 scope가 비어 있어 이 후보들은 의미 초안으로 남긴다. 칼/갑주/공포 소재의 실제 기능이나 서사적 원인은 외형 연구만으로 검증되지 않는다.

**대표 검증:** R37–R40, Q05·Q11. `partial_is_fail`이며 필수 조립·기점·빈 공간이 가려졌으면 통과하지 않는다.

## 9. 사례에서 확인한 차이와 미확인 범위

미쿠·테토 두 공식 그림은 이름을 지운 뒤에도 재사용 가능한 부품 관계를 관찰할 수 있었다. 다른 사례는 [37개 사례집](CHARACTER-CASEBOOK.json)에 버전·근거 상태·이름 없는 분해·반례를 남겼다. 캐릭터 이름은 연구 provenance에만 남기고 candidate lookup의 전역 트리거로 사용하지 않는다.

강한 반영을 보류할 사례는 다음과 같다.

- 초기 Black Rock Shooter에 대해 조회한 공식 자료가 Dawn Fall 버전이므로 초기판 도판을 따로 확보해야 한다.
- ENA는 제작자 인덱스 확인까지이며 초기 노랑/파랑 도판의 버전 직접 대조가 필요하다.
- Protogen 원 사이트가 JS 중심이라 종족의 허용·필수 규칙은 충분히 확인하지 못했다. 곡면 표시 패널 모티프와 종족 전체 규칙을 분리한다.
- Baselard＋외골격은 제조사 시리즈 확인까지이며 정확한 제품/무장 버전은 추가 확인한다.
- OS-tan·Wikipe-tan·Bowsette·Koishi의 해당 도안은 원 대화 자료라는 등급을 유지한다. 팬 공동 디자인이나 라이선스 변형을 단일 정식 기본형으로 승격하지 않는다.
- ASRA, Arnval, BOOTH 모델, hololive, 여러 게임 캐릭터는 공식/제작자 자료의 본문 또는 접근점을 확인했지만 도판의 모든 부착·비례를 픽셀로 검증하지 않았다.

이 항목들은 전체 연구를 멈추는 이유가 아니라, 해당 canonical 주장과 종족/색/버전 alias의 반영을 보류하는 이유다. 이름 없는 구조 초안도 실제 관찰과 core 바인딩을 거쳐야 한다.

## 10. 현재 데이터와의 대조 및 검증 경계

시작 시 live `load_runtime_data()`는 인덱스 메타데이터를 포함해 정상 로드됐고 profile 1,510개를 확인했다. 해당 시점의 77개 asset JSON 해시가 Git 기준본과 모두 일치한다. [시점 스냅샷](RUNTIME-SNAPSHOT.json).

작업 중 다른 운영 변경이 들어왔고 중간 재확인에서는 새 profile의 명시적 property scope 오류가 발생했다. 이 연구는 그 변경을 고치거나 되돌리지 않았다. **마감 재확인에서는 최신 live loader와 인덱스 메타데이터 검증이 다시 PASS였고 profile 1,564개였다.** [최종 관찰](FINAL-VERIFICATION.json). 중간 오류는 현재 미해결 오류라는 뜻이 아니다.

연구의 재사용 비교는 기존 profile 1,510개와 후보 항목 9,703개를 **검증된 Git 기준본에서 다시 로드**해 수행했다. [변경 영수증](LIVE-DRIFT-RECEIPT.json). 새 54개 profile과 변경된 기존 owner는 실제 반영 시작 시 추가로 대조해야 한다. 본 연구가 이 운영 증가분을 작성하거나 적용한 것은 아니다.

`COVERAGE-AUDIT.json`은 positive field의 단순 문자열 probe이다. 반례·출처 설명 전체를 긍정 커버리지로 세지 않았지만, 이 probe도 runtime exact routing 또는 의미 동등성 판정은 아니다. zero hit가 곧 데이터 부재라는 뜻은 아니다. [owner 비교표](OWNER-MAP.json)는 실제 ID가 존재함을 검증하고 부분 대응·비동일 관계까지 함께 기록했다.

후보 초안의 33개는 범위 없는 슬롯 10개, 여러 dimension 22개, 라벨만 남기는 1개로 보류했다. 나머지 154개도 중복/문맥/매체/실제 속성 바인딩 검토 대상이며 즉시 채택 가능한 후보가 아니다. `subject.body...` 같은 연구용 속성 이름은 현 runtime property namespace와 자동 호환되지 않는다.

리서치 구조·링크·참조 검증, 현재/기준본 로딩, 미래 semantic regression, 후보 노출, 실제 채택, 생성 이미지, 픽셀, 사용자 수용은 각각 별도 결과다. 제안한 혼동 쌍 40개와 정책 검증 12개는 **PROPOSED_NOT_RUN**이며, 현재 연구 파일 검증을 이 52개 회귀의 통과로 보고하지 않는다.

세부 데이터는 [171개 반영 판단표](TERM-DECISIONS.md), [의미 단위](SEMANTIC-UNITS.json), [후보 초안](CANDIDATE-DRAFTS.json), [회귀 제안](REGRESSION-PROPOSALS.json), [후보팩 맥락 8개](PACK-CONTEXT-PROPOSALS.json)에 있다.
