# 유혹적 컨셉 재시험

독립 서브에이전트 세 개에서 새 장면의 프롬프트와 데이터 적용 검증을 완료했다. 세 장면 모두 유혹적인 관계나 관찰자를 향한 초대를 중심 의도로 설계했다. 기본 이미지 도구는 실제 호출 5회 모두 출력 단계에서 차단했고, 전달된 이미지는 0장이다. 픽셀과 전체 인상은 `blocked_unscored`이며 성공·실패 점수로 계산하지 않는다. 사용자가 기본 도구 결과와 검증 보고서만 작성하도록 선택했으므로 대체 API는 실행하지 않았고 이 실행의 추가 생성은 종료했다. [사용자 선택 기록](USER-DECISION.json)

## 세 장면과 유혹을 표현하는 방식

| 장면 | 장면의 중심 관계 | 눈에 보여야 하는 형태 | 프롬프트 |
|---|---|---|---|
| A. 재즈 살롱 입구의 장난스러운 초대 | 들어가려던 사람이 보는 사람을 향해 돌아서며 따라오라는 신호를 보낸다 | 지정한 쪽 윙크, 반대 눈의 카메라 시선, 한쪽 입꼬리 미소, 안쪽으로 굽힌 검지, 커튼을 잡은 다른 손과 되돌린 고개 | [A 프롬프트](arm-a/prompt_en.txt) |
| B. 공연 뒤 발코니의 가까운 교감 | 한 사람의 집중된 시선과 가벼운 손목 접촉에 상대가 이미 시선·상체·미소로 응답한다 | 두 얼굴 사이의 작은 공간, 상호 시선, 여성 오른손에서 남성 왼쪽 손목 안쪽으로 이어지는 접촉, 연결된 전완과 상대의 응답 | [B 프롬프트](arm-b/final_prompt.txt) |
| C. 강변 정원 테라스의 기다림 | 보는 사람이 합류할 자리와 관찰자를 향한 시선이 정적인 기다림을 연결한다 | 옆의 빈 벤치 공간, 보는 사람 쪽으로 돌린 어깨, 직접 시선과 작은 비대칭 미소, 안정된 앉음과 쉬는 두 손 | [C 프롬프트](arm-c2/composed_prompt.txt) |

이것은 고정한 연출 의도다. 생성된 픽셀에서 그 의도가 읽혔다는 판정은 아니다. 실험자의 성인 나이·역할·관계 설정은 참고 사진 인물에 관한 신상 추론이 아니다. 같은 첨부의 눈에 보이는 얼굴과 머리만 입력으로 사용했다.

B의 프로필은 동일 인물의 얼굴과 드레스 네크라인이 한 프레임에서 함께 읽히는 조건이다. C의 프로필은 앉은 몸, 쿠션의 국소 눌림, 지지면과 일치하는 의복 주름을 연결한다. 두 프로필의 전체 구성요소 6개가 최종 프롬프트에 문자 그대로 들어 있고, 선택이 전체 렌더 기준으로 승격된 것도 확인했다. 이는 보조적인 형태/가독성 의미의 적용이며 유혹적인 관계 자체를 정의한 프로필의 적용이 아니다.

A의 두 후보는 앞서 연구로 대체 표현을 보강한 88개 기존 후보에 포함된다. 그 후보가 실제 팩에 노출되고 선택된 사실을 확인했다. 윙크·미소·고개 돌림은 독립 기본 프롬프트에 이미 있었으며, 새 대체 표현 때문에 검색이나 이미지가 개선됐다는 인과적 결론은 내리지 않는다. B·C의 다른 후보도 실제 선택과 프롬프트 문구를 추적했지만 그 두 후보를 앞선 연구의 새 데이터로 계산하지 않는다.

앞서 추가한 13개와 보강한 14개 시각 의미 프로필 중 이번 세 팩에 노출·채택된 것은 없다. 따라서 이 실험으로 강화한 시각 의미 데이터가 충분히 활용됐다고 판정할 수 없다. 한 팩마다 선택적 시각 프로필은 8개씩 노출됐지만, 대다수는 각 장면의 관계·손·노출 영역·행동 문맥에 맞지 않아 거절했다. 관련 없는 프로필을 채택해 수치만 늘리지 않았다. 자세한 원본→팩→선택→필수 문구→렌더 기준은 [부모 데이터 적용 검증](PARENT-DATA-APPLICATION.json)에 보존했다.

## 적용 경로 재검증에서 확인한 공백

검증 입력을 바꾸지 않고 동결한 코어·설정·소스에서 프로필 검색 단계만 다시 실행했다. 세 실행 모두 원래 팩에 노출된 프로필 8개의 ID 집합과 일치했다. 공개 후보 목록은 순위가 없는 재료이므로 배열 위치는 비교 기준으로 쓰지 않았다. 프로필 원본 1,787개와 후보 사전의 해시도 동결한 main과 일치했다. 새 팩이나 이미지 호출은 생성하지 않았다.

연구 대상 27개를 세 장면의 실제 검색 원문에 대조한 81개 점검에서는 구성요소 대체 표현의 문자 일치가 0개였고, 연구 대상 프로필의 검색 결과도 0개였다. 이는 현재 표현으로 그 경로가 활성화되지 않았다는 사실이다. 장면에 해당 형태가 전혀 없다는 판정은 아니다. 예를 들어 A는 왼손을 가슴 높이에, 오른손을 어깨 높이에 두도록 이미 묘사했지만, ‘같은 인물의 두 손이 서로 다른 몸통 기준 높이에 있다’ 프로필의 구성요소 대체 표현에는 잡히지 않았다. 다만 그 프로필이 요구하는 양팔의 연결과 각 손가락 배열 전체가 원문에 충분히 지정됐는지는 별도 문제다. 빠진 구성요소를 추론해 통과시키지 않았다.

A의 새 `se_beckon_shaped_finger_static_state` 슬롯 후보도 현재 코어에서 사용 자격은 있으나 실제 팩에는 노출되지 않았다. 저장된 손 포즈 검색문은 인물·사건 설명에서 왔고, 가슴 높이의 왼손·위로 향한 손바닥·안쪽으로 굽힌 검지라는 구체적 문장을 포함하지 않았다. 실제 노출은 포갠 손과 머리 뒤 한 손 후보였다. 이는 적합한 손짓 후보를 놓친 사례이며, 검색문의 범위와 후보 순위를 추가로 조사할 근거다. 현재 진단만으로 순위 탈락의 원인 전부를 확정하지 않는다. 슬롯의 관찰 문장 발견 경로도 따로 존재하므로 그것을 함께 확인해야 한다.

보강 우선순위는 두 가지다. 먼저 서로 다른 문장에 나뉜 손 소유·높이·손가락 정보를 같은 인물에 묶은 뒤 전체 구성요소가 충족될 때 대체 표현을 인식하도록 한다. 다음으로 동결한 손짓 관찰이 손 포즈 검색과 후보 배분에 실제로 전달되는지 확인한다. 분위기 단어만으로 정밀 프로필을 켜거나 특정 후보 ID를 강제로 채택하는 방법은 사용하지 않는다. [재실행 진단과 전체 대조 기록](PARENT-RETRIEVAL-DIAGNOSTIC.json), [읽기 전용 진단 코드](diagnose_visual_retrieval.py)

## 원본 이미지 검증의 한계

세 arm의 기본 도구는 HTTP 400 `moderation_blocked`, `moderation_stage=output`, `categories=[sexual]`를 반환했다. 내부 출력은 전달되지 않았다. 출력 검토의 분류는 유혹적인 연출 성공, 참고 외모 재현, 손 소유·시선·쿠션 형태의 성공을 증명하지 않는다.

독립 장면 게이트 A 7개, B 8개, C 8개와 별도의 적용 계약 게이트 A 5개, B 8개, C 8개는 생성 전에 고정했다. 총 23개 장면 관찰과 21개 계약 관찰이며 서로 다른 평가 층의 수를 합쳐 고유한 시각 특징 수로 주장하지 않는다. 이미지가 없으므로 이 기준의 픽셀 점수는 모두 없음이다. 부분 관찰을 통과로 승격하거나 다른 시도의 부분을 합치지 않는다.

첫 프로토콜은 arm별 1회였다. A·B가 이미지 없이 출력 차단을 반환한 뒤, 프롬프트·첨부·코어·선택·기준을 바꾸지 않은 재시도 1회씩만 별도 정책 추가 기록으로 허용했다. 두 재시도도 차단됐고 모든 최초 실패와 실제 호출 수를 보존했다. C는 1회 후 추가 기본 도구 호출을 하지 않았다. 사용자의 최종 선택에 따라 대체 API 호출은 0회이고, 생성 모델을 바꾸거나 프롬프트를 완화한 추가 실행도 없다.

## 다음 검증에서 보완할 점

1. 문맥에 맞는 세 장면을 만드는 시험과, 연구한 정밀 형태의 적용을 확인하는 시험을 분리한다. 후자는 원래 연구 키워드에서 arm마다 몇 개의 형태 목표를 미리 지정하고, 각 에이전트가 그 목표를 서로 다른 유혹적 상황에 독립적으로 배치하도록 한다. 어떤 정밀 프로필도 요청의 넓은 분위기만으로 강제 활성화하지 않는다.
2. 이번 독립 문장으로 실제 검색을 진단한다. 프로필이 나오지 않는 이유가 형태 구성요소 미지정인지, 자연스러운 대체 표현 인식 부족인지, 검색 순위·문맥·속성 호환 조건인지 구분하고 각각 수정 후보를 만든다. 부분 구성요소를 전체 의미로 승격하는 해결책은 사용하지 않는다.
3. 유혹을 위한 선택적 조합은 동일 대상의 시선, 표정, 손/의복 또는 상대와의 접촉, 이미 보이는 반응, 거리/자리 관계를 각각 연결한다. 중립적인 한 자세를 유혹의 보편적 정의로 만들지 않는다. 데이터 변경이 필요한 경우 작성 자료와 검색 동작 변경을 구분해 검증한다.
4. 향후 이미지 생성이 다시 요청되면 고정 프롬프트·첨부·기준과 새 실행을 연결해 픽셀 판정과 전체 인상을 각각 확인한다. 이번 실행은 기본 도구 결과와 보고서로 종료하며, 이미지 없는 기록을 나중에 성공으로 덮어쓰지 않는다. 사용자 선호는 별도 판단으로 남긴다.

현재는 새 데이터나 실행 코드를 수정하지 않았다. 병합 완료 main `98ca92a070a6127a2e03877ec8a5d3f0dfda0467`의 고정 소스 243개 파일로 검증했고, primary의 다른 초안은 입력으로 섞지 않았다. 새 커밋이나 푸시는 이 재시험에서 수행하지 않았다. 최초 C안은 장소와 동작 다양성을 위해 이미지 생성 전에 중단하고, 그 데이터를 본 에이전트를 재사용하지 않은 새 C2 에이전트로 대체했다. 관련 독립성·정책 변경은 [시험 프로토콜](TEST-PROTOCOL.ko.md), [B 재시도](ATTEMPT-POLICY-ADDENDUM.json), [A 재시도](ATTEMPT-POLICY-ADDENDUM-A.json)에 남겼다.

마지막 검증에서 동결 소스 243개, 기존 추적 초안 20개, 첨부 이미지, 세 arm의 생성 전 동결 파일과 최종 해시 목록이 모두 원래 바이트와 일치했다. 생성 기록 5개의 실패·재시도 연결과 이미지 경로 없음도 확인했다. [최종 검증 기록](FINAL-VERIFICATION.json)
