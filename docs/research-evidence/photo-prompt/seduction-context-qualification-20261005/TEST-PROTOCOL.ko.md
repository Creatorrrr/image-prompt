# 유혹적 장면 재시험 — 고정 프로토콜

최신 사용자 요청과 앞선 수정 의도를 보존해 세 개의 새 장면을 독립적으로 설계한다. 이전 수영장·수선·건널목 이미지는 새 컨셉의 입력으로 사용하지 않는다. 같은 첨부 인물의 눈에 보이는 얼굴·머리만 참고한다. 세 장면의 성인 나이·관계·역할은 실험자가 새로 정한 설정이며 원본 인물의 신상 추론이 아니다.

## 실행 범위

- 데이터와 실행 코드: 병합 완료 main `98ca92a070a6127a2e03877ec8a5d3f0dfda0467`의 243개 파일을 별도 runtime에 고정한다. 로컬의 다른 초안은 읽지 않는다.
- 세 에이전트에게 장난스러운 주의 끌기, 가까운 거리의 교감, 의도적인 기다림이라는 서로 다른 넓은 주제만 배정한다. 구체적인 장소·행동·연출은 각자 결정한다.
- `sensual=3`, `fetish=0`은 요청한 중심 인상을 표현하기 위한 실험자의 설정이다. 사용자가 숫자를 지정했다고 간주하지 않는다.
- 각 arm은 상대 arm의 프롬프트·후보팩·이미지·평가를 보지 않는다. 부모만 전체 비교와 별도 원본 이미지 검토를 수행한다.
- 각 arm은 생성 전 코어·기본 프롬프트·시각 관찰축·신체 동작 검토·장면 판정 기준을 고정하고, 그 다음 실제 검색을 수행한다.
- arm마다 실제 이미지 생성은 한 번이다. 결과를 보고 기준을 바꾸거나 가장 나은 결과만 골라 발표하지 않는다.

## 구분하는 증거

1. 시각 의미 데이터: 출처 파일과 프로필 ID, 검색 노출, 명시적 채택 여부, 전체 구성요소·관계·혼동 경계, 프롬프트 증거 문구, 실제 적용된 렌더 판정 기준.
2. 후보 데이터: 슬롯 후보 ID와 출처, 노출·채택·거절, 적용한 속성, 기본 프롬프트와의 변화. 슬롯 후보 사용을 시각 의미 프로필 사용으로 계산하지 않는다.
3. 프롬프트와 실행: 코어·팩·선택·런타임·원본 첨부의 정확한 바인딩과 감사 결과.
4. 이미지 형태: 실제 원본 픽셀에서 모든 필수 구성요소를 확인한다. 일부만 보이면 실패, 가림으로 판단할 수 없으면 관찰 불가로 별도 표시하고 전체 통과에는 포함하지 않는다.
5. 전체 인상: 설정값과 데이터 채택 사실을 먼저 보지 않고, 눈에 보이는 장면의 주된 인상을 서술한 다음 고정된 연출 의도와 비교한다. 매력적인 얼굴만으로 유혹적인 장면이 구현됐다고 판단하지 않는다.
6. 사용자 판단: 실험자의 인상 평가와 구분하며 사용자 수락은 아직 받지 않은 상태로 기록한다.

이 시험은 현재 데이터가 실제 실행 경로와 프롬프트 및 이미지 형태까지 연결됐는지를 확인한다. 데이터가 없는 대조 이미지를 생성하지 않으므로 데이터가 이미지 품질을 인과적으로 개선했다고 주장하지 않는다. 생성 전부터 기본 프롬프트에 있던 형태는 검색 후에 처음 생긴 것으로 계산하지 않는다. 실제 인물의 생각·욕망·동의는 사진에서 추론하지 않는다.

## 생성 전 주제 재배정

세 독립 초안이 공연장 계열 장소에 집중되어 장면 차이를 강화했다. 최초 C안은 재배정 지시를 받기 전에 Phase 2 생성기를 실행했으므로 재작성의 데이터 독립성을 주장하지 않고 `arm-c/SUPERSEDED.json`으로 중단·보존했다. 그 arm의 실제 이미지 생성은 0회다. 새 데이터 미열람 에이전트의 `arm-c2`를 최종 C안으로 사용한다. 최종 세 생성 arm은 A·B·C2다. 새 C안에는 야외의 기다림이라는 실험자 주제 범위만 주며, 다른 arm의 프롬프트·후보·이미지는 제공하지 않는다. 세 주제는 무작위 표본으로 통계적 대표성을 주장하는 실험이 아니라, 서로 다른 연출 전략을 확인하는 독립 설계 사례다.
