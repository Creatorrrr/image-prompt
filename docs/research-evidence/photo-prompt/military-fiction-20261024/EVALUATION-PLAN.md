# 검증·평가 설계

모든 검색·이미지 결과는 현재 `NOT_RUN`이다. 이 문서는 통과 결과가 아니라 재현 가능한 후속 평가 설계다.

## 연구 자료의 무결성

원문 표 24개·393행의 셀과 순서, K/V/C/S ID의 유일성, 출처 참조, 카드 연결, 한영 본문, 관계 endpoint·화면 gate, 현행 slot 이름을 검사한다. 이 검사로 공식 정의의 정확성·시각 품질·native qualification은 증명되지 않는다.

`validate_research.py`는 연구 폴더만 읽고 `validation.json`을 쓴다. 운영 후보·인덱스를 읽기 위한 초기화나 벡터·이미지 호출을 하지 않는다. 비교 대상 slot catalog는 직접 읽는 정적 이름 목록이다.

## 검색용 입력과 집계

- [evaluation-cases.json](evaluation-cases.json): 연구 작성자가 만든 한영 자연어 24사례, 48질의. 인접 의미의 혼동과 관계 보존을 검사한다.
- [evaluation-queries.json](evaluation-queries.json): 104개 카드의 한영 전체 문장 208질의와 위 48질의, 합계 **256질의**. 전체 문장 probe는 literal 노출 확인이며 일반화 성능으로 해석하지 않는다.
- [keyword-atlas.json](keyword-atlas.json)의 393행 원어는 별도 coverage smoke set이다. 대부분 자연스러운 한영 쌍이 아니므로 786개 bilingual 평가라고 부풀리지 않는다.
- 독립 holdout: 현재 0개. 원문·카드·개발용 질의를 보지 않은 작성자의 추가 입력을 source/index 조정 전에 별도로 동결할 때만 holdout으로 분류한다.

256질의를 원본과 stage에 각각 적용하면 512회 검색 실행이 된다. 각 실행의 BM25F·cosine·RRF는 하나의 검색 결과 안의 lane이며 별도 독립 샘플 수로 더하지 않는다. 393개 원문 smoke는 별도 집계하고 중복 질의 텍스트를 제거한 실제 수를 기록한다.

## 검색 노출과 채택의 별도 판정

| 평가 | 측정·기록 | 잘못된 판정 예 |
|---|---|---|
| 원문 무결성 | 실제 CID/RID·source hash·조건·effects·선택 branch | 제목이 맞으면 같은 뜻이라고 처리 |
| 노출 | 실제 전체 공통 pool의 rank, BM25F/cosine/RRF, sample 여부 | topic 전용 pool에서 높은 순위만 보고 |
| 관계 적합 | 선택 가능한 전체 소스가 의도·owner·lock을 보존 | 접점 하나만 일치하면 후보 전체 채택 |
| 문맥 분리 | 진단·법적 지위·동의·소리·기능이 추가되지 않음 | 목록 노출과 잘못된 prompt 채택을 동일시 |
| 언어 | KO/EN rank와 완결 의미 차이 | 같은 한국어 제목을 bilingual 성공으로 계산 |
| 일반화 | 자연어 사례와 독립 holdout 별도 결과 | 카드 전체 문장 검색 성공을 자연어 성능으로 보고 |

첫 staging에서는 구조·조건 위반 0건을 필수 목표로 한다. rank 성공 기준은 새 CID 매핑이 확정된 뒤 고정한다. 제안 출발점은 직접 부품 질의의 top-8 적합 소스 노출, 대비 질의의 뜻을 보존한 실제 선택, baseline 대비 새로운 의미 오염 0건이다. 소스가 없는 보류 사례를 강제로 pass시키기 위해 무관한 소스를 지정하지 않는다.

creativity 0/1/2/3의 원 window·sample limit은 실제 설치 정책을 그대로 사용한다. 샘플에 나오지 않은 순위 내 후보와 원래 낮은 순위를 구분한다. 같은 source closure·코드·질의 recipe·모델·벡터·seed를 가능한 범위에서 맞추고 불가능한 항목은 기록한다. 지금 예상 CID는 비어 있다. 연구 V ID는 runtime source proof나 기대값을 대신하지 않는다.

## 초기 이미지 비교 12장면 × 2조건

후속 생성 시 별도 테스트 요청문을 작성하고 조건·모델·reference scope를 동결한다. 아래는 검사할 관계의 설계이며 현재 사용자의 요청문으로 위조할 입력이 아니다. baseline은 후보를 읽기 전에 독립적으로 작성한다. 원본/확장 조건에 같은 요청 의미·creative controls를 적용한다.

| 사례 | 장면 | 동시에 읽혀야 할 핵심 |
|---|---|---|
| P01 | 생활관 점호 | 인물 줄과 보고자, 명부 지지 손, 얼굴 방향 |
| P02 | 소총 슬링 | 같은 총의 두 부착점, 끈, 어깨 지지 |
| P03 | PALS와 파우치 | 같은 패널, 격자 구간, 파우치 뒤 끈의 결합 |
| P04 | 열린 캐리어 | 수납구, 판이 이어진 상태, 탁자 지지 |
| P05 | 올린 NVG | 헬멧 마운트, 연결 팔, 눈 위 장치와 드러난 눈 |
| P06 | 무전 | 같은 수화기, 손·귀·입 관계, 본체까지의 케이블 |
| P07 | 지도 공동 주목 | 같은 지도 지점, 짚는 손, 다른 인물들의 시선 |
| P08 | 해치 | 몸통이 열린 해치 안으로 이어짐, 양팔의 테두리 지지 |
| P09 | 천 들것 | 같은 프레임 양끝, 두 운반자의 손, 몸을 받치는 천 |
| P10 | 노즈아트 | 기체 곡면·패널선·그림 경계, 옆의 실물 인물 구분 |
| P11 | 성인 패션 하네스 | 의복 층, 장식끈의 주인, 같은 링의 접점 |
| P12 | 재회 포옹 | 각자의 팔과 상대 등, 몸의 연속, 양쪽 발 지지 |

실행할 경우 최초 24장 계획이며 현재 호출은 0이다. 일부 접점이 멀거나 가려지면 `UNOBSERVABLE_NOT_PASS`, 일부만 맞으면 `PARTIAL_FAIL`, 서비스 차단은 `BLOCKED_UNSCORED`, 전송·저장 실패는 `TRANSPORT_FAILED`로 남긴다. 이미지가 없는데 픽셀 gate를 pass/fail로 임의 채우지 않는다.

같은 seed가 지원되지 않거나 모델이 비결정적이면 단일 쌍의 선호를 인과적 개선으로 단정하지 않는다. 관계 충실도·전반적 장면 전달·미감 선호·사용자 수용은 별도 항목이다. 전체 군대물 장르의 예술적 개선을 12쌍만으로 확정하지 않는다.
