## 합의한 다음 방향

먼저 **BM25F와 dense의 검색 문서 투영을 분리**한다. D1은 기존 41건 보강을
BM25F에만 넣고 dense는 기존 A를 유지한다. 동일한 단일 query로 각 lane 1회만
검색하므로 두 검색어 병합이나 추가 검색이 아니다.

Claude와 Codex의 독립 사후 계산이 일치했다.

| 조건 | 알려진 적합 연결 | 지원 목표 hit | 보강 대상 30연결 | 나머지 96연결 |
|---|---:|---:|---:|---:|
| A | 55/126 | 28/40 | 17/30 | 38/96 |

아니며 기존 62/126·28/40 운영 기준을 통과한 결과도 아니다.

## 1차 답변을 논의해 바로잡은 부분

Claude는 후속 검토에서 아래 6개 반론을 모두 수용했다.

1. 부분 보강의 노출군 이득을 전체 보강으로 외삽하지 않는다. 전수 처리 시
   미보강군 손실이 사라진다는 주장과 예상 +7~+17을 철회했다.
2. 대체 후보가 미판정이어도 기존 known-positive 누락은 recall 손실이다.
   unknown을 negative로 세지 않는 것과 기존 누락을 제외하는 것은 별개다.
3. 이미 본 21/30 아래로 새 합격선을 그어 성공 처리하지 않는다. 기존 전체
   gate를 유지하고 부분집단 결과는 설명 자료로 쓴다.
4. 일부 unweighted RRF/quota 실험으로 모든 융합 정책을 배제하지 않는다.
   이번 라운드에서는 효과를 분리하고 예산을 제한하기 위해 융합을 고정한다.
5. 설치 generation builder가 native D/field 재구성, 임베딩 입력, cross-lane
   token 일치를 강제한다. `project()` 한 함수 수정으로 끝난다는 주장을 철회했다.
   컴파일러·새 builder/검증기·manifest·코드 binding까지 정비한다.
6. lane 순위는 실패 위치이며 query/문서/모델 원인을 단독 확정하는 근거가 아니다.

## 2차 리뷰에서 반영한 사항

- 각 sparse 값의 허용 출처와 dense 입력의 정확한 재구성을 대체 불변식으로 명시.
- Q1 query의 로컬 임베딩 최대 12건을 비용 범위에 포함.
- A 기준 0건 목표 12개 전부를 대상으로 고정하고 이미 회복된 목표도 제외하지 않음.
- query 절별 원 요청/의도/목표의 pointer·quote 및 의역 대응을 점수 전에 봉인.
- Q1은 목표 ID/CID 예외가 아닌 일반 작성 규칙이며 새 요청에도 동일하게 적용.
- 새 확인 집합은 3요청·6목표, composition2/lighting2/action1/body_pose1,
  최대 96개 목표별 연결 판정. 유용 소재의 목표별 개수·목표 coverage·unknown을 보고.
- 검증된 lane 분리 계약은 품질 HOLD가 나도 미활성 자산으로 보관.
- 설치 전 복구 시험, 전환 후 기존 receipt 재생 확인.

다음 제안은 수정해 반영했다.

- ‘특정 CID에만 있는 어휘 금지’는 채택하지 않았다. 정당한 드문 요청 표현을
  막거나 corpus 전체 어휘 검사로 확대하지 않고, 작성 입력 격리와 의미 출처를 감사한다.
- 회수의 깊은/얕은 순위 이동만으로 query 의미 개선을 증명하지 않는다.
  순위 이동은 진단 기록이며 새 요청 확인을 대체하지 않는다.
- 새 6개 목표 중 하나라도 회귀하면 HOLD라는 규칙은 채택하지 않았다.
  사용자 목적에 맞게 전체 유용 목표 수와 연결 수를 비교하고 개별 무회귀는 요구하지 않는다.
