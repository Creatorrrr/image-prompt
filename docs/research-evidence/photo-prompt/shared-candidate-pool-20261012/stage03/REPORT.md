# 3단계 — 공통 원본 전체 이관

원본 18,266개를 영속 후보 18,250개로 이관했다. 슬롯 연결 12,020개와 역할 태그 112개를 보존했다. 같은 내용·실효 효과의 중복 16쌍만 공유했고, 내용이 다른 동일 bare ID 그룹 68개는 별도 후보로 유지했다. 원본 ID는 출처 및 운영 밖 이관 증빙에만 남는다.

인입 원본은 동결된 `baseline-effective-data.json`이다. importer와 별도로 작성한 비교 프로그램이 931,827개 필드/값을 대조했다. 슬롯 행 12,020개, 시각 프로필 3,834개, 그래프 노드 184개(visual atom 141, guard/router 43), 개념 3개, confounder 21개, 묶음 2,204개와 구성원 3,312개를 확인했다. locale·관계·효과·weight·조건·부속 정책 누락은 0건이다. 묶음 구성원 중 572곳의 별도 의미 조건은 원본을 복사하지 않고 해당 참조의 requirements로 보존했다.

신규 manifest와 34개 모듈만으로 적재 및 참조 검증이 통과했다. 무태그 프로필·관계·묶음도 공통 원본이다. 원본 checksum과 전체 대응은 MIGRATION-LEDGER.json에 기록했다. REFERENCE-TRANSLATIONS.json은 평가·삭제 근거이며 신규 runtime은 읽지 않는다. 외부 backup의 importer 재실행과 corpus hash 비교로 결정성을 확인했다.

이 커밋은 전환용 신규 원본을 고정한다. 공개 CLI·팩·receipt·운영 fixture의 소비 코드 전환은 5–8단계에서 검증하며, 구 원본 삭제는 9단계에서 수행한다. 신규 hybrid 품질이나 이미지 품질을 이 결과로 주장하지 않는다.
