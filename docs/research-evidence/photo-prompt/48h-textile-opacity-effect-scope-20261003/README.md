# CT091 canonical opacity effects: installed qualification

This DATA-only change adds the existing `appearance / main_subject / wardrobe.surface.sheer_opacity` effect to two ordinary CT091 variants and their two matching visual profiles. **Four existing records, two concepts; no new concepts or runtime changes.** Original family effects, owners, dimensions, semantic texts, labels, aliases and gates are retained. CT098 and other color-overlap proposals remain deferred.

## Evidence and limits

- Two source-guided public product cases expose the defect: an opaque fabric lock previously permits explicitly sheer/translucent candidates. The patch marks the retained public candidates ineligible, and actual selection triggers applicability/property-preservation failures. Independent cape fixtures remove them at discovery instead. These are distinct routes, not interchangeable counts.
- Ten source-unexposed but theme-targeted fresh requests were retained. Seven admitted on first materialization, two after separately recorded adapter repairs, and one remained unadmitted. None of the nine admitted requests naturally exposes CT091 because the existing human `surface_material` slot guard excludes it. Therefore this cohort shows **zero measured natural benefit**, not nine successful blocker tests.
- Alternate valid opacity paths are not aliases of the canonical path. Same-owner/layer hierarchy can conservatively reject a compatible lining-only change. Sheer cloth does not imply visible skin, and overall garment coverage is a different predicate. These limitations remain unchanged.
- All 22 before/after unchanged-baseline composition audits passed after a documented archive-order recovery. Initial failures remain in evidence: sorting JSON keys had changed control-definition iteration order without changing values or canonical pack identity. Restoring original control snapshot order recovered the checks; no scene or control strength was rewritten.
