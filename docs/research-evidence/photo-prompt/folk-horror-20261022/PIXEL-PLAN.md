# 원본 이미지 검증 계획

상태: NOT_RUN. 이번 조사에서 이미지·임베딩 API를 호출하지 않았다. 아래 36장은 후속 구현의 첫 비교 범위 제안이며 생성 결과·비용 집행이 아니다.

## 비교 설계

12개의 필수 요청을 각각 후보 없는 독립 baseline A, 현행 corpus 후보를 비교한 B, 보강 corpus 후보를 비교한 C로 생성한다. 총 36장. 후보 조회 전에 각 요청의 동일한 baseline/core/controls를 동결하고 세 arm에 복제한다. A/B/C는 같은 requester 의미와 모델·크기·생성 설정을 사용하고 prompt/receipt/index/release hash를 각각 남긴다. 가능한 경우 시드를 맞추되 API가 보장하지 않으면 그 한계를 기록한다. 후보 채택을 강제하지 않는다.

## 판정 단위

원본 파일을 실제 해상도에서 열고 전체 장면과 필요한 세부를 확인한다. 접점 확대 crop은 보조 자료이며 원본에서 연결을 읽을 수 없었던 상태를 PASS로 바꾸지 않는다. 서로 다른 arm/재생성의 부분을 합쳐 한 성공으로 만들지 않는다.

각 gate에는 `visible / partial / unobservable`, PASS/FAIL/UNOBSERVABLE, 파일·좌표·실패 이유를 기록한다. 다중 구성의 의무는 전부 동시에 보여야 한다. `partial_is_fail`, `UNOBSERVABLE_NOT_PASS`를 적용한다. 생략된 소유자·양끝·수·범위는 분위기로 보완할 수 없다. 문맥뿐인 인과·동의·혈통·신의 실재·음성·시간의 흐름은 긍정 픽셀 gate가 아니다.

비교 보고서는 의미 준수, 접점·해부·물성, 장면의 원인과 반응을 읽는 정도, 장르 인상, 전체 선호를 분리한다. source 무결성·검색 노출·prompt audit PASS·생성 성공은 이 판정의 대체물이 아니다. 선호는 블라인드 arm 순서에서 비교하고 사용자 수락은 실제 사용자의 판단으로 남긴다.

한 arm당 한 장은 모델 변동성을 추정하지 못한다. 첫 비교에서 새 의미의 표현 실패나 큰 차이가 발견되면 그 사례만 동일 설정으로 반복하고, 데이터 수정 전후를 다시 평가한다. 변화 없는 전 사례 재생성이나 유리한 이미지 선택을 반복하지 않는다. 도구가 이미지를 반환하지 않으면 NO_PIXELS로 기록하고 시각적 실패/성공 점수에 섞지 않는다.
