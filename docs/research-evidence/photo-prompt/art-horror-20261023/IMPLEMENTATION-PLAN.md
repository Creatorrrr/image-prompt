# Art Horror 데이터 반영 계획

이 문서는 연구 결과를 운영 source에 반영하기 위한 실행 명세다. 이번 요청에서 수행한 것은 조사·초안·검증 명세 작성이다. 아래 등록·인덱스·검색·생성 단계는 아직 실행하지 않았다.

## 목표와 완료 기준

Art Horror를 요청했을 때 문맥에 맞는 완결된 시각 관계를 선택할 수 있고, 일반적인 인물·미술관·의지·가죽·임신 도해 요청에는 공포·성적 의미·신체 손상을 자동 추가하지 않는 상태가 목표다. 등록된 데이터 수와 작품의 미적 품질을 같은 성공 지표로 쓰지 않는다.

데이터 반영 완료는 다음을 모두 확인한 상태다.

1. 154개 용어와 원 대화의 25개 작품/조합 행이 보존되고, 각각 가시적 실현·문맥·추가 확인 중 무엇에 속하는지 추적 가능하다.
2. 선택한 모든 후보의 한영 의미·매체·소유자·관계·개수·조건을 온전히 보존한다. 유사한 기존 source가 있으면 중복 추가 여부를 실제 본문으로 판정한다.
3. 실제 선택된 realization의 모든 양성 필드에 원문 단위의 검토 근거가 있다. 연구 graph나 출처 URL을 native fact/permission으로 바꾸지 않는다.
4. source/index closure와 실제 활성 런타임의 노출을 각각 검증한다. 자연 질의의 정밀도와 일반 통제군 오염을 따로 기록한다.
5. 생성 평가를 수행한 경우 필요한 모든 관계가 같은 이미지에서 관찰된다. 일부 충족·가려짐·출력 차단을 전체 성공으로 바꾸지 않는다.

## 단계 1 — 중복과 반영 단위를 결정

입력은 `semantic-cards.json`, `candidate-drafts.json`, `existing-source-snapshots.json`, `slot-mapping.json`이다. 64개 초안은 보강할 의미의 제안이며 추가할 CID 64개를 미리 확정한 목록이 아니다.

|판정|처리|예|
|---|---|---|
|기존 완결 의미와 일치|원문 유지, 출처/용어 연결만 검토|V01의 거울 손 불일치, V20의 방 모형|
|기존 원문의 일부와만 유사|원문 보존, 추가 의미를 별도 실현으로 검토|V11의 젖음 경계와 기존 새틴 광택|
|관계/매체의 새로운 차이|한영 전체 문장을 독립 후보로 검토|V21 영상 안의 흠집, V60 인화물 손상과 묘사된 상처|
|문맥/시간/음향만 해당|문맥 자료에 보존하고 양성 시각 검색에서 제외하는 설계|롱테이크, 소리 철수, 동의, 반복강박|
|원전 확인이 부족|정의 검토를 보류하고 가시적 형태만 제한적으로 유지|Mulvey의 상세 독법, informe, Camp|

기존 source의 조건·효과·binding·선택 branch를 통째로 읽는다. ID나 짧은 영어 문장이 유사하다는 이유로 승인하지 않는다. 최종 추가/재사용/보류 수는 이 단계가 끝난 뒤 결정한다.

## 단계 2 — 원문과 연구 registry 작성

제안되는 파일 범위는 다음과 같다. 날짜는 실제 반영일에 맞추고, 아래 이름은 계획이다.

- `assets/photo_art_horror_semantics_YYYYMMDD.json`: 개념 구분·원 대화 route·관계 graph·문맥·출처 ledger를 담는 연구 registry.
- `assets/photo_candidate_art_horror_YYYYMMDD.json`: 검토를 통과한 **완결된 가시 실현만** 담는 후보 모듈.
- `assets/photo_candidate_art_horror_bindings_YYYYMMDD.json`: 실제 149개 catalog 중 해당 의미를 지원하는 검토된 binding.
- `assets/photo_candidate_corpus_manifest.json`: 위 후보/binding의 명시적 등록. registry의 문맥 데이터를 양성 후보처럼 혼합하지 않는다.
- `references/art-horror-visual-semantics.md`와 유지보수 문서: 의미 경계·증거 수준·확인 공백.
- 관련 data fixture/평가 명세와 필요한 범위의 계약 회귀 테스트. 런타임 로직 변경이 필요해지면 이유와 범위를 별도 분리한다.

`candidate-drafts.json`은 운영 모듈 스키마가 아니다. 초안의 ID·graph·source list를 복사하는 것만으로 등록이나 자격 심사가 끝나지 않는다. 새 CID/RID와 binding ID는 최종 source 의미가 확정된 후 발급한다.

## 단계 3 — 실제 슬롯과 native 원문 검토

`slot-mapping.json`은 연구 차원을 현재 존재하는 슬롯으로 옮길 때 검토할 **대안**이다. 여러 슬롯에 모두 붙이라는 지시가 아니다. 예를 들어 매체 관계는 `medium`, 반사는 `reflection_logic`, 표면 흠집은 `image_artifact`, 접촉은 `contact_point`, 거리와 배치는 `proxemics`/`composition`일 수 있다.

특히 다음을 선행한다.

1. 실제 CID/RID의 `en`/`ko`와 definition·application contract 등 양성 필드를 완전히 읽는다. 역할에 필요한 소유자·작동·target·receiver가 원문 자체에 있는지 확인한다.
2. 검토용 문장과 실제 원문 인용을 연결한다. 다른 realization, metadata, alias, 연구 graph에서 빠진 endpoint를 빌려 오지 않는다.
3. source guard의 eligibility와 역할의 의미적 적합성을 구별한다. 유효한 source여도 모든 역할에 승인된 것은 아니다.
4. `lighting`에는 source/배치/받는 면의 완결된 구성이 필요하다. ‘얼굴과 손에 밝은 부분’은 더 좁은 조도·광질 역할로 검토할 수 있다.
5. 매체를 바꾸면 새로운 의미다. 실제 허구 인물의 상처·분장·밀랍·조각·그림 속 상처를 하나의 선택 branch에서 서로 자동 대체하지 않는다.
6. 맥락 카드는 검색을 통해 들어오더라도 양성 시각 의무나 hard activation으로 승격되지 않도록 실제 저장·검색 계약을 확인한다. 조사 메타데이터의 `positive_retrieval=false`만으로 운영 격리가 보장된다고 주장하지 않는다.

기존 authorial-core 선행과 검색 이후의 선택/감사는 유지한다. 새 registry를 초기 장면 저술 전에 읽도록 연결하는 변경은 이 계획에 포함하지 않는다.

## 단계 4 — index와 설치 상태를 분리하여 검증

1. 연구 시작 시점이 아닌 **실제 합쳐진 최신 source**에서 별도 index를 생성한다. 동시 수정과 관련 source/index 해시를 기록한다.
2. 재사용 vector는 ID·정확한 text hash·text recipe·provider/model/dimensions·무결성이 모두 맞는 경우만 허용한다. 다른 recipe나 layout을 이름만 바꿔 재활용하지 않는다.
3. dictionary/source 검증, index closure, payload/vector 범위·누락·중복 검증을 통과시킨다. 실패 시 이전 데이터의 보존 상태와 실패 근거를 남긴다.
4. `photo_installed_h_f2.py --check-runtime`으로 실제 선택된 설치본과 Python을 확인한다. 작업 source 변경과 설치 release 갱신은 별도 단계다.
5. 관리된 검색 receipt에서 실제 새/재사용 CID가 노출됐는지 관찰한다. 별도의 source pool에만 추가한 것을 활성 런타임에서 검색 가능하다고 표현하지 않는다.
6. 설치/활성화는 검증된 산출물의 명시적 allowlist로 수행한다. 이전 실행·receipt·현재 선택 포인터의 복구 근거를 보존한다.

## 단계 5 — 검색과 회귀 평가

현재 [평가 명세](evaluation-cases.json)는 113개다. 64개는 카드 문장을 이용한 개발용 smoke probe, 20개는 직접 작성한 경계 통제군, 29개는 문맥 처리 probe다. 이는 미실행 명세이며 독립적인 자연 질의 성능이나 holdout 결과가 아니다.

반영 시에는 다음을 별도 평가한다.

- **완결 의미 노출:** 동일 의미의 기존 source도 정답으로 인정한다. 목표는 특정 새 CID의 순위 올리기가 아니다.
- **한영 의미 동등성:** 개수·신체/비신체·매체·부정·원인 미상 등의 조건을 두 언어에서 동일하게 유지한다.
- **혼동 음성군:** 정상 반사, 돌 조각의 팔, 실제 허구 신체의 상처, 피부 같은 직물, 실제 피부, 인공 의지, 생식 도해를 구별한다.
- **일반 요청 오염:** 일반 초상·평온한 갤러리·의지 착용자의 일상·비행 드론에서 호러/성/질병을 추가하지 않는다.
- **비가시성:** 소리·동의·혈연·사별·변신 전후·롱테이크가 가시적 cue만으로 통과되지 않는다.
- **부정과 다의어:** ‘호러 제외’, sound drone/aircraft drone, 실제 그림/거울, 느린 전진/줌을 구별한다.

새로운 자연 질의와 경계 사례는 반영 전에 동결하고 hash를 남긴다. 같은 문장을 복사한 검색은 데이터 가독성 점검으로만 보고, 자연 질의 Recall@k·semantic precision·오염률을 별도로 보고한다. threshold와 budget은 결과를 본 뒤 낮추지 않는다. 현재 지정 문맥 통제군에서는 금지된 의미 승격이 한 건이라도 나오면 해당 범위를 재검토한다.

테스트는 영향을 받는 source/parser/binding/index/검색 계약부터 실행한다. 전체 테스트가 필요한 변경 범위인지 판단하고, 관계없는 로직을 수정하거나 전체 테스트 통과로 픽셀 품질을 대신하지 않는다.

## 단계 6 — 이미지 평가와 미적 판단

[PIXEL-PLAN.md](PIXEL-PLAN.md)의 첫 8개 장면군에서 기존 데이터와 추가 데이터 노출을 비교한다. 각 장면의 독립 저술 core·사용자 의미·creative controls를 동결하고, retrieval 노출·실제 후보 선택·최종 프롬프트·전송·저장 이미지·픽셀·미적 판단을 분리한다.

새 후보가 노출돼도 선택되지 않을 수 있다. 이때는 ‘검색 노출 확인’으로만 기록한다. 실제 사용되지 않은 후보 때문에 이미지가 좋아졌다고 해석하지 않는다. 모든 hard 관계의 양 끝점과 매체 경계가 같은 프레임에서 읽혀야 전체 통과다. 관객의 감정·의도·동의 등 원래 비가시적 의미는 이미지에 없는 증거를 요구하거나, 스틸만으로 통과시키지 않는다.

## 권장 순서와 산출물

|우선순위|작업|검토 가능한 결과|
|---|---|---|
|P0|매체·소유자·반사·몸/물체 경계, 기존 source 재사용 판정|CID/RID별 유지·확장·새 실현·보류표와 원문 인용|
|P0|시간·음향·동의·혈연·원인 정보의 문맥 보존|문맥 라우팅과 비승격 통제군 결과|
|P1|새로 필요한 시각 관계와 기존 슬롯 binding 작성|완결 한영 source와 field/role 검토 근거|
|P1|분리 index와 실제 설치본 검색 검증|source/index 해시·검증 로그·검색 receipt|
|P2|8개 장면군의 비교 이미지와 미적 평가|선택/비선택 기록·이미지·gate별 판단·한계|
|별도 보완|원전 공백과 나머지 작품의 상세 검토|추가 독서 범위와 수정된 정의/경계|

commit·push가 이어질 경우에는 기존 dirty/untracked 작업을 보호한 상태에서 파일 allowlist와 staged name/blob를 대조한다. 실제 테스트한 병합 source로 index를 만들고, 로컬·tracking·실제 원격 SHA를 확인한 뒤 임시 worktree를 정리한다. 이는 향후 출판 절차이며 이번 연구에서 수행하지 않았다.
