# 별도 범위로 검증할 후속 사양

이 사양은 변경 제안이며 구현하거나 승인한 내용이 아니다. 기본 요청·기본문·정답을 바꾸지 않고 새 독립 대조군을 패치 전에 동결한다. 네 원인을 한꺼번에 바꾸지 말고 각각의 효과와 퇴보를 분리한다.

## 1. 후보 속성 검사 누락

대상: 팩 생성의 기존 후보 적합성 표기와 공통 속성 계약 사이의 일치.

- 부분 카메라 잠금이 있는006에서 효과 범위가 없는 top-down/bird’s-eye 후보가 적합하다고 표기되지 않아야 한다
- 속성 잠금이 없는 입력의 기존 동작을 보존한다
- 명시적으로 다른 대상/다른 속성만 건드리는 대안, 겹치는 상위 속성, 빈/누락 효과 범위를 각각 대조한다
- 요청 문구나 특정 후보 ID를 위한 예외를 만들지 않는다
- 최종 선택·작성 감사도 같은 계약을 지키는지 별도로 확인한다. 팩 표기 개선을 이미지 품질 향상으로 계산하지 않는다

데이터만으로 부족한 이유: 일부 행에 효과 필드를 더하는 것은 다른 누락 행의 실행 경로를 고치지 않는다. 모든 기존 행에 임의의 속성 경로를 붙이면 근거 없는 세밀함을 선언하게 된다. 공통 누락/불명 효과 처리와 기존 호환성은 런타임 차원의 판단이 필요하다.

## 2. 중요한 슬롯의 후보 예산

대상: 원시 적합/조회 성공과 최종 팩 사이의 슬롯 배분.

- 007의 초점면 관계와009–012의 질감이 적합 조회 결과를 얻었을 때 단순 방문 순서 때문에 전부 없어지는 상황을 줄인다
- 총량 제한·중복 억제·결정적 재현성을 유지하고, 다른 명시적 핵심 슬롯을 밀어내는 퇴보를 함께 측정한다
- 숨겨진 원시 조회와 실제 노출 후보를 분리해 평가한다. 비선호 셔플의 표시 순위를 검색 순위로 계산하지 않는다
- 12건에 맞춘 슬롯명/문구 우선순위가 아닌 일반적인 배분 근거를 검증한다

데이터만으로 부족한 이유: 슬롯에 점수가 좋은 항목이 이미 존재해도 남은 예산이0이면 나오지 않는다. 발견 경로 opt-in을 임의로 켜는 것은 단순 어휘 수정이 아니라 라우팅 동작 변경이다.

## 3. 대상 범주의 전달

대상: 독립 작성 코어와 슬롯 범주 가드 사이의 의미 계약.

- 일반적인 숟가락·목도리·잔·종이봉투를 조회시키기 위해 원본 요청에 기술적 object 별칭을 삽입하지 않는다
- object/food/plant/environment/sign과 animal/human/unknown을 구별하는 독립 대조군을 둔다
- nonhuman을 object로 통째로 바꾸거나 generic을 일괄 허용하지 않는다
- 다른 원인인 후보 예산과 분리하여 범주별 적합 결과를 먼저 측정한다

데이터만으로 부족한 이유: 표면 후보의 어휘와 관계가 맞아도 앞단 범주가 불명확하면 차단된다. 몇몇 실패 명사만 별칭 목록에 추가하는 방식은 자연어 의미 전달 문제를 일반적으로 해결하지 못한다.

## 4. 슬롯 질의에 실제 소유 근거 전달

대상: light_direction의 setting 우선 질의와 요청 근거의 연결.

- 001의 그대로인 요청·기본문·우선순위/속성 근거로 역광 방향을 조회한다. setting에 정답 용어를 덧붙여 통과시키지 않는다
- 물체의 왼쪽/카메라의 왼쪽/광원의 왼쪽, 배경 광원/주체 조명, 명시적 제외를 독립 대조한다
- 엉뚱한 슬롯의 단어가 방향을 결정하지 않도록 소유 관계를 보존한다
- 필요한 슬롯 근거만 쓰고 전체 문장을 무차별 복제하거나 문장별 예외를 늘리지 않는다

데이터만으로 부족한 이유: 관련 근거가 슬롯 전용 질의에 들어오지 않는 단계의 문제다. 문맥에 맞지 않는 단어를 후보 데이터에 넣어 점수를 만들면 관련성을 오염시킬 수 있다.

## 완료 조건

원래/부분 잠금 입력, 독립 새 대조군, 기존 관련 테스트를 모두 실행한다. 소스·인덱스 바인딩과 양쪽 병합 의도를 검증하고 실패/미실행을 숨기지 않는다. 후보 도달·적합성 개선, 최종 작성 계약 준수, 실제 픽셀 품질은 각각 별도 결과로 보고한다. 전체 기존 테스트의 자료 누락은 해결 여부를 별도로 표시한다.
