## Why V12 is appropriately narrow

The actual frozen V11 before/after packs are byte-identical, while V11's visual-index source pin differs. V12 therefore has a dedicated zero-pack-delta rule rather than weakening the old four-leaf rule.

- The V10/V11 four-leaf validator function is verbatim unchanged
- V1–V11 manifests, old packs/proofs, universal V1, holdouts and oracle anchors remain unchanged
- Current universal V2 is exactly its archived old raw bytes with one validator-hash replacement
- V12 requires exact raw V11/current pack equality, canonical ID, full lineage, frozen inputs/recipe, source inventory, provenance and a code-pinned reviewed proof identity
- No pack field is exempt, including the four fields allowed to change in V10/V11
- Version 12 is explicitly registered; an unregistered V13 file cannot promote itself
- The illustration validator hashes opaque source bytes and reconstructs literal replacements; it does not import the photo runtime or interpret registry semantics

The security boundary is the unchanged reviewed validator and fixed proof anchor. Attacker-controlled files cannot choose a replacement anchor. This is not a claim to resist an attacker who is also allowed to rewrite the trusted validator code.
