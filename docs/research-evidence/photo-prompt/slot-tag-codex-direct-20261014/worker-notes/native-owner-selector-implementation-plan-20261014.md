## Workflow/receipt correction

`photo_workflow.py:compose_audit` already saves composed bytes and its independent report as separate run artifacts. The audit report will contain a source/core/graph/selection/composed-hash-bound native owner resolution receipt. Once a composition **successfully** audits, changing owner selections in that run is rejected. Same input replay and ordinary failed-audit correction keep current behavior; prompt revision with the same selection reruns normal audit without silently rebinding owners. `prepare_render` takes the audited resolution SHA and composed canonical SHA from the stored result, never caller overrides. `photo_workflow_worker.audit_bound(runtime=True)` compares stored/fresh result bindings. `audit_image_render_request.py` independently recomputes resolution from the same composed input/source and checks those request bindings. API preflight already calls both auditors and pins input bytes and reports, so its schema and runtime_sources receipt schema need no edit. This path is compatible with the existing coordinator and requires no pack mutation/republication.
