# Explicit latest-native review verification: first delivery

This delivery implements `native_reviews.py` and its isolated tests. It does not extend `native_adoption.py` yet. The existing adoption v1 cannot consume a verified latest set, and cannot use this module's report as a production authorization. Root may integrate this first contract before implementing adoption v2 and its explicit member/presentation-role/binding approvals.

## Read-only entry points

`verify_batch(assignment_path, batch_path, note_path, root=..., here=...)` reads only. It returns exact worker statuses and a shape/integrity report. It always reports `root_accepted=false`, `operational_native_qualified_count=0`, and `semantic_accuracy_certified=false`.

`verify_acceptance(root, artifact_ref, verified_batch)` checks an independently authored root acceptance. It never creates or writes acceptance. Every worker row digest and its exact approved/diagnostic_reviewed/pending status must match; root cannot change a pending row to approved in acceptance.

`verify_latest(manifest_path, root=..., here=...)` reopens each exact batch, assignment, note and acceptance; all IDs must be present exactly once against the same full current source/catalog, all statuses must be approved or diagnostic_reviewed, and all dependency proof payloads must equal the corresponding latest accepted child proof. Default inventory is exactly18,250. Small-fixture Python calls can supply another expected count, but the returned production gate is false; the CLI has no count override. The result still has operational qualification count0 and `canonical_applied=false`.

Future adoption v2 must call `verify_latest` afresh, require its production count gate, and bind the exact current source/catalog and latest-manifest digest. It must additionally verify every explicitly authored binding/condition/presentation-role/source-reference change under the final member contract. This first module supplies no binding ID generator, retarget/delete rule, semantic fallback, registration or apply path.

## Exact JSON input contracts

All paths resolve inside the explicitly supplied root. An artifact reference has exactly `file`, `file_sha256` (raw bytes), and `sha256` (decoded canonical JSON). JSON and gzip JSON are supported; duplicate keys and nonfinite values fail. Actor strings are collaboration-protocol assertions, not cryptographic authentication.

- Root assignment schema `photo-codex-native-review-assignment/v1`: `actor=/root`, actual `task_name`, `model=gpt-6.1-sol`, `reasoning_effort=high`, exact ordered `ids`, their exact `ordinals` in the immutable full order, and the input artifact reference.
- Root input schema `photo-codex-native-review-input/v1`: `actor=/root`, exact `ids`, original and current full-corpus snapshot artifact references, full order reference, `catalog_review`, per-CID `original_decisions` locators, per-CID `original_packets` references, and explicit `required_revisions` (including an intentionally empty object if none).
- `catalog_review`: full exact `before` and `after` catalogs, reviewer, `whole_catalog_reviewed=true`, hash-bound provenance artifact references, and explicit `changes`. Added roles and changed specifications are supported; historical and latest role sets need not match. Native specification shape, current spec digests, dimensions and full catalog digest are checked. No role is inferred or copied into a proof.
- Historical compiled locator: exactly `file`, `file_sha256`, one-based `item`, and `row_sha256`. The file must be under the actual run's `decisions/`, never `authored/`. Its candidate/source/catalog/reference bindings, original full source packet, and separately linked immutable authored judgement are checked. A pending historical judgement remains pending in that original artifact. New native status is a separate worker field. Unregistered amendment proposals do not replace the original compiled locator.
- Explicit delta items have `pointer`, `before_exists`, `before`, `after_exists`, `after`, and nonempty `reason`. Exact object-field subtree replacement/addition/deletion is supported, including complete lists as values. Overlapping edits, guessed old values, nonexistent parent objects and no-op edits fail. Applying the authored delta to the full original record must reproduce the full current record exactly. Candidate ID and original provenance prefix are preserved. Kind/reference changes thus require explicit delta, whole-meaning correction proof and separate root acceptance; shape alone cannot adopt them.
- Worker batch schema `photo-codex-native-review-batch/v1`: exact task/model/effort, assignment and input canonical digests, `prepared_count`, `actual_read_count`, and one explicit row for every prepared ID. No default status or missing-row inference exists.
- Row: `candidate_id`, `ordinal`, explicit `status` (approved/diagnostic_reviewed/pending), individual `rationale`, full `source_before` and `source_after`, `delta`, exact `original_compiled` locator, separate native v3 `proof` or null for pending, complete `dependency_records` with current qualified proof when applicable, full exact `reference_bindings`, explicit source/dependency reread booleans and an explicit `revision` object or null.
- Worker note schema `photo-codex-native-review-note/v1`: same task/model/effort/assignment/input bindings plus exact batch digest, prepared/actual counts and ordered `whole_source_read_ids` / `whole_dependency_read_ids`. Approved rows require full reading; a new proof requires both reading attestations. Pending unread prepared rows stay distinguishable from completed reads.
- The v3 proof retains all native fact modes, typed values, owners, operations, receiver/requires lists, full source-unit dispositions, actual realization inventory, full effects, current role specification hashes, current full catalog, whole-meaning digest, dependency and explicit legacy-guard closure and native-contract digest. The original review artifact string must be the real compiled `file#item`; assigned worker task and subagent direct-read method are exact. No modes/values/guards/empty lists are synthesized.

## Revision and acceptance boundaries

`required_revisions[cid]` has an exact `prior_review` locator (`artifact` reference, JSON `pointer`, canonical `sha256`), memo artifact references, and root reason. The new worker row's `revision` must carry that exact prior locator/memo list plus a new rationale. Missing, changed or extra revisions fail. Root must list known later memos explicitly in the immutable input; this verifier does not search the filesystem for semantic findings.

The frozen pilot25 input/assignment/proof/source/note artifacts use their historical formats. They are not automatically converted, accepted or amended. Its later golden-hour memo is not an ordinal11 exception in code. Root must provide a new exact assignment/input requiring that prior-pilot judgement and memo, followed by an explicitly authored worker revision and separate root acceptance. A shape-valid pending proof remains pending. This tooling does not reread or approve the25 candidate meanings.

Root acceptance schema `photo-codex-native-review-acceptance/v1` binds assignment/input/batch/note digests and a per-CID `{review_sha256,status}` map, with `actor=/root` and reason. The latest manifest schema `photo-codex-latest-native-reviews/v1` binds original/current full snapshot references, full order and explicit assignment/batch/note/acceptance artifact references. Neither document is generated by production code.

## Validation and remaining integration

17 isolated offline tests pass. They cover new catalog roles independent of historical role sets; preserved historical pending judgements; actual compiled rather than authored locator; historical packet/authored tampering; complete source delta/guard/kind/reference checks; exact task/model/effort/assignment/input/count attestations; partial reads; native v3 proof/hash/unit/effect/spec/closure failures; transitive binding-only candidate reference closure; explicit pending memo revision; independent root acceptance; full-inventory pending0 gate; diagnostic status and no positive roles; legacy pilot rejection; and duplicate/nonfinite JSON rejection. Repeated successful checks do not establish corpus semantic correctness.

A pre-existing adoption-v1 fixture (`test_removed_referenced_binding_never_falls_back_to_a_different_slot`) failed when initially included by an imported test class because the concurrently updated native `referenced_records` now binds explicit legacy guards as well as candidate meanings. New tests import its fixture module without collecting that old class. No adoption-v1 source/test file was modified in this delivery. Root should reconcile that fixture and the final member/presentation-role contract during adoption-v2 work.
