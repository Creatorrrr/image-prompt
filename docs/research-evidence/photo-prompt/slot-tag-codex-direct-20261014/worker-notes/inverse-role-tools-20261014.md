# Stage 5C inverse-role mechanical tools (offline preparation only)

Scope: new `inverse_role_search.py`, `local_execution_ledger.py`, and
`tests/test_photo_direct_inverse_search.py`. No existing canonical asset,
binding, index, runtime, global progress file, or commit was changed by this work.
No actual local embedding inference, external model/API/CLI, Gemini request,
download, or network request was made. Native layout fixture construction occurs
only inside isolated temporary directories; all model-worker entry is guarded in
the tests. Test vectors and explicit mocked traces are not real inference proof.

The tools prepare one bilingual scene-free query for each of the current 139
slots. Exact English and Korean authored descriptions and inclusion/exclusion,
owner, property-prefix, dimension, semantic-role, neighbor, applicability and
core-field boundaries are serialized from `photo_slot_queries.specification`.
No scene or candidate content enters query construction. The inclusion-oriented
BM25F fields and full-boundary embedding text derive from that same specification.
This preserves the two authored language versions; it does not establish their
semantic agreement, which remains part of direct source review. These inverse
role-mapping queries cannot stand in for runtime frozen-core slot-query proof.

`prepare_assets(assets, output)` reads the full current source, requires exact
`embeddinggemma2-local`/installed-space agreement, verifies the complete existing
source/index closure using `photo_search_layout.verify`, then exclusively writes
verification and a canonical query plan below an explicit dedicated descendant of
this evidence directory. Preparation does not call inference. The plan binds raw
source module hashes, full canonical source/catalog/bindings, every exact slot
specification/query text, manifest/vector-source/positive-pool hashes, local space
and installed-runtime binding. It refuses catalog counts other than current 139.
The real installed package/dependencies, actual source/index closure, and real
query-plan output have deliberately not been exercised or emitted by this worker.

`execute_queries(assets, output, run_id, execution_enabled=True,
before_start=counter_hook)` is the only inference entry. Root must review it,
wire CURRENT/global accounting first through the required callback, and explicitly
execute it later. It rechecks source/index/installed bindings. Durable exclusive
`planned.json` and `started.json` precede its one call to
`photo_embedding_provider.embed_many(..., space=explicit_local_space, kind='query')`.
Every run has a private provider cache and a unique run ID. There is no fallback,
automatic retry, or overwrite. Returned provider rows are saved before validating
per-input request, vector and real provider execution trace. Successful rows get
exact fresh-result/cache-hit receipts and trace hashes. Complete outcomes reference
the immutable saved result. Failed/started unknown outcomes produce
`exact_total=None`, retain `confirmed_minimum`, and list unknown run IDs; zero
confirmed results is explicitly a lower bound, not an exact zero. Process death
before an outcome leaves `started.json` visible and unknown. Planned/unstarted
runs are separated. Ledger totals cover only its recorded runs, not historical or
global usage. The root callback must preserve those distinctions in CURRENT.

The ledger accepts `kind='document'` for a future integrated document/build
embedding path. This tool's actual document/build execution is unsupported and
does not currently account for embeddings generated by unrelated scripts.

`retrieve_assets(assets, output, run_id, oracle_slots=(...))` accepts only a
completed saved result with exact query-plan/source/index/local-space bindings
and valid execution traces. It searches all source-positive IDs through native
`lexical_rank` and `cosine_rank`, audits BM25F replay and certified cosine coverage,
and checks independently implemented RRF. It never admits candidates based on
slot bindings/tags or adopts diagnostic records. It writes both lanes, union and
fused ranks, provenance source IDs, stored candidate hashes, actual reader-I/O
metrics, cosine pruning proofs and source/index/space hashes. Full-scan oracle
slots rebuild lexical documents from source and scan every stored vector without
using the routing tree, independently comparing both lane ranks and fusion.
No semantic labels, binding changes or completion decisions are written.

The fixtures include a best untagged cosine hit, an untagged lexical hit, a
diagnostic lookalike, negative cosine, native shards, independently rebuilt
full-scan ranks, deliberate lane omission/partition/fusion faults, dropped or
duplicate pool identities, immutable plan mismatches, invalid mocked trace,
durable pre-call receipts, cache-hit separation, failed unknown accounting, and
document-kind ledger support. A separate serialization-only fixture checks all
139 current catalog roles without invoking a model. These checks validate tool
mechanics, not actual-corpus retrieval relevance or role-mapping quality.

Root still must review tools, validate the installed local space and complete
source/index closure, freeze the real plan, wire global counters, explicitly run
inference, review the saved traces/counts, execute retrieval/oracles, and directly
adjudicate the results. Stage 5C and stages 6–8 are not complete from this work.
