# 표본 감사에 따른 후보 품질 개선 — 2026-10-13

앞선 무작위 1,000개 감사의 확인된 문제를 원본에 반영했다. 후보 본문·효과 110개, 슬롯 연결 452개, 슬롯 공통 적용 조건 3개를 수정했다. 중복을 제외하면 542개 후보에 본문 또는 연결 조건 변경이 있다. 원본 후보 18,250개와 연결 12,020개의 개수, canonical ID, binding ID, 구성원·프로필 참조, 연결의 역할·weight는 유지했다.

이 작업은 확인된 데이터 품질 문제의 보정이다. 전체 데이터에 적합한 슬롯을 여러 개 새로 연결하는 작업은 후속 계획으로 분리한다. 일반 시각 후보 12,004개의 연결 개수는 여전히 1개인 후보 11,988개, 2개인 후보 16개다. 넓지만 관련 있는 슬롯 30개를 모두 오류로 재분류하거나 자동 다중 태그로 확장하지 않았다.

## 검증 결과

- 원본·참조 검증: 18,250개 후보와 12,020개 연결에서 통과했다. 전체 corpus hash가 검토한 수정 ledger와 일치한다. 변경한 본문의 기존 출처, 묶음 구성원·프로필 참조·부속 요구사항과 연결의 ID·role·weight를 대조했다.
- 소재 조건 검증: 264개에서 명시된 주체와 보통의 fashion 또는 wildlife 계약으로 비교했고, 이전 거부 → 수정 후 허용을 확인했다. 이것은 적용 조건 검증이며 모든 후보의 요청별 채택을 보장하는 결과는 아니다.
- 관련 회귀 테스트: 85개 통과. 인물 없는 요청과 성인 허용 조건의 거부, 일반 촬영·소재·장치 역할의 적용 범위, 독립 슬롯 질의, 지연 shard reader, native runtime freshness를 확인했다.
- 인덱스: 검색 대상 18,186개 전체, vector leaf 3,850개, payload shard 286개, posting shard 373개를 검증했다. 변경된 검색 문장 97개만 새로 임베딩했고 기존 벡터 18,089개를 재사용했다. 사용 공간은 gemini / gemini-embedding-2 / 768 dimensions다.
- 실제 검색 질의: 보정한 의미를 토대로 작성한 16개 질의에서 BM25F 대상 순위는 모두 1위, 임베딩은 1~3위, 합성 RRF는 1~2위였다. 모든 질의가 태그로 분할하지 않은 18,186개 공통 풀을 검색했다. 각 lane은 별도 전체 스캔 결과와 일치했고 cosine shard 생략 증명도 통과했다. 질의당 확인한 vector leaf는 362~1,893개다. 캐시에 있던 leaf 접근과 실제 새 extent 읽기는 구분하며, 이 수를 그대로 디스크 I/O 횟수로 해석하지 않는다.
- 새 질의의 실제 임베딩 호출은 16회다. 데이터 갱신 97회와 합하면 이번 검증의 provider 호출은 113회다. 이미지 API는 호출하지 않았다.
- 로컬 current 실행 데이터는 새 generation으로 갱신한 뒤 실제 acquire 경로에서 본문 110개와 연결 452개의 반영 여부를 별도로 확인했다. 커밋·원격 푸시 상태는 이 생성 검증과 별개다.

최종 대조에서 #998의 구체적인 도움 동작에 다른 성인이 포함되는 만큼 행위자 수와 관계 효과도 선언했다. 이는 필수 조건을 검토할 때 추가 행위자를 놓치지 않기 위한 보정이다. 검색 문장은 바뀌지 않아 metadata 보정 뒤에는 전체 벡터 18,186개를 재사용했고 추가 provider 호출은 0회였다. 같은 text·slot·recipe·space의 실제 질의 벡터 16개도 재사용해 최종 corpus에서 순위와 oracle을 다시 대조했다. 초기 빌드·질의 실행 로그와 최종 결과를 모두 보존한다.

초기에 추가한 no_people 테스트 1개는 for_any의 적용 대상과 실제 인물 표지를 혼동한 단일 함수 반환값을 기대해 실패했다. 실제 후보 적격성 판정 경로에서 인물 없는 오브젝트 계약이 거부하는지 확인하도록 테스트를 수정했다. 런타임 동작을 그 기대값에 맞춰 바꾸지 않았다. 최초 로그와 최종 85개 통과 로그를 모두 보존했다.

기존 수정 중인 문서 2개의 SHA는 유지됐다. 이번 표본에서 본문이 그대로인 892개도 hash로 확인했다. 기존 판정표는 감사 당시의 판정으로 보존했고 수정 뒤 모두를 기계적으로 clear로 바꾸지 않았다.

감사 CSV의 줄 끝을 CRLF에서 LF로 정규화하고 문서 끝의 중복 빈 줄을 제거했다. CSV 1,000행의 파싱된 모든 필드 값은 동일하고 기존 UTF-8 BOM도 유지한다. 증빙의 출력 파일 hash를 새 표현에 맞춰 갱신했으며 이전 CSV bytes를 복원할 수 있음을 [FORMAT-VERIFICATION.json](FORMAT-VERIFICATION.json)에 기록했다. CSV 작성 코드도 LF를 사용하도록 수정했다.

## 근거와 한계

검토한 전체 전후 내용은 [FIXES.json](FIXES.json), 파일 고정값은 [SOURCE-BEFORE.json](SOURCE-BEFORE.json), 원본 검증은 [SOURCE-VERIFICATION.json](SOURCE-VERIFICATION.json)에 있다. [적용 코드](apply_fixes.py)는 감사 원본 hash와 검토한 제안을 확인하고 해당 모듈만 쓴다. [검증 코드](verify_source.py)와 [검색 검증 코드](hybrid_probes.py), [검색 결과](HYBRID-PROBES.json), [인덱스 빌드 기록](BUILD-REPORT.json), [실행 데이터 검증](RUNTIME-VERIFICATION.json)을 함께 보존했다.

태그 후보를 새로 분류하는 전체 데이터 검토는 후속 작업이다. 이번에 발견한 공통 조건 충돌은 해당하는 원본 전체에 보정했지만 모든 후보 18,250개의 의미를 새로 심사한 것은 아니다. 시점·소유 관계·부품 경계의 수정과 rank 검증은 생성 이미지의 실제 픽셀 품질·전문가 합의·실서비스 검색 정확도를 증명하지 않는다. 16개 질의는 작성한 정비용 질의이며 독립적인 운영 트래픽이나 미공개 holdout이 아니다. 역사·의도·소리·재료 정체 같은 맥락 정보는 단일 사진으로 증명할 수 없다는 이유만으로 제거하지 않았다.
