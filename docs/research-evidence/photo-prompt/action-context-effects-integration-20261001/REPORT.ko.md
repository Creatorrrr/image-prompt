# DATA 개선과 최신 main 병합

## 결과

계획한 행동 → 상황·관계·맥락 → 새 편집 효과 순서로 52개를 검토해 16개만 수정했다. 이후 요청받은 최신 main `98847a8bcc35f85142fe0eb4322e35eacbe9fdc2`를 받아 양쪽 변경을 함께 유지했다.

- 행동 24개 중 2개: 긍정 검색문에 섞인 과거 편집 지시·셀피 비교 표현 정리
- 상황·관계·맥락 16개 중 5개: 우산 방향과 마주 앉는 관계의 한영 일치, 조각 별칭을 완전한 상황 표현으로 정리
- 편집 효과 12개 중 9개: 넓은 제안 그룹의 효과 소유자를 실제 후보의 이미지 평면·직물 영역·종이 표면/가장자리 등과 일치
- 나머지 36개와 이전에 게시한 37개 수정은 보존

의도된 왕실·감금·아파트·반려동물·의상 동작 등의 특수성을 임의로 일반화하지 않았다. discovery 설정, 속성 잠금, 가중치, 태그와 기존 프리셋을 유지했다.

## 최신 main과의 결합

개선 작업은 먼저 `06bd1edb6dfc5f3b69aad78137ec3fd3755a9f97`에 로컬 체크포인트로 보존했다. 원본 평가 자료는 수정하지 않았다.

최신 main은 의복 구조·직물 표면·액세서리/신발·전통 복식의 네 확장에 후보 287개와 선택적 번들 30개를 추가한다. 기존 9,145개 슬롯 항목을 바꾸지 않았으므로 이번 16개와 원문 충돌은 없었다. 프리셋과 기존 번들도 유지됐다.

충돌은 생성된 semantic-index manifest 한 곳이었다. 어느 쪽 파일도 통째로 선택하지 않고, 실제 병합 사전으로 BM25F를 다시 만들고 키·전체 텍스트·모델·차원이 일치하는 캐시 벡터를 결합했다.

- 최종 슬롯 항목 9,432개, semantic 문서 10,174개
- 양쪽이 일치하는 벡터 9,871개, 이번 개선의 벡터 16개, upstream 새 벡터 287개
- 누락 입력 0개, 공유 벡터 불일치 0개, 병합으로 인한 API 호출 0회
- upstream의 runtime·validator·시각 프로파일/인덱스와 새 확장 파일을 그대로 유지
- 이번 16개 원본 항목을 개선 후 상태 그대로 유지, 이전 shard 세대도 보존

최종 사전/인덱스 해시는 `c59474d21f2d1ae56d228811f4d086d82a88e2d137e630d484a6e9ef3766975c`이다.

## 검색 결과와 한계

수정 전 고정한 32개 검색문(양성 18개, 대조 탐침 14개)을 사용했다.

개선 전후 9,887문서 기준:

- Dense 양성 18/18개가 전후 1위 유지
- BM25F 양성 14/18개가 전후 1위이며 모든 양성 순위 유지
- Dense 탐침은 3개 순위 하락, 10개 동일, 1개 역방향
- 역방향 결과는 ‘a quiet morning at home’에서 출근 러시 후보가 8→5위로 올라간 경우다. 이를 숨기거나 검색문·필터를 바꾸지 않았다

최신 main 병합 후 10,174문서 기준으로 같은 벡터를 재사용해 다시 계산했다:

- Dense 32개 전체 순위가 병합 전 개선 체크포인트와 동일
- 양성의 dense 18/18, BM25F 14/18 1위 유지
- BM25F에서 직접 전면 셀피 대조문의 거울 셀피 후보만 2→3위로 바뀜
- 관련 surface_material 후보군은 295→333개로 확장

이 문구들은 후보를 보고 작성한 슬롯 안 진단이며 독립 holdout이 아니다. 일부 탐침은 유효한 대안이다. 데이터 일치성 개선과 일반 검색 품질·최종 채택·이미지 품질 향상을 구별한다. 이미지 생성이나 픽셀 평가는 수행하지 않았다.

## 검증

원래 개선 체크포인트에서는 관련 테스트 107개가 통과했다. 병합 후 새 의복 검사 7개를 포함한 관련 테스트 114개가 통과했다(74개 + 40개). 결과는 `validation.json`에 기록한다. 독립 읽기 전용 검토도 원문 보존, 실제 캐시/인덱스와 고정 검색 결과를 확인한다.

이전 aggregate validator의 22개 오류는 upstream에서 이미 올바르게 수정됐다. `concept_terms`만 허용하던 검사를 기존 runtime의 scoped candidate 계약으로 바꾼 내용이다. 같은 이전 레지스트리에 대해 22→0을 확인했고, 필수 property scope가 없는 잘못된 입력은 여전히 거부한다. 병합 후 aggregate validator도 통과한다. 유효한 discovery/속성 메타데이터를 삭제하거나 이번 작업에서 validator를 별도로 느슨하게 만든 것이 아니다.

실제 semantic 및 visual-profile 인덱스 검증, 원문/파일 보존과 관련 테스트 결과를 따로 기록한다. 전체 저장소 테스트나 렌더 이미지 품질을 검증했다고 주장하지 않는다. 새로 받은 upstream의 별도 implementation-report에는 costume/traditional-clothing 인접 검사에서 기존 optional-routing fixture 불일치 6개가 남고, 이미지 사례 3개의 전체 통과는 0/3이라고 기록되어 있다. 이 검사는 이번 114개 회귀 묶음과 별개이며, 병합 후 이미지를 다시 생성하지 않았다.

## 비용과 복구

이번 DATA 개선에서 Gemini 요청은 문서 16개 + 검색문 32개, 총 48회 모두 한 번씩 성공했다. 자동 재시도는 없었고, 최신 main 병합에는 추가 호출이 없었다.

추가 보수적 상한은 $0.0786432, 이 작업 계열에서 기록한 누적 보수적 상한은 $0.770048이다. 별도 upstream 작업의 API 사용량은 이 장부에 포함됐다고 검증하지 않았으며, 실제 계정 청구액과도 구별한다. 계산 근거는 공식 [텍스트 가격](https://ai.google.dev/gemini-api/docs/pricing) $0.20/백만 토큰과 [입력 한도](https://ai.google.dev/gemini-api/docs/embeddings) 8,192토큰이다.

비공개 로컬 Git bundle은 개선 체크포인트와 병합 이력을 모두 보존한다. 각 전달 조각은 10 MB 미만이며, manifest의 순서와 SHA-256을 확인해 합친다. 기준 upstream 커밋이 있는 저장소에서 `git bundle verify` 후 별도 브랜치로 가져오면 된다. 이전 9,887문서 평가를 재현하려면 보존된 개선 체크포인트를, 최종 병합 결과는 bundle의 작업 브랜치를 사용한다. API 키나 새 API 호출이 필요 없다.

원격 push·PR·원격 병합·배포는 수행하지 않았다. 기존 작업이 있는 브랜치를 덮어쓰지 말고 복구 안내를 따른다.
