# 실제 이미지 검증 계획

이미지 호출·임베딩 호출·저장 이미지·픽셀 판정은 모두 미실행이다. [pixel-cases.json](pixel-cases.json)은 16개 검증군의 설계이고 생성 비용·횟수의 실행 승인이 아니다.

## 단계와 비교 조건

초기 실행안은 P03의 파울러·역트렌델렌버그를 서로 다른 요청으로 나누고 P06 청진, P14 초음파를 더한 **독립 요청 4개 × 조건 3개 × 1회 = 12장**이다. 이 시범에서 관계의 관찰 가능성과 평가 기준을 먼저 확인한 뒤 범위를 확대한다.

세 조건은 기존 데이터만 사용, 신규 데이터가 노출되되 작성자의 선택은 선택적으로 유지, 관계를 명시한 별도의 작성 목표안이다. 세 번째 조건은 의료전문가 검토를 받았다는 뜻이 아니다. 동일 요청·요청자 고정 조건·모델 버전·참조 범위·출력 설정을 맞추고, 후보에 접근하기 전 작성한 기본 장면과 실행 증거를 보존한다. 한 조건의 결과를 보고 다른 조건의 입력을 수정하지 않는다. 환경에서 데이터 노출을 공정하게 분리할 수 없으면 그 비교는 미실행 또는 제한 있는 탐색으로 기록한다.

전체 확대안은 16개 검증군 × 조건 3개 × 2회로 최소 96장이다. 두 가지 의미를 비교하는 군은 각각 독립 요청으로 나누므로 실제 수량은 더 늘 수 있다. 필요성·비용·호출 범위를 정하지 않은 채 이 수량을 자동 실행하지 않는다.

## 판정 단위

1. 선택된 완전 소스의 모든 대상·수량·부품·지지·연결 끝점을 열거한다.
2. 실제 저장된 원본을 열고 각 항목을 `visible`, `partial`, `unobservable`로 기록한다. 손·관의 접점은 충분한 확대에서도 판독 가능해야 한다.
3. 각 다중 구성 gate는 전부 함께 보일 때만 통과한다. 일부 접점·한쪽 손·중간 관만 보이면 전체 gate는 통과하지 않는다. `UNOBSERVABLE_NOT_PASS`, `partial_is_fail`을 유지한다.
4. 화면·도식·모형의 내용과 실제 몸을 구분한다. 움직임의 전후·압박 속도·소리·혈류·진단·동의를 픽셀 gate로 통과시키지 않는다.
5. 키워드 설명 없이 읽은 전체 이미지의 상황 이해, 주의의 중심, 인물의 존재감과 미적 선호를 별도 평가한다. 기술적 충실도와 동일 점수로 합치지 않는다.

장르만 그럴듯하거나 장비가 하나 보인 것으로 완전한 연결을 통과시켜서는 안 된다. 새 후보가 제시되었으나 채택되지 않았다면 신규 데이터의 이미지 기여로 계산하지 않는다. 작가가 작성한 새 세부 표현도 source adoption과 구분한다.

## 비교 기록

실행 시 요청·core·선택 후보·composed prompt·runtime request의 바인딩, 원본 이미지 경로와 해시, 모델·참조 범위, provider 결과, 실제 관찰 gate를 보존한다. 승인된 실행 범위 안에서만 추가 생성하며 차단·전송 실패·파일 부재는 실제 상태로 기록한다. 차단은 픽셀 증거가 없으므로 `BLOCKED_UNSCORED`로 남긴다. 프롬프트 감사 PASS, 이미지 반환, 부분 관계 PASS와 사용자 수락은 서로 다른 결과다.

질의 120개는 [EVALUATION-CASES.tsv](EVALUATION-CASES.tsv)에 있으며 모두 `NOT_RUN`이다. 개발 세트와 별도로 다른 평가자가 작성한 holdout을 후속 단계에서 확보하는 것이 좋다. 현재 파일을 독립 holdout으로 이름만 바꾸지 않는다.
