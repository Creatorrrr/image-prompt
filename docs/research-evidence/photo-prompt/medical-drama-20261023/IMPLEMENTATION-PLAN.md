# 의학물 데이터 반영 계획

이 문서는 연구 결과를 운영 데이터에 옮길 때의 구체적 순서다. 이번 작업에서는 연구 폴더만 작성했으며 운영 소스·인덱스·설치·활성화·이미지 호출·commit/push는 수행하지 않았다. 아래 항목은 계획과 예상 변경 파일이며 완료 상태가 아니다.

## 1. 반영 단위와 선택 기준

|분류|연구 산출물|후속 처리|
|---|---|---|
|신규 작성|A–G 100개 한영 시각 초안|기존 코퍼스와 전체 의미를 다시 비교하고 중복을 제외한 소스만 신규 등록|
|정본 재사용|R01–R22 22개와 기존 CID|전체 문장·조건·효과·슬롯 연결을 보존; 같은 CID의 소유자를 새 모듈로 복제하지 않음|
|수정 검토|R15 레지스트리 요약 차이, 기존 수의학 청진기의 미번역 한국어, R18의 치유 상태 해석|각 정본의 의미와 역사 기록을 비교한 뒤 최소 수정; 과거 증거를 덮어쓰지 않음|
|문맥·혼동 기록|X01–X42|진단·역할·의도·동의·시간·소리·제도를 문맥으로 유지; 긍정 외형 후보로 노출하지 않음|
|추가 자료 필요|H01–H08|정확한 임상/기구/역사 도판 확보 전에는 관련 일반 후보로 충족 처리하지 않음|

100개는 신규로 작성한 초안 수이며 순증 소스 수가 아니다. G06은 R20과 가깝다. 기존 의자·백의·장갑·성인·의상 조건이 맞으면 R20을 우선 재사용하고, 진찰대 변형이 독립적으로 유용한 경우에만 신규안으로 남긴다. B04처럼 장갑과 가운의 조합을 담는 후보는 부품 단어만 떼어 등록하지 않는다.

R15는 중요한 정본 확인 사례다. 의료 의미 레지스트리의 D16은 짧은 봉합선 문장을 담지만, CID의 현재 실제 소유자는 `photo_candidate_biopunk_body_horror_20261021.json`이고 전체 문장이 다르다. 연구의 R15는 정본 전체를 복사했다. 레지스트리의 예전 문장·그래프·슬롯을 새로운 승인 근거로 쓰지 않는다.

## 2. P0: 의미·소유·완전성부터 등록

첫 묶음은 임상 손동작, 환자 체위, 호흡·주입 장비, 복장·보조 장구의 혼동 경계다. B01–B15, C01–C14, D01–D18, E01–E11을 우선 검토한다. 의학물이라는 장르 자체로 자동 활성화하는 프로필을 만들지 않는다.

각 소스마다 독립적으로 다음을 작성한다.

1. 한영 완전 긍정 문장과 동등한 의미. `adult`, `manikin`, `fictional`, `illustrative`, `staged`, 수량·좌우·겹침·끝점은 문장의 일부로 보존한다.
2. 실제 요청에서 선택할 인물·물체·신체 부위와 부품 소유. 일반적인 `hand`나 `tube`가 여러 인물·장치에 섞이지 않도록 한다.
3. 모든 인물 추가·자세·의상·소품·공간·구도에 미치는 효과. 제시 슬롯의 이름만으로 변경 범위를 줄이지 않는다.
4. 실제 전제와 관계 조건. 한 개의 모호한 역할명이나 장르 태그가 전제 충족의 증거가 되지 않게 한다.
5. 실제 운영 스키마의 whole-source 검토와 qualification. 연구 그래프·출처·자체 해시는 native fact나 guard를 자동 생성하는 권한이 아니다.
6. 후보를 채택했을 때의 완전한 가시 의무. 선택하지 않은 다른 대안의 의무는 활성화하지 않는다.

예상 파일은 `skills/photo-prompt-image-generator/assets/` 아래의 `photo_medical_drama_semantics_20261023.json`, `photo_candidate_medical_drama_20261023.json`, `photo_candidate_medical_drama_bindings_20261023.json`과 기존 `photo_candidate_corpus_manifest.json`이다. 이 이름은 후속 구현안이다. 현재 운영 파일이 생겼거나 등록되었다는 뜻이 아니다.

기존 소스는 정본의 조건과 모든 바인딩을 보존한다. 실제 요청과 맞는 바인딩만 추가할 수 있으나, 바인딩이 intrinsic guard나 effect를 대체해서는 안 된다. 새 역할 제시도 같은 조건 검토를 받는다. 닫힌 가운 소스가 명시적인 진료 노출 요청과 충돌하면 이를 채택하지 않는다. 봉합 모형 후보에서 모형 문맥을 지우고 실물 시술로 바꿔서는 안 된다.

X 카드를 등록한다면 운영 스키마에 맞는 문맥/진단 기록으로 두고, 기본 긍정 검색·자동 의무에서 제외한다. 346개 route는 번역 사전이나 활성화 스위치가 아니라 관련 의미·선택지를 찾는 안내다. `수술복`, `기관삽관`, `탈모`, `고통`, `의료 페티시` 같은 단어가 다른 외형·사건을 자동 생성하지 않아야 한다.

## 3. P1: 장면·돌봄·분위기의 선택지를 늘림

A01–A14, F08–F12, G04–G06을 병원 생활·팀 협업·회복·기록·성인 연출의 선택지로 검토한다. 장면의 존재 이유가 분명해야 하며, 의료 소품의 숫자를 늘리는 방식으로 풍부함을 평가하지 않는다.

[SCENE-BLUEPRINTS.md](SCENE-BLUEPRINTS.md)의 8개 조합은 요청을 해석할 때 떠올릴 수 있는 연구 제안이다. 실제 이미지 작성의 초기 authorial core에 연구 후보를 미리 주입하는 예제 프롬프트 모음이 아니다. 각 새 요청의 의미와 기본 장면은 기존 독립 작성 절차로 정하고, 이후 선택 단계에서 전체 후보 의미와 비교한다.

성인 창작·법의학·상해·산과·정신의학을 자료에서 삭제하지 않는다. 실제 진료, 명시적 성인 연출, 강요·착취·학대, 교육 모형, 역사적 사실은 각각의 문맥과 근거를 유지한다. 한 소스의 가림·완전 착의·성인·모형 조건은 다른 요청 전체의 일반 규칙으로 전파하지 않는다.

## 5. 데이터 등록 뒤의 검증 순서

현재 연구 폴더의 `evaluation-cases.json`은 경계 48개와 일반 문맥 12개, 각각 한영 질의 총 120개를 담는다. 전부 미실행이며 작성자가 만든 개발 세트다. 독립 holdout이나 검색 결과로 부르지 않는다.

1. **소스 무결성:** CID 단일 소유, 한영 의미, 전제·효과·모든 바인딩, 문맥 카드의 긍정 제외, 도식/모형/성인 조건을 확인한다. 346개 route의 역참조와 복합어의 부분 후보 경계를 확인한다.
2. **네이티브 소스 검토:** 현재 운영 스키마에 맞춰 실제 소유자와 각 소스의 전체 의미를 검토한다. 등록 성공과 qualification을 별도 기록한다.
3. **검색 인덱스:** 실제 manifest가 가리키는 정본의 정확한 합집합에서 재구축한다. ID·전체 문장 해시·recipe·provider/model/dimension·벡터 무결성이 일치할 때만 재사용한다. 구형 layout을 이름만 바꿔 import하지 않는다.
4. **실제 검색:** 슬롯 검색과 요청 전체·기본 장면 검색의 실제 노출을 각각 측정한다. literal hit 수로 semantic/hybrid recall을 대신하지 않는다. rank@k·혼동 후보·일반 문맥 오염을 표로 기록한다.
5. **작성·감사:** 독립 작성한 기본 장면 이후 후보 전체를 검토한다. 채택·미채택·조건 충돌·예술적 선호를 구분하고 실제 prompt evidence와 정확한 요청 운반을 확인한다.
6. **이미지와 사용자 판단:** 저장된 원본을 실제로 열어 선택한 의무의 모든 구성·끝점을 한 화면에서 판정한다. `UNOBSERVABLE_NOT_PASS`, `partial_is_fail`을 유지한다. 사용자 수락은 별도다.

검색의 목표치는 실행 전 고정한다. 초기 제안은 명확한 단일 용어의 적절한 후보 또는 명시적 보류를 top 10에서 90% 이상 찾고, 일반 문맥 12개에서 임상 의무의 잘못된 채택을 0으로 유지하는 것이다. 이는 검색 성능 실측치나 배포 기준 승인값이 아니다. 외형 후보를 가질 수 없는 문맥 질의는 진단 기록이나 보류를 정답으로 인정하고 억지 시각 후보를 정답으로 만들지 않는다. 후보 노출과 채택은 별개 지표다.

문서·데이터만 바뀌면 관련 dictionary/source/index 검사를 범위에 맞게 수행한다. 관련 런타임 코드를 수정할 일이 생기면 그때 변경 영향에 맞는 테스트를 추가한다. 새 의학 용어를 지원하려고 초기 작성 논리를 바꾸는 것은 이 계획의 전제가 아니다.

## 6. 이미지 실험의 단계적 계획

[PIXEL-PLAN.md](PIXEL-PLAN.md)에 16개 검증군과 비교 조건을 정의했다. 첫 단계는 체위 2종·청진·초음파의 독립 요청 4개를 조건당 1회 비교하는 12장 제안이다. 다음 단계에서 반복과 기구·복장·재활을 확대한다. 같은 카드에서 파생한 문장만으로 평가를 통과시키지 않고 연결점·소유·전체 장면을 판정한다.

데이터가 후보에 노출되었더라도 작성자가 채택하지 않았다면 그 이미지의 차이를 신규 데이터의 기여라고 계산하지 않는다. 결과가 차단되거나 저장·운반이 확인되지 않으면 해당 픽셀 결과는 `BLOCKED_UNSCORED` 등 실제 상태로 남긴다. 생성 호출은 현재 수행한 것이 아니며 횟수·모델·참조 범위는 후속 실행 시 명시한다.

## 7. 설치·게시와 복구

이번 읽기 전용 installed recorder 검사에서는 `dependencies_and_installed_recorder` PASS와 이미지 호출 0·소스 기록 0을 확인했다. 이는 새 연구 데이터의 설치·노출 검증이 아니다. 후속 구현 전에 실제 selected generation과 현재 정본을 다시 확인한다.

공유 checkout은 시작 때부터 다수 변경이 있었다. 후속 반영은 현재 첨부 worktree/checkout의 적합성을 확인한 뒤 진행하고, 다른 변경을 reset·revert하지 않는다. source/index 수정 직전에 해시를 다시 기준화한다. 명시적 파일 allowlist로만 staging하며 `git add -A`는 사용하지 않는다. 별도 게시가 진행되는 경우 소스 검증·index closure·선택된 설치 릴리스·테스트 결과·실제 원격 SHA를 각각 기록한다. 게시 후 정리가 필요하면 push 확인과 보존 검증 이후에 수행한다.

복구는 이전 authored manifest와 검증된 index closure, 기존 selected runtime을 복구하는 단위로 설계한다. 과거 연구 파일·생성 기록·픽셀 실패를 새 결과로 덮어쓰지 않는다. 연구 단계의 현재 파일들은 그대로 남기고, 후속 구현 증거는 별도 하위 폴더에 추가한다.
