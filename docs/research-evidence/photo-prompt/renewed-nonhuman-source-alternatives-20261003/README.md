# 비인간형 의미 데이터의 기존 허용 범위 정합성

## 반영 내용

기존 프로필 2개의 메타데이터만 수정했다. 후보 추가, 검색 로직 변경, 활성화 별칭 확장은 하지 않았다.

1. `biohybrid_robot_living_synthetic_integration`: 운영자가 화면에 없는 독립 로봇도 정의·구성요소·구도에서 이미 허용하지만, 분리 근거 문구는 모두 사람/운영자를 언급하고 있었다. 기존 완전한 독립 몸체를 표현하는 `complete independent robot body`를 근거 대안 하나로 추가했다. 기존 운영자 근거 3개, 살아 있는 조직·합성 구조·기능적 연결의 필수 조건과 5개 렌더 게이트는 보존했다.
2. `summoner_distinct_entity_arrival`: 필수 구성요소와 근거는 국소적인 먼지·빛·그림자·밀린 사물 반응을 허용하는데, 구도 지시만 접촉 그림자나 밀린 재료로 좁혀져 있었다. 구도 지시를 기존 허용 범위와 맞췄다. 시전자·완전한 경계·별도 출현체·방향 관계·국소 인과관계 및 단순 광채/동행자/빈 원 배제는 그대로다.

13개 프로필과 관련 후보 32개를 점검해 나머지 11개 프로필은 유지했다. 별도 검토에서도 두 수정이 새 의미 도입이 아니라 기존 계약의 내부 모순 해소임을 확인했다.

## 전후 검증

기준 커밋은 `18a46eb413a40ace4eb7b8913755ff739ac5c3cb`다. 앞선 원인 조사 기준 `3c3b3a64`와 해당 원본 레지스트리 바이트가 동일함을 확인했다. 별도 acting-expression 작업의 추가 데이터는 이번 성과에 포함하지 않는다.

- 실제 V6 CLI: 동일하게 동결한 합성 입력 12개가 전후 모두 유효
- 전체 프롬프트 감사: 21개 전후 기대 결과 모두 일치. 기존 운영자 없는 biohybrid 1개만 실패→통과, 11개는 통과 유지, 9개는 실패 유지
- 근거 필드 직접 비교: 80개 중 위 독립 몸체 근거 1개만 수용으로 변경, 나머지 79개 결과 동일
- 후보·검색·core/잠금·embodiment preflight·의미 명료화·부정 가드·활성 프로필·렌더 게이트·대체물 배제는 12개 모두 동일
- 표적 프로필이 없는 부정 대조군 5개의 전체 후보팩은 바이트까지 동일
- 관련 후보팩의 차이는 의도한 근거/구도 메타데이터와 이에 따른 `pack_id`에 한정
- 1,507개 프로필의 벡터·검색 문장·BM25F는 전부 동일. 파생 시각 색인은 `registry_sha256`만 갱신
- 제공자 호출 및 추가 비용 0

## 해석의 한계

이는 합성 입력을 이용한 소스 정합성 검증이다. 자연어 검색 성능이나 이미지 품질 향상으로 해석하지 않는다.

운영자 없는 biohybrid의 원래 근거와 프롬프트를 바꾸지 않은 채, 유일한 실패 원인이었던 분리 근거 조건이 해결됐다. 사람을 이미지에 실제로 생성하던 문제가 픽셀에서 수정됐다는 주장은 하지 않는다.

Summoner는 자연스러운 국소 빛 반응 문장만으로는 기존의 정해진 근거 앵커를 충족하지 못한다. 전후 모두 실패하며 그대로 보존했다. 정해진 전체 대안 문구도 구체적인 관찰 설명을 더해야 최소 단어 수를 충족한다. 이번 구도 지시 정합성 수정은 이 제약이나 검색 별칭을 완화하지 않는다. 정해진 근거를 포함한 빛·그림자·물체 변위 사례는 원래도 통과했고 수정 후에도 통과한다.

의도적으로 잘못 만든 구성 8개는 표적 근거 검사뿐 아니라 embodiment 검사에서도 실패한다. 이를 특정 필드 하나만으로 거부됐다고 주장하지 않으며, 80개 직접 필드 비교로 근거 가드를 별도로 확인했다.

초기 입력 작성 중 발견된 단어 수·위치 속성 이름·필수 잠금·근거 소유권/판타지 의도 표기 오류는 원본 및 수정 내역과 함께 보존했다. 원래 합성 요청·프롬프트·조사에서 가져온 근거는 유지했고, 유효한 BEFORE를 동결한 뒤에만 소스를 수정했다. AFTER를 통과시키기 위한 입력·기대값 수정은 없었다. `valid-before-map.json`이 각 유효 실행을 명시한다.

## 증거

`diagnostic-evidence.tar.gz`에 원인 조사, 별도 소스 검토, 정확한 두 변경 지점, 동결 입력과 초기 실패, 24개 CLI 실행, 42개 구성 감사, 직접 근거 비교, 파생 색인 검증, 회귀 검사 로그를 보존한다. 큰 원본 벡터 색인의 중복 사본은 제외하고 기존 Git 상태 및 항목 동일성 검증을 사용한다. 파일별 SHA-256은 아카이브의 `export-manifest.json`에 있다.

전체 테스트의 별도 고정본 검사는 진행 중이다. 이번 표적 검사 결과를 최신 main 전체 회귀 통과로 표현하지 않는다.

## 표적 회귀 검사

새 회귀 검사 4개와 기존 fantasy/humanlike/imaginal 검사 22개가 모두 통과했고, 사전 메타데이터 검증도 통과했다. 새 검사는 수정 전 의도한 실패 1개·오류 1개를 재현하고 기존 경계 검사 2개는 통과했다. 수정 후에는 4개 모두 통과한다.

기존 검사 첫 실행에는 존재하지 않는 모듈 이름을 지정한 작업 명령 오류가 있었다. 해당 실패 로그를 별도 보존하고, 실제 저장소의 정확한 3개 모듈 이름으로 다시 실행한 22개 성공 로그를 최종 근거로 삼았다. 이를 제품 회귀 실패나 성공한 전체 검사로 바꾸어 기록하지 않는다.

재현 시 BEFORE는 위 기준 커밋, AFTER는 이 변경을 포함한 커밋을 사용한다. 아카이브의 로컬 경로 표기는 `REPOSITORY_ROOT`와 `EVIDENCE_ROOT`로 치환되어 있으므로 각 checkout과 추출 위치에 맞춰 지정한다. 입력 해시·소스 해시·유효 실행 지도를 먼저 확인해야 하며, 이미 수정된 소스에서 과거 실패를 기대하도록 검사 결과를 바꾸면 안 된다.
