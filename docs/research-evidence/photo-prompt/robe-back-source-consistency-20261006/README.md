# 도교 의례복 원본의 뒷면 관계 정합 수정

선정된 박물관 자료는 도교 의례복의 뒷면인데, 기존 후보에는 학 자수를 옷 앞면에 놓는 조건이 섞여 있었다. 큰 탑 원형 구역, 해·금까마귀와 달·옥토끼의 분리된 위쪽 구역, 흰 학 자수가 모두 같은 뒷면에 속하도록 시각 프로필·일반 후보·묶음의 한국어와 영어 설명을 맞췄다.

원래 [조사 단위의 variant_scope](https://github.com/Creatorrrr/image-prompt/blob/b4120b84da1009416876ce0c521978e9e28e1fd6/docs/research-evidence/photo-prompt/religion-myth-iconography-20261003/UNIT-SEEDS.json#L2075)는 해당 의례복의 뒷면을 명시하지만, 같은 조사 단위의 구성 요소에는 ‘옷 전면의 흰 학 자수’라는 문구가 있었다. [통합 코드](https://github.com/Creatorrrr/image-prompt/blob/b4120b84da1009416876ce0c521978e9e28e1fd6/docs/research-evidence/photo-prompt/religion-myth-integration-20261003/author_integration.py#L159)는 이를 영어 robe front 조건으로 고정했다. 이를 별도 앞면 변형으로 의도했다는 기록은 검토 범위에서 찾지 못했다.

원본은 [Met 소장품 30.75.3](https://www.metmuseum.org/art/collection/search/68508)의 [뒷면 자료](https://collectionapi.metmuseum.org/api/collection/v1/iiif/68508/188467/main-image)다. 실제 [앞면](https://collectionapi.metmuseum.org/api/collection/v1/iiif/68508/188466/main-image)에도 학이 있으므로, 앞면의 학 자체가 틀렸다는 주장은 아니다. 이번 변경은 선택된 뒷면 자료의 관계를 일관되게 표현한다. 새 앞면 변형을 추가하지 않아 기존 앞면 표현의 가능성은 줄어든다.

## 변경 범위

최신 기준은 `6b0338ebe6ad3a9a5ee3c603fc742311ad921054`의 공식 horror V31이다. 로컬 DATA 검증 커밋 `3197ca8ecbff80d2dec110c6c506090c9ab16e62`는 로컬 출처이며 원격 조상을 뜻하지 않는다. 게시 도구의 커밋 메타데이터가 달라 최종 원격 SHA는 별도 기록한다. 재현은 공개 기준 6b와 고정한 트리·원본·파일 해시에 의존한다.

시각 프로필 25개, 일반 후보 11개, 연결 묶음 7개 문자열을 맞췄다. 유지보수 참조 2곳과 불변 후속 기록은 별도 출처 변경이다. 새로운 후보 ID나 모티프를 추가하지 않았고 관계 소유 대상·필수 성분 API·검색 및 순위 로직도 그대로다.

일반 의미 10,396개와 시각 프로필 2,193개 중 두 입력의 기존 실제 임베딩을 재사용했다. 나머지 12,587개 전체 레코드, upstream horror의 310개 신규 항목 및 기존 464개 shard 파일은 정확히 보존했다. 새 일반 008 및 시각 011 shard만 추가한다. 검증한 새 세대를 별도 로컬 runtime store에 게시한 뒤 동일 세대에서 CLI와 receipt를 확인했다. 이번 최신 재검증의 API 호출은 0회다.

우산 예문 수정은 적용하지 않았다. 이전 c558의 8입력·4조건 비교에서 그 수정만으로 두 유용할 수 있는 별도 선택지가 사라졌다. 우산 원본·벡터는 최신 6b와 동일하다. 이미 실행된 미적용 우산의 비용도 그대로 계산했다.

## 최신 실제 효과와 손실

같은 노출 회귀 입력 5개를 최신 전후 동일 코드·원문·잠금·seed로 실행했다. 전후 10회와 공식 V31 경계 전후 2회, 총 12회 CLI 및 receipt가 통과했다. 새로운 비공개 평가가 아니며, 이전 c72 결과를 최신 결과로 합산하지 않았다.

- 뒷면 A: 의례복 일반 후보와 묶음이 추가되고 기존 전경 가림 후보가 사라졌다. 제거된 전체 관계는 요청되지 않은 손 동작을 전제하므로 유용성 손실이 불확실하다. 일반적인 뒷면 장식 요청만으로 구체적 모티프 전체의 채택이 입증되는 것도 아니다
- 정면 B: 기존 일반 의례복 후보와 묶음이 사라지고, 보조 목록에 남은 같은 ID도 뒷면 의미가 된다. 앞면 표현의 실제 축소다. 새 렌즈 후보는 보호된 요청 속성과 겹쳐 명시적으로 부적합하므로 보상이 아니다
- B의 추가 변화: 소형 모형을 비교·조정하는 보조 동작이 사라지고 붉은 보석 항목이 들어온다. 원래 요청에 동작의 특정 선행 맥락이 없어 유용성 손실은 입증되지 않았지만 무해하다고 가정하지 않는다. 보석은 범위상 허용되어도 미적 적합성이 미평가 상태이고, 같은 의미의 대체재도 아니다
- B의 창작 예시: 매혹적 표정·허리 묶은 실내복 대신 보석·옷단 잡기가 표집된다. 제거된 두 항목은 보조 목록에 그대로 있고 옷단 잡기도 원래 접점 후보에 있어, 전체 선택지 소실과 구별한다
- 데님 C: 묶음의 사전 연결 해시만 달라지고 의미·순서는 같다. C의 절제된 감정 시각 후보는 이미 c72에서 최신 before로 바뀔 때 사라졌으므로 이번 수정의 유지 성과나 손실로 계산하지 않는다
- 박물관 뒷면 및 가상 정면 대조: 후보 객체까지 동일하다. 원래 정하지 않은 동물 정체성이나 정면 장식을 입력에 끼워 넣지 않았다

변경 경로는 A 3개, B 5개, C 1개다. 소스 정합 복구가 승격 근거이며, 손실 없는 검색 개선·순 효용·완성 프롬프트 채택·이미지 품질 개선을 입증한 것은 아니다. [독립 DATA 검토](INDEPENDENT-DATA-REVIEW.md)에 전체 의미와 선택 경로의 구분이 있다.

## 역사와 고정 경계

이전 c72용 의례복 V31은 로컬 검증과 커밋까지 끝났지만 main 게시 전 공식 horror V31이 추가되어 보존 상태로 남겼다. 해당 구현의 최초 57/58 및 좁은 수정 후 3개 재실행 기록은 c72에 한정되며 최신 검사로 바꾸어 표시하지 않는다. 최신본은 공식 V31을 보존하는 V32를 사용한다.

공식 V31 before는 원본 팩과 바이트 단위로 같다. after는 `core_retrieval.canonical_sha256`, `core_retrieval.slot_corpus_sha256`, `pack_id`, `provenance.tags_hash` 네 값만 바뀌며 후보 객체·순서는 같다. upstream의 V30→V31 41개 차이와는 별개다. 그 변화에는 새 슬롯·기존 선택지 밀림·긴장 관계 변경이 있으므로 이번 네 해시 차이를 전체 변경의 무손실 증거로 쓰지 않는다.

공식 V31 원래 호출부는 receipt를 읽는 버전 목록에 31을 넣지 않아 기존 검증 함수에 None을 전달한다. 원본은 그대로 보존하고, 새로운 V32는 receipt를 필수 검증하며 과거 V31의 실제 sidecar는 원본 CLI를 사용하는 별도 감사로 확인한다. 기존 테스트 이름만으로 과거 receipt 검증을 주장하지 않는다. 최초 영향 검사 46개 중 45개가 통과했고, 한 검사의 4개 과거 인덱스 되돌림 하위 사례가 실패했다. 독립 검토에서 후속 기준의 증거가 사라진 경우를 엄격히 거부하도록 고쳤다. 새 회귀 3개, 기본 /tmp 환경의 수정 후 3개, 최종 영향 재실행 20개가 통과해 고유 단위 검사 49개의 마지막 결과가 모두 통과다. 소스 검사 4개도 별도로 통과했다. 49개 전체를 최종 코드에서 다시 실행했다는 뜻은 아니며, 초기 실패·수정 전후 코드 해시·실행 범위는 [검증 기록](BOUNDARY-VALIDATION.json)에 보존한다. 현재 V32의 실제 CLI와 필수 receipt 감사도 별도로 통과했다.

## 재현과 비용

`QUALIFICATION-INPUTS.json`은 원본 20파일의 해시, CLI 인수·정확한 seed 및 전후 팩/receipt 해시를 포함한다. 입력 경로는 이 증거 폴더 기준으로 해석한다. 각 소스에서 먼저 `publish_photo_runtime_snapshot.py`로 별도 로컬 store를 검증·준비하고, 생성과 receipt 감사에서 같은 절대 `PHOTO_RUNTIME_STORE`를 사용한다. 검증 환경은 CPython 3.12.14이며 API 요청은 필요하지 않다. 대형 팩·전체 후보 목록을 중복 복사하는 대신 재현 입력·해시·요약을 보관한다.

세 원본 객체의 `SOURCE-SCOPE-BEFORE.json`은 c72 출처 표기를 유지한다. 세 객체 전체가 최신 6b에서도 같음을 확인해 네 소스 검사에 그대로 쓴다. 박물관 진단 두 입력의 초기 형식 오류와 별도 형식 어댑터, c558의 두 초기 seed 불일치 실행은 원래 이력으로 보존했다. 최신 입력의 의미는 고치지 않았다.

두 실제 벡터의 원래 976토큰 비용은 약 $0.0001952다. 미적용 우산을 포함한 원래 세 요청은 1,148토큰, 약 $0.0002296이며 실청구액이 아닌 추정이다. [임베딩 출처](EMBEDDING-PROVENANCE.json)는 원본 HTTP 응답 미보관과 로컬 입력/모델 결합의 한계도 명시한다. 이번 재색인과 최신 평가의 추가 호출은 없다.

4.25MB짜리 전체 항목 해시 목록은 1,767바이트 요약과 10,686바이트 `verify_index_entry_provenance.py`로 줄였다. 이 검사는 원래 12,589개 순서·입력·벡터와 전체 목록 해시를 오프라인에서 정확히 재구성한다. 검증 증거 해시 연결만 갱신한 뒤 관련 세 검사와 기본 V32 CLI를 다시 통과했다. [축약 검증 기록](COMPACTION-VALIDATION.json)과 [독립 재검토](INDEPENDENT-COMPACTION-REVIEW.md)는 이전 코드 해시·실패·통과 범위를 따로 보존한다.

원본 1,354개를 복원하는 목록은 기존 Git blob을 재사용한다. 새 보존 경로 6개는 체크아웃에서 약 9.64MB를 차지하지만 원본 blob의 새 전송은 필요 없다. 테스트용 재현 디렉터리는 서로 독립적인 복사본이다. 전체 테스트 실행이나 전체 이미지 품질 통과로 확대하지 않는다.
