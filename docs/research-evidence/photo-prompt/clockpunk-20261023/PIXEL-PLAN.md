# 검색·저술·이미지의 분리 비교 계획

상태: **NOT_RUN**. 첫 단계 제안은 아래 12군×3 arm=36장이다. 수량은 실행 제안이며 생성 실적이나 품질 보증이 아니다. 반복 생성 예산은 포함하지 않았고 이 연구에서는 이미지 API를 호출하지 않았다.

## 비교 arm

- A: 독립적으로 작성·고정한 baseline와 기존 데이터 세대. 기존 후보를 모두 decline해도 baseline은 완전해야 한다.
- B: 같은 요청 의미/controls를 유지하고 새 구조 후보를 검토한 최종 프롬프트. 모든 채택/거절과 owner·effect의 변화를 기록한다.
- C: 같은 의미/controls를 유지하되 새 생활/장면 대안을 검토한 최종 프롬프트. 중심 관계·공간을 실제로 다르게 설계할 수 있으나 requester-owned 조건은 바꾸지 않는다.

공통 baseline을 의도적으로 공유하는 paired 비교이며 3개의 독립 저자 연구라고 부르지 않는다. 별도 cold-start 검증은 후보·다른 arm을 보지 않은 요청 해석과 freeze가 필요하다. seed/모델/해상도/transport를 동일하게 유지할 수 있는지는 실제 generator 지원을 확인한 뒤 기록한다. seed를 맞춰도 후보의 인과 효과가 완전히 분리됐다고 주장하지 않는다.

## 12개 최초 평가군

| 군 | 핵심 과제 | 요청에 선택된 경우 반드시 보여야 하는 관계 | 혼동/완전 실패 기준 |
|---|---|---|---|
| 1 | 동력 태엽/실태엽 | 각각의 코일과 소유 축·통/밸런스 휠을 분리 | 둘을 하나의 스프링으로 합치거나 작은 부품이 식별되지 않음 |
| 2 | 추 구동 | 추→줄→드럼과 수직 하강 여유 | 추를 진자처럼 붙이거나 줄 종단이 숨음 |
| 3 | 탈진/캠 | 팔레트/치면 또는 팔로어/캠 프로필의 선택된 접촉 | 접촉 없이 부품이 떠 있거나 두 기구를 혼합 |
| 4 | 퓨지/래칫 | 원뿔 홈·체인 양끝 또는 걸쇠/비대칭 이 | 장식 원뿔·고리로 대체, 잠금 강도·힘 보정은 사진 채점 제외 |
| 5 | 랙/웜/베벨 | 요청한 형식의 맞물림과 축 관계 | 형식 교체, 자기잠김을 외형 PASS로 처리 |
| 6 | 유성/제네바 | 선택된 선/유성/링/캐리어 또는 핀/슬롯 | 명칭만 맞고 소유자·접촉이 틀림, 전 주기 기능은 채점 제외 |
| 7 | 세 천문기구 | 평면 레테/천구 고리/행성 팔 중 요청한 구조 | orrery와 혼천의·아스트롤라베를 서로 치환 |
| 8 | 필기와 감기 | 인형 손→펜→종이 또는 작업자 손→크랭크→소켓 | 펜촉이 종이 밖, 손이 다른 소유자, 감기 축이 끊김 |
| 9 | 수리와 가동 공간 | 선택된 교체품/게이지 접촉 또는 패널/레일/뒤 통로 | 장면이 혼잡해 종단이 안 보임, 수리 성공·시간 반복은 채점 제외 |
| 10 | 의수·해부·혼성 몸 | 신체/소켓/보철 또는 모형/분리 덮개/표현 층 | 실제 몸·표현물·외장을 무단 합치거나 추가 팔다리 |
| 11 | 지역별 전통 | 자격루 용기·수운의상대 탑·가라쿠리 중 선택한 한 실현 | 문화·연대·동력 무단 혼합. 구슬 작동 등 조사 미완 세부를 필수화 |
| 12 | 성인 유물·서사 경계 | 유물/덮개/도상 또는 종이/플랩/현실 손의 소유 층 | 실제 성행위·직업·동의를 유물 도상에서 추정하거나 표현 층 합병 |

## 픽셀 판정과 기록

각 case는 생성 전에 exact 요청/코어/controls/source generation/선택 CID·RID/프롬프트/transport hash를 고정한다. owner별 위치, 필요한 두 종단, 접촉/연결/포함, 최소 식별 조건을 문장으로 정한다. 일률적 crop·확대율·보편 픽셀 수를 발명하지 않고 실제 장면의 투영 크기·대비·심도·가림을 검토한다.

개별 gate는 `PASS / FAIL / UNOBSERVABLE / NOT_RUN`으로 기록한다. **전체 case PASS는 적용되는 모든 가시 gate가 PASS일 때만** 부여한다. 일부가 맞아도 부분은 완전 통과가 아니고, 가림·작은 크기·초점 이탈은 `UNOBSERVABLE_NOT_PASS`다. 보기 좋은 사진이라는 판단과 기계/관계 의미의 완전 판정은 별도 기록한다.

정지 사진에서 시간·소리·냄새·반복·자기잠김·정확도·동의·인격·소유권은 평가 대상에서 `not_observable_in_still`로 남긴다. 요청상 필수인 시간적 주장이 있으면 별도 시퀀스/영상/측정 설계를 만들며, 그 근거가 없으면 요청 전체를 통과시킬 수 없다. 연구의 context graph를 visible gate로 잘못 채점하지 않는다.

실패를 고치기 위해 새 프롬프트를 저술하면 parent hash·허용 scope·수정 이유를 남기는 별도 child로 관리한다. 다른 arm에만 도움이 되는 조건이나 requester 의미 변경을 숨기지 않는다. 이미지 생성 차단/전송 실패/저장 실패는 각각 상태를 보존하고 `blocked_unscored` 또는 미검증으로 분리한다.

## 전환 조건

1. 대표 구조가 실패하면 해당 신규 실현은 운영 채택을 보류하고 구조 단순화·소유 연결·시점 문제를 원인별로 수정한다.
2. 검색 노출이 늘었어도 실제 채택이 0이면 그 이유를 기록한다. 단순 노출을 개선 성과 전체로 보고하지 않는다.
3. 36장 결과는 최초 개발 표본이다. 보편적 품질·통계적 우월성·사용자 수용을 주장하지 않는다.
4. 실행 후 실제 saved image를 열어 판단하고, 텍스트 audit만 통과한 결과를 픽셀 PASS로 기록하지 않는다.
