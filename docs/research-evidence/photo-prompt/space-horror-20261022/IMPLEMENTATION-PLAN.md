# 데이터 반영 계획

이 문서는 연구 완료 시점의 실행 제안이다. 작업 폴더에는 다른 변경이 있으며 운영 선택자는 별도의 봉인 설치본을 가리킨다. 연구 문서 생성이나 현재 소스 수정만으로 기본 실행이 바뀌지 않는다. 단계별 종료 조건을 충족한 기록만 다음 단계의 근거로 사용한다.

## 0. 실행 전 기준을 다시 고정한다

- 현재 HEAD·dirty 목록·manifest와 각 원문 모듈·연결·슬롯·인덱스·`retrieval-runtime.json`의 해시를 새로 저장한다. 이번 [BASELINE.json](BASELINE.json)은 연구 시점의 기준이다.
- 재사용할 기존 후보와 조건, 실제 선택된 realization, 소유자, 효과, 연결의 전체 원문을 검토한다. 스냅샷 40개와 [CORPUS-FINDINGS.md](CORPUS-FINDINGS.md)는 검토 시작점이다.
- 최신 `references/maintenance.md`, `references/installed-h-f2.md`와 실제 설치본 계약을 확인한다. 메모리의 v6 절차를 현재 절차로 간주하지 않는다. 이번 확인에서는 새 실행이 H-F2 material v2와 core-derived validation context를 사용한다.
- 별도 적용용 사본/적절한 worktree에서 명시적인 파일 목록으로 구현한다. 무관한 dirty·untracked 자료와 기존 런 기록은 보존한다.

종료 조건: 입력 SHA와 의도된 변경 목록, 현재 설치 generation이 재현 가능하다. 기존 자료가 바뀌었다면 의미 검토를 갱신한다.

## 1. 200개 키워드의 해석 경로를 고정한다

[`keyword-routes.json`](keyword-routes.json)의 원문 번호를 유지하고 묶인 명칭을 자동 동의어로 분해하지 않는다. 각 항목을 `still / proxy / sequence / context / nonvisual`로 처리한다. 현재 분포는 48/29/22/79/22다. 이 분류는 검색 레코드 종류나 장르 진위를 보장하는 런타임 규칙이 아니다.

|결정|채택 기준|예시|
|---|---|---|
|reuse|기존 전체 의미·조건·효과가 같은 경우|미세중력 선실, 정상 EVA, 일반 부착 접점, 블랙홀 선택형 원반|
|refine|실제 누락 관계나 번역의 차이를 명시적으로 보완할 경우|선체와 생체 조직의 지지 관계, 두 경계 사이의 격리 이동|
|new|기존 원문으로 구별되는 관계를 담을 수 없는 경우|두 해치 전이실, CO2 제거 유로, 자유롭게 끝난 안전줄|
|context|한 장의 시각 사실이 아닌 정의·판단 축|공유 의식, 강압·혈연, 시간 루프, AI 목표, 대우주 가설|
|defer|정확한 판본·원전·과학·도상 검토 또는 가시 증거가 부족한 경우|V45 도상, V41·V47·V61의 주제 완료 주장, Blindsight 세부 메커니즘|

카드별 잠정 처리와 실제 CID 이웃은 [adoption-matrix.json](adoption-matrix.json)에 있다. V56·V57도 물리/투영 구분을 보완할 때까지 등록은 보류한다. 이 행렬의 `new`는 작성 검토 제안이지 의미 부재 판정이나 최종 등록 승인이 아니다.

`new`는 어휘 0건만으로 승인하지 않는다. 영어/한국어·표기 변형·실제 성분·관계와 조건을 함께 검토한다. 범용 격리실을 만들려고 특정 세계관 후보의 primary guard를 삭제하지 않는다.

## 2. 의미 데이터와 후보를 함께 저술한다

예정 파일은 다음과 같다. 실제 스키마는 적용 시점 기존 소비자에 맞추며 파일을 만들기 전 정확한 계약을 확인한다.

|예정 대상|내용|필수 검토|

|`skills/photo-prompt-image-generator/references/space-horror-semantics.md`|사용 범위·과학/허구 구분·제한·증거 상태|연구·등록·노출·선택·픽셀을 같은 pass로 쓰지 않는지|
|별도 후보 인덱스/봉인 설치 generation|변경된 원문에 맞는 검색 자료|현재 운영 선택자를 바꾸기 전 독립 검증|

64개 카드가 64개 신규 후보라는 뜻은 아니다. 61개 초안 중 V45는 도상, V56·V57은 물리/투영 검토가 선행한다. V41·V47·V61은 긍정 재료로 옮기지 않고 문맥으로 보존한다. 기존 관계를 재사용하면 초안 ID와 실제 CID/RID의 매핑을 남긴다. 임의 ID·가짜 native 승인·연구 그래프를 native fact로 변환하지 않는다.

출처는 정의/작품 문맥의 근거다. 카드의 선택형 기하를 원전의 공식 형상처럼 기재하지 않는다. 여러 시각 대안은 동시 의무가 아니며 생체선·외계생물에 성적 상징을 기본 추가하지 않는다. 기존 source의 성적 의미가 실제로 있는 경우에는 그 의미를 숨겨 범용 후보로 전용하지 않고 전체 적합성을 검토하거나 별도의 독립 원문을 작성한다.

## 3. 소유자·관계·효과를 정확하게 바인딩한다

양성 후보마다 다음을 기록한다.

1. 주체·부분·도구·경계·목적지·결과가 누구에게 속하는지와 무엇이 연결/분리되는지.
2. 실제 채택 시 바뀌는 dimension, object target, property와 source/binding의 조건. broad/unknown effect로 부분 잠금 호환성을 승인하지 않는다.
3. EN/KO 각각의 전체 긍정 의미와 실제 realization. 한 언어에서만 인원·부착·단절·원인 조건을 빠뜨리지 않는다.
4. 식별 성분과 모든 중요한 끝점이 함께 보이는 gate. 화면 밖/가림/작은 투영으로 판독 불가하면 `unobservable`, 일부만 있으면 `partial`이다.
5. 의식·인과·강압·혈연·질병·시간 경과·과학 측정처럼 사진만으로 검증 불가한 나머지 의미. 보이는 단서와 별도 유지한다.

source-native 채택을 만들 경우 실제 선택 RID의 긍정 필드별 근거, guard·참조 closure·소유/허용 효과를 현재 검증기로 심사한다. 이번의 관계 그래프와 출처 링크는 해당 권한을 부여하지 않는다. H-F2의 `inspiration_only` 결과도 전체 고유 의미와 조건을 무시한 전용 허가가 아니다.

## 4. 변경 범위에 맞는 검증과 별도 검색 평가

현재 유지보수 명령과 스키마를 다시 확인한 뒤 사전·source/binding·인덱스 검증을 실행한다. 근거가 확인된 의미 변화에 맞춰 인덱스와 벡터를 갱신한다. 실패 시 현재 데이터로 되돌아가는 묵시적 fallback이나 검색 시 자동 rebuild를 추가하지 않는다. 설치본 검사는 `photo_installed_h_f2.py --check-runtime`으로 수행할 수 있다.

평가 입력은 [evaluation-cases.json](evaluation-cases.json), [TSV](EVALUATION-CASES.tsv)에 **148사례/296개 한영 질의**로 준비했다.

|분할|사례|목적|
|---|---:|---|
|development_exact_realization|64|카드의 구체 장면을 입력했을 때 전체 관계를 유지할 수 있는지 확인하는 개발 회귀|
|natural|32|짧은 자연스러운 성분·장면 요청에서 적합한 재료를 찾는지|
|boundary|24|가까운 어휘·반대 연결·과장된 의미·guard 전용을 거부하는지|
|context|12|비가시 개념을 고정 모양 또는 입증된 사실로 승격하지 않는지|
|control|16|일상·과학·제품·인접 장르 요청에 호러를 강제하지 않는지|

모든 사례는 작성자가 자료를 본 상태에서 만들었으므로 **독립 holdout이 아니다**. 실제 구현 전에 별도 자연 요청 24개를 정답·허용 관계와 함께 봉인하고 수정에 사용하지 않는다. 기존 사건의 의도를 새 후보에 맞춰 다시 쓰지 않는다.

구 인덱스와 신 인덱스에서 같은 입력·같은 슬롯 범위·같은 creativity를 사용하고 슬롯별 및 `__request_topic__`, `__baseline_prompt__` 결과를 별도 기록한다. 실제 H-F2의 BM25F와 로컬 cosine 두 경로 및 결합 순위를 보존한다. 키워드 검사·후보 ID 포함 여부·임베딩 가까움만으로 의미 적합성을 판정하지 않는다.

권고 종료 기준은 아래와 같다. 숫자는 이번 실측 결과가 아닌 사전 제안이다.

- 자연 질의 32개와 신규 holdout에서 언어별·주제별 relation-relevant recall@8 및 첫 유효 순위의 분자/분모를 보고한다. 신규 소스가 기존에 이미 있던 정답을 밀어내는지도 확인한다. 초기 목표는 natural의 양 언어 각각 28/32 이상이며 기존 대비 하락을 숨기지 않는다.
- control·boundary·context에서 후보가 검색에 보이는 것과 실제 채택/하드 의미 승격을 분리한다. 연관 후보 노출 자체를 오염으로 계산하지 않는다. 잘못된 자동 하드 의미 승격, guard 우회, requester lock 변경은 0건이어야 한다.
- trace에 source 원문 해시, 실제 CID/RID, query scope, rank/표본 선택, 검토 결정, literal prompt evidence를 남긴다. 후보가 노출됐지만 전부 거절한 경우도 정상 결과로 기록한다.
- 작은 표본의 비율만으로 전 장르의 일반화를 주장하지 않는다. 실패한 하위군을 공개하고 해당 소스만 보완해 관련 회귀를 반복한다.

## 5. 이미지와 장면 품질을 평가한다

[PIXEL-PLAN.md](PIXEL-PLAN.md)의 12장면 × 3 arms × 2회 = 72회 생성 제안을 따른다. 실제 생성은 별도 실행 단계다. 연구/검색 무결성 검증을 위해 자동으로 이미지 API를 부르지 않는다.

각 장면의 동일한 요청·독립 작성 core·baseline·창작 제어·하드 의미를 먼저 고정한다. A는 독립 baseline, B는 기존 설치 데이터, C는 새 자료를 사용하는 비교다. core를 후보를 본 뒤 바꾸지 않는다. 재구성이 필요하면 열린 선택만 수정하고 `authorial_decisions`에 남긴다. 잠긴 뜻을 바꿔야 하면 현재 rebuild/retry 계약을 따른다.

관계 gate·과학/허구 적합성·주제 충실도·장면의 인과 가독성·미적 선호를 분리한다. 보류/차단/미생성/미관찰은 이미지 성공도 실패한 픽셀도 아니다. 출력 차단은 `blocked_unscored`로 남기며 변경 없는 반복을 하지 않는다. 공급자가 결정적 이미지 seed를 지원하지 않으면 seed 대조라고 주장하지 않고 독립 반복으로 기록한다.

## 6. 봉인 설치·활성화·롤백

연구 검증 → 원문/연결 검증 → 별도 검색 평가 → 실제 prompt 전달/픽셀 비교 → 명시적 allowlist의 봉인 설치 → 비활성 설치본 확인 → 선택자 전환 → 기본 경로 smoke 확인 순서다. 적용 방식은 그때의 유지보수 도구를 따른다. 기본 실행에서 실제 사용된 generation·source hash·선택/거절을 확인해야 반영 완료다.

실패하면 직전 설치 선택자와 정상 generation으로 복원하고 새 generation은 진단을 위해 보존한다. 다른 작업·CURRENT·기존 실행 기록을 정리 대상으로 삼지 않는다. 커밋·push·PR은 별도 요청 범위와 명시적 파일 allowlist를 따르며 이번 연구에서는 수행하지 않았다.

각 차수의 후보 수는 `reuse/refine/new` 심사 후 확정한다. 장수·단어 수·후보 수를 채우는 것보다 현재 프레임에서 구별되는 관계와 과장되지 않은 주장 범위를 종료 기준으로 삼는다.
