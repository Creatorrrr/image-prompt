## 비교 설계

12개의 서로 다른 요청을 고정한다. 여러 카드가 나열된 행은 실제 입력에서 동시에 모두 요구하지 않으며 그 행의 하나의 구체 요청을 선택한다. 연결과 이탈처럼 반대 상태는 하나만 지정하고 반대 상태는 별도 경계 검사로 둔다.

각 요청에 3 arms × 독립 반복 2회 = 6결과, 합계 72회를 비교한다.

- A: 후보 조회 이전 독립 작성 baseline 그대로.
- B: 기존에 봉인된 설치 데이터에서 반환된 전체 재료를 검토한 뒤 선택한 구성.
- C: 새 데이터의 별도 봉인 설치본에서 반환된 전체 재료를 검토한 뒤 선택한 구성.

세 arm은 같은 실제 requester text·active spans·참고 이미지 범위·창작 제어·core/lock·baseline에서 출발한다. B/C는 검색 결과를 따라 자기 정답을 다시 만들지 않는다. 같은 수의 후보를 억지로 채택하지 않으며 무채택도 기록한다. B/C의 비교 검토 시간·표현 분량·전체 장면 개발 기회를 비슷하게 맞춘다. 실행 순서를 섞고 이미지 리뷰에서 arm 이름·출처를 가린다.

공급자의 결정적 image seed가 지원되면 그 조건을 기록하되, 지원되지 않으면 같은 seed 실험이라고 표현하지 않는다. 두 번의 독립 출력은 변동성 확인을 돕지만 통계적 일반화를 보장하지 않는다. core와 requester 요구의 충실도, 데이터 노출, 후보 채택, 마지막 prompt의 의미, 실제 pixel을 연결해 실패 위치를 찾는다.

## 판정

1. 생성 여부·실제 이미지 경로·모델·request ID·원문 hash·선택 자료·전달 prompt를 저장한다.
2. 각 관계와 중요한 수량/상태를 `visible / partial / unobservable / contradicted`로 판정한다. 부분·미관찰은 해당 필수 의미의 pass가 아니다. 핵심 부분의 projected size·가림·대비를 실제 이미지에서 판단한다.
3. 모든 중요한 **가시** 관계가 통과한 경우만 visible-contract pass로 집계한다. 비가시적 주제는 `contextual_not_pixel_verifiable`로 별도 남겨 전체 의미 입증으로 올리지 않는다.
4. 과학/허구 구분, 사용자 지정 의미 유지, 상황·행동·반응 연결의 가독성, 주된 인상·시각적 위계·미적 선호를 따로 기록한다. 고어·기술 소품·장르 신호가 많다는 이유로 점수를 올리지 않는다.
5. 후보가 검색되었는지, 검토되었는지, 실제 prompt에 쓰였는지, 픽셀에 구현되었는지를 각각 보고한다. 사용자 수용은 별도 `pending`이다.

제안된 적용 gate는 requester 의미/guard 위반 0건과 C에서 새 관계의 판독 개선, 대조 장면의 유의한 퇴행 없음이다. 72개 소표본의 결과는 사례별·arm별 분모와 함께 제시한다. 유리한 일부 이미지로 전체 강화 성공을 선언하지 않는다. 차단·미생성은 `blocked_unscored`로 별도 분모를 공개한다.

픽셀만 실패했을 때 원문을 늘리는 방식으로 자동 재시도하지 않는다. geometry·source 채택·잠금 충돌·투영 크기·생성 변동 중 어디에서 어긋났는지 구분한 뒤 해당 단계만 수정한다.
