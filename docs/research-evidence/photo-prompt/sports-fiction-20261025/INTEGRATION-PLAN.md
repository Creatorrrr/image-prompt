# 스포츠물 리서치 반영 계획

작성일: 2026-10-25, Asia/Seoul. 이 문서는 후속 반영 작업의 범위·순서·완료 기준이다. 이번에는 리서치 문서와 초안만 작성했다. 운영 등록·인덱스 재구축·이미지 생성·커밋·푸시는 수행하지 않았다.

## 1. 목표와 반영 단위

요청 전체에서 스포츠 문맥을 해석한 뒤, 필요한 형태를 구체적인 선택형 후보로 찾을 수 있게 한다. 종목·기술 이름은 탐색 단서이고, 실제 후보는 **선수·신체 부위·장비·상대·지지면·선택 단계 사이의 완전한 관계**를 표현한다.

성공 기준은 후보 수의 증가가 아니라 다음 항목이다.

1. 같은 단어의 다른 종목 의미가 섞이지 않는다.
2. 한 프레임에서 양립할 수 없는 동작 단계가 합쳐지지 않는다.
3. 공·셔틀·퍽·배턴·시위·검·스케이트·휠체어의 소유와 접점이 유지된다.
4. 기존 일반 의복·머리·질감·촬영·공간 후보를 정확하게 재사용한다.
5. 서사·의도·동의·진단·시간·경기 판정이 보이는 형태만으로 확정되지 않는다.
6. 검색 노출, 프롬프트 반영, 실제 픽셀, 사용자 판단을 각각 검증한다.

초안은 [semantic-cards.json](semantic-cards.json)의 102개 카드와 [candidate-drafts.json](candidate-drafts.json)의 102개 후보, [binding-drafts.json](binding-drafts.json)의 204개 바인딩이다. 모두 검토 전 상태이며 실제 등록 수는 검토 결과에 따라 줄거나 분할될 수 있다.

여기에 모든 연구 메타데이터를 positive 검색 문장으로 투영하라는 뜻은 없다. 정의·반례·민감 개념·검증 상태는 해석과 심사용 데이터다. 현재 지원되는 진단용 record kind와 projection 계약을 확인하고 사용한다. 시각 후보에는 선택된 상태의 보이는 내용만 들어가며, ‘정답’, ‘PASS’, ‘문제없음’ 같은 연구 판정 토큰이 검색 근거로 섞이지 않게 한다.

장르·종목 이름만으로 자동 착용 의상, 카메라 구도, 연령, 파라 등급, 노출, 부상, 오라, 승패를 강제하는 새 로직은 이 계획에 필요하지 않다. 데이터 반영으로 해결되지 않는 문제가 실제 회귀에서 확인될 때만 별도 로직 변경의 근거와 범위를 제안한다.

## 7. 검증 순서와 합격 기준

### 7.1 데이터 구조 및 보존

원문 330행·기술 70항목의 ID가 모두 남아 있고, source/card/binding 참조가 존재하며 중복 ID가 없어야 한다. 한·영 문장은 동일 선수·부위·장비·접점·단계·수량을 보존해야 한다. 간결한 태그로 바꾸는 과정에서 의미를 잃으면 승격하지 않는다.

기존 재사용 후보의 proposition·conditions·effects·provenance는 정당한 변경 의도 없이는 바꾸지 않는다. 연구 메타데이터의 추가가 역사적 후보 의미를 소급 변경하지 않도록 이전 레코드의 해시와 전체 계약을 대조한다. 바인딩과 source module이 함께 존재해야 한다.

### 7.2 문맥·노출 회귀

[regression-cases.json](regression-cases.json)의 64개 사례를 현행 검색·팩 생성 경로에 연결한다. 실행 전의 기대 명세와 실행 결과를 별도 파일로 저장한다. 특히 `Upset→Set`, `Spokon→KO`, `Giant→Gi`, `Promotion→Promo` 같은 부분 문자열 연결은 오답이다. 사용자 정의와 부정이 일반 사전이나 후보보다 우선해야 한다.

성공적인 노출은 올바른 후보가 적합한 문맥에서 검토 가능한 상태로 나온다는 뜻이다. 노출되었다는 사실이 선택·프롬프트 반영·이미지 성공은 아니다. 리시브/디그, bib 세 의미, singlet 두 형태, 런지, butterfly, tuck, 라메, 팀 에이스/서비스 에이스를 서로 반례로 검사한다.

### 7.3 운영 인덱스 검증

현재 저장소의 `scripts/build_shared_candidate_index.py`, `scripts/validate_photo_prompt_dictionary.py`와 관련 H-F2 테스트의 실제 인자·설치 환경을 확인한다. 소스 검사·일반 테스트는 저장소 환경에서, sealed runtime 또는 임베딩이 필요한 인덱스 작업은 프로젝트가 지정한 실행 환경에서 수행한다. 라이브러리가 없는 소스 경로의 import 실패를 검색 품질 실패나 성공으로 바꿔 보고하지 않는다.

최종 병합한 authored source에서 파생 인덱스를 재구축하고, source/dictionary/layout/hash 일치를 확인한다. 과거 리서치 산출물을 새로운 인덱스와 맞추기 위해 소급 덮어쓰지 않는다.

### 7.4 프롬프트와 픽셀

[pixel-evaluation-plan.json](pixel-evaluation-plan.json)에 12개 독립 장면의 위험과 필요한 관찰 요소를 지정했다. 수영 단계, 배턴·양궁 접점, 리베로 대비, 펜싱 겹침, 휠체어·패드 등은 별도 증거가 필요하다. 12는 초기 평가 설계이며 모든 종목의 충분성을 보장하는 기준 수가 아니다.

후속 이미지 작업에서는 각 요청의 원문·독립 authorial core·선택 특징·신체 동작 검토를 먼저 고정하고 그 뒤 후보를 검색한다. 후보 출처와 선택 ID, 최종 프롬프트·negative·transport·반환 이미지를 보존한다. 연구용 카드가 최초 사용자 의미를 사후에 바꾸지 않게 한다.

픽셀 합격은 선택된 모든 필수 관계가 같은 원본 이미지 또는 명시된 패널에서 관찰되는 경우다. 일부만 보이면 `partial_is_fail`, 가려지면 `UNOBSERVABLE_NOT_PASS`다. 검열·전송 오류 등으로 이미지가 없으면 품질 성공·실패 점수를 만들지 않고 `BLOCKED_UNSCORED`로 남긴다. moderation block을 우회하도록 프롬프트를 바꾸지 않는다.

### 7.5 사용자 판단

로컬 데이터 검사, 검색·팩, 프롬프트 감사, 원본 픽셀 평가, 사용자의 만족 여부를 별도 상태로 둔다. 이번에는 이 중 리서치 산출물의 구조·참조 검사를 수행한다. 픽셀·운영·사용자 수용은 미실행 상태다.

## 8. 작업 환경과 전달

후속 통합 시 현재 checkout의 dirty 상태와 동시 작업을 새로 확인한다. 적절한 기존 worktree가 있으면 재사용하고, 격리가 필요하면 관리되는 worktree를 사용한다. 연구 폴더·승격할 authored modules·의도된 인덱스만 명시적 허용 목록으로 커밋한다. 전체 dirty 상태를 한 번에 stage하지 않는다.

원격이 진행되면 강제 push 대신 authored source를 보존해 병합하고 파생물을 재구축·재검증한다. 발행이 요청된 작업에서는 로컬·추적·실제 원격 SHA를 구분해 확인하고, 정리는 관련 작업물과 증거가 보존된 뒤 범위 한정으로 진행한다.

이번 요청의 완료물은 **근거와 한계를 포함한 리서치·후보 초안·반영 계획**이다. 위의 운영 등록·생성·발행은 후속 실행 단계로 명시되어 있으며 이번 조사 결과로 수행했다고 보고하지 않는다.
