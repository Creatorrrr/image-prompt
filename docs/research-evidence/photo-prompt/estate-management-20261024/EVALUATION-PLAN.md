# 영지물 의미·후보·생성 결과 평가 계획

현재 상태: **192개 사례를 정의했으며 검색·runtime·이미지 실행은 NOT_RUN이다.** 이번 `validate_research.py`는 연구 파일의 연결·graph·범위 표식을 검사할 뿐 이 사례들을 실행하지 않는다.

## 1. 평가 층과 증거

| 층 | 검사 질문 | 필요한 증거 |
|---|---|---|
| 연구 연결 | 원 행·카드·출처·owner·관계가 끊기지 않는가 | 로컬 JSON/graph 무결성 |
| 역사·번역 | 해당 출처가 정확한 용어·시기·구조를 지지하는가 | 출처 구절/유물 도판·수동 한영 의미 대조 |
| 정본·역할 | 조건·effects·선택 owner·role가 전체 의미를 보존하는가 | 현재 native source 검증과 source-unit proof |
| 검색 | 실제 자연어에서 적합 후보가 보이는가 | 실행한 query/receipt·actual result·의미 적합 판단 |
| 프롬프트 | 채택된 전체 관계가 허용 범위 안에서 전달되는가 | frozen core·선택 source·literal phrase·audit |
| 픽셀 | 같은 owner의 모든 필수 연결이 보이는가 | 저장 원본·원본 해상도 관찰·arm별 gate 판정 |
| 수용 | 사용자가 원하는 장면과 품질인가 | 사용자 판단; 연구자가 대신 승인하지 않음 |

## 2. 계획 사례의 구성

각 시각 카드에 3종 사례를 만들었다.

1. **정상 관계 60개:** 한영 완전 문장으로 질의한다. 조회된 후보가 같은 물건·같은 역할·같은 상태를 보존하는지 읽는다.
2. **혼동 경계 60개:** 가까운 다른 공정·옷층·권리·의례를 같은 뜻으로 취급하지 않는지 본다.
3. **가림/오소유 60개:** 연결 한쪽을 가리거나 다른 사람의 손·다른 기계의 축에 연결해 실패 여부를 판정한다. 가림과 잘못 그려진 관계는 구분한다.

추가 일반 대조 12개는 현대 계약서, 박물관의 사람 없는 의복 전시, 연인의 손잡기, 현대 제분 모형, 천 코이프, 드레스 보디스, 판타지 노동, 검지장/쌀 포대, 성인 착의, 사람 없는 영지, 격자문, 세 구획 밭이다.

이들은 기대 결과가 적힌 평가 설계다. 문장을 파일에서 찾았다는 이유로 실행 PASS를 만들지 않는다. 수량 192는 독립적인 역사 정의나 native 자격 192건을 뜻하지 않는다.

## 4. 우선 생성할 독립 장면 3개

이 단계는 향후 이미지 생성 요청 시 수행한다. 각 arm은 자체 요청과 독립 기본 프롬프트로 시작하고, 다른 arm의 프롬프트나 실패 결과를 초기 의미의 근거로 쓰지 않는다.

### Arm 1 — 현물 인도와 장부 대조

상황: 창고 입구에서 곡물 인도와 기록을 확인하는 업무 장면. B01의 인도와 B06의 대조를 한 장면에 모두 넣을 경우 인원·손·책·계량 용기의 실제 수량과 시야를 먼저 검토한다. 한 프레임에서 너무 작아지면 필수 관계를 보존하는 한 장면을 골라 다른 관계는 별도 arm으로 분리한다.

필수 gate 예시:

- 주는 사람의 손→같은 자루 입구→같은 곡물→계량 용기.
- 받는 기록자와 실제 필기면; 인도자의 손과 뒤섞이지 않음.
- 두 장부를 채택했다면 각 책·대응 행·가리키는 손·다른 담당자의 시선.

별도 문맥: 납부가 세금인지 지대인지, 체납/횡령이 있는지, 개혁이 성공했는지. 이 항목은 픽셀 점수에 넣지 않는다.

### Arm 2 — 수차의 공급·축·배수

상황: C01의 한 가지 급수 형식을 가진 수차. 구체적으로 상사식이면 높은 홈통이 같은 수차 위쪽 물받이에 닿고 중심축과 하류 배수로가 보인다. 제분 공정까지 요구한다면 내부 가공부 연결이 보일 수 있는 구조와 시야를 먼저 해결한다.

필수 gate 예시:

- 유입 홈통→위쪽 물받이·수차의 같은 위치.
- 같은 수차 중심→벽 안으로 이어지는 축.
- 수차 하부→분리된 배수 경로.

회전 방향·동력 효율·실제 제분 완료는 정지 화상에서 검증하지 않는다. 수차 주변 분위기만 비슷하면 FAIL이며, 축이 벽 뒤에 숨으면 보이는 구간만의 부분 관찰로 기록한다.

### Arm 3 — 봉신예와 근접 의례 구별

상황: E01의 모은 두 손과 받는 두 손이 함께 읽히는 인물 장면. 무릎 꿇음·왕관·문장은 선택적 배치이며 핵심 증거를 대신하지 않는다.

필수 gate 예시:

- 안쪽 손 두 개가 같은 인물에게 이어짐.
- 바깥에서 감싸는 손 두 개가 다른 인물에게 이어짐.
- 네 손의 접촉·포개짐·손목 연결이 함께 보임.

책에 손을 얹거나 검을 어깨에 댄 모습으로 바뀌면 다른 의례이므로 FAIL. 잘린 손목·겹친 소매 때문에 주인을 알 수 없으면 UNOBSERVABLE_NOT_PASS. 법적 봉신 성립·진심의 충성은 점수화하지 않는다.

## 5. 후속 픽셀 확장

- **착의 F08:** 실제 두 사람, 착용자의 옷, 시종 손, 같은 끈, 고리 관통. 소유자 교환·끈이 피부에 붙는 오류를 확인.
- **지지 의복 F07:** 허리 부착·옆 받침·그 위 치마의 관계. 외부 치마만 보인 결과를 내부 구조 PASS로 만들지 않음.
- **갑옷 G02:** 겉천·겉 리벳·안쪽 겹판의 같은 고정점. 내부가 가려진 경우 미관측.
- **하역 C08:** 배/부두 연결·짐의 하중·운반자 손과 발·수레/창고 통로. 짐을 떠 있게 만들거나 손 주인이 바뀌면 FAIL.
- **동아시아 I01:** 측량 담당자·줄·말뚝·별도 기록 담당자·실제 기록면. 서양 문서·제도와의 무분별한 합성 금지.

## 6. 판정과 재시도

모든 gate에 `observability=visible|partial|unobservable`, 실제 관찰, 전체 필수 관계 판정, 원본 경로를 기록한다. 눈에 보이는 오소유·불연속은 FAIL, 가려진 증거는 UNOBSERVABLE_NOT_PASS다. partial_is_fail을 유지한다.

blocked 결과는 BLOCKED_UNSCORED이며 픽셀이 없다. 무응답·저장 실패는 결과를 먼저 조정·복구한다. 안전 차단을 피하려고 표현을 바꾸거나 요청 identity를 바꿔 새 성공으로 포장하지 않는다. 수정이 허용된 재시도라면 실제 수정 범위·부모 hash·원래 필수 관계를 유지하는 현행 절차를 따른다.

검색·프롬프트 audit와 픽셀 결과를 각각 보고한다. 위 세 arm이 모두 성공해도 60개 후보 전체의 역사성·검색 정밀도·예술적 품질 또는 사용자 수용이 자동 승인되는 것은 아니다.
