# 영지물 세 컨셉 재생성: 원인 분석과 보완

2026-10-24, Asia/Seoul. 원래 세 출력과 실패 기록은 수정하지 않았다. 이 문서는 관찰한 결함과 개선 가설을 구분한다. 한 번의 출력으로 모델 내부 원인이나 데이터 추가의 인과 효과를 확정하지 않는다.

| 컨셉 | 원본 픽셀에서 확인한 결함 | 이전 프롬프트·데이터의 한계 | 이번 보완 |
|---|---|---|---|
| A · 타작장 점검 | 타작장 둘레는 닫혀 보이고 도로가 인물·건물 뒤에서 끊김. 배수 출구와 낮은 젖은 지면, 장화 밑창은 화면 밖. 책임자는 지시선 끝 대신 주인공을 봄 | `unbroken track`, `both boots` 등 의도는 이미 있었다. 그러나 눈높이의 가까운 인물·도면·전체 생산 경로를 함께 요구하면서 경계의 실제 출구, 도로 가림, 출구의 프레임 여백을 구체적으로 해결하지 못했다. 이는 구도 충돌 가설이며 확정된 모델 원인이 아님 | R01 실제 경계 틈과 전체 운반 경로, R02 수로 출구·받는 지면, R03 같은 작업 대상의 지시·시선과 발 접지 옵션. 작성자는 독립적으로 전체 시야와 전경 가림을 재설계 |
| B · 경계 청원 | 두 손끝이 강의 다른 둑/다른 구획을 선택. 자와 손이 상단 경계 연결을 덮음. 펜촉은 대응 제본 장부가 아닌 뒤의 종이에 닿음 | 같은 구획과 같은 장부를 지시하는 문장은 있었지만, 서로 다른 색 구획·직접 경계 위의 자·끝점을 가리키는 손이 동시에 등장했다. `writing in that entry`는 펜촉과 실제 기록면의 접점을 충분히 구체화하지 못했다. | C · 공동 화덕 | 한 받침 손과 빵의 접점이 가림. 작은 초기 틈보다 크게 갈라진 두 반쪽으로 보임. 기존 A07 곡물함–담당자 관계는 통과 | 네 손을 각각 구분하는 공간 배치 없이 빵의 양쪽 아래를 잡게 했다. `has just received`, `presenting it back`, `begins to pull apart`라는 여러 시간적 단계를 한 장에 담으려 했다. 작은 틈과 남은 연결부의 형상은 충분히 명시하지 않았다 | R07 네 손목·네 실제 접촉면, R08 좁은 틈과 넓게 남은 껍질 연결부. 작성자는 같은 컨셉에서 손 배치와 관찰 방향을 독립 재설계 |

이전 데이터는 관계의 이름과 완전한 관찰 기준을 이미 상당 부분 포함했다. 실패를 데이터 누락 하나로 환원하지 않는다. 이번 8개 예시는 같은 대상, 정확한 물리 carrier, 양 끝점과 실제 접촉면의 보이는 구성을 더 구체적으로 제공하는 선택형 자료다. 어느 예시도 성공을 보장하거나 자동 채택되지 않는다.

## 데이터와 프롬프트의 변경 경계

- 새 선택형 시각 후보 8개, 역할 연결 21개와 별도 의미 sidecar를 추가했다. 기존 영지물 후보 78개와 역할 연결 56개는 바꾸지 않았다.
- 원래 컨셉·의도한 action·참조 외모를 보존한다. pose/body geometry/composition/framing/camera 등 필요한 실현만 수리한다. 사용자 요구와 작성자 구도 선택을 새 ownership review로 구분한다.
- 원본의 실패 gate는 완화하지 않는다. 보이지 않는 접점은 상상해 채우지 않는다. `partial_is_fail`, `UNOBSERVABLE_NOT_PASS`, `BLOCKED_UNSCORED`를 유지한다.
- 데이터 원문 등록, 봉인 검색 노출, 실제 프롬프트 사용, 생성 픽셀과 사용자 판단은 각각 기록한다. 데이터는 역사적 고증, 법적 소유권·작위·권리, 시간적 최초성이나 기능 성능을 인증하지 않는다.

## 재시도 계보에서 발견한 별도 실행 문제

1. 과거 `scope_inventory`의 입력 해시까지 byte-equal로 복제하라는 계보 검사와 새 요청의 해시를 요구하는 중립 검사가 충돌했다. 의미 항목·owner·state·complete·증거와 참조 입력 바이트는 보존하면서 새 요청/envelope/input inventory와 검토 입력 ID만 올바르게 다시 묶도록 수정했다. 잘못된 새 해시, 바뀐 참조·owner·scope·항목은 계속 거부한다.
2. 기본 런타임 커널이 다른 작업으로 갱신되면 예전 부모를 새 커널로 감사하려 하여 `runtime_restart_required`가 발생했다. 부모의 검증된 봉인 실행 파일과 Python으로 기존 감사를 실행하고, 새 child의 계보 검증은 새 coordinator가 수행하도록 분리했다. 부모 파일·감사·호출 한도·기준을 변경하지 않는다.

새 scope 회귀 검사 16개와 기존 retry 정책 검사 30개가 통과했고, 실제 부모의 봉인 감사와 세 child attach도 통과했다. 이후 실제 child freeze와 설치본 전체 검증을 별도 증거로 기록한다. 이 실행 수리는 픽셀 성공과 별개다.

## 비교의 한계

세 작성자는 동일 참조와 각자의 닫힌 retry projection만 사용해 새 독립 코어를 동결한다. 다른 arm의 프롬프트·결과를 전달하지 않는다. 대기 중 이전 요약이 노출된 C 준비 세션은 저작·검색·생성 없이 종료하고 새 무이력 C 저작 세션으로 교체했다. 최종 세 저작자만 각 한 장씩 생성한다.

이번 비교는 프롬프트·데이터·런타임 수리가 함께 들어간 전후 사례다. 서로 다른 샘플의 결과 차이가 데이터만의 인과 효과나 전체 모델 정확도를 입증하지 않는다. 사용자 선호는 실제 피드백 전까지 미판정이다.

독립 코어·검색·프롬프트·생성·픽셀의 실제 상태는 [재시험 결과](REPAIR-AND-RETEST-RESULTS.md), 생성 전에 고정한 판정 기준은 [RETEST-GATES.json](RETEST-GATES.json)에 기록한다.
