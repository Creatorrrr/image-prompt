# 관찰 결과를 다음 데이터 보강에 반영하는 계획

이번 반영과 요청된 세 독립 테스트는 완료했다. 아래는 추가 데이터 변경·추가 생성 전에 사용할 후속 계획이다. 현재 통과 여부를 바꾸기 위해 이 계획의 변경이나 추가 생성은 실행하지 않았다.

## 1. 먼저 재현 가능한 회귀 기준을 복구한다

현재 authored DATA와 과거 sealed V24/V32/V33 자료의 바이트가 작업 시작 전부터 일치하지 않는 부분을 별도 변경으로 정리한다. 최초 변경·현재 변경·이번 확장 두 파일을 각각 비교하고, 과거 validator는 과거 소스를 읽게 한다. 최신 source를 과거 seal의 대체 payload로 쓰거나, 과거 hash와 실패 결과를 최신 값으로 덮어쓰지 않는다. 실패한 import·누락 fixture·전역 CT073 유지관리 표시 누락도 별도 원인으로 해결한다.

완료 조건은 현재 데이터 검사와 과거 재현 검사가 각자 정확한 소스 세대에 연결되고, 실행 누락 없이 full discovery 결과를 보고할 수 있는 것이다. historical oracle가 실제 의미 변경을 발견하면 그 변경의 기존 검토 근거를 확인한다. 단순히 assertion을 삭제하거나 expected hash를 교체하지 않는다.

## 2. 어두운 여백은 배경 영역의 실제 공간 관계로 강화한다

근거: B 두 시도에서 배경 식물·유리창 구조가 얼굴 옆 공간을 계속 채웠다. 어두운 색이나 흐림만으로는 장식과 얼굴을 분리하는 여백 관계가 되지 않았다.

검토 대상은 `egr_dark_lateral_negative_space`의 대상 선언·풀이·번들 멤버 효과다. 후보는 얼굴의 외곽/머리 실루엣과 주변 장식 사이에 있는 기존 배경 영역을 구체적으로 가리켜야 한다. 외곽 실루엣을 삭제하거나, 머리를 바꾸거나, 필요한 물건을 없애는 효과를 새로 암묵적으로 넣지 않는다. 해당 공간 자체의 위치·범위·세부 밀도를 명시할 수 있는 기존 속성 계약을 먼저 확인한다.

다음에는 동일한 소유 대상과 접촉 관계를 가진 단순 배경/복잡한 배경의 짝을 만든다. 얼굴 양옆 실제 저밀도 간격과 주변 장식과의 분리를 각각 확인하고 한쪽이라도 실패하면 전체 FAIL이다. 조명이 어둡다는 관찰만으로 통과시키지 않는다. 필요하면 후보 문구 수정 전후의 기준 이미지를 같은 요청으로 비교한다.

## 3. 피부 온도 대비는 머리카락·전역 색조와 분리한다

근거: C 두 시도 모두 금빛 머리카락은 보였지만 피부 경계의 한정된 따뜻한 구역은 확인되지 않았다.

`egr_cool_skin_warm_reflected_edge`의 정의·대상·풀이에 이미 있는 피부 소유권을 유지한다. 실제 얼굴 피부에서 광원 쪽 볼/턱/귀 등 특정 경계와 중앙 피부를 동시에 볼 수 있는 장면을 검토한다. 색온도 수치나 후보 문구만으로 사실을 인정하지 않는다. 광원 위치·피부 경계의 방향·카메라 가시성이 함께 맞아야 한다.

다음 독립 사례에서는 머리카락에만 따뜻한 빛이 있는 인접 부정 사례, 전체 얼굴이 따뜻한 부정 사례, 한 피부 경계에만 따뜻한 빛이 있는 목표 사례를 구분한다. 중앙 피부와 따뜻한 피부 경계가 같은 얼굴에 보이는지 전부 검사한다. 임계 색차 수치를 데이터에서 새로 발명하지 않고 필요하면 사람이 확인할 수 있는 비교 영역을 함께 기록한다.

## 4. 기계적 접촉은 한 프레임에서 경로를 추적하게 한다

근거: C의 필수 visibility/projection 검사에서 줄의 마지막 부착 지점이 보이지 않았다. 이는 새 색 후보의 실패와 별개다.

데이터를 바꾸기 전에 장면의 같은 손→같은 줄→도르래→같은 이동 부품의 경로가 한 이미지에 드러나는 전용 단순 테스트를 만든다. 필요한 부착 지점을 장식 뒤에 숨겨 문제를 회피하지 않는다. 손과 줄의 접촉, 장치의 지지 구조, 마지막 고정 지점과 이동 방향을 각각 확인한다. 이 관계는 현재 auditor-derived 신체 필수 검사의 일부로 남긴다.

복잡한 장면에서 이를 드러낼 수 없으면 열린 프레이밍·카메라·배경 세부를 줄이는 선택을 검토한다. 원래 요청자가 고정한 얼굴·머리·행동을 바꾸거나 계약상의 가시성 검사를 삭제하는 수정을 하지 않는다.

## 5. 금빛 모자이크 검색 실패는 holdout으로 유지한다

근거: 전체 2,290개 프로필에 실제 임베딩을 적용한 풀이 6개 중 모자이크는 embedding/hybrid 모두 목표를 반환하지 않았다. 6개 중 나머지 관계의 성공으로 이 실패를 평균 처리하지 않는다.

목표는 금색 타일 각각의 경계·접합선과 광택 분포라는 관계가 금박 같은 넓은 금빛 표면과 분리되어 발견되는 것이다. 수정 전 문장·소스·모델·차원·결과를 고정하고, 정의/구성요소/후보 검색 텍스트에 이 차이가 충분히 표현됐는지 검토한다. provider/model/dimensions/text hash가 모두 일치하는 벡터만 재사용한다.

평가 문장을 authored exact alias로 복사하거나 similarity threshold·margin을 낮춰 성공을 만들지 않는다. 새로운 독립 풀이와 인접 부정 표현을 추가해 이전 실패 문장을 holdout으로 계속 평가한다. 검색 개선 뒤에는 작은 금빛 벽면 소유 대상을 가진 별도 픽셀 사례를 만들며, 검색 통과와 이미지의 타일/접합선 통과를 각각 기록한다.

## 6. 41개 프로필·60개 후보의 나머지 범위를 검증한다

현재 native coverage는 일반 후보 4/60개이고, 새 프로필을 선택한 native hard gate coverage는 0/41개다. 다음 순서는 직물 구조(레이스·튤·크레이프), 꽃 표면(서리·이슬·마른 꽃잎), 금빛 표면(회화·금박 같은 외관·모자이크), 공간/광학(슬릿·초점·입자·안개·확산), 색 역할(세 대상 팔레트)이다.

각 가족에 목표 관계·가까운 혼동 관계·대상이 없는 문맥·부정 문맥을 마련한다. 사례는 테스트 작성자의 창작 설정으로 명시하고 실제 사용자 요청에 요구사항을 덧씌우지 않는다. 독립 작가에게 후보명·profile ID·선택 결과·기존 이미지·연구 카드의 정답 목록을 사전에 주지 않는다. 작가는 전체 장면과 컨트롤을 먼저 고정하고 이후 정상 pack의 노출→채택→literal delta→native 관찰을 기록한다. 노출 실패는 노출 실패로 남기고 pack에 목표를 주입하지 않는다.

선택된 프로필이 실제 공용 계약에서 hard gate를 파생하면 그 정확한 게이트를 검사한다. 일반 후보만 채택했다면 그 의미 전체를 보조 관찰로 검사하며 profile 검증으로 부풀리지 않는다. 각 실행은 한 이미지의 모든 구성요소가 통과해야 완료되고, 여러 시도의 다른 성공을 합칠 수 없다. 사용자 취향은 별도 수용 기록을 받기 전까지 pending으로 유지한다.

## 실행 순서와 완료 조건

| 순서 | 산출물 | 통과 조건 |
|---|---|---|
| 1 | current/archived 소스 분리·회귀 기준 정리 | 실행 누락과 분류 불명 오류를 숨기지 않는 재현 보고 |
| 2 | 여백·피부·기계 연결의 고정된 단순 비교 사례 | 각 사례의 모든 소유 대상·관계·가시성 확인 |
| 3 | 검색 텍스트 수정안과 이전 실패 holdout | 목표 발견, 인접 혼동/부정의 비활성화 유지 |
| 4 | 필요한 authored DATA 변경과 인덱스 재생성 | 기존 필드·잠금·필수 gate 보존, 바인딩 검사 PASS |
| 5 | 나머지 가족의 독립 복잡한 native 사례 | 노출·채택·문구·픽셀 근거를 분리하고 전체 관계 검증 |
| 6 | 사용자 비교 수용 기록 | 기술 PASS와 사용자 선호를 각각 확인 |

기준 이미지가 없는 현 결과를 '향상'으로 평가하지 않는다. 후속 품질 비교가 필요하면 같은 고정 요청에서 후보 채택 전·후의 두 이미지를 만들고 기준/수정 문구와 모든 결과를 보존한다. 이 비교 역시 모델의 변동성을 고려해 단일 사례의 일반화 범위를 제한한다.
