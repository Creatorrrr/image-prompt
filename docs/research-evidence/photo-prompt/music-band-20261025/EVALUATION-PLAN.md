# 음악물 확장 평가 설계

평가 데이터의 현재 상태는 전부 `planned_not_executed`다. 이번 작업은 구조 validator만 실행하며 검색·선택·픽셀 점수는 만들지 않는다.

## 서로 다른 평가 집합

| 집합 | 크기 | 용도 | 해석 한계 |
|---|---|---|---|
| 카드 파생 smoke | 124사례·한영 248질의 | 새 문장이 검색 대상에 정확히 들어갔는지 확인 | 연구 문장과 동일한 쉬운 확인. 품질·일반화·독립 holdout으로 보고하지 않음 |
| 수동 경계 개발 | 44사례·한영 88질의 | 다의어·동작·장치·인물·매체·성인·학교·사람 없는 요청의 경계 | 연구를 읽고 작성한 개발 집합. 답안 ID는 연구 카드이므로 이후 native CID mapping 심사 필요 |
| prospective 픽셀 | 16사례 | 손/현·활/엔드핀·케이블·화면·단일 마이크·다중 지지의 실제 가시성 | 아직 프롬프트 workflow·source 자격·이미지 도구를 실행하지 않음 |
| 미래 독립 holdout | 최소 24사례 제안 | 실제로 보지 않은 자연 질의·공백·다른 장르·문화·편성의 일반화 | 이번에는 생성하지 않았다. 후속 독립 평가에서 사람이 정답을 먼저 심사하고 동결 |

## 실행 전에 고정할 계약

전/후 release의 정확한 source·code·index·vector recipe·모델 공간·generation 해시를 보존한다. 현재 installed release와 새 authored 파일을 섞지 않는다. 한국어/영어 입력, frozen requester envelope/core/controls, 각 슬롯 query, 전체 주제 query, baseline query, 후보 view, 표본 seed를 기록한다.

연구 카드에 예상 답이 있다고 해당 CID를 강제 선택하지 않는다. 현재 native 원문이 어떤 보존 조건을 요구하는지 사람이 먼저 확인하고 `research card → allowed native CID/RID → complete selected meaning`을 mapping한다. 새 card가 보류됐거나 기존 source와 다른 뜻이면 평가 대상/정답에서 명시적으로 보류한다. 조건 불일치 후보는 순위가 높아도 채택 불가다.

## 검색과 채택 지표

1. **Recall@8 / MRR**: 실제 의미에 맞고 현재 조건을 충족하는 source가 해당 query의 첫 8개 안에 있는지, 첫 적합 결과 순위가 무엇인지 수동 답안으로 채점한다. 단어 포함·카드 ID 동일 여부만으로 채점하지 않는다. 시각 정답이 있는 개발 사례에서 한영 각각 Recall@8 90% 이상을 제안 기준으로 두되 실행 전에 대상과 기준을 고정한다.
2. **Precision@8**: 반환 결과 전체 명제가 요청과 양립하는지 채점한다. discovery-only·context·inspiration-only를 별도 분모로 남긴다. 지표가 모호하면 원문과 사람의 판정 이유를 보존한다.
3. **금지 의미 채택률**: D01–D44의 오독이 실제 최종 문장으로 들어간 사례 수. 통과 기준은 0이다. 공통 풀에서 오답이 검색됐다는 것과 그 오답을 채택한 것은 다른 사건이다.
4. **전체 관계 보존율**: 선택한 source의 사람 수·악기·손·지지·케이블·좌우·매체 경계가 prompt에 모두 보존되는지. native audit 통과 외에 한영 의미를 수동 검토한다. 필수 관계 누락 0을 요구한다.
5. **일반 요청 회귀**: 음악 없는 기차·회로·미디 스커트·웨지 신발·제품 턴테이블·사람 없는 공간·기본 인물 요청을 포함한다. 무단 음악 요소 채택 0, 기존 정답 검색 Recall@8의 5%p 초과 하락 없음이라는 제안 기준을 전/후 같은 질의에 적용한다.

숫자는 이 계획의 제안 통과 기준이며 관찰한 결과가 아니다. 카드가 보류되어 정답이 없거나 여러 실현이 가능한 사례를 강제로 0/1 정답으로 만들지 않는다. dev·smoke·holdout 결과를 합쳐 평균 하나로 보고하지 않는다.

## 실제 동작과 장치 경계의 중요 사례

- D07/D08/D09: 오픈 림샷·어쿠스틱 크로스스틱·TD-07KV rim-to-rim. 외형이 비슷해도 작동 조건을 이전하면 실패다.
- D13/D14/D15: MIDI 노트/오디오, 녹음 컴핑/재즈 반주. 같은 단어의 sense를 보존한다.
- D16/D30/D43: 원맨=한 팀, 여성 밴드≠운동·성년 자동 판정, 재즈 트리오의 악기 편성은 요청대로 유지한다.
- D20/D22/D23/D24: 같은 착용자의 케이블, 한 캡슐, 각자 악기, 다른 관객들의 지지 손은 owner와 relation을 평가한다.
- D34/D35/D36/D38: 성인 누드·성적 강요·모조 피·학교 요청을 각각의 의미로 유지한다. 민감한 핵심을 삭제하거나 다른 의미로 승인하지 않는다.
- D37/D39–D42: 사람 없는 장면과 비음악 다의어의 원래 뜻을 유지한다.

## 픽셀 평가와 인과적 품질 주장

`prospective-pixel-cases.json`의 16사례는 가시 접점과 관계를 사전에 적은 설계다. 후속 이미지 검증을 실행할 때는 먼저 현재 workflow로 source와 독립 요청/core를 동결하고 한영·owner·effect 자격을 확인한다. 같은 요청과 controls로 기존/신규 release를 비교하는 기본안은 16쌍이며 실제 호출 수는 그 후속 작업의 범위로 정한다.

실제 입력 prompt·도구 parameters·선택/거절 CID/RID·원문 해시·저장 이미지 경로를 남긴다. 각 gate는 `visible / partial / unobservable`를 먼저 판단한다. 필수 요소 중 하나가 가려지거나 다른 인물에 붙으면 전체 gate는 통과할 수 없다. 공급자 차단/실행 실패는 `BLOCKED_UNSCORED`로 구분한다. 결과가 없는 시도를 이미지 품질 실패나 성공으로 계산하지 않는다.

source 무결성, 검색 노출, native 선택, prompt 보존, 실제 픽셀, 예술적 선호, 사용자 수용을 따로 보고한다. 전/후 독립 반복·동일 조건·눈가림 사람 평가 없이 '데이터가 이미지 품질을 개선했다'는 인과 주장을 하지 않는다. 단일 생성의 성공도 재현성이나 사용자 수용을 보장하지 않는다.
