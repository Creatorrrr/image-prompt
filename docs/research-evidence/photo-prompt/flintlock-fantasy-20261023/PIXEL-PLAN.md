# 실제 이미지 검증 설계

현재 상태: NOT_RUN. 이 문서는 이미지 생성 결과가 아니다. 아래 여덟 요청군은 의미·출처·물리 관계 검토 후 사용한다. 첫 회차는 1·4·6군의 baseline/staged 두 arm, 총 6장을 제안한다. 남은 다섯 군과 원인 구분용 ablation은 결과에 따라 확장한다.

## 공통 실행 계약

요청의 의미·피사체 수·구성 anchors·금지 변화·controls·출력 규격을 먼저 고정한다. 두 arm에서 같은 요청/controls/대상 버전을 사용하고 seed를 지원하면 기록한다. seed 미지원이나 확률적 변동은 제한으로 남긴다. baseline은 기존 세대, staged는 새 데이터를 포함하는 격리 세대다. 선정 CID/RID·decline 이유·actual source·qualification·최종 literal prompt·전송 hash를 연결한다.

source 텍스트에 요청한 관계가 없으면 픽셀 단계 이전에 미채택으로 남긴다. 새 태그만 보고 프롬프트를 작성하지 않는다. 카드에 사람이 있다고 요청에도 사람을 추가할 권한이 생기지 않는다. source를 사용하지 않은 arm의 이미지 성공을 새 데이터의 효과로 세지 않는다.

## 판정 단위

관계 gate는 양 endpoint와 실제 연결/분리/방향을 모두 요구한다. count gate는 요구된 전체 수량을 센다. 크롭·가림·낮은 해상도·경계 융합으로 확인할 수 없으면 `UNOBSERVABLE_NOT_PASS`다. 부분 부품이 맞아도 요청한 전체 관계가 없으면 `partial_is_fail`이다.

필요한 gate 중 하나라도 실패하면 그 이미지의 해당 전체 의미 사례는 FAIL이다. 미생성·provider 오류·moderation 차단에는 픽셀이 없으므로 `BLOCKED_UNSCORED` 또는 `ERROR_UNSCORED`로 분리하고 시도 수/생성 수/평가 가능 수의 분모를 따로 보고한다. unchanged blocked prompt의 자동 반복은 하지 않는다.

이미지 한 장에서 실제 기능·시간 동기화·불발/지연발화·정보 수신·정치적 충성·노예 신분·동의·마법 원인·치료 효과를 증명하지 않는다. 필요한 경우 별도 서사 주장/다중 프레임/실제 데이터로 분리하고, 그 증거가 없으면 보류한다.

권장 기록 필드: request/core/controls hash, source generation, selected CID/RID, source quotations, prompt/transport hash, image absolute path/hash, generator metadata, each gate의 PASS/FAIL/UNOBSERVABLE 및 bbox·관찰 이유, local gate 결과, whole-scene 결과, user acceptance. generator metadata가 제공하지 않은 seed나 실제 모델명을 추정해서 채우지 않는다.
