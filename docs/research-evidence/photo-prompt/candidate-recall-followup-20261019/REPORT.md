## 검색·검증 범위

각 arm은 공통 positive 풀 **18,180 CID / 18,182 actual RID 전체**에서
경쟁했다. 원문 pool 18,250 CID 중 70 diagnostic은 기존 positive 검색 대상이
아니며 이 정책을 바꾸지 않았다. 슬롯 태그 필터나 context 사전 제외를 추가하지 않았다.

각 arm의 75개 목표는 기존 본 평가 67개와 기존 보조 8개다. **목표당 BM25F
1회·local cosine 1회**를 실제 실행했다. 세 arm 합계는 각 lane 225회이며,
진단·아카이브 감사는 추가 검색을 하지 않는다. RRF10, F2 가중치·k1/b·전역
DF/길이 정규화, 실제 RID 평가 후 CID 중복 제거, top8을 그대로 유지했다.
새 query와 과거 query 결과를 운영에서 합치는 방식도 만들지 않았다.

각 세대는 원문 body, 원래 D/fields, baseline/native manifest, 승인 리뷰와
전체 실행 커널·투영 코드를 보유한다. sparse 값은 native part 또는 승인된
리뷰에서만 올 수 있고, dense는 원래 D 또는 원래 D+해당 요약으로만 구성된다.
출처 없는 텍스트를 넣고 바깥 파일 hash를 다시 계산해도 거절한다.
새 리뷰는 native 승인이나 효과 변경 권한이 아니다.

- 관련 단위·precore·workflow·권한 전달 회귀 검사 **79개 PASS**.
- 실제 세대 변조 거부 **6종 PASS**, 원본 복사본 재검증 PASS.
- query 출처·CID 주입·누락·추가 query·대상 변경 거부 **5종 PASS**.
- 새 로컬 입력: D1b 문서 41건, Q1 query 12건. 기존 문서와 query 증거는 재사용.
- Gemini·원격 fallback·전수 의미 검토·원문 보강·이미지 생성은 0건.
- 실행 중 OS sandbox로 네트워크와 연구 checkout 읽기를 차단했다.
- 작업 전 파일 40,451개의 hash, 모든 입력/코드/query 봉인, 설치 세대 전체
  seal, CURRENT와 설치 선택 파일의 원래 hash를 확인했다.

기존 보조 4요청·8목표의 알려진 적합 연결은 각 arm에서 29/29로 유지됐다.
같은 판정을 재사용한 포화된 보조 집합이며 새 일반화 평가를 대체하지 않는다.
이번 126개 연결도 반복 사용한 개발 자료다. 새로운 요청에서의 개선을 입증하지 않았다.

## 확인한 개선과 남은 한계

두 lane의 문서 투영을 분리해, sparse 이득을 유지하면서 알려진 dense 희석
손실 1건을 회복하는 D1을 실제 코드 경로에서 검증했다. 독립 출처 검증 계약도
구현했으므로 품질 HOLD와 별개로 재사용할 수 있는 구조적 진전이다.

그러나 요약만 더한 D1b도 55/29였고, 검색어를 한 번 재작성한 Q1도 D1보다
적합 연결 1건이 늘어난 데 그쳤다. A에서 0건이던 12개 목표 중 Q1은 2개 목표에서
적합 3연결을 회수했으며, 해당 12개 중 composition/lighting 목표는 여전히 0건이다.
이번 범위에서는 문서 공유 문제의 일부 비용을 분리했지만, 슬롯 의도에 맞는
후보를 충분히 상위로 올리는 문제를 해결하지 못했다.

이 결과로 데이터 자체에 의미가 없거나 전수 보강이 반드시 실패한다고
판단하지 않는다. 이번에 측정한 세 정책의 개선 크기로는 전수 보강·추가
정책 탐색·운영 전환을 정당화하지 못했으므로 고정된 중단 조건을 적용했다.
