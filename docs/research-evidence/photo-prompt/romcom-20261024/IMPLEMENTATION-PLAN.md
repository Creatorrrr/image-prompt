# 러브코미디 데이터 반영 계획

2026-10-24. 목적은 **요청한 러브코미디 장면의 관계와 웃음의 계기를 더 정확히 검색·선택·표현하면서, 일반 장면에 연애·접촉·노출·시간 이력을 발명하지 않는 것**이다. 이번 요청의 실행 범위는 조사와 반영 계획이다. 연구 폴더의 초안·평가 설계만 작성했으며 운영 source, manifest, index, 설치본을 변경하지 않았다.

## 1. 변경 단위와 의존 순서

## 3. 제안 파일과 등록 경계

사진 경로에서 구현할 경우 다음 파일 단위를 제안한다. 실제 스키마는 구현 시점 현행 유지보수 규약으로 다시 확인한다.

- `skills/photo-prompt-image-generator/assets/photo_romcom_semantics_20261024.json`: 의미·표제·용례 지위·출처 범위·보류·시각/문맥 분리. 연구 전용 필드를 운영 사실로 취급하지 않는다.
- `skills/photo-prompt-image-generator/assets/photo_candidate_romcom_20261024.json`: 중복을 제거하고 실제 source 심사를 통과한 완결 시각 대안만. 기존 CID를 단지 장르별 파일에 복제하지 않는다.
- `skills/photo-prompt-image-generator/assets/photo_candidate_romcom_bindings_20261024.json`: 각 현행 slot의 정의와 실제 조건·효과를 검토한 optional binding만.
- `skills/photo-prompt-image-generator/references/romcom-visual-semantics.md`: 등록한 범위·재사용/수정 이유·검증 결과·미확인 정의·실제 생성 한계.
- `photo_candidate_corpus_manifest.json`: 최종 승인된 실제 모듈만 추가. 운영 index는 확정 source union에서 별도로 재생성한다.

다음은 현재 연구 파일이며 운영 source가 아니다.

- [semantic-cards.json](semantic-cards.json): 99개 저작 시각 대안과 19개 문맥 경계.
- [candidate-drafts.json](candidate-drafts.json): native ID·effects·proof를 아직 만들지 않은 후보 제안.
- [keyword-routes.json](keyword-routes.json): 각 원 용어에서 선택적/인접 대안으로 가는 연구 경로. 동의어·자동 활성화 규칙이 아니다.

일러스트레이션에서는 현행 `illustration_universal_scene_candidates_v1.json`, `illustration_universal_semantic_bindings_v1.json`, `research_evidence_moe_elements/moe_meaning_contracts_v2.json` 등 해당 경로의 계약을 먼저 읽는다. 사진의 CID·binding·proof를 그대로 복사하지 않는다. M 카드와 성격·팬덤 맥락은 매체를 명시한 별도 변경으로 검증한다.

## 4. 재사용·수정·추가·문맥·보류의 결정 규칙

|결정|필요 조건|이번 조사에서의 예|
|---|---|---|
|reuse|전체 한영·선택 분기·owner·대상·개수·지지·매체·조건·효과가 맞음|두 사람 손깍지, 소매 천 잡기, 이마 접촉의 기존 source|
|refine|같은 원 뜻에 실제 번역 누락·대상 모호함·조건/효과 누락이 있으며 기존 의미를 유지할 수 있음|우산의 짧은 구도 라벨을 전체 관계의 증거로 과대사용한 연결 수정|
|new|전체 source 의미 비교 후 필요한 완결 대안이 없으며 독립적으로 결합 가능|같은 이어폰의 분기와 두 귀를 함께 갖춘 대안 검토|
|context|정지 외형이 의미를 입증할 수 없거나 요청이 별도로 서술한 사실|가짜 연애, 슬로번, 우발성, 간접 키스의 이전 사용, 공식 커플|
|defer|용례·구조 도판·역할·effects·native 근거·가시성 중 필요한 것이 부족|미확인 조어의 정착 정도, 복합 재단의 정의, 연속 사건의 픽셀 확인|

구체 CID와 원본은 [existing-source-decisions.json](existing-source-decisions.json)에 포함했다. 예를 들어:

- `cand_e88cd98b3bce5a3f938e3043f720708e`: 다른 두 사람의 교차 손가락. R03과 의미가 가깝지만 전체 한영·접점·각 손목·현재 qualification을 함께 확인한다.
- `cand_e6266c74eb3a5eea9cacdf3a0d15c0ed`: 등과 무릎 아래의 공주님 안기. R15가 추가한 발 지지를 기존 source가 원래 보장한다고 간주하지 않는다.
- `cand_8269c0fedfca57d5b3bbfffd27497653`: 상대 턱 아래 손끝. R27의 직접 이웃이며 자기 턱 괴기로 연결하지 않는다.
- `cand_67d7910889fa5a1cb3fef1300f76eb71`: `shared umbrella close frame`. 구도 조각을 전체 캐노피·두 머리의 증거로 승격하지 않는다.
- `cand_972acf2f94535c50a0d0b1767483530f`: `restrained bystander double take`. 시간 정보가 빠진 놀람 표정으로 정착시키지 않는다.

연구 그래프에 A/B가 있다는 사실은 실제 요청에 두 인물이 존재한다는 증거가 아니다. source의 넓은 `dimensions`나 연구 `observable_gate`도 실제 owner별 효과·조건·field-local 근거를 대신하지 않는다. 사람/소품/레이어/개수/시선/접촉/지지/매체/카메라를 새로 바꾸는 부분을 각각 검토한다. 같은 값으로 덮어쓰는 것도 효과 심사에서 제외하지 않는다.

W04처럼 소매 접힘과 풀린 넥타이를 함께 저작한 카드는 두 속성의 선택권을 검토한다. 장면상 결합된 대안으로 남길지, 독립된 분기/후보로 나눌지 확정하고 해당 분기만의 전체 의미와 effects를 qualification한다. 카드에 여러 slot을 제안했다는 이유로 전부 승인하지 않는다.

## 5. 사전 근거와 잔여 조사

317개 중 독립 어휘 주장을 확인한 41개는 해당 문서의 특정 범위만 뒷받침한다. 나머지 276개는 원 정의를 보존한 상태이며 개별 출처 검증 완료로 표시하지 않는다. 작업량은 단순히 276개의 사전 링크를 채우는 방식으로 정하지 않고 채택할 의미와 혼동 위험을 기준으로 정한다.

우선 조사할 잔여 항목은 다음과 같다.

1. **형태를 실제로 채택할 외형**: 하프업과 다른 묶임 방식, A라인/플레어/펜슬, 스위트하트/데콜타주, 슬립/네글리제/베이비돌, 가터 연결, 수영복의 서로 다른 구조. 도판이나 실물 소장품을 보고 형상 차이와 출처 범위를 기록한다.
2. **정착 여부가 불분명한 설명형 표현**: meet-disaster, 계약 관계의 진심화, 감정의 온도차, 불량해 보이는 순정파 등은 설명형 표현을 그대로 인정하고 정식 장르명으로 승격하지 않는다. 실제 출판·팬덤 사용을 별도 확인한다.
3. **팬덤별 경계가 다른 유형**: 세부 dere, 하렘/역하렘/why-choose/CNM, BL/GL, OTP/캐넌 등은 공동체·언어·장르별 차이를 유지한다.
4. **민감한 관계·해프닝**: 우연/고의, 실제 접촉/시선, 기존 약속/배신, 친족/의붓 관계, 권력/합의, 수위/등급은 정확한 주장별 근거를 보완한다. 해당 어휘를 삭제하거나 비노출 대안이 원뜻을 충족했다고 판정하지 않는다.

미확인 어휘를 모두 시각 후보로 만들 필요는 없다. 반대로 시각 형태의 근거가 부족하다는 이유로 사용자가 지정한 관계·의도·수위를 조용히 다른 뜻으로 약화하지 않는다. 해당 의미를 문맥으로 유지하고 검증 범위를 정확히 밝힌다.

## 6. source·index 검증

구현 직전 현행 [maintenance.md](../../../../skills/photo-prompt-image-generator/references/maintenance.md)를 확인한다. 조사 시점에는 아래 entrypoint와 옵션이 존재했다. **아래 운영 검사는 이번 연구에서 실행하지 않았다.**

```sh
python3 skills/photo-prompt-image-generator/scripts/photo_installed_h_f2.py --check-runtime
.venv/bin/python skills/photo-prompt-image-generator/scripts/validate_photo_prompt_dictionary.py
.venv/bin/python skills/photo-prompt-image-generator/scripts/build_shared_candidate_index.py --verify
```

`build_shared_candidate_index.py`의 `--output-assets`, `--runtime-store`, `--verify`, `--publish`를 확인했다. 실제 최종 source union과 현행 text recipe·provider/model·차원·vector integrity가 모두 일치할 때만 이전 벡터를 재사용한다. 텍스트가 같아도 recipe가 바뀌면 옛 벡터를 새 규약인 것처럼 재표기하지 않는다. 변경된 source만의 임시 topic index로 성능을 평가하지 않는다.

순서는 source 구조·한영/owner/effects 심사→각 CID/RID의 실제 field-local/native qualification→별도 경로의 전체 공통 index→source/hash/vector closure 확인이다. 활성 manifest와 설치 선택은 이 검증 이후 단계다. build 도중 source가 바뀌면 해당 결과를 재기준화하며 이전 실패를 새 이름으로 지우지 않는다.

## 7. 검색·선택 평가

현재 [개발 질의](development-cases.json)는 시각 카드의 한영 198개와 혼동 경계 양쪽 92개, 총 290개다. 카드 문구와 겹치므로 **작성자에게 노출된 개발셋**이다. 검색은 실행하지 않았고 독립 holdout은 없다.

검증할 가설은 다음과 같다.

|가설|비교에서 달라질 것|경쟁 설명과 확인 방법|
|---|---|---|
|H1. 완결 소유자/접점 표현이 올바른 대안의 노출·선택을 개선|source의 전체 관계와 심사된 binding|단순 키워드 중복 효과인지 비동의어 자연어·한영·혼동쌍으로 확인|
|H2. 문맥 분리가 연애·시간·의도 발명을 줄임|context/direct 분리와 채택 경계|단지 모든 대안을 차단해 감소한 것인지 적합한 양성 요청의 허용 선택률도 함께 확인|
|H3. 계기와 상대 반응을 함께 유지하면 코미디 상황이 더 잘 전달|연결된 사건·시선·반응 대안|소품 추가·문장 길이만의 효과인지 같은 사용자 의미·동일 조건의 compose/픽셀로 구분|

baseline과 stage는 같은 전체 공통 pool, 같은 슬롯 정의·언어·모델 공간·예산·독립 사용자 요청에서 비교한다. 각 slot의 candidate-free query, BM25F, 실제 query embedding, cosine, RRF, 최종 CID/RID/rank와 source hash를 기록한다. slot 태그 선필터·topic 전용 pool·강제 가산점으로 정답 노출을 만들지 않는다.

보고 지표는 의미 가족·언어별로 나눈다.

- **노출**: top-10에 적합한 완결 대안이 있는가. 원뜻에 맞는 후보가 없다면 억지 정답을 만들지 않는다.
- **선택 가능성**: 실제 owner/조건/허용 effects를 통과했는가. 검색에 보임과 최종 채택은 다르다.
- **오선택**: 자기/상대 교체, 접촉/틈 치환, 문맥→외형 승격, 불필요한 인원·성적/폭력적 의미·매체 변경의 건수.
- **compose 보존**: 필수 양끝·지지·개수·가림 경계가 최종 한영 프롬프트에서 유지되는가.

독립 확인용으로는 12개 의미 가족×양성/혼동 요청×한영=48개 요청을 다른 작성자가 카드 문구를 보지 않고 구성하고 기대 관계를 먼저 동결하는 안을 제안한다. 현재 이 작성자는 배정하지 않았다. 같은 작성자가 추가한 표현은 추가 개발셋으로만 표시한다.

완료 기준은 필수 owner/의미/허용 범위 위반 0건, 적합 양성 요청에서 대안을 전부 차단하지 않을 것, 가족별 노출·선택의 baseline 대비 결과와 실패 이유를 보고할 것이다. 성능 임계치는 실제 비교 전 기준 데이터를 보고 동결한다. 결과를 본 뒤 기준을 낮춰 통과시키지 않는다.

## 8. 픽셀 평가와 실제 활성화

[PIXEL-PLAN.md](PIXEL-PLAN.md)에 사진 12장면×baseline/stage=24장 비교를 제안했다. 첫 3쌍에서 입력·전송·비교 의미가 성립하는지 확인한 뒤 남은 장면을 진행한다. 카드 문장을 사용자 요구인 것처럼 복사하지 않고, 실제 요청에서 독립 core와 owner·허용 범위를 확정한 동일 계약으로 양쪽을 실행한다. 아직 생성·전송·픽셀 판정은 모두 NOT_RUN이다.

관계의 필수 양끝 중 하나라도 누락되면 partial 실패, 가려지거나 너무 작으면 `UNOBSERVABLE_NOT_PASS`, 출력 차단은 `BLOCKED_UNSCORED`다. 생성 거절이나 파일 미확보를 품질 성공/실패 픽셀로 환산하지 않는다. 안전상 비노출 장면으로 변경했다면 원 요청의 성공으로 합산하지 않는다. 동일 입력·실패·수정 시도의 계보를 보존한다.

실제 선택·전송 receipt·저장 픽셀·사람의 장면 판독을 연결한다. source 등록, index 성공, 설치 경로 전환, 모델 픽셀, 사용자의 수용은 독립 상태다. 동일한 모델·해상도·비교 계약을 유지하고 seed/모델 비결정성 통제가 안 되면 적은 쌍에서 데이터의 인과 효과를 단정하지 않는다.

채택된 source와 검증된 sealed generation을 별도 비활성 설치로 확인한 뒤 활성 선택을 전환한다. 이전 generation과 설정은 복구 가능하게 보존한다. 문제가 있으면 선택을 되돌리고 실패 증거는 유지한다. 커밋·push가 후속으로 요청되면 명시한 파일만 stage하고 실제 remote SHA까지 확인한다. 현재 작업 폴더의 다른 수정·삭제·미추적 파일을 정리 대상으로 삼지 않는다.

## 연구의 완료와 후속 작업의 상태

이번에 완료한 것은 전체 입력 복구·출처별 주장 정리·시각/문맥 초안·기존 source 비교·반영 계획·평가 설계다. 개별 미확인 용례, 운영 source 심사·등록, index 재구축, 검색 성능, 실제 이미지, 설치 활성화와 사용자 수용은 각각 미실행/미확인으로 남아 있다. 이 문서를 저장했다는 사실은 후속 실행이나 예약 작업을 시작하지 않는다.
