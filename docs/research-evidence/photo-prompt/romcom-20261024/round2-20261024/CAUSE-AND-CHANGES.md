# 러브코미디 재시험: 원인 분석과 개선 내역

이 문서는 첫 생성 3건의 실제 프롬프트·검색 기록·저장 이미지를 분석한 결과다. 인덱스 등록, 검색 노출, 참고자료의 실제 활용, 네이티브 계약에 따른 후보 선택, 이미지의 가시적 구현을 구분한다. 재생성 결과는 같은 폴더의 `RESULTS.md`에 별도로 기록한다.

## 신규 자료가 최종 프롬프트에 쓰이지 않은 이유

**등록 누락은 아니었다.** 기존 118개 레코드는 실행본에 들어 있었고, 긍정 후보 99개와 진단용 제외 항목 19개도 구분돼 있었다. 그러나 다음 단계들에서 결과가 줄었다.

| 첫 시험 | 순위 창 안의 신규 자료 출현 횟수 | 실제 샘플 출현 횟수 | 최종 참고자료 활용 | 네이티브 후보 선택 |
|---|---:|---:|---:|---:|
| A 꽃꽂이 | 1 | 0 | 0 | 0 |
| B 스케이트 | 4 | 0 | 0 | 0 |
| C 파라솔 | 4 | 2 | 0 | 0 |

이 표의 출현 횟수는 같은 자료가 다른 질의에 다시 나온 경우를 포함한다. A/B의 순위 창에 신규 자료가 전혀 없었던 것은 아니다. 실제로 작성자에게 전달되는 샘플에 없었다.

당시 creativity=1 정책은 질의마다 서로 다른 CID의 상위 32개에서 8개를 균등 추출했다. 개별 자료는 그 창에 들어도 75% 확률로 빠진다. B의 baseline 질의에서는 신규 자료가 3위였어도 추출되지 않았다. 이는 순위와 실제 노출 사이의 손실을 설명한다. 낮은 순위의 원인이나 최종 선택의 원인까지 이 확률 하나로 설명하지는 않는다.

조회 문구도 실제 사용과 맞지 않았다. 공통 주제 질의에는 정확한 한국어 장르명 외에 컨셉·참조 이미지·테스트라는 전달 문구가 함께 들어갔다. 반면 새 자료의 검색 문장은 주로 국소적인 손·물체·자세 관계를 설명했다. 연구 문서의 장르 분류와 라우트 메타데이터는 검색 점수를 자동으로 높이지 않는다. 이전에 사용한 직접적인 기하 묘사 질의의 높은 순위는 실제 장면 질의의 발견 성능을 충분히 검증하지 못했다.

C가 실제로 읽은 신규 자료는 굽은 우산을 향한 무표정 반응과 상대 허리를 감싸는 팔의 구성이다. 원래 선택한 물방울·파라솔·냅킨 장면에는 각각의 완전한 의미가 들어가지 않았다. 그대로 채택하지 않은 판단은 이해할 수 있지만, 첫 초안에 없다는 이유만으로 가능한 대안 검토까지 생략해서도 안 된다. 작성자가 정한 장면과 사용자가 고정한 요구를 구별하고, 열린 차원에서 가능한 완성된 대안을 비교하도록 개선했다.

또한 H-F2 자료는 **창작 참고자료**다. 원래 118개에 붙인 연구상의 주체 관계와 연결 189개는 네이티브 의미·역할 증명의 승인이 아니다. 따라서 검색 등록만으로 `chosen_candidate_ids`에 넣을 수 없다. 첫 시험은 이 네이티브 선택뿐 아니라 참고자료 활용도 모두 0이었다. 세 최종 프롬프트가 각각 독립 baseline과 바이트 단위로 같았으므로, 그 이미지들을 새 데이터의 효과라고 주장할 수 없었다.

## 세 이미지가 실패한 직접 원인

| 시험 | 저장 이미지에서 확인한 결함 | 개선할 가시적 조건 |
|---|---|---|
| A | 풍성한 꽃과 여분 꽃처럼 보이는 요소가 마지막 한 송이를 다투는 상황을 약화했다. 두 사람의 즐거운 꽃 공유로도 읽혔다. | 실제 수량 제한, 반대 방향의 별도 손, 대비되는 표정, 두 접점과 얼굴의 동시 판독 |
| B | 맨 오른쪽 스케이트가 잘려 날과 얼음의 접촉을 확인할 수 없었다. | 네 스케이트·네 날·네 접촉부, 바깥쪽 얼음 여백까지 한 프레임에 포함 |
| C | 손이 조작해야 할 크랭크 대신 그 위 기둥을 잡았다. | 손잡이의 실제 접촉, 노출된 크랭크 팔, 기어박스와 기둥까지의 연속 연결 |

이는 픽셀에서 확인한 실패다. 생성기의 내부 주의 배분이나 일반적인 인물 사진 구도 선호는 가능한 설명일 뿐, 측정한 내부 원인이 아니다. 프롬프트 감사나 도구 성공을 픽셀 통과로 대신하지 않았다.

## 스킬과 데이터에 반영한 변경

스킬에는 장면의 결정적 가시적 대비와 가장 그럴듯한 경쟁 해석을 함께 검토하도록 추가했다. 장르 형용사·두 사람의 미소·장식의 풍성함만으로 희소성이나 코믹한 실수를 증명하지 못한다. 접촉 대상이 실제 조작부인지, 필요한 지지 끝점이 프레임 안에서 모두 보이는지, 얼굴 강조 때문에 손·발·장치가 잘리는지를 구도 단계에서 해결하도록 했다. 후보 검토 문서에는 노출·비교·실제 최종 활용·네이티브 선택을 따로 기록하고, baseline에 이미 있던 요소나 탈락한 대안을 채택 실적으로 세지 않도록 명시했다.

데이터에는 기존 상호작용 자료 **50개에 한국어·영어 장르 조회 문구**를 추가했다. 기존 118개의 원문 명제, 조건, 효과, 출처와 317개 라우트는 유지했다. 이와 별도로 다음과 같은 **전용 장면 템플릿이 아닌 일반 구도 참고자료 6개**를 추가했다.

| ID | 새 참고자료의 의미 |
|---|---|
| P01 | 제한된 공유 자원, 반대 방향의 접근, 구별되는 손의 주체와 반응 |
| P02 | 연결된 가시적 계기와 서로 다른 두 반응 |
| P03 | 균형 자세에 필요한 모든 지지 끝점과 그 바깥의 여백 |
| P04 | 기둥·외장과 구별되는 실제 조작부의 접촉 |
| P05 | 결정적 접점과 두 얼굴을 동시에 읽히게 하는 크기·깊이·초점 |
| P06 | 작은 실수와 유난히 태연한 표정·자세, 이를 향한 상대 반응의 대비 |

결과는 **124개 레코드 = 긍정 참고자료 105개 + 제외 진단 19개**, 실제 카탈로그에 맞는 연결 **203개**다. 기존 연결 189개는 보존했고 유효한 14개를 더했다. 존재하지 않는 역할 이름에 대한 3개 제안은 연결하지 않았다. 새 6개에는 네이티브 승인을 부여하지 않았고, 원래 특수한 구성의 완전한 계약을 일반 영감이라는 이름으로 우회하지 않았다. 채택 할당량·주제별 우대·질의 재추첨도 넣지 않았다.

## 발견과 활용을 검증하는 방법

이전 실제 질의 11회와 이미 발급된 임베딩, 같은 난수 시드로 개선 전후 인덱스를 오프라인 비교했다. 기존 검색·추출 커널에서 신규 자료의 순위 창 출현은 **9→109회**, 실제 샘플 출현은 **2→32회**였다. A/B/C별 샘플은 **0→7, 0→12, 2→13회**였다. 이는 수정에 사용한 개발 질의의 비교이며 미지의 질의에 대한 일반 성능 증명이나 이미지 품질의 인과 효과가 아니다.

재시험의 실제 작성자는 서로 독립된 새 서브에이전트 3개다. 각자 자기 장면과 닫힌 재시도 맥락만 받고 의미를 먼저 고정했다. 같은 참조 파일과 기존 설정을 유지했고, 다른 시험의 출력은 받지 않았다. 각자 실제 반환된 자료 전체와 조건을 읽고 완성된 대안들을 비교한 뒤, 최종 문구에 남은 기여만 기록했다. 각 에이전트의 이번 이미지 도구 호출 한도는 1회다.

실제 재시험 노출은 A **9개/11회**, B **6개/7회**, C **7개/8회**의 러브코미디 자료였다. 최종적으로 A는 P05 한 개, B는 P06 한 개, C는 P02와 P06 두 개를 사용했다. C의 두 출처는 **하나의 겹치는 표정 수정**을 설명하며 독립된 두 개선으로 세지 않는다. B의 지지점·여백은 독립 baseline에 이미 있었으므로 P03의 새 채택 효과로 세지 않는다. 세 경우 모두 baseline과 최종 프롬프트가 실제로 달라졌다. 네이티브 후보 선택은 여전히 0개다.

## 실행·검증 경계

시각 의미 테스트 7개와 닫힌 재시도 범위 재결합 테스트 16개를 통과했다. 원본 보존과 전체 소스·벡터·실행 폐쇄 검증도 통과했다. 재시도 도구는 이전 부모를 부모 자신의 검증된 실행본으로 감사하고, 동일한 의미 재료의 현재 요청 출처만 재결합한다. 소유자·사실·상태·완결성·참조 바이트와 기존 의무를 완화하지 않는다.

이번 개선은 공용 로컬 기본 실행본에 반영했다. 다른 작업의 동시 자료 추가도 보존했다. 세 이미지 거래는 고정 시험 실행본에 묶이고, 공용 반영본과 이번 124개 자료·203개 연결·실행 코드가 같음을 별도로 검증했다. `SKILL.md`와 연구용 의미 문서는 네이티브 매니페스트 구성원이 아니므로 별도의 작성 지침 스냅샷과 해시로 기록한다. 시험 시작 후 동시 작업이 스킬·기본 실행본을 갱신한 사실도 숨기지 않고, 이번 변경의 보존 여부를 확인한다.

B에서는 호출 전 참조 역할 문구의 확대가 닫힌 맥락과 달라 차단됐다. 기존 실행 흐름이 예전 요청을 새 매개변수보다 먼저 검증해 수정까지 막는 순서 문제가 있었다. 검색을 다시 하거나 감사·보존 조건을 낮추지 않고, 역할 한 필드만 교정한 prospective 요청에 같은 계보·구성·실행 감사를 전부 수행하고 관리 원자적 revision으로 기록하는 좁은 복구 도구를 마련했다. 원래 요청·실패 증거·고정 입력과 자료는 보존한다. 경로·해시·첨부·배경·프롬프트 변경을 거부하는 6개 회귀 테스트를 추가했고, 실행 문서에는 정확한 역할 복사와 이 복구 경계를 명시했다. 이 과정 자체는 이미지 호출을 하지 않는다.

최종 판정은 생성 전 등록한 기존 결함 기준과, 최종 활용이 확인된 새 일반 지침의 가시적 구현을 분리한다. 부분 구현은 실패이며 관찰 불가는 통과가 아니다. 세 장의 사람에 의한 정성 검토, 스킬과 데이터가 함께 바뀐 전후 비교이므로 데이터만의 인과 개선이나 통계적 일반화를 주장하지 않는다. 실제 감정·의도·관계 이력·정체성·나이는 정지 이미지로 확정하지 않는다. 사용자 수용은 직접 피드백 전까지 pending이다.
