# 아이돌물 데이터 반영 계획

## 완료 상태와 목표

현재 완료된 것은 리서치와 연구용 초안이다. 이 계획의 후속 실행 목표는 **요청자가 정한 아이돌물 의미를 바꾸지 않으면서 구체 장면 대안을 더 정확하게 찾고, 적합한 것만 선택하며, 선택한 관계가 실제 이미지에 보이게 하는 것**이다.

초안 120개를 그대로 일괄 등록하는 것을 성공 기준으로 삼지 않는다. 기존 소스와 완전히 같은 명제는 재사용하고, 의미가 다른 것은 새 소스로, 비가시 의미는 문맥으로, 근거가 부족한 것은 보류로 남긴다. 등록량은 검토 뒤 확정한다. `candidate-drafts.json`은 V3 런타임 코퍼스가 아니며 직접 manifest에 추가하면 안 된다.

## 1단계 — 기준 상태와 소유권을 고정한다

입력: `seed-keywords.json`, `CORPUS-AUDIT.json`, 현재 manifest, 현재 설치된 sealed release.

1. 구현 시작 시 branch/HEAD, manifest SHA, 모든 대상 소스·바인딩 SHA, 설치된 세대와 CURRENT를 다시 기록한다. 이번 조사 때의 source manifest와 설치된 recorder 세대는 서로 다른 증거다.
2. 현재 체크아웃에 다른 작업이 많으므로 변경 목적에 맞는 기존 격리 작업공간이 있으면 재사용하고, 없으면 구현용 작업공간을 만든다. 사용자 변경을 reset·stash·일괄 복사하지 않는다.
3. 파일 허용 목록을 작성한다. 이번 주제와 관계없는 원본 CID·바인딩·인덱스·설치 포인터가 섞이지 않게 한다. 기존 파일은 수정 전후 해시로 보호한다.
4. 기존 소스별 처분을 확정한다. `existing-source-triage.json`의 12개는 검토 시작점이며 재사용 승인이 아니다. 관련 의복·손·학교·미디어 소스를 추가로 비교한다.

산출: `BASELINE.json`, 파일 허용 목록, 비교할 기존 CID 목록, 보존 해시.

완료 조건: 모든 변경 파일의 목적이 설명되고, 하나의 CID가 하나의 payload owner만 가진다. 읽기 전용 recorder 점검 PASS를 데이터·검색·이미지 합격으로 해석하지 않는다.

## 2단계 — 원문 의미와 근거를 좁게 확정한다

입력: 325개 라우트, 120개 카드, 45개 문맥 구별, H01~H09.

- 복합어는 원문을 유지한다. `팬싸·영통 팬싸`, `왁킹·보깅`, `레더·라텍스·PVC`의 일부 구성만 확인하고 전체를 검증 완료로 표시하지 않는다.
- 출처의 실제 확인 범위와 작성자가 만든 장면을 필드로 분리한다. 모든 카드의 `source_support`는 현재 분야 맥락 수준이다. 직접 표본·문장 근거가 필요한 사실은 이 단계에서 추가한다.
- EN/KO를 대조해 인원·수·좌우·시제·부분/전체·접촉/비접촉·옷/몸·실물/표시 화면이 일치하는지 읽는다. 단순 번역 문자열 존재만으로 합격 처리하지 않는다.
- 소유자를 명시한다. 손이 잡는 물건, 마이크 그릴이 향하는 관객, 귀와 케이블과 수신기, 허리벨트와 스타킹, 실제 사람과 사진·모니터 속 인물은 각각 분리한다.
- 단일 이미지로 입증 불가한 부분은 N 카드로 남긴다. 동의·실제 연애·실력·첫 수상·회귀·원테이크·립싱크·그루밍 등은 장면의 분위기로 확정하지 않는다.
- 성인 관능의 후보는 성인 조건과 표현 범위를 정확히 보존한다. 요청에 없는 가림옷·노출 축소·전역 금지·특정 성별/체형을 추가하지 않는다. 모든 아이돌이나 연습생을 자동 성인으로 분류하지 않는다.

보류 처리: H01의 성인 패션 경계, H02의 재료, H03의 동작, H04의 일본 문화, H05의 주관적 스타일, H06의 숨은 제작 정보, H07의 시간·음성·효과, H08의 권력·건강 문맥, H09의 현행 계약은 필요한 근거를 별도 수집한다. 해당 근거가 없으면 비가시/미확인 상태가 정상 결과다.

완료 조건: 325개 각각의 상태가 `기존 재사용 / 새 가시 대안 / 문맥 / 추가 근거 필요` 중 하나 이상으로 명시된다. 120개 모두가 가시 후보로 승격될 필요는 없다.

## 3단계 — 실제 소스와 바인딩을 나눠 작성한다

예상 대상 경로는 다음과 같다. 파일명은 구현 시 충돌을 확인하고 확정한다.

| 파일 | 역할 |
|---|---|
| `skills/photo-prompt-image-generator/assets/photo_idol_fiction_semantics_20261023.json` | 연구 카드·원문 라우트·출처·혼동 경계; 연구 메타데이터 |
| `skills/photo-prompt-image-generator/assets/photo_candidate_idol_fiction_20261023.json` | 검토를 통과한 완전한 선택형 가시 소스와 제외된 문맥 진단 |
| `skills/photo-prompt-image-generator/assets/photo_candidate_idol_fiction_bindings_20261023.json` | 승인된 개별 역할 바인딩 |
| `skills/photo-prompt-image-generator/assets/photo_candidate_corpus_manifest.json` | 새 후보·바인딩 모듈만 등록; 기존 모듈 소유권 유지 |
| `skills/photo-prompt-image-generator/references/idol-fiction-semantics.md` | 의미 경계·사용 조건·증거 한계 |
| 주제별 focused 테스트/평가 파일 | 실제 새 불변조건과 의미 충돌의 검증 |

소스 계약:

1. EN/KO의 완전한 명제를 한 CID가 소유한다. 원문 전체를 짧은 태그로 치환하지 않는다.
2. intrinsic 조건·효과·의존성·선택 분기는 후보에 한 번만 둔다. 바인딩에 두 번째 효과 payload를 만들지 않는다.
3. 실제 positive field의 완전한 인용과 source-local anchors를 검토한다. source URL, 카드 ID, 그래프, 체크리스트 해시가 native fact의 근거를 대신할 수 없다.
4. 사람·의복·장비·모니터·표시 인물·전달 대상과 모든 receiver를 구별한다. 새 멤버·손·옷을 만드는 효과가 잠긴 코어를 변경하지 않는지 검사한다.
5. 복수 인원·의자·수신기·거울이 필요한 후보는 그 전제를 명시한다. 한 명 요청에 다섯 멤버 대형을 무조건 적용하지 않는다.
6. `proposed_slots` 219개는 검토 대기 목록이다. 카드의 모양이 각 역할 정의에 직접 맞는지 확인하고 부적합한 역할은 등록하지 않는다. 태그 일치만으로 바인딩을 승인하지 않는다.
7. N 카드는 positive retrieval에서 제외된 문맥/진단으로 유지한다. ‘팬’, ‘idol’ 단독 질의에 착취·범죄·질병 설명이 일반 시각 대안처럼 뜨지 않게 한다.
8. 새 장르 profile이나 하드 의무를 자동 생성하지 않는다. ‘아이돌’만으로 성별·나이·미모·관능·교복·군무·응원봉·다인원을 강제하지 않는다. 초기 의미 해석과 독립 코어의 기존 순서는 유지한다.

완료 조건: source qualification과 각 role의 검토가 따로 통과한다. 연구 메타데이터만 붙은 레코드는 native 승인으로 표시하지 않는다.

## 4단계 — 작은 묶음부터 통합한다

| 우선순위 | 대상 | 먼저 하는 이유 | 출구 기준 |
|---|---|---|---|
| P0a | I021~I022, I083~I096, I109~I110 | 팬행사·손·장치의 혼동이 구체적이고 검증 가능한 범위 | 핵심 소유자·양 종점, 한영 일치, 적합 role 통과 |
| P0b | I001~I010, I059~I082 | 제작·의복의 구조를 늘리면서 일반 소스 재사용 가능 | 기존 중복 제거, 의복 층위·지지·노출 범위 보존 |
| P1a | I011~I020, I033~I042 | 다인원·촬영·시간 경계가 복잡함 | 정지/시퀀스 구분, 인원 잠금·시점·미디어 경계 통과 |
| P1b | I043~I058, I097~I108 | 분위기 다양성을 늘리되 인물 외형 강제 위험이 있음 | 고정 템플릿·미모/나이/성정체성 추론 없음 |
| P2 | I023~I032, I111~I120와 보류 주제 | 행사·문화·버추얼·어두운 서사에 문맥 의존성이 큼 | 행사별 근거, 표시/실물 구분, 원인·동의 과장 없음 |

각 묶음마다 리뷰 결과에 따라 카드 수와 순서는 바뀔 수 있다. 일본·버추얼·성인 관능·폭력/침해 주제를 영구적으로 제외하는 순서가 아니다. 근거와 관계 복잡도에 따른 작업 순서다.

## 5단계 — 검증·검색·설치를 각각 확인한다

유지보수 지침의 현재 명령은 구현 시 같은 버전에서 다시 확인한다.

```bash
python3 skills/photo-prompt-image-generator/scripts/photo_installed_h_f2.py --check-runtime
.venv/bin/python skills/photo-prompt-image-generator/scripts/validate_photo_prompt_dictionary.py
.venv/bin/python skills/photo-prompt-image-generator/scripts/build_shared_candidate_index.py --verify
```

의미 텍스트가 달라진 실제 소스는 인덱스 갱신이 필요하다. 현재 지정된 모델 공간·문서 recipe·텍스트 hash·차원·vector integrity가 맞는 경우만 벡터를 재사용한다. 활성화할 새 인덱스를 빌드할 때는 해당 저장소의 현재 provider·네트워크·비용 권한을 확인한다. 이번 리서치는 embedding 호출을 하지 않았다.

작성 소스 검증 → source-local 의미·role 검토 → focused 회귀 → 인덱스 통계·payload/vector closure → 고정된 query로 검색 평가 → staged sealed release → 설치 코드·recorder 점검 → 새 설치 세대에서 동일 질의·guard 재확인 순으로 진행한다. 소스가 빌드 도중 달라지면 새 기준으로 재검토하며 가동 manifest를 덮어쓰지 않는다.

한글/영어 자연 질의별 후보 노출, 의미 적합성, 실제 채택, 전체 프롬프트 전송, 저장 픽셀을 별도 열로 기록한다. source 등록과 검색 recall 개선을 이미지 품질 개선으로 보고하지 않는다.

## 6단계 — 실제 이미지와 사용자 판단

[PIXEL-PLAN.md](PIXEL-PLAN.md)의 장면은 후속 실행 설계다. 현재 요청은 리서치·계획이므로 이미지 호출은 하지 않았다. 후속 이미지 검증 때에는 독립적으로 장면을 작성·고정하고 후보를 조회한다. 새 후보 채택을 할당량으로 강제하거나 테스트용 소품·인원을 코어에 끼워 넣지 않는다.

전체 장면의 인원·의복·접촉·시선·장치·매체 경계가 함께 통과해야 관계 합격이다. 작은 부분이 보였다는 이유로 전체 합격 처리하지 않는다. 필수 연결점이 가리거나 프레임 밖이면 `UNOBSERVABLE`이며 PASS가 아니다. 미학적 아이돌 인상, 기술적 관계 합격, 사용자 선호는 별도 기록한다.

## 7단계 — 공개와 복구

공개 범위의 정확한 diff와 검증 결과를 정리하고 사용자에게 검토 가능한 상태로 제공한다. 이번 요청만으로 commit·push·merge·설치 활성화를 실행하지 않는다. 후속으로 해당 행동이 승인되면 같은 행동을 다시 승인받을 필요 없이 그 범위에서 진행한다.

게시 시 이전 sealed generation과 CURRENT, 원본 CID, 보호 해시를 남긴다. 회귀가 생기면 이전 포인터로 되돌리고 새 데이터·증거는 보존한다. 생성물 정리는 참조 폐쇄와 허용 목록으로 확인하며 다른 작업의 파일을 정리하지 않는다.

최종 완료 기준: 의미/출처 검토, 소스 무결성, native 역할 검토, 양언어 검색 적합성, 잠금 보존, 설치 노출, 저장 이미지 관계, 사용자 수용 중 무엇이 실제 확인되었는지 각각 설명할 수 있다. 아직 실행하지 않은 단계에는 `not_run`을 남긴다.
