# 후속 이미지 검증 설계

아래 8개는 생성된 결과가 아니라 평가할 장면 종류다. 실제 실행 시 현재 사용자 요청·controls를 먼저 해석하고 독립 프롬프트와 코어를 작성·고정한 뒤 후보를 조회한다. 카드 사용을 강제하지 않는다. 장면에 없는 표식·테스트 문구·인원·소품을 후보 사용 증거를 만들기 위해 추가하지 않는다.

## 장면별 관찰 계약

| 장면 | 검증할 의미 | 필수 가시 관계 | 대표 실패 | 비가시 주장 |
|---|---|---|---|---|
| A. 세 멤버의 거울 연습 | 실물 인원과 반사 매체 | 실물 셋, 각 발-마킹, 대응하는 거울상과 프레임 | 거울상을 네 번째 멤버로 추가, 위치 대응 오류, 발 잘림 | 수개월 연습·실력·월말평가 주기 |
| B. 대면 사인회 | 펜·앨범·팬·아티스트 | 펜 소유자, 펼친 앨범의 접점, 탁자 양측 손 | 팬 손이 펜을 잡음, 손 겹침, 사인면 가림 | 동의·실제 친분·행사 조건의 일반화 |
| C. 공통 모티프의 무대 | 개별 의복과 팀 구성 | 선언된 멤버 수, 의복별 모티프 소유, 앞뒤 대형 | 모든 옷이 한 벌로 합쳐짐, 센터 추가·누락 | 리더·인기·최고 실력·칼군무의 타이밍 |
| D. 인이어를 확인하는 퍼포머 | 귀-장치의 경로 | 귀 안 이어피스, 귀 뒤 선, 실제 수신기 연결과 허리 고정 | 입 옆 마이크로 치환, 선 끊김, 팩이 다른 사람에게 붙음 | 라이브 가창·립싱크·신호 품질 |
| E. 성인 무대 의복의 연결 | 선택한 가터 또는 하네스 구조 | 요청에 맞는 시작점·끈·집게/버클·종점, 다른 의복과의 층위 | 무의미한 떠 있는 스트랩, 지지점 가림, 임의 가림옷·노출 변경 | 실제 구속·착취·자발성 |
| F. 버추얼 제작실 | 실물 퍼포머와 표시 아바타 | 실물 한 몸, 표시 화면 테두리, 화면 속 아바타 분리 | 아바타가 실제 두 번째 사람으로 나옴, 화면 경계 소실 | AI 자율성·실시간성·신원 동일성 |
| G. 투샷 체키를 든 손 | 실제 손과 사진 내부 인원 | 실제 손 소유, 종이 테두리, 인쇄 영역 안 두 인물 | 인쇄 얼굴이 실제 얼굴로 돌출, 현장 사람을 불필요하게 추가 | 실제 연애·행사 참여 권리·인지 |
| H. 통제 경계의 갈등 | 문턱·경호원·밖 인물·안쪽 퍼포머 | 양측 공간, 경호 손의 방향, 안쪽 인물 거리 | 손 소유자 이동, 인물이 문에 합쳐짐, 물리 경계 불명 | 반복 스토킹·공격 의도·실제 범죄 판정 |

E는 한 이미지에 모든 의복을 넣는 시험이 아니다. 가터와 하네스는 별도 대안 또는 별도 프레임으로 평가해, 작은 접점이 서로 가려지는 문제를 통제한다. C도 멤버 수와 대형은 독립 요청에서 정해진 것을 따른다.

## 정지·시간 평가의 분리

한 장의 사진은 엔딩의 시간적 위치, 실제 떼창, 정확한 군무 타이밍, 리플 시작 순서, 바디롤·트월킹의 경로, 원테이크, 립싱크를 증명할 수 없다. 이들은 영상 또는 시퀀스가 별도로 요청되고 확보될 때 검증한다. 여러 생성 프레임의 일관성이 실제 연속 촬영 이력까지 증명하는 것도 아니다. 시간 비교에서는 각 프레임의 인원·의복·카메라·매체 경계를 먼저 확인한다.

## 판정 기록

각 필수 관계는 `PASS / FAIL / UNOBSERVABLE`로 기록한다. 전체 합격은 모든 필수 관계가 PASS일 때만 가능하다. 가림·크롭·해상도 부족으로 필수 장식석·집게·이어피스가 확인되지 않으면 UNOBSERVABLE이며 전체 관계는 통과하지 못한다.

먼저 저장 이미지를 평소 감상 크기로 보고 장르 인상·장면 정보·인물 매력을 서술한다. 이후 원본 크기와 필요한 crop으로 관계를 검토한다. 원본을 확인하지 않고 prompt literal·pack·해시만으로 픽셀 합격을 기록하지 않는다. crop에서만 보이는 작은 요소와 전체 장면에서 읽히는 요소를 따로 표시한다.

아래 여섯 결과를 분리한다.

1. 신규 소스가 자격 검토를 통과했는가.
2. 설치된 세대의 검색에서 노출되었는가.
3. 작성자가 코어에 맞아 실제로 선택했는가.
4. 전체 literal과 참고 입력이 실제 도구에 전달되었는가.
5. 저장된 이미지가 필수 관계를 모두 보이는가.
6. 사용자에게 매력적이고 적절한 결과인가.

모델의 차단·오류·누락·부분 실패는 그대로 기록한다. 재시도는 그때 적용되는 스킬·도구의 절차와 현재 권한 범위를 따르며, 실패를 데이터 등록 성공으로 상쇄하지 않는다. 이번 리서치의 이미지 호출 수는 0이다.
