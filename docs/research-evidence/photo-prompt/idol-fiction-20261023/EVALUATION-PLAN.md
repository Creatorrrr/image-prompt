# 의미·검색·회귀 평가 계획

현재 `evaluation-cases.json`의 76개는 모두 **이번 연구자가 작성한 개발용 평가 설계**다. 검색·native 검증·이미지는 실행하지 않았다. 개발 사례를 독립 holdout으로 부르지 않는다.

| 종류 | 수 | 목적 |
|---|---:|---|
| 한글/영어 자연 질의 | 40 | 서로 대응하는 20쌍에서 의미 적합성과 양언어 접근 확인 |
| 혼동·부정 조건 | 20 | 나이·직책·사생활·질병·재료·동의·성공·매체 소유 추론을 차단 |
| 시간·비가시 문맥 | 8 | 정지 대리물이 시간·음성·권한·반복성의 증거가 되는 오류 확인 |
| 복합 장면 | 8 | 손·장치·의복·매체가 결합할 때 모든 관계를 함께 보존 |

## 데이터 무결성 검증

325개 원문 용어의 보존과 각 route의 처분, 카드 ID·출처 ID·문맥 ID의 유효성, 한영 명제, 원문 설명과 창작 예시의 분리, 각 CID 단일 소유권, 문맥의 positive 제외, 실제 source guard/효과/role 검토 상태를 검사한다. `validate_research.py`의 PASS는 **연구 파일의 참조·구조·상태표시**만 검증한다. 자연어 의미·출처의 진실·native 자격·이미지 품질은 수작업과 별도 평가가 필요하다.

## 기존 소스 회귀

일반 교복/프레피, 스포츠 저지, 패션 하네스, 종교적 idol, 무대 밖 통신용 헤드셋, 귀 장치 없는 성인 포트레이트, 비인간·무인 장면, 실제 사진과 그려진 얼굴이 함께 있는 요청을 통제군으로 둔다. 공통 단어가 있다고 아이돌 태그·성인 조건·다인원·군무·화장·응원봉을 끼워 넣지 않아야 한다.

반드시 확인할 잠금은 인원, 나이·주체 범주, 얼굴/참고 범위, 의복 층위·노출, 손의 소유자와 물건, 좌우·방향, 접촉/비접촉, 실제 공간과 표시 매체다. 신규 후보에 필요한 전제가 빠지면 discovery·review 상태로 남기거나 채택하지 않는다. source guard를 충족하지 못한 같은 역할을 unbound 제안으로 우회하지 않는다.

예: I083은 오른손 하트이고 I096도 오른손 마이크다. ‘마이크와 다른 손 하트’ 요청에서 두 완전 명제를 그대로 동시에 채택하면 충돌한다. 손을 임의로 바꾸어 기존 literal을 채택했다고 기록하면 안 된다. 적합한 별도 대안을 선택하거나 새 완전 소스를 검토해야 한다.

## 검색 평가 프로토콜

1. baseline과 변경 release의 source/index/generation, embedding model space와 recipe를 고정한다.
2. 같은 요청·controls·독립 코어·query 의미를 사용한다. 테스트 전에 코어가 신규 후보를 보고 특정 literal을 요구하도록 바뀌지 않게 한다.
3. 한국어와 영어는 각각 실제 질의 임베딩·BM25F·cosine·RRF 증거를 보존한다. 영어 의미를 한글 alias만으로 대신 검증하지 않는다.
4. top-10과 top-20을 직접 읽어 관련성·역할 적합성·전제·잠금 충돌을 판정한다. 새 카드 ID의 등장만을 성공으로 세지 않고, 의미가 같은 기존 적합 소스도 정답 집합에 포함한다.
5. source 후보 발견, 역할 제안, guard 통과, 실제 선택을 분리한다. 발견된 부적합 후보를 선택하지 않은 것은 guard 성공일 수 있으며 검색 precision과 섞지 않는다.
6. 사례별로 기대 소스가 왜 맞는지·어떤 소스가 왜 틀리는지 문장을 남긴다. 세부 출처가 held인 의미를 gold positive로 올리지 않는다.

권장 측정 열: `request_hash`, `core_hash`, `release_id`, `language`, `slot`, `candidate_id`, `rank`, `source_eligible`, `role_review`, `relevance`, `lock_conflict`, `selected`, `literal_transport_verified`, `pixel_result`.

초기 목표는 아래와 같이 제안하며 baseline 분포와 적합한 gold 집합이 확보된 뒤 고정한다. 현재 달성했다는 뜻이 아니다.

- 의미 적합한 선택 대안이 존재하는 개발 질의의 Recall@20 ≥ 0.85.
- 역할 제안 단계에서 수작업으로 판단한 Precision@10 ≥ 0.80.
- 한글·영어 paired query의 recall 격차 ≤ 10%p를 검토 목표로 사용. 작은 표본의 변동도 함께 보고한다.
- 잠긴 수·좌우·의복·나이·매체·동의 사실을 위반하는 **최종 채택**은 0건.
- 문맥 진단을 가시적 효과 소스로 최종 채택하는 사례는 0건.
- 위 성능을 개선하더라도 일반 통제군에서 의미 오염이 증가하면 묶음을 축소해 재검토한다.

## 독립 holdout 확보

실제 통합 전, 카드 literal과 개발 query를 보지 않고 작성된 새 요청 24개 이상을 별도로 고정한다. 한글/영어, 단일/다인원, 의복/행동/매체, 자연어 부정·조건을 포함하고 평가자·작성 시점·hash를 남긴다. 독립 작성 근거가 없으면 `fresh_queries_same_author`라고 부르고 blind holdout으로 보고하지 않는다. holdout 결과를 보고 후보·query를 고친 뒤 같은 결과를 새 holdout 성공으로 재사용하지 않는다.

## 이미지 평가로 넘어가는 기준

소스와 설치 검색이 통과한 묶음만 [PIXEL-PLAN.md](PIXEL-PLAN.md)의 후속 실행 대상으로 삼는다. 이미지 생성은 별도 요청 범위에서 수행한다. 새 후보 노출·채택·prompt transport·실제 픽셀은 각각 따로 보고하며, 가려진 필수 관계를 부분 PASS로 승격하지 않는다. 사용자 선호와 장르 인상도 기술 합격과 별도로 기록한다.
