# 파일럿에서 보정한 의미 판정 규칙

검토자는 Codex다. 후보를 먼저 읽고 개별 TSV에 판정을 작성했다. 기존 태그·문자열 포함·BM25F·cosine·native fit으로 승인 슬롯을 생성하지 않았다. 재검토도 같은 검토자의 원문·경계 재독이며 독립된 인간 전문가 심사로 계산하지 않는다.

1. 후보 본문 전체의 실제 의미를 읽고 소유자·속성·관계가 있는 역할을 승인한다. 프로필·묶음은 자기 완전한 의미를 심사한다. 하위 후보의 태그를 합집합으로 복사하지 않는다.
2. 후보 수나 태그 수를 채우는 기준을 두지 않는다. 하나의 역할만 있으면 하나를 유지한다. 넓은 관련성, 메타데이터 차원 교집합, 높은 검색 순위는 직접 역할 근거가 아니다.
3. `or`, 조건부 절, `minimum_realizations`, 선택된 예, 이미 정한 값의 보존, 필수 적용 전제를 구분한다. 승인된 역할은 원문 전체의 대안·조건을 보존한 연관이다. 모든 역할이 한 분기에서 동시에 존재한다는 뜻이 아니다. 5단계에서 분기별 소유 효과와 role 조건을 구현·검증한 뒤 6단계에서 적용한다.
4. 시선 방향, 명명 시선 대상, 눈맞춤·이탈, 머리·몸 방향, 눈의 모양을 독립적으로 본다. 감은 눈·머리 회전만으로 눈 방향을 정하지 않는다. `gaze_direction`을 추가했다.
5. 손톱·발톱 판의 모양·마감·색은 피부 문양이나 손 관절 자세가 아니다. `nail_appearance`를 추가했다. 임상 상태·나이·정체성은 추정하지 않는다.
6. 얼굴 이외 신체의 국소 부피·윤곽·근육·힘줄 형태는 부위 이름·연결 구조·상대 비율·자세·옷 부피와 독립적이다. `body_form`을 추가했다. 제작물 안에 그려진 몸은 그 제작물의 표현 대상에 귀속한다.
7. `skin_tone`은 같은 피부 부위의 색을 다룬다. 선언된 조명·화이트밸런스 기준 아래의 보이는 색도 허용하지만 그 색으로 고유 색소·민족·정체성을 역추정하지 않는다. 화장·그레이딩·피부색 안감은 별개다.
8. 물리 표면, 대기 물질, 렌즈·필름 형성 효과, 신호·복제 흔적을 구분한다. 신호 dropout을 테이프의 물리 표면 손상으로 옮기거나 사진 veil만으로 물리 안개를 추가하지 않는다. soft light bloom은 실제 광질의 부드러움과 다르다.
9. 반사, 투과, 그림자는 서로 다른 광학 관계다. 반사 대응이 없는 양방향 거울 장치 POV를 reflection으로 바꾸지 않는다. 그림자 형태만으로 실제 입사 방향을 정하지 않는다.
10. 명시 성인·생활 맥락과 성적 표현·fetish styling을 구분한다. 소재·속옷 모양·신체 노출만으로 성적 맥락을 추가하지 않는다. 성인 및 human 전제는 canonical/profile/member 조건에 그대로 남긴다.
11. 문화·행사·시대·세계·서사·정서를 분리한다. 시장·지역 이름으로 의상·민족·건축을 발명하지 않는다. 과묵함·표정으로 실제 성격이나 관계를 진단하지 않는다. 관계 개념의 requester 우선·retrieval only 계약을 보존한다.
12. 진단 음성 예의 얼굴·소품·행동을 긍정 후보로 추출하지 않는다. 구체 긍정 값이 없는 guard·router·조율 규칙은 진단 분류 전환안으로 기록한다. 이번 6개 전환안은 아직 운영에 적용하지 않았다.
13. 묶음의 동시 실현과 대안을 구분한다. 드레스의 분홍 시스와 버스티에의 누드 저지를 한 옷에 합치지 않는다. 개별 원전·조건·참조를 보존한 완전한 대안 한 개를 선택한다.
14. 한 프레임의 시점도 일치시킨다. 잔이 받침에 놓인 상태와 공중에서 내려오는 상태를 동시에 강제한 구성은 받침에 막 닿는 순간으로 보정한다. 일반 참조 후보의 더 넓은 뜻을 무조건 좁히지 않는다.

`REVIEWS.jsonl`은 원본·검토 의미 hash, 출처, 조건, 효과, 참조, 개별 결정 파일·행, 유지·추가·제거·거부 판정, positive field 발췌와 native fit 진단을 기록한다. field 발췌는 의미 검토의 원문 대조 자료이며 태그 승인 알고리즘이 아니다. 구체 전체 원본은 `SAMPLE.jsonl`과 `SUPPLEMENT.jsonl`에 있다.

`CORRECTION-PROPOSALS.json`은 정확한 변경 전후 레코드 11개를 고정한다. source shape·참조 검증을 통과했지만 분기 선택·효과·구성의 runtime 검증과 실제 적용은 5단계에서 수행해야 한다. 운영 candidate 본문·조건·효과·영속 연결은 이번에 바꾸지 않았다. 검색·인덱스 검증은 의미 심사·생성 픽셀 품질의 점수가 아니다.
