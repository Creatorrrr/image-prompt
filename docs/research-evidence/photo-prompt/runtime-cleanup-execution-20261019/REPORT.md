# bytecode·구 shard 추가 정리 결과

2026-10-19 · 8단계 완료 · 운영 H 단독+F2 및 기존 CURRENT 유지

## 실제 정리 결과

| 대상 | 정리 수 | 원래 파일의 논리 크기 |
|---|---:|---:|
| 정확히 재생성한 bytecode | 45파일 | 510,854 bytes |
| 1차 구 shard | 6세대 / 4,327파일 | 744,888,835 bytes |
| 2차 구 shard | 2세대 / 1,443파일 | 199,550,435 bytes |
| 합계 | 8세대 + bytecode / 5,815파일 | 944,950,124 bytes (약 945MB) |

이번 대상 45개/8세대는 모두 검증을 통과해 정리했으며 추가 DEFER는 0건이다.
같은 파일시스템의 작업 전용 경로로 먼저 격리하고, 원래 경로가 없는 상태에서
검사를 통과한 뒤 해당 격리본만 제거했다. 3개 격리 디렉터리는 모두 없어졌다.
정확한 파일별 원래 경로·SHA·권한은 TARGETS.json.gz와 RESTORE-LOCK.json.gz,
이동·검증·삭제 순서는 JOURNAL-04/05/06.json, 완료 목록은 REMOVED.json에 있다.

약 945MB는 원래 경로에서 제거한 파일의 논리 크기다. Git 이력과 과거 실행에
필요한 봉인 복사본을 보존했으므로 실제 물리적 확보 공간을 뜻하지 않는다.
복원 근거·보호 기준선·검사 증거가 추가됐으며, 7단계까지 추적 트리의 논리 크기
변화는 -933,952,059 bytes다. 마지막 리포트·안내 문서는 이 수치에 추가된다.
Git 이력 재작성·prune·GC는 하지 않았다.

  원래 수정 176개와 미추적 작업을 커밋에 섞지 않았고 stash/reset/clean하지 않았다.

  `6235873c869b…`, `85e3161b28b0…`, 롤백용 `89b2a0e79319…` 등 5세대

- 공용·유지보수 모듈 4개, 기존 아카이브와 원문·카탈로그·슬롯 binding·리뷰·판정,

## 복원 수단

shard는 Git commit/blob과 보존된 봉인 세대의 동일본을 각각 이용해 5,770개
전체를 오프라인 복원했다. 원래 상대 경로·bytes·권한을 고정했고 복원 시 기존
경로를 덮어쓰지 않는다. 약 944MB를 새 보관물에 중복 저장하지 않았다.
Git 객체가 없는 경우 자동 fetch하지 않으며 네트워크도 차단한다.

bytecode는 현재 소스 35개와 기존 실험 아카이브 소스 10개로 재생성했다.
Python 3.12.13에서 35개, 3.14.3에서 10개의 전체 bytes가 일치했다. 임시 소스
복사본에만 원래 header의 mtime을 적용했다. 작은 BYTECODE-RECOVERY.zip
261,543 bytes와 lock을 추가하여, 이후 과거 interpreter가 없더라도 원래 cache
bytes 자체를 복원할 수 있게 했다. 캐시 본문은 실행하지 않았다.

공통 positive 풀은 18,180 CID/18,182 RID, 실제 슬롯당 BM25F 1회·local cosine
1회, F2/RRF10/top8/CID 중복 제거를 유지했다. main source/code/model 지문도
정리 전과 같다. 실제 설치 코드의 두 질의는 원래 issued 점수·전체 순위와
정확히 비교했으며 일반 CLI도 기존 결과를 재현했다.

`a1f199…`는 저장된 lexical 384개·cosine 384개·RRF 689개가 정확히 일치했고
pruning 감사도 통과했다. 여기의 RRF30은 과거 실행 재현 조건이며 현재 운영은
RRF10이다. `f82ab4…`는 저장된 dense 상위 10개 ID·대상 순위 1위가 같았고
점수 차이는 사전에 고정한 절대 허용 오차 1e-12 이내였다. 새 판정은 하지 않았다.

validator는 원래 shard·연구 checkout 읽기를 차단한 임시 복원 트리의 봉인
코드로 payload·binding·벡터·routing·postings를 다시 검증하고 과거 qualification과
비교했다. hash만 일치한다는 이유로 재현을 통과 처리하지 않았다.

기본/권한/native, 실제 설치, 일반 CLI, archive 재현의 네트워크 및 원본 프로젝트·
운영 store 쓰기를 OS sandbox로 차단했다. 일반 CLI의 store/run과 모델 검증용
복사본은 독립된 임시 경로에 두었다. 원본 CURRENT 변경은 0회이며 테스트용
임시 fixture의 pointer 생성과 구분한다. Gemini·새 임베딩 추론·이미지 호출·새 의미
판정은 모두 0회다. 기존 실험의 HOLD 판정도 그대로 재현했다.

이 결과는 지정한 회귀·복원·저장 질의 검사의 성공이다. 모든 역사 CLI, 새 요청의
검색 의미 품질이나 생성 이미지 품질을 전수 검증한 것은 아니다.

## 복원·재검사 안내

실제 명령과 경로는 같은 디렉터리 README.md를 따른다. 복원은 아직 없는 임시
루트에서 실행하며 현재 스킬 경로·선택된 세대·CURRENT를 교체하지 않는다.
과거 validator 재실행은 이미 있는 결과를 덮어쓰지 않는 새 label을 사용한다.
완료된 freeze/prove/GC 단계를 다시 실행해 삭제 수를 중복 집계하지 않는다.
