# Gaslamp native pixel 검토 계획

상태: **NOT_RUN**. 이미지 API 호출·프롬프트 실행·픽셀 검토를 수행하지 않았다.

## 비교 설계

12개 군마다 새 요청과 후보 독립 core를 먼저 동결한다. 각 군 내부의 A/B/C는 같은 core/controls를 사용한다.

- A: 후보 보강 없는 기본 core.
- B: 조사 기준선의 기존 source에서 실제 검색/선택한 보강.
- C: 검토·등록된 Gaslamp 확장 source에서 실제 검색/선택한 보강.

최초 비교는 **12×3=36장**이다. 생성의 비결정성을 고려할 때 한 장씩의 비교는 실패 발견용이며 통계적으로 우월함을 입증하지 않는다. 반복은 원인 분석이 필요한 군만 새 번호로 계획한다. 다른 군의 저술 결과를 초기 core에 재사용하지 않는다. 특정 후보가 core의 열린 차원과 맞지 않으면 거절하고 그 거절을 실패나 개선으로 꾸미지 않는다.

| 군 | 핵심 | 대상 카드 | 반드시 볼 관계 |
|---|---|---|---|
| P01 | 가스등/점등 | G03/G05 | 광원-버너-하우징, 성인-봉-개구부 접점 |
| P02 | 제조/저장 기능 구분 | G06/G07 | 먼저 한 실현을 선택; 배관 양끝과 실제 기능 경계 |
| P03 | 의복 실루엣 | G27/G28 | 한 실현을 선택; 둘레 확장과 착용자 후방 돌출을 구분 |
| P04 | 샤틀렌 | G33 | 같은 허리-걸쇠-체인-도구 |

P02/P03처럼 두 대안을 다루는 군은 촬영 전에 한 구체 실현을 고정하고 A/B/C를 맞춘다. 나머지 대안도 qualifying하려면 별도 군·예산·출력 증거가 필요하다. 한 이미지로 서로 다른 변형을 모두 통과시켰다고 보고하지 않는다.

## 출력별 검토 기록

`case/core/controls/source/index/CID/RID/hash → selected literal evidence → final prompt/transport hash → provider result → saved original image → gate review`

1. **component:** 물건·부품·소유자가 실제로 보이는가.
2. **relation:** 관계의 양끝과 접점·경계·연속성이 같은 프레임에 보이는가.
3. **identity/medium:** 실물/모형/사진 속 상/반사상/가상 신체를 혼동하지 않았는가.
4. **whole scene:** 선택 실현의 필수 관계가 모두 성립하는가. `partial_is_fail`.
5. **claim limit:** 동의·생사·성분·법·원인·소리·시간·정체를 픽셀로 과잉 판정하지 않았는가.
6. **artistic judgment:** 요청 의미·장면의 납득·시선의 중심·과밀 여부를 별도로 기술한다. 기술 gate만으로 사용자 수용을 판정하지 않는다.

보이지 않는 것은 성공으로 추정하지 않는다. `UNOBSERVABLE_NOT_PASS`; 애초 픽셀로 답할 수 없는 질문은 `BLOCKED_UNSCORED`다. component 성공률·relation 성공률·완전 scene 성공률을 따로 보고한다. 기술적 생성 성공은 의미 구현 성공과 다르다.

현재 36장 중 생성/평가한 이미지는 **0장**이다. 연구 카드에 gate가 있다는 이유로 native 픽셀이 통과한 상태는 아니다.
