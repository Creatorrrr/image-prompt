# 캐릭터 외형 100개 반영 후 이미지 재검증

사용자의 “아까 테스트한 방식과 같은 방식으로 다시 테스트해줘”에 따라 이전의 독립 3개 에이전트 방식을 반복한다. 원본 첨부 사진 하나를 모든 실행에 실제로 전달하며, 각 실행의 컨셉·개별 외형 선택은 에이전트 소유다.

1. 각 에이전트가 독립 난수 시드와 복잡한 사진 컨셉을 결정한다. 원본 요청 봉투를 변경하지 않는다. 스킬의 허용된 중립 카탈로그·창작 설정·참조 픽셀만 사용해 사전 코어를 고정하고 검증한다.
2. 고정 후 현재 데이터로 후보팩을 1개 생성한다. 일반 슬롯 후보와 시각 의미 후보의 노출, 선택, 최종 프롬프트 증거를 구분한다. 선택된 시각 의미는 전체 선택 의무와 픽셀 기준을 따른다. 코어에 적힌 자유 표현만으로 시각 의미 후보가 자동 발견됐다고 추정하지 않는다.
3. 프롬프트·실행 요청을 검증하고, 세부 외형의 구성 요소·관계·소유자·혼동 경계·가시성 기준을 이미지 생성 전에 고정한다.
4. 각 실행은 image_gen 내장 도구를 1회 호출한다. 재시도·CLI/API 대체·다른 실행 결과의 입력은 사용하지 않는다. 원본 이미지, 정확한 프롬프트·부정 표현·도구 인수, 해시, 실행 기록을 보존한다.
5. 각 실행의 자체 리뷰와 조정자의 원본 픽셀 대조를 구분한다. 필요한 모든 구성 요소가 같은 소유자에서 보여야 통과한다. 일부 구현은 실패이며, 필요한 부분이 가려지면 확인 불가로 남기고 통과시키지 않는다. 생성이 차단된 실행은 시각 점수의 분모에 넣지 않는다.
6. 데이터·인덱스, 후보 노출, 후보 선택, 프롬프트·실행 검증, 픽셀 결과와 사용자 선호 판단을 구분해 보고한다. 사용자 승인은 아직 받지 않았다. 서로 다른 장면 3개는 동일 장면의 이전 데이터 대비 개선량을 증명하는 대조 실험이 아니다.

실행 중 레지스트리·인덱스·생성기·설정·중립 카탈로그 파일 해시를 고정한다. 이 요청에서는 데이터 수정·커밋·푸시를 수행하지 않는다.
