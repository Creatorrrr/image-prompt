# 실제 이미지 비교 계획 — 미실행

상태: `NOT_RUN`. 이 문서는 후속 생성·평가 설계이며 이미지 호출 권한·실행·품질 승인 기록이 아니다. 이번 작업에서는 이미지·임베딩 모델을 호출하지 않았다.

## 비교 arm과 통제

각 군에서 하나의 독립 요청과 resolved creative controls를 먼저 정한다. 장르 단어 유무와 관계없이 요청 전체 의미를 이해해 완전한 장면을 저술하고, 후보를 읽기 전에 core/intent lock을 동결한다. 요청·인물·매체·카메라·출력 크기·모델/버전·후처리를 동일하게 유지한다. 연구자가 후보를 저술한 사실은 기록하고 독립성이 검증됐다고 과장하지 않는다.

| arm | 내용 | 확인할 질문 |
|---|---|---|
| A | retrieval 없이 독립적으로 완성한 장면 | 데이터 없이도 성립하는 기준 장면은 어떤가 |
| B | 같은 frozen 의미에서 현행 corpus를 사용한 장면 | 기존 자료만으로 필요한 관계가 가능한가 |
| C | 같은 frozen 의미에서 검증된 보강 source도 선택 가능한 장면 | 새 자료가 실제 선택되고 프롬프트와 픽셀에 유용한 차이를 만드는가 |

A의 프롬프트에서 이미 같은 관계를 완전히 구현한다면 C가 새 후보를 선택했어도 데이터 기여가 입증된 것은 아니다. B와 C의 후보 노출·선택·거절 및 실제 source/RID를 남긴다. 세 arm은 새로운 세부를 의무적으로 같은 수만큼 추가하는 실험이 아니다. 후보를 모두 거절하는 선택도 유효하다. 생성의 확률성과 장면 재구성 차이가 있어 1장씩의 초기 비교를 인과 효과의 통계적 증명으로 해석하지 않는다.

## 우선 12군과 필수 확인점

| 군 | 대표 실현 | 픽셀에서 필요한 증거 | 실패·판단 경계 |
|---|---|---|---|
| A | A03 주둥이–물–고리–컵 | 시작점·중간 전이·고리·컵의 위치·연속성 | 물과 사슬을 별개 소품으로 배치하면 실패 |
| B | B02 손–거울 불일치 | 같은 오른손, 펼친 손/쥔 상, 거울 경계 | 다른 인물의 손이나 잘린 거울은 미확인 |
| C | C03 등관–외투 구멍–천장 릴 | 같은 착용자, 구멍 둘레, 소켓/릴 양끝, 관 통과 | 옷 위에 얹힌 관·한쪽 끝 가림은 실패 |
| D | D02 두 단말–Y 선 | 한 Y자 선의 양 갈래가 두 실제 포트에 각각 닿음 | 중간 단절·단말 수 변화는 실패. 공동 의식은 평가하지 않음 |
| E | E05 유기적 벽의 패치 수선 | 손–패치 접촉, 벽의 형태, 경계·고정점 | 피부 치료로 치환되거나 패치가 떠 있으면 실패 |
| F | F03 문자 홈–도선–두 단자 | 같은 판, 도선 경로·양끝·단자 | 빛나는 문자만 있으면 실패. 주문 효과는 문맥 |
| G | G03 작업자–기둥 | 같은 바닥과 두 접지, 상대 규모 | 원근/가림으로 크기 비교가 불가능하면 미확인 |
| H | H01 같은 방의 모형 | 실제 방/모형의 구분, 창·탁자의 배치 대응 | 일반 미니어처만 있으면 실패. 무한/메타렙시스는 미입증 |
| I | I04 두 외피–공유 막 | 두 다른 개체, 막의 양 edge, 각 접합의 연속 | 단순 겹침·한쪽 접합 가림은 실패 |
| J | J06 소매–가시 | 천의 걸림·당김, 피부와 가시 사이 틈 | 신체 관통으로 바꾸면 요청/후보 의미 위반 |
| K | K05 두 성인–한 원판 | 각자 손의 소유, 단일 원판, 양쪽 접촉 | 원판 중복·손 융합 실패. 합의/기억 융합은 판단하지 않음 |
| L | L05 두 성인–기록함 | 한 함의 바닥 지지와 손잡이 잡기, 두 손의 소유 | 떠 있는 함·한 사람 손으로 합쳐짐 실패. 상속 성립은 문맥 |

초기 제안은 12×3=36장이다. 왜상의 각도 의존성을 평가하려면 B04에서 정렬 시점과 비정렬 시점을 별도 생성/관찰해야 하며 이 추가 컷은 36장에 포함하지 않았다. 시간적 전이·움직임·소리는 정지 이미지로 PASS 처리하지 않는다. 실제 모델이 seed를 지원하지 않으면 seed가 통제됐다고 보고하지 않는다.

## 판정 기록

각 결과에는 exact request/core/controls/pack/source/RID/prompt/runtime hash, 원본 파일 경로·해시·해상도·생성 요청 ID, 모델과 실행 결과, 전체 이미지와 필요한 확대 위치를 기록한다. 원본 픽셀을 확인하지 않고 프롬프트·썸네일·모델 자기평가만으로 구현됐다고 판정하지 않는다. 오류·차단·미생성은 별도 실행 결과로 보존하며 다른 의미의 요청으로 몰래 대체하지 않는다.

`component_gates`와 전체 긍정 문장의 **재료·개수·부위·같은/다른·자세·안/밖**까지 검사한 뒤 모든 `render_gates`의 방향 관계를 본다. 순수 관계 그래프만 맞아도 원문 속성이 틀리면 전체 실패다. 세부 판정은 PASS/PARTIAL/FAIL/UNOBSERVABLE이며 PARTIAL과 UNOBSERVABLE은 필수 조건의 성공으로 합산하지 않는다.

기술적 관계 구현과 별도로 전체 장면의 전달력·시선 흐름·불필요한 복잡성·사진적 재질과 조명·의도한 긴장을 평가한다. 가능하면 arm 표기를 가린 별도 리뷰를 사용한다. 기술 PASS는 사용자 수용과 같은 상태가 아니다. 첫 비교에서 C의 선택·프롬프트·픽셀 중 어느 단계에서도 개선이 관찰되지 않으면 데이터 기여는 미입증으로 남긴다. 실패군에서만 원인을 고친 뒤 필요한 비교를 반복하고 실패 결과도 분모에 남긴다.
