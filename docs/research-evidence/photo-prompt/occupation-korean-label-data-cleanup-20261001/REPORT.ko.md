# 직업 피사체 한국어 라벨: 항구의 어부 1행 채택

## 채택과 보류

5개 직업 행의 `ko`가 영어 문장 그대로인 문제를 검토했다. 5개 번역은 모두 원문에 충실했지만, 검색 영향까지 검증한 뒤 `harbor_fisherman` 한 행만 채택했다.

- 채택: `동틀 무렵 항구에 있는 어부`
- 보류: 용접공, 자동차 정비공, 논에서 일하는 농부, 대장장이의 정확한 번역 4개
- 보류 이유: 번역 오류가 아니라, 해당 번역을 포함한 문서 벡터가 무관한 직업 검색에 더 가까워지는 측정된 tradeoff

원안에서는 대장장이가 정비공 near-miss의 dense 순위에서 23→7, 36→10으로 올라갔다. 정비공·농부·용접공에서도 역방향 변화가 있었다. 정비공 영어 양성의 lexical 순위도 16→19로 내려갔다. 네 행과 벡터를 baseline 그대로 복원하니 모두 해소됐다. 사용하지 않는 원안 벡터와 결과는 그대로 보존했다. 정확한 번역을 나쁜 번역으로 분류하지 않았으며, 반복적인 표현 다듬기나 검색 로직 확장으로 결과를 맞추지 않았다.

최종 데이터 변경은 어부 행의 `ko` 한 값뿐이다. 원래 항구·동틀 무렵이라는 조건과 모든 영어 문구·태그·가중치·human 적용 조건을 보존했다. 다른 네 직업의 한국어 라벨 공백은 아직 해결되지 않았다.

## 고정된 이중언어 진단

영어·한국어 각각 양성 5개와 near-miss 5개, 총 20개를 편집 전에 고정했다. 원안과 채택안의 모든 결과를 보존했다.

- Dense: 양성 10개 모두 1위 유지, near-miss 10개도 baseline 순위와 동일
- Korean lexical: 항구 어부 양성 q11이 no hit→1위
- English lexical: 항구 어부 near-miss q10이 18→26위
- 그 밖의 lexical target 순위는 baseline과 동일
- Dense 상위 5개 ID 순서는 20개 모두 baseline과 동일
- Lexical 상위 5개 변화는 q11에 올바른 어부 행이 1위로 들어간 경우뿐

강가의 취미 낚시꾼 near-miss에서는 어부 행이 dense 2위에 남는다. 장소·시간 차이를 검색이 완전히 구분한다는 주장은 하지 않는다. 작성된 소규모 이중언어 진단이며, 독립적인 언어 일반화 또는 렌더링 품질 증거도 아니다.

## 로컬라이제이션과 V6 표현

`localize`와 중간 후보 요약은 한국어 라벨을 반환한다. 현재 V6는 `label_en`/`label_ko`를 그대로 노출하지 않고, 두 라벨에서 순서 없는 `concept_terms`를 만든 뒤 라벨 필드를 제거한다. 최종 어부 행은 기존 영어 용어 6개를 모두 보존하고 한국어 용어 5개를 더한다. 20개 제한 안에 들어가므로 기존 용어가 잘려 나가지 않는다. 영어 semantic description도 정확히 이전과 같다.

## 검증과 남은 실패

독립 read-only 검토가 실제 한 행 변경, 10,173개 baseline 벡터 재사용과 새 벡터 1개, bundle 무변경, 모든 120개 baseline/proposal/accepted method-query 결과 행을 확인했다. 저장된 25개 입력·시도와 생성 문서 벡터 5개는 모두 유지했다.

- DATA/background 141개 및 effect/bundle/profile 40개: 총 181개 통과
- 추가 기존 role/projection 검사 11개: 10개 통과, 1개 기존 실패
- 기존 실패는 지역 평판 검색의 social-recognition 후보가 요구한 top6 대신 7위에 있는 경우다. 수정 전후 3개 고정 query 모두 top12 ID 순서가 같고, 수정 전에도 동일하게 실패함을 독립적으로 재현했다. 기대값을 바꾸지 않았다.
- 이 결과를 전체 저장소 테스트 통과로 표현하지 않는다. 실패 로그와 baseline 비교 JSON을 보존했다.

25회가 각 한 번 성공했으며 추가 API 시도 비용 상한은 $0.04096, 추적 누적 상한은 $1.0911744다. 4개의 미채택 문서 벡터도 비용에서 빼지 않았다. 청구서 실측은 아니며 별도 upstream 비용은 대조하지 않았다.

최신 main pull 이후 검사와 정상 push/remote 확인은 별도 publication 단계다. 이 사이클의 publication commit checkout에서 `replay_acceptance.py`를 실행하면 API 없이 세 상태와 현재 index를 검증한다. 원래 `dense-final.json`/`lexical-final.json`은 5개 원안 결과이며, 실제 채택 결과는 `dense-accepted.json`/`lexical-accepted.json`이다.
