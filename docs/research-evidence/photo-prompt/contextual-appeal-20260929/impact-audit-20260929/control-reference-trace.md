## 왜 필수 보존이 되었는가

1. 실행별 요청에는 `controls`와 `topic` 두 구간이 있다. `controls`에는 사용자의 `sensual_editorial=3, fetish_fashion=3`이 들어 있다.
2. SKILL.md와 검증기는 **모든 활성 요청 구간에 최소 한 개의 보존 앵커**를 요구한다. 설정 구간도 예외가 아니다.
3. 각 앵커는 사용자 원문 일부와 초안의 실제 문구를 연결해야 한다. 작성 에이전트는 `sexual_tone`을 잠그고, 그 증거로 다음 복장 문장을 직접 넣었다.

```json
{
  "anchor_id": "core_appeal",
  "source_text": "sensual_editorial=3, fetish_fashion=3",
  "dimension": "sexual_tone",
  "prompt_evidence": "a fitted corset-like bodice; pale satin straps cross her waist into small silver rings"
}
```

4. 코어 검증은 원문이 요청에 있는지, 증거 문구가 초안에 있는지, 필드·차원·구간을 충족하는지 검사한다. **그 설정값이 그 특정 의상을 필수로 요구하는지까지는 판단하지 않는다.**
5. 최종 감사는 등록된 앵커 문구를 모두 문자 그대로 보존하도록 요구한다. 또한 대안 검색은 이 문구를 입력으로 사용한다. 그 결과 선택한 의상이 보존 의무와 검색 조건 양쪽에 들어갔다.

현재 스킬은 에이전트가 정한 의상·포즈를 사용자 요구처럼 잠그지 말라고 명시한다. 따라서 이는 의도된 코르셋 규칙이 아니다. 하지만 설정 준수와 시각 문구 보존을 분리하지 못한 계약이 잘못된 연결을 만들기 쉽게 하고, 자동 검증도 이를 통과시킨다. 지난 보고서에서 지적한 에이전트의 과도한 잠금에 더해 확인한 구조적 원인이다.

## 개선 시 분리해서 다룰 부분

- 값과 의미의 보존은 설정 스냅샷으로 검증하고, 그것을 구현한 특정 의상 문구의 보존과 구분한다. 사용자 설정을 무시하거나 원문에서 삭제하자는 뜻은 아니다.
- 사용자 지정 의상 속성과 에이전트가 선택한 구현을 구분하는 검토가 필요하다. 설정값만을 근거로 생긴 의상·소재 앵커를 특히 점검한다.
- 설명을 고친다면 특정 복장 금지 목록을 늘리는 것보다 사용자가 의도한 넓은 표현 범위와 강도의 의미를 정렬하고, 같은 강도를 서로 다른 방식으로 구현한 구상을 비교해야 한다.
- 문구의 편향 효과는 같은 주제·참고 이미지·작성 모델에서 정의만 달리한 독립적인 초안 비교로 확인할 수 있다. 이번 조사에서는 이를 실행하지 않았다.
