# Scene-diversity DATA qualification: preserve the corpus

## Decision

**KEEP the existing corpus. Neither proposed carried-load row is accepted.** Temporary containment scenes also do not yet justify a new candidate beyond existing photographic concepts in combination. This is a bounded research/qualification result, not a new DATA cycle or a retrieval improvement claim. Runtime, source candidates, indexes and tests are unchanged.

The useful outcome is a reproducible separation between an interesting scene idea, a distinct data concept, compatible source scope, actual consumer exposure, and safe optional adoption. Merely adding plausible keywords would not establish these.

## Research and frozen proposals

Independent development research considered temporary containment, awkward cargo through bottlenecks, and supported loose-part repair. It produced development scenes, wrong-neighbor controls and reserved transfer scenes. X originals could not be opened; attributed mirrors were inspiration only. No popularity or verified latest-trend claim is made. All qualification requests are **synthetic audit inputs, not actual user messages**.

Official furniture-delivery guidance supports the limited physical observation that a rigid item's orientation and dimensions interact with the available opening. It does not validate carrying safety, the geometry of these synthetic scenes, or photographic/model quality:
- [West Elm measuring guide, page 2](https://www.westelm.com/weimgs/rk/images/i/201928/0021/images/pdf/design-details/guides/how_to_measure.pdf)
- [DFS measuring guide](https://www.dfs.co.uk/help/measuring-buying-guide)

The first frozen action proposal, `carried_rigid_load_opening_clearance_relation`, failed qualification: its wildcard effects conflict with every partial property lock, while prose-only application conditions disappear from the ordinary public semantic surface. Its preliminary underlocked fixture and function-boundary probes are preserved, but cannot establish a production gain.

A separately authored frozen proposal, `rigid_load_opening_evidence_crop`, instead owns only crop framing. Its public concept units preserve the prerequisites and prohibit changing load orientation, clearance, contacts, support, viewpoint or objects. Its existing-schema `core_assertion_discovery: true` flag was explicitly compared with the same row's flag disabled. Neither flag is a new runtime rule. No proposal was inserted into repository assets; tests append private in-memory copies only.

## Independent input qualification

Six scenes were frozen without candidate/proposal/result access: original mirror/gate scene, drying-rack transfer, wheeled cart, strap adjustment, empty-handed doorway pose, and a separately prescribed tight mirror crop. Each has a 156–165-word independent baseline, literal semantic and property anchors, and five text-plausibility body-action checks. No pixel or solver validation is claimed.

All original requests, baselines, reviews and anchor/lock sets are retained. Preflight revisions r1–r4 are preserved with hashes and exact deltas. They expanded short literal evidence spans and interpretation descriptions, separated duplicated anchor evidence, and corrected a mistaken exclusion representation: the desired empty-handed state is retained positively by the baseline/property anchors, not listed as an excluded meaning. No retrieval ran until all six records passed. The adapter supplies existing test-wire enum values and deterministic controls solely for explicitly labeled synthetic fixtures; it does not assert actual requester provenance.

## Three-arm actual consumer results

Each frozen r4 input ran through `load_runtime_data` and the normal `generate_candidate_pack` producer in three arms: unchanged corpus, private frozen row with opt-in, and private identical row with opt-in disabled. All 18 runs completed. Every emitted pack preserved the exact baseline, source request and full intent lock. Final public candidate order is seeded/non-preferential and is not a relevance rank.

The new row displaced an existing framing option in the two exposed wrong-neighbor packs. Thus visibility alone would misleadingly count noise as progress. The row's public prose conditions survive, but do not constitute an executable scene-presence guard.

No case discovered the new row through the opt-in lane. Independent priorities lacked the minimum shared lexical content, except the crop-locked input whose framing scope is correctly closed to discovery. The flag-on and flag-off arms have identical candidate ID sets in these six cases. This is a **six-case result**, not proof that the flag can never affect routing.

The unchanged proposal ranks first in both broad and focal raw retrieval for the mirror, crop, cart and drying-rack cases. Actual function tracing distinguishes cap exposure from ranking. Correct raw position does not establish actual presence or semantic suitability. The actual shared count at subject-framing entry is 64 for mirror/crop/strap/drying-rack, 52 for cart, and 59 for empty-handed. Both wrong-neighbor emissions displace `pc_px10_component_3`. Exact discovery intersections, output packs and candidate-ID deltas are in the archive.

## Independent semantic comparison and containment KEEP

An independent reviewer, without retrieval results, recommends preserving all six baselines and the corpus. The drying-rack scene already has the relevant co-visibility. Existing crop-boundary anchor integrity and contour/contact-preservation concepts cover the photographic work in combination. Some portrait-specific candidates have narrower applicability; this is not a claim that every inspected ID is independently selectable in every scene.

For the separate containment family, the distinctive water/spill mechanism belongs to authored action/environment geometry. Once it exists, crop/contact/cause–trajectory–consequence/focus concepts already cover the photographic refinement. Housing-defect mitigation has a legitimate occupied-housing boundary and should not be broadened to routine market/nursery/pool scenes. An offline diagnostic found relevant generic rows eligible but absent from bounded retrieval; it was not a public-pack or image evaluation.

## Follow-on use and limits

- Preserve these request-complete wrong-neighbor and crop-lock controls when evaluating runtime coverage changes
- Compare consumer exposure, property/dimension compatibility and semantic adoption separately; do not promote a candidate because it appears more often
- A cap/routing improvement must not treat cart or empty-handed emission as success
- Do not tune the frozen row or original scene statements to this small transfer set; any revised hypothesis requires a new independent freeze
- No paid API calls, new embeddings, runtime edits, source additions, or accepted DATA cycles resulted from this investigation
