# 스페이스 오페라 데이터 반영 및 독립 이미지 시험

게시 범위와 로컬 보존 자료의 구분은 [PUBLISHING.md](PUBLISHING.md)를 참조한다. 아래 설치·이미지 결과는 해당 시점의 고정된 실행본 기록이며 새 소스 게시본과 검색 모집단이 다를 수 있다.

상태: 데이터 반영·최신 설치본 검증·검색 194건·독립 이미지 생성 3건·원본 픽셀 리뷰 완료. 장르 표현은 세 장에서 확인했지만 엄격한 전체 기술 자격은 세 장 모두 실패했다. 실패를 보존하며 사용자 판단은 대기 상태다.

## 반영 범위

- 원본 291개 키워드 경로, 시각 의미 카드 72개, 문맥 구분 26개를 보존했다.
- 완전한 한·영 시각 후보 62개와 선택적 역할 연결 120개를 추가했다. 기존 압력·열·생명유지 후보 3개는 수정 없이 재사용했다.
- 문맥·보류 레코드 33개는 양성 검색에서 제외했다. Ringworld 세부, coilgun 비교, 특정 glassing 범위, ectogenesis 해석의 근거 공백은 그대로 보류했다.
- 관찰 가능한 부품, 소유자, 방향 관계, 혼동 경계, 출처, 전체 효과 범위를 별도로 보존했다. 연구 관계 그래프를 실행 시의 스칼라 사실이나 채택 승인으로 바꾸지 않았다.
- 모든 신규 후보의 자동 native 승인은 꺼 두었다. 개별 이미지의 통과가 전체 후보의 승인으로 승격되지 않는다.

## 검증

원본 리서치 파일 38개 해시와 기존 소스 범위의 후보 20,054개·역할 연결 14,687개 보존을 확인했다. 다른 작업이 최신 설치본을 등록하여 그 검증된 버전으로 다시 합쳤고, 그 기준의 기존 canonical 후보 20,143개를 모두 보존했다. 현재 전체 working raw corpus도 별도 검증을 통과했다. 반영 이후 공유 작업공간의 기존 후보 모듈 5개에서 추가 해시 변경을 관측했다. 이 파일들은 이번 데이터 작성 대상 밖이므로 되돌리지 않았고, 최종 해시 관측을 final-protected-source-hashes.json에 따로 남겼다. 초기 등록 보존 검사와 이후 공유 트리 상태를 혼동하지 않는다.

봉인된 실행 소스와 H-F2 설치본의 전체 검증, 설치 Python·NumPy·recorder 검사, 기존 계약·전체 장면 쿼리 회귀 테스트 12개가 통과했다. 실행 커널은 해당 최신 검증본에서 변경하지 않았다. 실행 시험은 5fafd235… 세대에 고정했다. 이후 다른 작업이 86e91bb0… 기본본을 등록했으며, 실행 코드 해시가 같고 이번 두 canonical 후보 모듈이 바이트 동일하게 보존된 것을 별도로 확인했다. 이미 고정한 시험은 재검색·재샘플하지 않았다.

한·영 검색 194개(개발 130, 경계 40, 일반 대조 24)를 실행했다. 개발용 정답 130개는 목표 후보가 모두 상위 10개 안에 노출됐다. 이 쿼리는 작성한 자료에서 만든 개발 쿼리이며 독립 holdout이나 기존 대비 개선의 증명은 아니다. 일반 대조 24개 중 2개에서도 신규 후보가 상위 10개에 노출됐다. 해당 노출을 장면 채택 허가로 보지 않았으며, 일반 장면의 실제 생성·자동 침투 부재는 이번 검색 시험으로 증명하지 않았다.

## 독립 시험 설계

최종 세 에이전트는 서로의 기본 프롬프트나 자료를 읽지 않는 fresh context에서 시작했다. 각 기본 프롬프트·의도 잠금·사전 픽셀 기준을 후보 자료 접근 전에 고정했다. 초기 두 초안은 대기 중 에이전트 목록에서 과거 연구 요약이 노출돼 평가에서 제외하고 새 에이전트로 교체했다. 실제 평가 대상은 a2, b2, c 세 개다.

무작위 추첨한 서로 다른 주제 축을 각 에이전트가 독립적으로 구체화했다. 첨부 사진은 얼굴·머리카락의 외형 참고로 한정했다. 각 장면은 성인인 가상 전문직 인물로 저작했다. 기본 인물의 신원·나이·성격을 사진에서 추정하지 않았다.

| 시험 | 컨셉 | 핵심 사전 픽셀 기준 |
|---|---|---|
| a2 | 궤도 조선소의 수리 완료 인수인계 | 같은 카세트의 양쪽 손 접촉, 실제 선체와 도크 연결, 인물·선체·작업 구조의 크기 관계 |
| b2 | 변경 화물선의 의약 물자 보급 위기 | 세 잔여 실린더와 빈 홈, 손과 실린더·상자의 연결, 거주 목적지와 다른 대형선 |
| c | 다종족 승무원의 구조 항로 보정 | 서로 다른 세 승무원과 같은 장치의 각 접촉, 렌즈를 지나는 광선과 별 표식 종점, 호송선 규모 |

검색 노출, 재료 선택, 프롬프트 전달, 실제 생성, 픽셀 가시성, 사용자 판단을 각각 기록한다. 필수 관계는 양 끝과 중간 연결이 함께 보여야 통과한다. partial·unobservable은 완전 통과가 아니며, 이미지가 없으면 픽셀은 UNSCORED다. 사용자 수용 판단은 pending이다.

조선소 장면의 V24 혼동 경계는 기존 교량→포트와 받침→선체의 접점 명료화에 영감으로 쓰였다. V24의 전체 원문 후보를 native 채택하거나 완전히 픽셀 자격 승인한 것은 아니다. 나머지 두 장면은 이번 신규 후보를 채택하지 않았다. 세 장면에서 신규 자료 노출은 각각 3/3/2개 고유 후보였고, 전체 원문 native 채택은 모두 0개다. 기본 프롬프트가 이미 저작한 함대·장르 요소를 데이터 기여로 귀속하지 않았다. 생성 전 텍스트 대안 비교는 수행했지만 동일 조건 baseline 이미지를 생성한 인과 대조는 없다.

코디네이터도 각 저장 원본을 직접 검토했다. C의 초기 코디네이터 해석에서는 내부 손잡이와 안쪽 링, 렌즈와 광선의 2차원 겹침을 넓게 읽었다. 고정된 baseline과 사전 관계를 재대조해 두 항목을 partial 실패로 정정했다. 초기 해석과 정정 사유를 보존했으며 이미지나 사전 테스트 기준을 바꾸지 않았다. 세 사전 testcase 파일의 해시 보존도 확인했다.

## 후속 보완 우선순위

1. 조선소의 발 지지 상태까지 증명하려면 다음 시험을 전신 구도로 시작한다. 이번 장면의 핵심 7개 통과와 별도의 신체 지지 미관측을 합쳐 완전 통과로 표시하지 않는다.
2. 보급 장면은 같은 3개 실린더와 빈 홈을 유지하되, 손바닥과 단단한 케이스 테두리를 동시에 보이는 각도로 접촉면을 배치한다.
3. 다종족 장면은 중앙 손잡이와 안쪽 링을 명확히 나누고, 손이 링의 지정 위치를 잡도록 한다. 광선의 발광점·렌즈면 진입/이탈·표식 종점을 한 시야에서 구분하는 측면 구도로 검증한다.
4. 넓은 주제 질의에서 opera glove 같은 어휘 잡음이 관찰됐다. 문맥이 풍부한 슬롯 질의와 전체 주제 질의를 분리해 평가하고, 원문 의미·조건을 바꾸지 않는 구문 중의성 회귀를 보강한다. 일반 대조 쿼리의 신규 노출 2건도 채택 여부까지 시험해야 무관한 장면 침투 부재를 주장할 수 있다.
5. V24·V65·V62 등의 전체 원문 후보를 승인하려면 완전한 부품·소유자·관계를 노출하는 별도의 native qualification 시험을 준비한다. 이번 세 장의 부분 영감이나 장르 성공으로 자동 승인하지 않는다. 보류한 네 출처 공백도 먼저 보충한다.

이 항목들은 다음 실험 계획이며, 이번 최초 3장 시험의 실패를 덮기 위한 재생성은 수행하지 않았다.


## 증거

세부 증거는 같은 디렉터리의 integration-evidence 아래에 있다. data-integration.json, source-preservation.json, historical-preservation.json, canonical-source-validation.json, complete-working-source-status.json, successor.json, install-active.json, installed-runtime-check.json, focused-tests.json, retrieval-qualification.json, ordinary-control-exposure-review.json, INDEPENDENCE.json을 구분해 확인한다. 최종 집계는 FINAL-VALIDATION.json, 각 에이전트 결과는 arms/a2/report.json·arms/b2/arm-result.json·arms/c/arm-summary.json, 코디네이터 픽셀 리뷰는 coordinator-review-a2.json·coordinator-review-b2.json·coordinator-review-c.json에 있다.

이 작업은 로컬 소스 반영과 설치본 검증이다. 커밋·푸시는 수행하지 않았다.
