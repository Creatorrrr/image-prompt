# 연기 용어에 기반한 시각 의미·후보팩 강화 리서치

조사일: 2026-10-03 KST. 상태: **리서치와 반영 설계 완료, 운영 데이터 반영·검색 실행·이미지 검증 전**.

## 1. 결론과 권장 방향

강화의 중심은 감정어의 수를 늘리는 것이 아니라, **문맥상 의미 → 선택 가능한 관찰 형태 → 소유자와 대상의 관계 → 가까운 반례 → 검증 가능한 증거**를 연결하는 것이다. 같은 입꼬리·눈꺼풀 형태가 다른 상황에서 다른 역할을 하므로, 감정 이름 하나에 고정된 얼굴을 붙이면 표현의 폭과 원 요청의 의미를 함께 잃는다. 얼굴 움직임과 감정의 일대일 대응이 상황과 문화에 걸쳐 성립한다고 볼 수 없다는 검토 결과를 이 설계의 한계 조건으로 삼았다. [Barrett et al., 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6640856/)

이번 패키지는 다음을 담는다.

- 원 대화의 **13개 절·25개 표·368개 표 행** 전체 범위와 각 행의 반영 경로.
- 공식 체계, 논문, 용어 창안자, 교육기관, 사전 등 **40개 출처**의 지원 내용과 한계.
- **64개 개념 설계**: 정지 형태·문맥 변형·시간·음성·메타데이터를 구분한 초안.
- 기존 후보 **11개 재사용**, 새 후보 **38개**, 관찰 형태 프로필 **11개**, 후보 번들 **11개**.
- 실행 전 문맥 회귀 사례 **75개**, 정지 이미지 비교 **11쌍**과 영상·음성 후속 평가 계획.

368은 표의 행 수이다. 한 행에 여러 단어가 묶여 있으므로 고유 단어 수, 완전히 검증된 뜻의 수, 새 프로필 수를 뜻하지 않는다. 40개 출처를 읽은 사실도 모든 한국어 관용 표현의 뜻이나 생성 모델의 동작을 검증했다는 뜻은 아니다. 아래의 구체적인 얼굴 조합은 **출처를 참고한 저작 제안**이며, 과학적으로 필수인 감정 공식이 아니다.

우선 반영할 것은 입술 누르기/조이기, 눈썹 안쪽/전체 올리기, 아래 눈꺼풀 올리기, 윗입술 들기, 자기 손과 입의 소유권처럼 가까운 형태를 혼동하기 쉬운 항목이다. 플러팅·억눌린 감정·코미디는 이 형태들 위에 문맥과 선택 조건을 얹는다. 미세표정의 지속시간, 시선 왕복, 목소리, 연기 방법론은 별도의 관찰 매체와 메타데이터로 남긴다.

## 2. 조사 범위와 증거 방식

범위의 출발점은 [연기 용어 조사](chatgpt-conversation://6abfdef9-2904-83ee-853f-e5e012a7db35)이다. `read_thread` 응답이 20,000자에서 잘려 실제 렌더된 대화의 10–13절까지 DOM으로 추가 확인했다. 원 답변의 주장은 근거로 사용하지 않았고, 표의 용어 범위만 [SOURCE-TERM-GROUPS.json](SOURCE-TERM-GROUPS.json)에 보존했다.

현재 데이터 비교는 Git 커밋 `0adb5f6e56416e2656dfb4150d0724867530c2bc`에 고정했다. 조사 중 공유 작업 디렉터리의 별도 병합이 시작되어 JSON 충돌이 발생했기 때문이다. `git show`로 원본을 읽고, 순수 컴파일러의 바이트가 고정 커밋과 같은지 확인한 뒤 집계했다. 원본 74개 파일의 SHA-256과 당시 상태는 [SOURCE-MANIFEST.json](SOURCE-MANIFEST.json)에 있다. 작업 트리나 병합 결과를 최신 운영 상태로 간주하지 않는다.

증거는 다섯 층으로 구분한다.

| 층 | 이번에 확인한 것 | 아직 확인하지 않은 것 |
|---|---|---|
| 용어·연구 | 출처의 의미 범위, 관찰 방법, 한계 | 모든 구어 표현의 번역 등가성 |
| 저작 데이터 | 고정 원본의 항목·필드·기존 ID | 새 초안의 사용자 선호 |
| 구조 | 프로필 투영·후보 확장 구조와 참조 검증 | 문맥별 resolver/ranking/후보 노출 |
| 생성·픽셀 | 평가 설계와 필수 요소 | 실제 생성 결과와 이미지 성공률 |
| 수용 | 없음 | 사용자의 표현 적합성 판단 |

[SOURCES.md](SOURCES.md)는 각 출처를 원문 페이지 확인, 초록 확인, 검색 결과 초록 확인으로 구분한다. FACS 유료 매뉴얼은 확보하지 않았고, 인증 코딩을 수행하지 않았다. 논문·데이터셋의 이미지를 수집하거나 학습에 사용하지 않았다.

### 3.1 이미 있는 기본 형태

`pv_eyes_closed`, `pv_half_lidded`, `pv_smile_closed`, `pv_smile_teeth`, `pv_asymmetric_mouth`, `pv_parted_lips`, `pv_puffed_cheeks`, `pv_raised_brows`, `pv_wink`는 기존 **후보 ID**이다. 이 9개에 대응하는 `pv_profile_*` 얼굴 하드 프로필은 이번 고정 원본에서 발견되지 않았다. 후보 존재와 하드 시각 의미 프로필 존재를 혼동하지 않는다.

## 4. 얼굴 국소 형태: 가까운 이름을 다른 관찰 요소로 분리

FACS는 얼굴의 관찰 가능한 동작을 다루는 체계이다. 이를 감정 진단표로 쓰지 않는다. 여기서는 명칭 교차 참조를 사용하고 실제 프로필은 보이는 요소로 작성한다. [FACS 공식 안내](https://www.paulekman.com/facial-action-coding-system/)

### 4.1 눈·눈썹·시선

| 구분 | 보존할 관찰 요소 | 혼동 경계·조건 |
|---|---|---|
| 눈 감기 / 윙크 | 두 눈 닫힘 / 한쪽만 닫히고 반대쪽 열림 | 윙크에 호감·성적 분위기를 자동 부여하지 않음 |
| half-lidded | 위 눈꺼풀이 홍채 일부를 덮지만 눈은 열림 | 졸림·위협·호감은 문맥상 선택; 동의어가 아님 |
| squint | 눈 틈의 축소; 어느 눈꺼풀·볼이 움직였는지 명시 | 밝은 빛, 집중, 의심의 상황을 구별 |
| squinch | 아래 눈꺼풀 경계가 올라가 눈 틈이 좁아지는 선택형 | 일반 squint, 눈 완전 닫힘, 미소와 구분 |
| smize | 눈 주변에서 미소를 전달한다는 넓은 포징 표현 | 눈·볼·입의 여러 실현을 허용; 한 조합을 필수로 만들지 않음 |
| 눈썹 전체 올림 | 양쪽 눈썹의 전체 상승 | AU5의 눈꺼풀 상승과 다름 |
| 안쪽 눈썹 올림 | 눈썹 안쪽 끝의 상대적 상승 | 슬픔을 자동 확정하지 않음 |
| 한쪽 눈썹 올림 | 요청한 쪽만 상승 | 고개 기울임에 의한 높이 차와 구분 |
| knitted brows | 미간 쪽으로 모임·내려감 | 분노 외에 집중·불편함 등 문맥 가능 |
| 곁눈질 / side-eye | 얼굴 방향에 비해 홍채가 측면으로 향함 | 고개만 돌린 것과 구분; 조롱·경계·호기심은 별도 |
| 아래보기 / 올려보기 | 홍채의 방향과 대상 높이 | 숙인 고개+올려본 눈, 든 고개+아래 본 눈도 허용 |
| 초점 풀림 / 먼 곳 보기 | 요청된 대상 정렬과 눈 방향 | 이미지에서 정신상태·실제 조절 초점을 측정했다고 보고하지 않음 |

Squinch는 창안자의 안내에서 아래 눈꺼풀 올림을 강조한다. 자신감이 있다는 평가나 특정 AU 조합은 이 자료로 보증되지 않는다. Smize는 사전에서도 눈으로 미소를 표현한다는 넓은 용어이며, 같은 의미의 여러 형태 제안을 유지하는 것이 적절하다. [Peter Hurley](https://peterhurley.com/blog/squinch-single-easiest-tip-looking-confident-photos), [Collins smize](https://www.collinsdictionary.com/dictionary/english/smize)

Side-eye의 사전적 평가 범위는 비난에만 한정되지 않는다. 따라서 `side-eye = 적개심`, `downcast = 수줍음`, `direct gaze = 자신감` 같은 하드 결합을 만들지 않는다. [Merriam-Webster side-eye](https://www.merriam-webster.com/dictionary/side-eye)

| set jaw / clenched teeth | 닫힌 입·유지된 턱 형태, 보이는 경우 치아 맞물림 | 힘의 크기·통증·의도를 사진에서 측정하지 않음 |
| chin up / chin raiser | 머리 방향으로 턱을 듦 / 턱 조직·아래입술의 국소 변화 | head orientation과 AU17을 분리 |

입술·눈썹의 상대적 위치는 얼굴의 기본 형상, 렌즈·머리 각도에 영향을 받는다. 자연스럽게 높은 눈썹이나 깊은 주름을 표현 동작으로 오인하지 않도록 동일 배우의 중립 비교 프레임이 있으면 활용한다. 없으면 모호한 상대 변화는 불확실 또는 관찰 불가로 기록한다. 이 표는 정식 AU 코딩 기준을 대체하지 않는다. [CMU FACS 명칭 참고](https://www.cs.cmu.edu/~face/facs.htm)

## 5. 미소·웃음: 형태, 사회적 기능, 시간의 분리

Closed-mouth/toothy/asymmetric/broad/faint는 입·치아·좌우·크기 요소로 쓸 수 있다. Smug, polite, knowing, sheepish, rueful, cynical, conspiratorial은 장면 속 태도나 기능이다. Spread/fade/suppressed laughter는 시간과 조절 과정이다. 이 세 축을 한 줄 동의어로 합치지 않는다.

미소를 보상·친화·우위 조절의 사회적 기능으로 구분하는 연구는 같은 “웃음” 안의 다양성을 참고하는 데 유용하다. 그러나 모든 미소를 세 분류로 강제하거나, 그중 한 형태로 실제 진정성을 판단하는 근거는 아니다. [Martin et al., 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8340880/)

| 용어 | 반영 방식 | 금지할 축약 |
|---|---|---|
| smirk / smug smile | 요청된 자만·우위·장난 문맥에 형태 선택지 연결 | smirk는 반드시 한쪽 입꼬리 |
| sneer | 경멸 연기의 윗입술·입꼬리 등 복수 실현 분리 | smirk와 같은 별칭으로 처리 |
| wry / rueful / bittersweet | 아이러니·후회·복합 장면을 보존한 작은 미소 선택 | 비대칭이면 후회 또는 악의 |
| knowing / conspiratorial | 정보 공유나 공모가 원 요청에 있을 때만 관계 연결 | 새 비밀·파트너 자동 생성 |
| polite / forced / nervous | 표시 목적·긴장·억제 문맥과 형태를 구분 | 눈 주름이 없으면 거짓웃음 |
| Duchenne-like | 볼/눈 주변과 입꼬리의 조합 형태 | 실제 행복·정직·동의 보증 |
| 웃음 참기 / 번짐 / 사라짐 | 한 프레임 상태와 전체 변화 순서를 별도 기록 | 정지 프레임으로 과정 통과 |

Smirk의 사전 의미는 자만·우쭐함 등의 미소이며 비대칭이 정의의 필수 조건은 아니다. [Merriam-Webster smirk](https://www.merriam-webster.com/dictionary/smirk)

정지·동적 미소 자극을 비교한 연구에서는 동적 조건의 이점이 특히 친화적 미소에서 유의했다. 이를 모든 표정의 영상 우월성으로 확대하지 않되, 미소가 번지거나 사라지는 요청의 검증에 시간 정보가 필요하다는 설계와 구분한다. [Orlowska et al., 2018](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2018.00938/full)

## 6. 32개 감정 묶음: 장면 의미의 구체화, 얼굴 공식의 배제

아래는 원 대화의 묶음을 어떻게 저작 데이터로 세분화할지에 대한 제안이다. 같은 행의 단어들도 자동 동의어가 아니다. “있다면 보존할 정보”는 원 요청에 없을 때 만들어 넣을 정보가 아니다. 얼굴 후보는 국소 형태 조합 중에서 선택하며 중립적·억제된 실현도 허용한다.

| 원 감정 묶음 | 세분화에 사용할 정보가 있다면 보존 | 가까운 의미와의 경계 |
|---|---|---|
| 기쁨·즐거움·환희 | 대상, 표현 크기, 조용한/큰 실현 | 성취 원인을 자동 추가하지 않음 |
| 재미·익살·장난기 | 웃음의 대상, 장난의 상대, 억제 여부 | 행복·조롱과 합치지 않음 |
| 만족·뿌듯함·성취감 | 완료·성취 사건이 실제 요청됐는지 | 넓은 만족을 보상 사건으로 고정하지 않음 |
| 안심·안도·긴장 해소 | 확인된 안전, 이전 위험, 같은 프레임/전후 구분 | 단순 평온과 다름; 원인 발명 금지 |
| 기대·설렘·들뜸 | 기다리는 대상이나 직전 단계 | 현재의 기쁨과 미래 지향 구분 |
| 궁금함·관심·몰입 | 관찰 대상, 주의 방향, 진행 중 과업 | 혼란·성적 관심 자동 추론 금지 |
| 감탄·경외·압도 | 요청된 대상과 크기·거리 관계 | 크게 뜬 눈을 공포로 확정하지 않음 |
| 자신감·확신·여유 | 발화·자세·선택의 맥락 | 정면 시선 하나로 성격 판단 금지 |
| 자부심·긍지 | 자기/집단/성과의 대상을 원문에서 확인 | 오만·타인 비하와 구분 |
| 우쭐함·거만·득의 | 요청된 상대적 우위 연기 | 비대칭 미소를 필수로 만들지 않음 |
| 다정·애틋·친밀 | 관계와 시선 대상이 명시됐는지 | 애정과 성적 관심을 분리 |
| 걱정·연민·보살핌 | 누가 누구를 걱정·돌보는지 | 원치 않는 부상·아동·접촉 추가 금지 |
| 감사·감격·벅참 | 감사를 전하는 대상·행동 | 눈물만으로 감사 원인 판단 금지 |
| 그리움·향수·갈망 | 부재·기억·원하는 대상 | 눈을 멀리 보면 모두 그리움이라는 공식 배제 |
| 외로움·소외·공허 | 장면의 관계/공간 의미 | 인물 수·쓸쓸한 배경을 자동 변경하지 않음 |
| 서글픔·비통·상실 | 상실이 원문에 있을 때 그 범위 | 눈물·사망·장례 소품 필수화 금지 |
| 후회·자책·미련 | 과거 행동이나 미해결 대상 | 죄책감·수치와 원인 분리 |
| 죄책감·수치·굴욕 | 자신의 행위/타인의 평가 맥락 | 아래 시선으로 도덕적 상태 진단 금지 |
| 수줍·머쓱·민망 | 호감, 노출된 실수, 낯섦의 차이 | 직접 시선을 유지하는 수줍음도 허용 |
| 불안·초조·긴장 | 불확실한 결과와 기다림 | 떨림·심박을 정지 사진에서 증명하지 않음 |
| 공포·경악·위축 | 요청된 위협과 거리 | 밝은 빛·놀람에 의한 눈 움직임과 구분 |
| 당황·혼란·망연 | 정보 부족·지연된 이해의 맥락 | microexpression 또는 동공지진으로 일괄 처리 금지 |
| 의심·불신·경계 | 의심하는 대상과 정보 | 모든 곁눈질을 불신으로 확정하지 않음 |
| 불편·짜증·성가심 | 자극, 방해, 강도 | 분노·혐오와 구분 |
| 화남·분개·격노 | 표출/억제, 대상, 강도 | 폭력·소리·대립 인물 자동 추가 금지 |
| 원망·억울·서운 | 관계·불공정의 정보가 원문에 있는지 | 분노 하나로 평탄화하지 않음 |
| 역겨움·혐오·경멸·냉소 | 감각적 불쾌와 사회적 평가를 분리 | 코 찡그림과 경멸을 자동 등치하지 않음 |
| 부러움·시기·질투·경쟁 | 비교 대상, 관계 위협, 과업 | 새 삼각관계나 연인 자동 생성 금지 |
| 실망·좌절·체념·절망 | 기대 실패/포기/잔여 의지 | 자세 하나로 절망 확정 금지 |
| 지루함·피로·무감각 | 과업·시간·상태가 주어졌는지 | half-lidded를 관능으로 전환하지 않음 |
| 결의·단호·고집 | 목표, 버티는 선택, 행동 | 굳은 턱에서 실제 의지·힘을 판정하지 않음 |
| 애증·씁쓸·복잡한 심경 | 동시에/순서대로 존재하는 의미 | 동일 프레임의 조합과 전환 서사를 구분 |

감정 경험의 여러 범주와 연속적인 연결을 다룬 연구는 이 목록을 고정된 몇 가지 얼굴로 축소하지 않을 근거가 된다. 해당 연구의 27개 자기보고 범주가 여기의 32개 언어 묶음을 실증한 것은 아니다. [Cowen & Keltner, 2017](https://doi.org/10.1073/pnas.1702247114)

기존 `photo-character-mechanism-graph/v2`의 `surface_affect`, `underlying_affiliation`, `affect_leak_timing`, `affect_leak_intentionality`를 먼저 검토한다. 새 감정 분류기를 만들 필요는 없다. 단, underlying이나 leakage는 **요청된 연기 설정**일 때의 메타데이터이며 실제 사람의 마음을 이미지에서 알아낸 결과가 아니다.

## 7. 울음·억제·복합 감정

눈물 고임, 흐른 자국, 붉은 눈시울, 입술 누름, 닦는 손은 관찰 형태 후보이다. 목이 메거나 흐느끼는 소리는 음성이고, 눈물 참기·울음 삼키기·정리하기는 조절 과정이다. 각 요구를 다른 증거로 검증한다.

| 복합 요청 | 같은 프레임에서 선택할 수 있는 형태 예시 | 그대로 주장할 수 없는 것 |
|---|---|---|
| 울지 않으려고 웃음 | 눈물 고임 + 작은 입꼬리 상승 | 실제 울음 억제의 성공 |
| 화났지만 공손함 | 작은 사회적 미소 + 요청된 국소 긴장 | 숨긴 진짜 분노 |
| 기쁘지만 들키기 싫음 | 작은 변화·폐쇄된 입 형태의 선택지 | 상대가 알아차리지 못했다는 결과 |
| 수줍지만 시선 유지 | 작은 미소 + 잠긴 직접 시선 | 아래보기 필수 |
| 경멸하면서 친절함 | 요청된 태도 + 선택된 미소·입술 요소 | 실제 인격·도덕성 |
| 안도하면서 화남 | 요청된 두 의미 + 양립 가능한 형태 선택 | 원문에 없는 위험 사건 |
| 기쁘면서 서러운 재회 | 눈물과 미소의 공존; 요청된 관계 유지 | 없던 상대·접촉·과거 이야기 |
| 상처받았지만 품위 유지 | 절제된 형태·자세 | 실제 심리적 회복 |
| 안도 뒤 울음 | 이후 상태의 정지 프레임 또는 순서 있는 시퀀스 | 단일 프레임으로 '뒤'의 순서 |

얼굴만으로 애매한 강한 표현을 해석하는 것과 몸·상황을 함께 보는 것은 다를 수 있다. 이를 몸짓 사전의 고정 감정 공식으로 역전시키지 않고, 요청된 몸·손·대상을 누락하지 않을 근거로 사용한다. [Aviezer et al., 2012](https://pubmed.ncbi.nlm.nih.gov/23197536/)

## 8. 성인 호감·매혹 용어의 문맥 분해

성인 호감의 표현은 일반 미소·장난·수줍음, 상황적 유혹, 평가어, 매체의 기능을 나눠 조사했다. 미소·윙크·입술 물기는 일반 집중·연극·코미디에서도 나타날 수 있으므로 그 동작 자체가 성적 톤을 바꾸는 근거가 되어서는 안 된다.

| 용어 | 구분할 뜻 | 데이터 반영 |
|---|---|---|
| coy | 수줍음·수줍은 척·말하기를 꺼림 | 여러 시선·머리 방향 선택지를 허용 |
| 새침 | 차갑거나 도도한 태도 등 한국어 문맥 | coy/coquettish와 자동 동의어화하지 않음 |
| coquettish / flirtatious | 교류 속 장난·호감 표현 | 명시된 성인 교류와 대상만 보존 |
| 애교 | 귀엽게 보이려는 태도 | 비성적 귀여움·예능 맥락 보존 |
| sultry | 덥고 후텁지근한 날씨 / 열기·매혹의 뜻 | 날씨와 인물 표현 문맥을 먼저 분리 |
| smoldering / smouldering | 불씨 / 억눌린 감정 / 호감 연기 문맥 | 철자 변형과 의미 변형을 구분 |

## 11. 시각 의미 데이터와 후보팩 데이터에 각각 무엇을 넣을지

시각 프로필에는 **관찰 불변 요소가 있는 좁은 형태**를 넣는다. `authored_components`가 발견용 요소, 프롬프트 증거, 구체 지시, 픽셀 gate의 단일 원본이 된다. “입술 누르기”에는 닫힌 경계와 눌린 입술을, “자기 손으로 입 가리기”에는 같은 배우의 팔–손 연결과 같은 배우 입의 겹침을 각각 기록한다. 관찰할 수 없는 실제 힘·정서·음성을 필수 요소로 삼지 않는다.

후보팩에는 국소 형태를 재조합할 **선택형**, 문맥이 허용할 때만 쓰는 **상황 변형**, 관련 시각 프로필을 묶는 **optional bundle**을 넣는다. 기본 원자 후보의 별칭 추가, 상황 변형, 하드 프로필은 서로 다른 작업이다. 검색 결과의 프로필이 후보팩에 있다는 이유만으로 사용자 요구가 되지 않는다.

원 요청과 authorial core·intent lock을 먼저 고정하고 이후 하나의 holistic V6 pack에서 관련 슬롯을 찾는다. Exact term도 전체 문맥·부정·소유권 조건을 통과해야 요청 범위의 하드 의무가 된다. BM25F/embedding 발견은 선택 전까지 조언이다. 후보를 모두 거절할 수 있어야 하며, 새 형태의 채택은 잠긴 배우·시선·포즈·표정 속성을 침범하지 않아야 한다.

이번 초안에서 `coy_variant`는 머리 방향과 시선이 함께 변하므로 `pose`와 `expression`을 모두 선언했다. `chin_up`은 head orientation, 시선 관련 행은 eyes.eyeline을 명시했다. 특히 `gaze_target`의 고정 원본 슬롯 기본 차원이 빈 목록이므로, 새 항목의 시선 변화 영향은 별도로 적어야 한다. 슬롯명만으로 잠금 충돌을 처리했다고 간주하지 않는다.

## 12. 보강의 충분성을 판단할 기준과 남은 불확실성

충분함은 별칭 수나 후보 수가 아니라, 자주 쓰는 혼동 쌍을 정확히 구분하고 이름 없는 표현에서도 요소·소유권을 보존하며 요청하지 않은 의미를 추가하지 않는 능력으로 평가한다. 데이터 검증, 검색 결과, 프롬프트, 생성 픽셀, 사용자의 표현 판단은 각각 독립적인 결과로 기록한다.

우선순위는 국소 형태(P1), 상황·복합 표현(P2), 코미디·한국어 관용어(P3), 영상·음성·시간 메타데이터(P4)이다. 원 대화 모든 행의 경로는 [TERM-DECISIONS.md](TERM-DECISIONS.md)에 있다. 하드 프로필로 전환하지 않은 시간·음성·평가 용어도 버리지 않고 해당 매체와 저작 정보로 남긴다.

남은 확인 사항은 원어의 번역 경계, 자연스러운 얼굴 기본형과 동작의 구분, 문맥 guard의 실제 강제 여부, 이름 없는 요소 묘사의 검색 품질, 11개 프로필의 원본 픽셀 실현이다. 이미지 생성은 수행하지 않았으며 새 데이터의 생성 성공이나 사용자 수용을 주장하지 않는다. 반영 단계와 중단·수정 기준은 [IMPLEMENTATION-PLAN.md](IMPLEMENTATION-PLAN.md)에 명시했다.
