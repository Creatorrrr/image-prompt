# V12: exact architecture DATA identity with zero pack delta

This is a separately registered immutable boundary successor for two Korean
architecture aliases. It does not broaden the V10/V11 four-leaf transition.
The DATA-only commit and its actual parent are recorded in
`verified-data-commit.json` and the fixed `V12-zero-delta-proof.json`.
The DATA commit precedes this maintenance patch; no self-referential commit
identifier is used. Publication and final verification are separate steps.

## What changed

Only `activation.exact_terms[1]` in `pf_rib_vault_chapel` and
`pf_venetian_arcade` changed, as frozen in `two-alias-proposal.json`. The genuine
visual-profile index was rebuilt by the production builder, reusing all 1,622
cached vectors with unchanged texts and entries. Network sockets and credential
file reads were blocked. The ordinary semantic index and vector shards remain
unchanged. No new profile, component duty, gate, selection rule or retrieval
algorithm was introduced.

The frozen seed-910000 production boundary pack remains byte-identical:
SHA256 `6c097471705589a4db45daf5aa164017f2c7b512dcaab880e9e58bb3882f5589`,
pack ID `96a0c50349d492f5`, all 64 complete candidates and their public order.
The before V11 source identity passes; after DATA fails that same V11 identity
because the visual-index hash changed. The dedicated V12 registration accepts
only the exact qualified after source and identical raw pack.

## Enforced contract

- V1–V11 manifests, existing historical packs and transition proofs are preserved
  byte-for-byte. V11's actual raw pack is appended as its archive
- V12 names and hashes the exact V11 predecessor. Full lineage, frozen input bytes,
  generation command, seed, preserved contract, canonical pack ID, negative and
  private-field rules remain checked
- A code-pinned proof hash binds the actual DATA commit/parent, old qualified DATA
  identity, both source inventories, exact aliases and qualification receipts
- The original four source pins are retained; only the visual-index value changes.
  An additional fixed inventory binds all 83 top-level JSON DATA/index files.
  Missing, extra or changed files fail closed; unchanged semantic-index metadata
  continues to bind its active vector shards
- The archived palace source is reconstructed using exactly two unique raw UTF-8
  JSON-string replacements. Its full result must equal the live source bytes
- The actual raw pack must equal the archived V11 raw pack. No fields are removed,
  normalized or exempted, even the four fields permitted by V10/V11
- Only version 12 is newly registered. Merely adding a V13 manifest cannot make it
  current, and explicit version 13 is rejected
- The old universal-V2 descriptor is archived. The current descriptor must equal
  it byte-for-byte except for the existing validator SHA256 value. Universal V1,
  holdouts, oracle constants, case expectations and invariants are unchanged

The illustration validator hashes opaque source bytes and compares literal byte
replacements. It does not import the photo runtime or interpret its registry
semantics. The independently qualified source patch establishes the two exact
JSON leaf locations. Historical V10/V11 unit replays explicitly select their
version and mock only their saved generator output/source identity. They are
labeled historical simulations; actual CLI evidence remains separate.

## Qualification limits

The 18-input, 36-arm production replay measures a precision/recall tradeoff.
Five incompatible Korean cases stop receiving false hard obligations. Both
reviewed Korean exact phrases and the unchanged English exact aliases receive
the intended hard contract. Both complete legacy Korean positives lose hard
activation despite retaining their intended architectural meaning. This is a
real recall cost, not a claim that every paraphrase is improved.

Optional visual candidate IDs/order change in six of the 18 inputs, including
unrelated optional-candidate displacement. The two independent synthetic theme
cases remain separate from source-guided cases. Their absence of hard activation
does not establish unseen-query generalization.

Eight content-replacement mutations fail the frozen literal-anchor obligations.
Both appended contradictions that retain the original anchors still pass.
These results establish bounded literal-evidence checks, not a general semantic
contradiction detector. No rendered images or fresh embedding-query qualification
were produced. Frozen boundary equality does not establish image quality or
qualify this DATA change for every other request.

## Future maintenance

This is one immutable registration, not a generic allowed-delta facility.
A future DATA/index identity change requires fresh qualification and a separately
reviewed successor even when its frozen pack is unchanged. Preserve the existing
four-leaf workflow for its original transitions. Do not overwrite historical
baselines, auto-discover versions, force a cosmetic pack change, relax the source
pins or use recomputed checksums as authorization.

Focused and full-suite outcomes are recorded separately after execution. A
focused pass is not a complete repository pass, and pre-existing failures remain
reported rather than rebaselined.
