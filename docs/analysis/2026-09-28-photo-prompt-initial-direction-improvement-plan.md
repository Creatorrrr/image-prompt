# Photo Prompt 초기 연출·설정 반영 최종 개선안

작성일: 2026-09-28. 상태: 개선안 구현·관련 구조 검증 완료. 기존 확장 회귀 실패 별도 확인. 저장 강도 2/1 유지. 이미지 생성 미실행.

아래 1~9절은 승인된 개선안이며, 당시 구조를 설명하는 부분은 수정 전 상태를 기준으로 한다. 실제 구현과 검증 결과는 10절에 기록한다.

## 1. 목표와 결정

최초 기본 프롬프트를 작성할 때부터 이번 생성에 적용되는 설정의 의미를 이해하고, 인물·사건·의상·공간·촬영 방식을 하나의 작가적 방향으로 구성한다. 마지막 작가적 패스는 이 방향을 유지하거나 더 선명하게 다듬는 역할을 맡는다.

인물의 매력과 존재감은 장면 속에서 표현한다. 카메라 거리, 노출 정도, 특정 표정이나 의상 하나를 매력의 공통 정답으로 지정하지 않는다. 사용자가 요청한 표현과 실제 설정값이 초기 선택에 영향을 주도록 하고, 결과의 매력은 실제 이미지와 사용자 판단으로 확인한다.

이번 개선은 아래 항목을 함께 적용하는 안이다.

1. 초기 단계에서 읽을 수 있는 짧은 설정 명세와 이번 실행의 설정 요약을 제공한다.
2. `sensual_editorial`에 관능적 의상·소재 표현을 포함하고 `fetish_fashion`과 함께 사용할 수 있게 한다.
3. 숫자마다 의미를 제공하고, 실제 값과 맞지 않는 고정된 저강도 안내를 없앤다.
4. 사용자 지정 사항은 세부 속성 수준으로 보호하고, 지정하지 않은 선택지는 남긴다.
5. 구성 전체에 영향을 주는 다른 설정도 초기에 고려한다.
6. 최종 검증에서 설정 전달, 프롬프트의 표현, 이미지의 표현, 사용자 선호를 구분한다.

현재 저장값인 `sensual_editorial=2`, `fetish_fashion=1` 자체를 올리거나 내리는 변경은 포함하지 않는다. 기존 작가적 방향 수립과 마지막 정리 단계도 유지한다.

## 2. 개선 전 구조에서 확인한 원인

| 현재 구조 | 결과에 미칠 수 있는 영향 |
|---|---|
| 코어 작성 전에는 `SKILL.md`와 중립적인 관찰 항목 목록 외의 프로젝트 자료를 읽을 수 없다. 설정 정의가 있는 assets·references·scripts는 제외된다. | 사용자 대화에 직접 나온 의도는 반영할 수 있지만, 저장된 기본 설정과 그 해석은 초안에 전달되지 않는다. |
| `sensual_editorial`의 허용 차원과 후보 경로에 의상·소재가 빠져 있다. | 의상 선택은 먼저 끝나고, 관능적 방향은 시선·포즈·빛 등으로만 보완하기 쉽다. |
| `appearance` 전체를 잠그는 방식이 남아 있다. | 특정 의상의 종류·색을 보존하려다가 사용자가 지정하지 않은 재단·핏까지 막을 수 있다. |
| 현재 강도 2/1에서도 `configured_low_intensity_default`와 저강도 설명이 사용된다. | 숫자와 자연어 안내가 어긋난다. |
| 감사는 설정값, 허용 차원, 해석문, 실제 프롬프트 구절의 존재를 확인한다. | 강도 2에 맞는 인상이 실제로 드러나는지는 확인하지 못한다. |

따라서 초기 설정 전달만 고쳐서는 충분하지 않다. 적용 범위와 강도 의미, 잠금 구조, 결과 검토가 함께 맞아야 한다. 이것은 현재 코드에서 확인한 구조적 문제이며, 이미지 모델 내부 동작이나 개선 후 미적 효과까지 입증한 것은 아니다.

## 3. 초기 단계에 설정을 전달하는 방법

### 허용할 자료

기존 코어 작성 전 허용 목록에 **창작 설정의 정의와 이번 실행에 확정된 값**을 추가한다. `precore/creative_controls.json`을 단일 명세로 두고, 관련 값과 의미를 담은 실행 요약을 만든다. 이 경로와 실행 요약을 구현했으며 실제 인터페이스는 10절에 기록한다.

요약에는 설정별 이름, 적용값, 범위 또는 선택지, 해당 값의 의미, 출처를 담는다. 활성화되었거나 요청 해석에 필요한 설정만 보여준다. 의상 목록, 프리셋 문장, 과거 성공 사례, 후보 팩은 초기 자료에 추가하지 않는다. 짧은 강도 설명은 읽을 수 있지만 예시의 복장을 그대로 선택하도록 만들지 않는다.

### 해석과 출처

- 먼저 사용자의 요청 의미와 참고 이미지의 사용 범위를 파악한다. 설정 명세가 낯선 요청어의 뜻을 대신 정의하지 않는다.
- 사용자 명시 사항과 이번 요청에 적용되는 명시적 설정을 우선하고, 미지정 값에는 저장된 설정과 내장 기본값을 순서대로 사용한다. 기본값으로 사용자 지정 복장·상황·제외사항을 덮어쓰지 않는다.
- 설정값은 코어 작성 전에 한 번 확정한다. 후속 후보 검색·작성·감사에서도 같은 값을 사용한다. 중간에 변경된 저장 설정을 다시 읽어 같은 실행의 값이 달라지지 않게 한다.
- 실제 사용자 문장, 저장 설정, 에이전트의 연출 선택을 구분한다. 설정 설명을 `source_request`나 사용자 인용문으로 넣지 않는다. 저장된 기본값으로 사용자 소유의 잠금·주장을 만들어내지 않는다.
- 실행 요약과 명세의 버전·해시를 코어 및 후속 산출물과 연결한다. 기존 요청·코어 바인딩 구조를 활용하고 중복 기록을 늘리지 않는다.
- 기본값 해석은 후보 검색 없이 수행한다. 명세를 읽는 제한적인 준비 경로를 허용하고, 초기 프롬프트 작성자에게 구현 코드나 후보 데이터 전체를 제공하지 않는다.

## 4. 초기에 고려할 설정과 후기에 남길 설정

| 설정·정보 | 최초 기본 프롬프트에서 고려할 내용 | 적용 방식 |
|---|---|---|
| `sensual_editorial` | 관능적 인상을 의상·자세·표정·빛·장면 관계에 어떻게 반영할지 | 적용값과 강도 의미를 초기에 제공 |
| `fetish_fashion` | 소재·구조·액세서리의 패션 표현을 장면에 어떻게 통합할지 | 적용값과 강도 의미를 초기에 제공 |
| `adult_appeal_emphasis` | 두 축 중 무엇이 연출을 이끌고 무엇이 보조할지 | 두 강도 및 명시적 선택과 일관되게 해석. 비활성 축을 다시 켜지 않음 |
| `creativity` | 사용자 지정 사항을 지키면서 미지정 부분을 얼마나 새롭게 해석할지 | 0~1 값과 의미 제공. 예술성 점수나 기괴함의 의무로 사용하지 않음 |
| 의도한 감상 경험·사용 목적 | 친밀함, 긴장감, 장엄함 등 이미지가 남길 주된 인상과 시각적 중심 | 기존 `interpreted_intent`·`visual_priorities` 활용. `viewer_experience`의 on/off와 감상 목표 자체를 구분 |
| 참고 이미지의 사용 범위·`reference_edit_mode` | 얼굴·헤어·의상·색감·구도 중 무엇을 참고하고 보존할지 | 요청에서 지정한 범위를 초기에 확정. 얼굴 참고를 전신 복장 고정으로 확대하지 않음 |
| `surreal_mode`·`surreal_intensity` | 활성화된 경우 현실성과 비현실적 설정을 장면 전체에 어떻게 결합할지 | `auto`는 한 번 결정해 공유. 추가 레이어 off가 사용자가 요청한 판타지 장면을 제거하지 않음 |
| `trend_layer` | 활성화된 레트로 플래시·콜라주 등의 형식이 구도·빛·재질에 미치는 영향 | 선택된 방향을 초기에 고려하고 마지막에 중복 삽입하지 않음 |
| 사용자가 정한 화면 비율·용도·필수 문구 | 구도, 여백, 시선 흐름, 글자 배치 | 기존 사용자 요구사항으로 우선 반영 |

`surreal_intensity`의 현재 설명은 추가 슬롯 수에 가깝다. 이를 곧바로 시각적 강도라고 설명하지 않는다. 기존 슬롯 수 제어를 내부 동작으로 유지하면서 초기에 제공할 미적 의미를 별도로 명확하게 정하거나, 버전을 올려 의미를 바꾸는 선택을 구현 전에 확정한다.

추가하면 유용한 연출 정보는 **촬영의 연출 정도**(스냅·연출 화보·정제된 광고)와 **장면의 정보 밀도**(집중된 구성·맥락이 풍부한 구성)다. 첫 구현에서는 기존 의도 해석에 짧게 기록한다. 새로운 필수 숫자 파라미터로 만들지 않고, 요청과 주된 연출 방향에서 선택한다. 사용자가 값을 직접 지정할 필요가 확인될 때만 별도 옵션을 도입한다.

다음 항목은 초기 예술적 방향을 정하는 독립 설정으로 확대하지 않는다.

- `detail_level`: 프롬프트의 표현 분량을 조절한다. 장면의 복잡도와 동일시하지 않는다.
- `novelty`, `semantic_weight`, `semantic_profile`, `filter_strictness`: 검색·후보 선택을 위한 내부 설정으로 유지한다. `creativity`와 중복되는 별도 미적 지시를 만들지 않는다.
- 후보 수·선택 예산·seed: 검색과 재현성 제어로 유지한다.
- `artistic_final_touch`: 필요한 경우 후기에 사용하는 표면 표현 보완이다. 최초의 작가적 방향과 동일시하거나 고정 문구를 앞으로 옮기지 않는다.

## 5. 두 축의 범위와 강도

### 표현 범위

`sensual_editorial`은 인물의 관능적 분위기와 표현을 담당한다. 시선·표정·자세·몸의 선·조명·프레이밍뿐 아니라 의상의 핏, 재단, 넥라인, 드레이프, 소재, 피부가 드러나는 방식도 선택 수단에 포함한다. 잠기지 않은 `appearance`·`material`을 허용 범위에 추가하고 관련 후보 경로도 맞춘다.

`fetish_fashion`은 가죽·라텍스·코르셋·스트랩·장갑·부츠 등 소재와 구조, 액세서리에서 드러나는 패션 어법을 담당한다. 이 목록은 예시이며 필수 의상 목록이 아니다. 가죽 가방 끈이나 새틴 소재가 있다는 사실만으로 해당 어법이 구현되었다고 판단하지 않는다.

같은 의상이 두 축에 기여할 수 있다. 관능적 의상을 전부 `fetish_fashion`으로 넘기거나 서로 다른 의상·소품을 하나씩 덧붙이게 하지 않는다. 장면에 적합한 하나의 스타일링 안에서 두 방향을 조화시킨다.

### 0~3의 의미

| 값 | `sensual_editorial` | `fetish_fashion` |
|---|---|---|
| 0 | 이 축에 의한 추가 관능 연출을 하지 않음 | 이 축에 의한 추가 패션 연출을 하지 않음 |
| 1 | 관능적 인상이 은은한 보조 요소로 드러남 | 해당 패션 어법이 제한적인 보조 요소로 드러남 |
| 2 | 의상 또는 인물 표현과 장면의 관계에서 관능적 방향이 분명하게 읽힘 | 의상·소재·구조·액세서리의 선택에서 해당 패션 방향이 분명하게 읽힘 |
| 3 | 관능적 표현이 이미지의 미적 방향을 주도함 | 해당 패션 어법이 스타일링의 미적 방향을 주도함 |

이는 정성적 순서 척도다. 2가 1의 두 배라는 뜻도, 노출 면적의 비율도, 완성도 점수도 아니다. 강도 0은 사용자가 이미 요청한 표현을 제거하라는 지시가 아니다. 강도 3도 사용자 지정 장면과 잠금을 무시할 권한을 주지 않는다.

높은 값에서 단순히 수식어·포즈·액세서리를 늘리지 않는다. 적은 선택으로 강한 인상을 만들 수 있고, 많은 디테일이 있어도 축의 성격이 드러나지 않을 수 있다. 노출이나 가슴골은 가능한 표현 수단으로 다룰 수 있지만 강도별 필수 조건으로 지정하지 않는다. 반대로 가리는 의상이나 추가 안감을 숨은 기본값으로 넣지도 않는다.

초기 작성자에게는 최소·최대값뿐 아니라 이 정의, 현재 값에 해당하는 설명, 설정 출처를 함께 제공한다. 현재 값이 2인데 저강도라고 안내하는 메타데이터와 문구는 실제 값에 맞게 수정한다.

## 6. 사용자 지정 사항을 세부 속성으로 보호

사용자가 “찢어진 흰 드레스”를 지정했다면 드레스라는 종류, 흰색, 찢어진 상태와 그 말에 필수적으로 포함되는 형태를 보호한다. 별도로 지정하지 않은 핏·넥라인·드레이프는 요청 의미와 참고 범위를 유지하는 안에서 선택할 수 있게 한다. “참고 이미지의 의상을 그대로”처럼 의상 전체를 지정한 경우에는 그 범위 전체를 보존한다.

구현에서는 기존 `intent_lock`을 버전이 있는 세부 속성 표현으로 확장한다. `appearance` 전체 잠금을 단순 삭제하는 방식은 사용하지 않는다. 어떤 속성이 사용자 요구로 고정됐는지, 어떤 속성이 열려 있는지를 표현하고 후보·직접 작성 문장 모두 같은 경계를 적용한다. 다른 차원을 경유해 고정된 의상의 종류나 색을 바꾸는 우회도 막는다.

에이전트가 초안에서 선택한 카디건·티셔츠·손 위치는 사용자 지정 사항과 구분한다. 코어 동결은 초안과 출처를 보존하며, 사용자 요구에 묶이지 않은 연출 선택은 최종 구성에서 다듬을 수 있다. 필수 증거 문구도 실제 사용자 의미를 증명하는 범위로 작성해 부수적인 선택까지 잠기지 않게 한다.

남은 자유도로 설정의 의도를 충분히 표현할 수 없다면 요청한 강도와 제약 사유를 함께 남긴다. 전체 축을 불필요하게 꺼버리거나, 약한 표현을 강도 2의 성공으로 보고하지 않는다. 실제 표현 정도는 후속 검토에서 판단한다.

기존 팩·코어는 저장 당시 계약으로 읽는다. 새 계약이 없는 과거 산출물을 세부 속성 방식으로 재해석하지 않는다.

## 7. 개선 후 작성 흐름

1. 사용자 요청의 의미, 참고 범위, 고정 사항을 파악한다.
2. 이번 실행의 관련 설정과 강도 의미를 확정한다.
3. 주된 감상 경험과 작가적 방향을 정한다. 인물·의상·장면·빛·촬영 방식을 함께 선택한다.
4. 이미 완결된 사진으로 읽히는 기본 프롬프트를 작성하고, 필요한 공간·신체 관계와 설정 반영을 검토한 뒤 코어를 동결한다.
5. 후보 자료를 조회해 정확성이나 표현에 도움이 되는 내용만 채택한다.
6. 마지막 작가적 패스에서 시각적 중심을 강화하고, 겹치는 지시와 불필요한 장식을 줄인다. 이미 충분한 축을 증명하려고 새로운 디테일을 반드시 추가하지 않는다.
7. 최종 문장과 런타임 입력을 확인한다. 이미지 생성이 요청된 경우 실제 결과의 표현과 매력을 별도로 검토한다.

기존 `interpreted_intent`, `visual_priorities`, 축별 해석 기록을 활용한다. 매 단계 같은 내용을 다시 쓰게 하거나 새로운 예술성 점수·최소 변경 수·노출량·카메라 거리 기준을 추가하지 않는다. `creativity`가 높아도 초기 단계에 후보 개수나 기발한 아이디어 개수 할당을 옮기지 않는다.

## 9. 검증과 완료 기준

### 구조·동작 검증

- 초기 작성과 후보 팩·최종 작성에서 같은 값·정의·출처를 사용한다.
- 설정 2/1을 저강도라고 고정 설명하지 않는다. 값 0도 명시적인 사용자 요구를 삭제하지 않는다.
- 두 축이 의상에 함께 기여할 수 있고, 구체적인 사용자 지정 사항과 참고 범위는 유지된다.
- 초안의 임의 선택이 사용자 잠금으로 승격되지 않는다. 새 계약과 과거 계약을 각각 올바르게 처리한다.
- 초기 단계에 허용한 설정 외의 후보·과거 프롬프트가 유입되지 않는다.
- 수정된 코드 경로와 기존 감사에 관련된 집중 테스트 및 스킬 형식 검증을 수행한다. 예술적 판단을 단어 개수·문구 매칭 테스트로 대신하지 않는다.

### 프롬프트·이미지 검토

활성화된 축이 어떤 선택에 반영되었는지, 그 선택이 장면과 조화를 이루는지 검토한다. 초안부터 충분히 표현됐다면 후기에 새 문구가 없어도 인정한다. “관능적”, “가죽”, “강도 2”라는 단어의 존재만으로 통과시키지 않는다.

이미지는 설정 정보를 가린 상태에서 전체 인상, 인물의 존재감, 의상과 상황의 조화, 설정 방향의 식별 가능성, 지시를 시연하는 듯한 어색함을 살핀다. 이후 설정과 대조한다. 표현 정도의 평가는 판단 기록이며 정확한 강도 측정치로 발표하지 않는다. 최종적인 매력 개선 여부는 사용자의 비교 판단으로 확인한다.

구현 후 재시험은 최근 비교한 달의 폐허·편의점·손편지 고백 3개 주제와 동일한 요청·참고 이미지로 시작하는 안이다. 각 주제는 독립된 `gpt-6-sol`/`max` 작성자가 처리하며 생성 도구와 전달 입력을 기록한다. 이 문서 작성 자체로 재시험을 실행하지 않는다.

재시험을 진행할 때는 이전에 지정된 안전필터 재시도 조건인 동일 프롬프트로 최대 3회 추가 시도를 기록하며, 첫 성공 이미지를 보존한다. 필터 차단은 이미지 품질 점수와 분리한다. 프롬프트 작성 모델과 이미지 생성 모델을 구분하고, 도구가 실제 이미지 모델 식별자를 공개하지 않으면 확인 불가로 적는다.

한 번씩 생성한 전후 비교는 사례 확인으로 보고한다. 일반적인 개선 효과나 모델 차이의 원인을 판단하려면 같은 입력과 실행 조건을 최대한 맞춘 반복 비교가 필요하다. 이미지 모델·seed를 고정할 수 없다면 그 한계를 명시한다. 이 추가 비교는 별도 실험 범위로 둔다.

완료 조건은 **설정이 최초 선택에 실제로 반영되고, 사용자 지정 의미가 유지되며, 후기 과정이 이를 약화시키거나 기계적으로 덧붙이지 않는 것**이다. 구조 검증 완료와 시각적·사용자 평가 결과는 별도로 보고한다.

## 10. 구현 및 검증 기록

### 반영한 동작

- `precore/creative_controls.json`을 저장값·범위·강도 의미의 단일 원천으로 사용한다. 기존 `sensual_editorial=2`, `fetish_fashion=1`과 일반 v6 `creativity=0.5`를 유지했다. 기존 품질 설정 파일과 CLI는 이 원천을 참조한다.
- `precore/creative_controls.py`가 후보 자료를 읽지 않고 요청별 설정을 확정한다. 실제 요청 해시, 정의 스냅샷, 값의 출처, 적용 조건과 `surreal_mode=auto`의 단일 결정을 기록한다. 코어의 `creative_controls_sha256`와 후속 `--creative-controls-json`이 같은 스냅샷을 연결하며, 뒤늦은 불일치 설정은 거부한다.
- 초안부터 두 축과 `creativity`, 참고 범위, 감상 경험, 활성화된 초현실·트렌드 방향을 함께 고려하도록 스킬을 수정했다. 연출 정도와 정보 밀도는 기존 의도 설명에서 다루며 새로운 필수 숫자 입력은 추가하지 않았다.
- `sensual_editorial`에 의상·소재 차원과 후보 경로를 연결했다. 같은 스타일링이 두 축에 기여할 수 있으며, 강도별 의미와 저장값의 출처를 제공한다. 고정된 저강도 기본 설명과 중복 기본값을 제거했다.
- `photo-intent-lock/v2`는 기존 의미 앵커에 `target`·`property`를 추가해 색·종류 등 지정된 속성을 보호한다. 새 `photo-adult-appeal-dimension-scope/v2`와 후보·직접 작성 경로가 같은 경계를 검사한다. 같은 대상·속성은 다른 차원으로 기록해도 보호하며, 효과 범위가 불명확한 전체 의상 후보로 부분 잠금을 덮어쓰지 않는다. 과거 v1은 당시 범위를 유지한다.
- 초기 표현을 유지하는 `realization: baseline`과 실제로 다듬는 `realization: refined`를 구분했다. 초안에 이미 있는 표현은 새 디테일 없이 유지할 수 있다. 문구·해시·선언 검증이 감각적 강도나 사용자 선호를 입증한다고 설명하지 않는다.
- 요청에 없는 가림 의상·추가 안감을 기본으로 넣는 규칙이나 새로운 안전 판정 체계는 추가하지 않았다. 기존 사용자 제외사항과 적용 조건은 출처를 유지한다.

### 확인한 범위

- 초기 설정·의도 잠금·작가적 코어·자료 격리 관련 집중 테스트 81개가 통과했다(중복 실행 제외). 마지막 속성 잠금 보완 후 설정·축 범위·자료 격리 34개 테스트도 다시 통과했다.
- 기존 생성기·구성 계약의 확장 회귀 344개에서는 14개 테스트에서 15건의 실패가 발생했다. 실패한 모든 항목을 작업 시작 전 코드·assets·테스트 스냅샷으로 재실행해 같은 실패를 확인했다. 변경하지 않은 fixture·연구 문서는 원래 작업 디렉터리의 파일을 사용했다. 전체 저장소나 확장 회귀가 모두 통과했다고 보고하지 않는다.
- 실제 CLI로 설정 확정 → 코어 바인딩 → v6 후보 팩 → 작성된 최종 프롬프트 → 이미지 도구 전달 입력 검증을 실행했다. 구성 감사와 전달 입력 감사 모두 통과했다. 오프라인 rule 모드의 구조 검증이며 이미지 도구 호출은 하지 않았다.
- 달의 폐허·편의점·손편지 고백의 과거 팩은 당시 품질 설정 스냅샷을 사용하면 현재 감사 코드에서 모두 통과했다. 편의점 팩을 새 품질 설정으로 재검사하면 기존 번들의 소스 해시 불일치가 발생한다. 원래 소스 스냅샷으로 재현했으며 해시 검증을 약화하거나 과거 결과를 수정하지 않았다.
- 스킬 형식 검사, 사전 메타데이터 검증, 변경된 Python 모듈 문법 검사, `git diff --check`가 통과했다.

확장 회귀의 기존 실패 분류:

| 분류 | 실패 건수 | 수정 전 재현 결과 |
|---|---:|---|
| 경비원 모에 프리셋 기대값 | 2 | 같은 두 프리셋 불일치 |
| v4 역할 장면의 열린 action 슬롯 기대값 | 2 | 같은 action 누락 |
| 연구 재사용 주석의 `no ` 문자열 요구 | 1 | 같은 문구 불일치 |
| 간호사·경찰 의상의 이전 ID 기대값 | 7 | 같은 새 ID와 이전 ID 불일치 |
| 강제 슬롯 등록 기대값 | 1 | 같은 140개 항목 |
| 의미 인덱스 입력 개수 기대값 | 1 | 동일하게 9168과 6910 불일치 |
| 인덱스 빌더 테스트 복사본의 의존 파일 | 1 | 같은 `photo_candidate_semantics` 누락 |

위 기존 실패를 숨기기 위해 기대값·holdout·연구 문서를 바꾸지 않았다. 이번 변경과 관련한 집중 검증과 기존 실패를 분리한 결과다.

이번 구현에서는 이미지를 새로 생성하지 않았다. 초기 설정의 전달과 선언된 변경 범위는 검증했지만, 작성 순서의 실제 준수와 관능적·작가적 표현의 개선은 작성 결과 및 이미지 비교에서 별도로 확인해야 한다.
