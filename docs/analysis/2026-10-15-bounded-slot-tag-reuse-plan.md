# 기존 검토를 재사용하는 제한된 슬롯 태그 개선 계획

작성일: 2026-10-15, Asia/Seoul. 상태: **계획 작성 완료, 구현·운영 적용 미착수**.

149개 슬롯의 운영 전환은 완료됐다. 이번 후속 작업은 이미 검토한 소수 후보에서 근거가 현재와 일치하는 연결을 추가하거나 보류를 해제하는 것이다. 전체 18,250개 의미 재검토, 전체 보류 해소, 전체 태그 완성을 종료 조건으로 삼지 않는다. 후보 본문·조건·효과·종류를 고쳐야 하는 항목은 후속으로 남긴다.

## 1. 현재 상태와 남은 작업

## 3. 작업량과 중단 경계

- 첫 배치: 위9개 후보·19개 관계만 확인한다. 나머지 긍정75개는 보정이나 재심사로 확장하지 않는다.
- 보충 배치: 기존 파일럿609개 대장의 metadata를 자동 비교해 **후보 최대12개·관계 최대24쌍**을 먼저 고정한다. 선택 후 탈락한 후보의 대체 후보를 찾지 않는다. 적합한 항목이 없으면0개로 종료한다.
- 추가로 원문 의미를 확인하는 범위는 두 배치 합계 **최대21개 후보·43개 관계**다. 이미 적용한6220은 변경 없는 비교 사례로만 사용한다.
- 보충 우선순위는 보류 의존 후보의 복구에 도움이 되는 기존 관계, 새 슬롯의 기검토 관계, 기존 다중 역할 누락 순서다. 동순위는 CID·slot ID로 고정한다. 슬롯마다 후보를 채우거나 동일 후보에 임의로 태그 두 개를 보장하지 않는다.
- 참조 의미가 새 검토를 요구하거나 원문·조건·효과·소유자·종류 보정이 필요하면 보류한다. 참조를 따라 새 후보 의미 심사로 확대하지 않는다. 이미 검증된 참조의 정확한 동일성 확인은 허용한다.
- 전체 ID·참조·중복·무관한 원본 보존의 자동 검사는 수행한다. 이것을 전수 의미 검토로 집계하지 않는다.

## 4. 단계별 구현·검증·커밋 계획

### 1단계 — 재사용 범위와 근거 고정

첫 배치9개와 비교 사례6220의 CID를 기준선에서 읽고 현재 원본·149개 명세·원래 binding·수용 batch/note/acceptance를 결합한다. 보충은 파일럿 대장의 기존 긍정 연결 중 현재와 같은 의미·조건·효과·관련 명세를 가진 항목만 후보로 삼는다. 옛139 catalog의 전체 hash가 다르다는 이유로 모두 다시 읽지 않고, 해당 역할과 판정에 필요한 이웃 의미의 차이를 대조한다. hash 동등성만으로 달라진 명세의 판정을 승격하지 않는다.

최대12개·24쌍의 보충 명단을 원문 재확인 전에 동결한다. 진단·제거 판정·분기 한정·종류 변경·필수 보정이 있는 항목과 원본 조건을 증명할 기존 binding이 없는 추가안은 이번 적용에서 제외한다. 기존 scoped 적용기의 추가 연결 조건을 넓히지 않는다.

검증: CID/관계 중복0, 수용·초안 구분, 기수용 근거의 파일/hash 일치, 고정 상한 준수. 결과는 재사용 검토 대상·보류 이유 목록이며 새 승인 수는0이다. 실행 시 이 단계의 도구·목록·검증 결과만 커밋한다.

### 2단계 — 기존 근거를 현재 관계 판정으로 제한해 재사용

고정한 사례의 원문과 기존 검토 이유·긍정 인용·현재 관련149 명세를 대조한다. 의미·소유자·관찰 대상·분기·직접/맥락 역할과 intrinsic/binding 조건이 유지될 때만 `retain` 또는 `add`를 확정한다. 관련 부분이 달라지거나 근거가 모자라면 `defer`로 종료한다. 보류 이유를 없애기 위한 새 본문·효과·조건·application_contract·native proof를 작성하지 않는다.

기존 `reviewed` 또는 `deferred` metadata와 현재 binding의 정확한 before/after, 수용 파일·JSON pointer·인용, 이번 판단 이유를 연결한다. 첫 배치와 보충의 중복은 한 번만 센다. 운영 의미 자격은1개로 유지하고 태그 검토가 native 효과 권한으로 승격되지 않는지 확인한다. `review_required`가 남는 후보는 그대로 보고한다.

검증: 기존 의미 근거의 유효성, 보류 해제 이유, 음성/인접 역할 경계, 원래 조건 보존. 전체 역할을 새로 심사했다고 표시하지 않는다. 확정된 관계 판정과 관련 검사 후 별도 커밋한다.

### 3단계 — 격리 적용과 무결성 검증

현재149 catalog를 그대로 둔 명시적 scoped manifest로 확정한 관계만 새 staging 디렉터리에 적용한다. 해제는 해당 binding의 보류 metadata만 옮기고 원래 ID·조건·role·weight를 보존한다. 추가는 같은 후보의 기존 binding 조건·role·weight를 정확히 계승하는 witness와 결정적 ID를 요구한다. 원문 후보와 비대상 연결·정책은 유지한다. 이미 존재하는 관계를 중복 추가하지 않는다.

참조된 관계 삭제·전역 guard 완화·optional member 의존성 차단 해제는 하지 않는다. 기존 구현으로 표현할 수 없는 항목은 보류하고 일반 태그 자동 부착기나 전수 native 도구의 gate 우회를 만들지 않는다.

검증: 전체18,250 CID 보존, 후보 원본·149 catalog 불변, 중복 관계/고아 참조0, 정확한 변경 allowlist, 멱등 재실행 또는 이미 적용 상태의 명확한 거부. 보류 의존 closure를 다시 계산해 복구·계속 중지 후보를 구분한다. 격리 산출물과 검증을 별도 커밋한다.

### 4단계 — 운영 반영과 로컬 검색 데이터 갱신

검증한 연결·정책만 운영 assets에 반영한다. 현재18,180 positive 문서의 전체 입력 text·ID·모델·차원·recipe가 같을 때만 기존 로컬 벡터를 재사용한다. 태그 metadata 변경으로 문서 입력이 예상과 다르게 달라지면 원인을 확인하고 해당 사례를 제외하며 범위를 넓히지 않는다. 후보 본문이나 positive 집합 변경은 이번 계획에 포함하지 않는다.

BM25F 통계·payload·routing·manifest의 필요한 파생 closure를 갱신하고 검증한다. 슬롯 검색 대상은 전체 공통 positive 풀이고 태그 필터·태그 수에 따른 추가 RRF 투표를 만들지 않는다. Gemini·외부 심사·모델 다운로드 없이 설치된 고정 로컬 공간만 사용한다.

검증: 같은 공간 벡터의 정확 재사용, 원본/인덱스 일치, 실제 운영 acquire와 보류 차단. 변경 원본과 대응하는 인덱스를 같은 단계에서 완성한 뒤 커밋한다.

### 5단계 — 제한된 의미 회귀·149개 기술 검증·마감

영향받은 역할의 기존 양성·인접 음성·owner/조건·제외 사례를 재사용해 추가/해제 관계가 예상대로 제시되는지 확인한다. `review_required` 또는 조건 부적합이면 자동 채택 성공으로 세지 않는다. 보류가 남은 구성원의 묶음은 계속 차단되는지, 원래 다른 역할의 검색을 해치지 않았는지 확인한다.

동결된149개 질의의 BM25F+로컬 cosine/RRF, issued receipt 발급·실제 재생·독립 감사를 새 source/index/generation으로 실행한다. 질의 text·모델·recipe가 같은 벡터는 정확 cache를 재사용하되 과거 receipt/source hash를 새 결과로 바꾸지 않는다. cache가 없으면 해당 질의만 로컬 추론한다. 이는 기술 회귀이며149개 슬롯 의미를 전수 재검토하는 작업이 아니다.

관련 전체 스캔 oracle과 lazy 순위·생략 근거·64MiB reader cache·64개 descriptor 한도를 확인한다. 모든 질의가 적은 shard만 읽는다고 주장하지 않고 실제 읽기량과 필요 시 streaming을 보고한다. 운영 경로를 변경하지 않은 검사·이미지·새1,000개 표본·전수 benchmark를 추가하지 않는다. 현재 기술 경로의 실패가 생기면 해당 변경을 고치거나 제외한 뒤 영향 범위를 다시 검증한다.

실제 확정/적용/보류 수, 추가/해제/유지 관계, 의존 후보 복구 수, native 자격1 유지, 원본·무관한 작업 보존, Gemini0, 생략 범위를 최신 대장과 결과 리포트에 남긴다. 이 단계 결과를 커밋하고 종료한다. 변경0개여도 이유와 검증이 완결되면 제한된 계획은 완료할 수 있다.

## 5. 완료 기준과 계속 남길 일

완료 기준은 고정된 두 배치의 모든 사례가 적용 또는 사유 있는 보류로 끝나고, 실제 변경의 무결성·검색·재생·운영 반영이 검증되는 것이다. **3,489개 보류0·전체 태그 완성·149개 슬롯별 최소 연결 수를 요구하지 않는다.** 첫 배치 최대 신규10/해제6은 상한이며 실적 약속이 아니다. 보충도24쌍 이내이며0개를 허용한다.

나머지 보류, 운영 원본 보정이 필요한 연구 승인, 옛 초안의 최종149 자격화, 새 역할 후보 발굴, 전체 의미 정확도 평가는 후속으로 남긴다. 재사용 후보가 부족해도 이 항목으로 확대하지 않는다. 실제 native 자격 추가가 필요해지면 별도 작업으로 정하고 이번 관계 개선의 필수 조건으로 삼지 않는다.

이번 요청에서는 계획 문서와 읽기 전용 기준선만 작성했다. 운영 데이터·코드·인덱스·활성 runtime을 변경하거나 구현 커밋·push를 수행하지 않았다. 후속 실행에서는 단계마다 구현·검증 후 해당 변경만 커밋하며, 무관한174개 기존 tracked 변경과 미추적 작업을 보존한다.
