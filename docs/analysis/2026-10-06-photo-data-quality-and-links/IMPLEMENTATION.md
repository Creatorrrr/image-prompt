# 구현과 독립 검증 결과

작성일: 2026-10-07. 설계의 P0–P3를 구현했다. 후보와 시각 의미 원본은 계속 분리하며 기존 번들의 선언을 연결의 원본으로 사용한다. 사용법은 [관리 도구 README](../../../tools/photo_data_maintenance/README.md)에 있다.

## 반영 내용

- `audit`: 전체 등록 원본의 출처·내용 수집, 구조 오류와 동일 표현 등의 검토 단서. 오류가 있는 draft도 입력과 진단을 보존하며 정상 연결 조회는 차단한다.
- `build`: 검증된 불변 런타임 세대에서 후보·번들·프로필과 명시적 edge를 생성한다.
- `query`: 후보 → 번들 → 시각 의미 및 역방향을 같은 graph에서 조회한다. 다대다 경로를 보존하고 미연결을 허용한다.
- `diff`: 추가·삭제·내용 변경·출처 이동·관련 검토의 stale 상태를 구분한다.
- 현재 조회: 실제 source root, 검증 세대와 원본 지문, 도구 코드·레시피와 파일 해시를 결합한다. 검증 세대의 inventory도 독립 재계산한다. 관리 `CURRENT` 게시 경쟁과 게시 중 원본 변경을 거부한다.
- 검토 기록: 전체 항목 내용 해시를 결합한 판단 3건(유지 2, 보류 1)과 부분 연관 경로 1건을 보존한다. 자동 의미 확정·중복 삭제·필수 활성화는 수행하지 않는다.

새 파일을 등록하거나 새 행을 추가한 뒤 기존 검증·인덱스 재생성·세대 게시를 완료하고 `build`하면 전체 명시적 관계가 갱신된다. 이전 보고서는 고정 조회에 남으며 현재 조회는 낡은 보고서를 현재 결과로 반환하지 않는다. 최신성 기준은 지정한 로컬 원본이며 원격 Git 갱신은 별도 기존 절차의 책임이다.

## 실제 데이터 점검

깨끗한 작업 기준은 `origin/main`에서 관측한 `96e20422316276a4e0b5ed97f44152e4931e7504`다. 작업 브랜치와 현재 주 작업 폴더는 데이터가 다르므로 결과를 구분했다.

| 범위 | 후보 | 번들 | 시각 의미 | 명시적 edge | 구조 오류 | 의미 검토 단서 |
|---|---:|---:|---:|---:|---:|---:|
| 격리된 기준 + 이번 정비 | 10,360 | 964 | 2,193 | 2,971 | 0 | 46 |
| 기존 별도 데이터를 보존한 주 작업 폴더 | 10,440 | 1,031 | 2,249 | 3,105 | 0 | 46 |

46건은 실질 중복 확정이나 전수 의미 정비 완료 건수가 아니다. 43건은 미검토이고 3건에 유지·보류 근거가 있다. 미연결 항목은 정상 정보다. 연결은 전체 외형 충족·필수 활성화·검색 노출의 증거가 아니다.

실제 입력에서 확인한 세 항목만 원본 정비했다.

1. `cello_endpin_seated_bowed`: 역할명만으로 앉은 첼로 연주 자세가 필수가 되던 문제를 수정했다. 악기·활 연주·앉은 지지 조건을 요구하고 활 검사 문맥을 제외한다. 명시적으로 앉아서 활로 연주하는 영어·한국어 긍정 사례는 유지한다.
2. `pr_casual_crop_subject_legibility_candidate`: adult와 행위의 가독성을 전제하므로 human 범위를 명시했다.
3. `rb_shared_wind_response_candidate`: 모발·옷자락을 함께 전제하므로 human 범위를 명시했다.

세 항목의 조건만 달라졌다. 선언된 연결·ID·외형 서술은 보존했다. [최종 diff](../../research-evidence/photo-prompt/data-quality-links-20261007/SEMANTIC-DIFF-FINAL.json)는 내용 변경 항목이 정확히 이 세 개이며 추가·삭제·출처 이동이 없음을 보여준다. 두 인덱스는 공식 빌더와 batch size 1로 다시 만들었으며 semantic 10,396개와 visual 2,193개의 정확한 텍스트·벡터 공간 일치를 확인해 전부 재사용했다. 주 작업 폴더에서도 10,476개·2,249개를 전부 재사용했다. 임베딩 호출과 네트워크 접근은 차단한 상태로 실행했다.

## 다섯 독립 프롬프트 사례

주제 선택은 분야별 후보 풀에서 seed `4146498122124364748`로 무작위 추출했다. 원본 요청은 검증용 합성 사례임을 기록했다. 각 서브에이전트에는 전체 부모 대화를 전달하지 않았고, 별도 venv·skill·runtime store·출력 폴더를 제공했다.

모든 사례가 DATA에 접근하기 전에 요청 envelope와 baseline·core·controls·features·embodiment를 동결했다. 이후 불변 세대의 regular read-only 원본만 전달했다. 최초 결과를 보존하고 같은 입력으로 수정 세대에서 다시 작성·검증했다. 기술적 schema 사본의 변경은 원본과 구분해 기록했으며 의미 변경으로 감사 결과를 맞추지 않았다.

다섯 실제 프롬프트 사례는 API 호출 없이 lexical 검색 경로로 실행했다. embedding-only/융합/선택 후 의무 승격 경계는 기존 visual 회귀에서 별도로 검증했다. 외부 임베딩 서비스의 실제 응답 품질을 이 사례들로 평가했다고 주장하지 않는다.

| 사례 | 주제 | 공식 프롬프트 감사 | 요청 의미 | 연결·현재성 |
|---|---|---|---|---|
| 01 | 바닷바람 속 공연 전 활을 확인하는 성인 첼리스트 | PASS | PASS | PASS |
| 02 | 아침 자연광의 구리 주전자와 접힌 리넨 | PASS | PASS | PASS |
| 03 | 뒤쪽 아침 햇빛이 비추는 숲속 폭포 물보라 | PASS | PASS | PASS |
| 04 | 겨울 저녁 기차역 플랫폼 지붕의 빗물 자국 | PASS | PASS | PASS |
| 05 | 낮은 옆빛으로 보는 마른 솔방울 접사 | PASS | PASS | PASS |

첨부 증거는 [다섯 사례의 프롬프트와 평가](../../research-evidence/photo-prompt/data-quality-links-20261007/QA-SUMMARY.md)에 모았다. 각 에이전트는 원본 참조에서 전체 2,971개 edge를 별도로 계산해 대조하고 노출 후보·관련 프로필의 양방향 경로를 검사했다. 정상 현재 조회, 손상 보고서, 잘못된 source root의 거부를 확인했다. 최종 도구의 draft 형식 방어 수정 뒤에도 별도 최종 도구 복사본으로 관리 결과와 현재성 검사를 재확인했다.

첼리스트 최초 감사는 잘못 활성화된 연주 의무 4개 때문에 실패했다. 수정 뒤 동일한 baseline으로 실패 0개가 됐다. 나머지 사례에서도 정비한 두 인물 전제 후보가 사람 없는 문맥에서 제외되는 것을 확인했다. `uncovered_intent` 경고는 후보 채택 대신 직접 서술로 요청 앵커를 보존했다는 비차단 경고이며 결과에서 숨기지 않았다.

## 구현 회귀와 보존

최종 관리 도구 32개, 데이터 정비 후 악기·범위 11개와 visual retrieval·의무·선택/렌더 검토 40개의 테스트가 통과했다. 기존 구조·freshness·후보 의미 49개는 관리 도구 구현 단계의 기준 검사에서 통과했으며, 최종 DATA 전체 재실행 결과로 합산하지 않는다. 사전 단독 실행의 잘못된 테스트 모듈 이름은 정정하여 실제 두 visual 모듈만 실행한 최종 로그를 사용했다. dictionary/index 검증도 통과했다. 주 작업 폴더의 최종 관리·범위 테스트는 36개 통과했다.

독립 코드 검토와 입력 반례에서 찾은 세 문제를 수정했다: 품질 설정 파일의 draft 수집 누락, 잘못된 semantics 형식의 처리, 잘못된 슬롯 collection 형식의 처리. 최종 독립 반례 검사에서는 배열/문자열 슬롯·문자열 semantics·배열형 품질 설정을 오류 보고서로 보존했고 품질 설정의 수집 중 변경도 거부했다. 원본 바이트와 manifest 해시를 직접 대조했다.

V32와 이전 동결 fixture는 수정한 현재 DATA로 재해석하지 않는다. 작업 브랜치에서 원본 Git blob·mode·sha256을 인증하는 원본 복구와 V33 후속 경계를 추가했다. 현재 검증과 과거 재현의 Python 환경도 구분한다. 최종 history 실행 결과는 해당 [history 기록](../../research-evidence/photo-prompt/data-quality-links-20261007/history/README.md)에 있다.

V33·history의 현재 테스트 16개, 원본 V32 assertion 28개와 그 재현 wrapper가 통과했다. V32는 원본과 같은 CPython 3.12.14/Unicode 15.0.0을 선택하고, V33와 다섯 사례는 현재 3.14.3에서 검증했다. 기존 동결 파일 132개가 기준 Git 원본과 바이트 단위로 동일함을 확인했다. 새로운 원본 snapshot은 9개·12.6MB이며 기존 보관 파일을 재사용했다.

주 작업 폴더에는 관리 도구·테스트와 세 항목의 수정만 반영하고 그 폴더의 실제 전체 원본으로 파생 인덱스를 재생성했다. 별도 작업의 기존 파일 149개 해시를 유지했다. 최신 main 기준의 V33 동결 경계 검증은 격리 작업 브랜치에서 수행하며, 주 작업 폴더의 별도 DATA를 그 qualification에 섞지 않는다. 커밋·푸시는 수행하지 않았다.

## 판단과 남은 범위

새 관리 기능은 정상 동작한다. 앞으로 원본이 늘어도 등록 원본과 명시적 연결을 다시 추출하는 구조이며, 양쪽 참조를 별도 수작업으로 갱신하지 않는다. 전체 항목의 관계를 의미 유사도로 일괄 추론할 필요도 없다.

프롬프트 감사와 요청 보존은 다섯 사례에서 통과했지만 전체 후보 풀의 의미 호환이 보장된 것은 아니다. 일부 기존 horror/mockumentary 등의 인물 전제 후보가 사람 없는 요청에서 advisory로 노출되는 사례와 scope 밖 제안은 미채택 상태로 기록했다. 이 항목들은 P3의 후속 의미 정비 목록이며 관리 graph의 명시적 연결 정확성과 구분한다. 주전자 문장에는 반사광·확산광의 소유가 모호한 표현도 남아 있다.

작품 판단은 텍스트 수준의 부분 검토다. 이미지 생성, 실제 픽셀 품질, 사용자 수용은 검증하지 않았다. P4의 새 관계 보강, 46건의 전수 의미 판정, 미연결 전량 해소는 이번 작업에 포함하지 않았다.
