# 후보·시각 의미 데이터 점검과 양방향 연결 조회 설계

작성일: 2026-10-06 · 구현 반영일: 2026-10-07 · 결과: [IMPLEMENTATION.md](IMPLEMENTATION.md)

이 문서는 전체 원본의 품질 점검, 기존 명시적 연결의 양방향 조회, 필요한 관계의 추가 검토를 설계한다. 구현 순서와 완료 조건은 [WORK_PLAN.md](WORK_PLAN.md)에 둔다. 설계 작성 당시에는 운영 데이터와 코드를 수정하지 않았으며, 후속 구현과 검증 결과는 [IMPLEMENTATION.md](IMPLEMENTATION.md)에 기록했다.

## 1. 결정과 범위

**전체 원본을 자동 점검하고 기존 참조로 관리용 연결 조회를 만든 다음, 발견된 문제를 우선순위에 따라 정비한다.** 모든 설명을 완벽하게 고치거나 모든 후보와 시각 의미의 관계를 새로 추론하는 일을 조회 기능의 선행 조건으로 두지 않는다.

- 후보 원본과 시각 의미 원본은 분리해서 유지한다. 기존 번들이 연결 선언의 원본이다.
- 역방향 목록은 생성물이다. 프로필과 후보 양쪽에 같은 연결을 수동으로 작성하지 않는다.
- 연결은 여러 후보·번들·프로필 사이에 성립할 수 있다. 미연결 항목도 정상일 수 있다.
- 관리용 연결은 검색 순위, 후보 채택, 시각 의미의 필수 활성화 규칙에 사용하지 않는다.
- 번들 경유 연관과 의미 전체의 충족을 구분한다. 명시적 참조의 존재만으로 의미 검토가 끝났다고 표시하지 않는다.
- 기존 벡터 샤드 수를 유지한다. 조회 기능 자체는 새 임베딩, 이미지 생성, 그래프 DB를 요구하지 않는다.
- 관리용 도구와 검토 기록은 운영 스킬의 원본·실행 코드 경로 밖에 둔다. 독립 초안·코어 동결 전의 실시간 요청 처리에는 연결 조회를 추가하지 않는다.

## 3. 원본 상태를 구분하는 두 입력 방식

### 편집 중 원본 점검: `draft`

잘못된 참조 때문에 정상 로더가 실패하더라도 오류를 모아서 보여줄 수 있어야 한다.

1. 명시된 스킬 루트의 매니페스트를 읽고 기본·등록 원본을 수집한다. 등록 누락 파일은 진단 대상으로 표시하며 정상 코퍼스에 자동 편입하지 않는다.
2. JSON 중복 키, 구문 오류, 파일 누락을 보고한다. 한 파일의 오류 때문에 다른 읽을 수 있는 파일의 진단까지 중단하지 않는다.
3. 읽은 원본 바이트를 관리 보고서의 입력 보관 영역에 복사하고 해시를 기록한다. 필요한 JSON만 보관하며 벡터 본문 전체를 복제하지 않는다.
4. 수집 전후의 파일 존재·해시·매니페스트와, 사용할 수 있는 협력 편집 epoch를 확인한다. 수집 도중 변경되면 `capture_changed`로 실패하고 완성된 보고서처럼 게시하지 않는다.
5. 정상 컴파일이 가능한 항목은 기존 검증기를 재사용한다. 무효 항목과 해석 불가능한 참조는 진단에 남긴다.

출력에는 `input_mode=draft`, `validation_status=incomplete|invalid|structurally_checked`를 표시한다. 오류가 있는 입력의 부분 연결은 진단 전용이며 정상 조회 대상으로 게시하지 않는다. 해시가 안정됐다는 사실은 비협력 편집자의 여러 파일 수정이 논리적으로 완료됐다는 증거가 아니다. draft 결과를 검증·게시된 운영 세대로 표현하지 않는다.

### 검증·게시된 세대의 연결 조회: `generation`

명시한 세대 ID를 기존 `RuntimeSnapshotProvider.load_generation(..., independent_audit=True)`로 검증한 뒤, 그 세대의 루트에서 원본 위치와 컴파일 결과를 함께 읽는다. 해당 세대의 코드·Python 환경과 호환되는 프로세스를 사용한다. 코드가 맞지 않으면 기존 오류를 보여주고 새 코드로 과거 자료를 재해석하지 않는다.

최신 상태를 요구하는 관리 조회는 로컬 모드의 `acquire(bootstrap=False)`로 확인한 세대와 보고서 세대를 비교한다. 원본 변경이 미게시 상태이거나 세대가 다르면 최신 조회로 반환하지 않는다. 기존 준비 캐시의 검증·복구는 기존 정책을 따른다. 관리 도구는 원본·필수 인덱스·런타임 CURRENT를 자동 수정하거나 원격 fetch를 실행하지 않는다.

역사 조회는 고정된 세대를 명시해 허용하며 `historical`로 표시한다. 새 보고서가 없을 때 이전 보고서를 최신 결과로 대체하지 않는다.

## 4. 품질 점검과 판정

모든 원본을 점검하되 자동으로 확정할 수 있는 오류와 의미 검토가 필요한 의심을 구분한다.

| 분류 | 점검 대상 | 기본 처리 |
|---|---|---|
| 구조 오류 | 중복 JSON 키, 잘못된 스키마, 같은 슬롯의 ID 충돌, 프로필·번들 ID 충돌, 참조 누락·모호함, canonical 참조 순환 | 해당 입력의 정상 연결 게시 차단 |
| 원본·파생 모순 | authored 구성요소와 증거·지시·검증 기준의 충돌, 잘못된 구성요소 참조 | 기존 컴파일러·검증기로 차단 |
| 중복 의심 | 동일 설명, 동일 positive text, 사실상 같은 요소·조건을 가진 별도 항목 | 검토 목록. 자동 삭제·합병하지 않음 |
| 모호한 설명 | 대상·위치·형태·관계·조건이 빠진 설명, 추상 라벨만 있는 항목 | 원문·필드·이유를 보여주고 의미 검토 |
| 관계 의심 | 번들 설명과 구성원의 불일치, 프로필의 필수 조건과 번들 설명의 충돌, 부분 지원을 전체 구현으로 설명함 | 해당 관계의 의미 검토 상태 표시 |
| 정상적인 겹침 | 후보와 프로필의 역할에 따른 반복, 대상·조건·슬롯·변형이 다른 유사 항목 | 차이와 유지 근거를 기록 |
| 미연결 | 관련 프로필 없는 번들, 번들에 참여하지 않는 후보, 후보 연결이 없는 프로필 | 정보. 연결 생성이나 실패를 강제하지 않음 |

모호함 탐지는 완전한 자연어 판정기가 아니다. 짧은 문장이나 구성요소 개수만으로 결함을 확정하지 않는다. 확정 가능한 형식 오류는 `error`, 의미상 의심은 `review`, 정상 정보는 `info`로 기록한다.

중복 의심을 수집할 때 원문과 정규화한 비교용 텍스트를 함께 보존한다. 비교용 정규화는 Unicode·대소문자·여백 정도로 제한하고 원본 문장을 바꾸지 않는다. 숫자, 방향, 부정, 조건, 관계의 주체·객체는 제거하지 않는다. 텍스트 일치만으로 의미 동등성을 선언하지 않는다.

중복 판정은 대상·소유자, 슬롯·변경 속성, 형태·위치·연결, 적용 조건·제외 조건, 필수 구성요소, 증거·검증 기준을 비교한다. 동등하면 기존 대표 ID와 별칭·정당한 변형 관계를 검토한다. 완전히 다른 슬롯의 항목을 canonical 참조로 묶는 등 기존 계약 밖의 통합은 하지 않는다. 실제 삭제·이관에는 모든 참조의 영향 목록과 인덱스 재생성 결과가 필요하다.

외형 요소 보강은 관찰 가능한 대상과 관계를 설명하되, 자료로 뒷받침하지 못하는 세부를 새 필수 조건으로 만들지 않는다. 복합·공동 의무는 `authored_components/v2`의 다대다 구조를 유지한다. 구성요소와 후보 또는 렌더 기준 사이의 일대일 대응을 추측하지 않는다.

## 5. 연결 모델

첫 구현은 원본에 선언된 관계 두 종류만 추출한다.

| 종류 | 방향 | 근거 |
|---|---|---|
| `member_of` | 후보 → 번들 | `candidate_ids`와 필요한 `candidate_slots` |
| `associated_with` | 번들 → 시각 의미 | 기존 `hard_profile_id` / `hard_profile_ids` |

`hard_profile_ids`라는 필드 이름을 필수 활성화나 완전 구현으로 해석하지 않는다. 현재 컴파일 결과의 `associated_profile_ids`와 `profile_activation=independent_request_evidence_only`를 존중한다. 후보의 서술형 `relations` 안에 있는 신체·물체 관계도 데이터 레코드 간 참조와 혼동하지 않는다.

노드 ID는 후보 `slot:<slot>:<entry_id>`, 번들 `bundle:<id>`, 시각 의미 `profile:<id>`로 구분한다. ID는 파일·샤드·배열 위치에서 만들지 않는다. 역방향 인접 목록은 같은 edge 배열에서 생성한다.

후보와 프로필 사이의 직접 edge를 일괄 생성하지 않는다. 양방향 질의는 다음 경로를 반환한다.

```mermaid
flowchart LR
    C[후보] -->|member_of| B[번들]
    B -->|associated_with| P[시각 의미]
```

- 프로필 출발: 관련 번들 → 각 번들의 참여 후보.
- 후보 출발: 참여 번들 → 각 번들의 관련 프로필.
- 번들 출발: 참여 후보와 관련 프로필.

여러 경로를 통해 같은 후보·프로필이 나오면 경로를 보존하고 고유 항목 수도 별도로 표시한다. 링크 수나 미연결 수를 의미 범위·품질 점수로 환산하지 않는다. 실시간 요청에서의 검색 노출·선택 가능성·픽셀 구현은 이 구조 조회의 결과에 포함시키지 않는다.

실제 예시로 `clean_beauty_clamshell`은 7개 후보와 `clamshell_dual_source_portrait_light`, `soft_light_shadow_edge_relation`을 참조한다. `slot:light_shape:lit_clean_vertical_catchlight_pair`에서 이 번들을 거쳐 프로필로 이동할 수 있지만, 이 후보가 두 프로필의 모든 조건을 충족한다는 판정은 생성하지 않는다.

## 6. 보고서와 검토 기록

관리 생성물은 운영 assets에 등록하지 않는다. 실행별 출력 디렉터리의 파일은 다음과 같다.

| 산출물 | 내용 |
|---|---|
| `manifest.json` | 입력 모드·루트·커밋 관찰값·dirty 여부·세대 ID·소스 지문·매니페스트 해시·도구/정규화/노드 투영 레시피·코드/환경·출력 해시 |
| `inventory.json` | 후보·번들·프로필, 원본 파일과 JSON Pointer, 컴파일·문맥 확장의 출처, 항목 내용 해시 |
| `findings.json` | 항목/필드별 error·review·info, 탐지 규칙, 원문 근거, 검토 기록과 그 유효성 |
| `links.json` | 두 종류의 명시적 edge와 양방향 인접 목록. 검증된 generation 입력에서만 정상 게시 |
| `SUMMARY.md` | 문제 우선순위, 연결·미연결 현황, 이전 실행 대비 증감, 증거 범위 |

생성물의 결정적 본문과 관찰 시각 등 실행 메타데이터를 분리한다. 동일 입력·레시피에서 inventory/findings/links의 정렬과 내용은 재현 가능해야 한다. 원본 순서가 의미를 갖는 구성요소·관계·증거 배열은 정규화 과정에서 재정렬하지 않는다.

검토자의 유지·수정·거절 판단은 제안 위치 `docs/data-maintenance/photo-data-review-decisions.ndjson`에 기록한다. 이 파일은 관리용 판단의 원본이며 운영 활성화나 새 연결 선언의 원본이 아니다. 구조 오류를 검토 기록으로 면제하지 않는다.

검토 기록은 `record_id`, `finding_or_path_key`, `decision`, `rationale`, `evidence_refs`, `input_entity_hashes`, `recipe_versions`, `reviewed_at`을 가진다. 지원 수준은 필요할 때 `partial_support`, `collective_support`, `insufficient`, `undetermined`로 설명한다. 전체 의미 지원은 필수 요소·조건 전체의 근거가 있을 때만 기록한다.

entity 해시는 파일 경로와 시각 메타데이터를 제외한 전체 컴파일 의미 레코드에 결합한다. 후보의 문맥 확장·조건·속성, 번들의 구성원·구성요소, 프로필의 의무·활성화 조건을 포함한다. 처음에는 보수적으로 전체 의미 레코드를 사용하고, 검토 무효화가 많다는 측정 없이 필드를 임의로 빼지 않는다.

경유 관계 검토에는 후보·번들·프로필 해시를 모두 결합한다. 같은 ID의 설명·조건·구성원이 바뀌거나 투영 레시피가 바뀌면 과거 판단은 `stale`로 표시한다. 현재 보고서의 source fingerprint만 비교해 모든 과거 판단을 무효화하지는 않는다. 관련 엔터티가 동일하면 검토는 유지할 수 있다.

자동 생성된 명시적 연결은 `origin=authored_reference`, 의미 검토는 기본 `unreviewed`다. 원본 참조가 유효하다는 사실과 의미가 타당하다는 판단을 같은 상태 필드에 합치지 않는다.

## 7. 지속성·게시·증분 처리

- 기존 등록 파일의 새 항목은 다음 생성에서 자동 포함한다. 새 원본 파일은 기존 매니페스트에 명시적으로 등록한다.
- 새 항목에 연결이 없으면 미연결 정보로 남긴다. 연결이 필요 없는 항목을 새로 만드는 것도 허용한다.
- 참조 대상 삭제·ID 변경·후보 슬롯 이동은 영향 받는 번들과 경로를 보고한다. 남은 잘못된 참조를 자동 제거하지 않는다.
- 파일 이동은 출처 위치를 갱신한다. 동일 의미의 안정 ID를 유지하고, 같은 ID를 다른 개념에 재사용하지 않는다.
- 보고서는 staging에서 생성·검증하고, 내용 주소를 가진 디렉터리를 완성한 뒤 관리용 CURRENT를 원자적으로 바꾼다. 이 CURRENT는 런타임 CURRENT와 별개다.
- 관리 CURRENT에는 세대·원본 루트/namespace·source fingerprint·보고서와 도구 레시피 지문을 결합한다. 오래된 작업이 최신 포인터를 덮지 못하도록 lock과 기대 포인터 비교를 사용한다.
- 생성 도중 운영 세대가 바뀌면 완성한 보고서는 과거 세대 보고서로 보존할 수 있다. 최신 관리 포인터로 활성화하려면 원본·편집 상태·현재 세대를 다시 확인한다.
- 기본 조회는 고정 보고서의 세대를 표시한다. 최신성을 명시적으로 요구하면 현재 원본까지 확인하며, 단순 보고서 열람을 최신 확인으로 표시하지 않는다.
- 보존된 운영 세대 내부는 수정하지 않는다. 관리 보고서는 별도 저장소에서 생성·재생성한다. 자동 원본·세대·벡터 삭제 정책은 추가하지 않는다.

첫 버전은 전체 순회와 명시적 edge 재생성을 사용한다. 핵심 자료구조는 ID별 노드와 인접 목록이며 모든 후보×프로필 조합을 펼치지 않는다. 실제 생성 시간·메모리를 측정한 뒤에만 증분 최적화를 결정한다.

의미 검토는 내용 해시가 바뀐 항목, 해당 항목이 참여하는 번들·프로필 경로, 관련 중복 의심 그룹을 우선 대상으로 삼는다. 새로운 항목과 기존 항목 사이의 중복도 비교해야 하므로 변경된 파일 내부만 비교하고 끝내지 않는다. 전체 구조 검증은 계속 유지한다.

## 8. 추가 관계 보강의 별도 단계

미연결 항목을 모두 연결하는 목표는 두지 않는다. 기존 보고서로 의미 있는 부족 영역을 찾은 뒤 필요한 영역에 한해 다음 절차를 적용한다.

1. 대상·조건·변경 속성으로 비교 영역을 줄인다. 공통 토큰이나 기존 로컬 검색을 이용해 작은 후보 목록을 만든다.
2. 기존 벡터를 활용한다면 검증된 동일 세대의 두 인덱스를 각각 해석한다. 다른 모델·차원·벡터 공간 사이의 직접 코사인 비교는 하지 않는다. 첫 버전은 벡터 없이 시작한다.
3. 구성요소·소유자·관계·필수 조건과 반례를 비교해 검토 제안을 만든다. 제안과 명시적 links는 다른 파일/상태로 유지한다.
4. 검토 결과가 번들 연관을 뒷받침하면 기존 번들 원본의 프로필 참조를 보강하고 다시 검증·생성한다. 새 후보나 번들이 필요한 경우 기존 데이터 계약으로 작성한다.
5. 구성요소 단위의 직접 후보→프로필 연결이 반드시 필요한 사례가 생기면 그때 별도 스키마를 설계한다. 기존 번들 연관으로 표현할 수 없는 관계를 억지로 참조에 넣지 않는다.

전체 의미 비교나 외부 모델 호출을 기본 경로에 포함하지 않는다. 자동 유사도 판단을 검토 완료로 간주하지 않는다.

## 9. 완료 기준과 증거 범위

필수 범위는 전체 자동 점검, 명시적 참조의 양방향 조회, 검토 상태/무효화, 제한된 우선 정비, 지속적인 변경 처리와 검증이다. 새 관계의 추론·대량 보강은 후속 선택 범위다.

- 원본에서 선언된 유효 edge는 누락 없이 양방향에서 동일하게 조회된다. 잘못된 참조는 오류로 남고, 미연결은 정상 표현된다.
- 서로 다른 원본 루트·세대·도구 레시피의 결과를 섞지 않는다. 변경 중 입력과 오래된 최신 포인터를 올바르게 거부한다.
- 동일 ID의 내용 변경과 번들 구성 변경은 관련 검토 상태를 무효화한다. 실제 참조를 지우거나 활성화 규칙을 바꾸지 않는다.
- 도구만 추가한 단계에서는 고정 입력의 공개 후보팩·검색 결과·시각 의미 블록이 기준 실행과 동일하다.
- 실제 원본 정비 단계에서는 변경 이유·참조 영향·인덱스 재생성·회귀 결과를 별도 기록한다. 과거 기대값과 산출물을 덮어쓰지 않는다.
- 형식·참조·관리 조회의 통과를 묘사 정확도, 검색 노출, 이미지 구현, 사용자 수용의 통과로 보고하지 않는다.

현재 수량 확인과 코드 조사만 완료한 상태다. 전체 중복·모호함·관계 타당성의 전수 감사나 관리 도구 구현은 아직 수행하지 않았다.
