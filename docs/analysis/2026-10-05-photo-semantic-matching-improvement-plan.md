# 사진 프롬프트 의미 판정과 후보 적용 개선안

작성일: 2026-10-05. 상태: 스킬 작성·검토 지침의 공통 절차는 반영 완료. 데이터·판정 코드 개선과 변경 전후 비교 이미지 검증은 제안 단계다.

목표는 요청과 맞는 의미가 표현이나 입력 형식 때문에 탈락하는 경우를 줄이고, 실제 의미 충돌·근거 부족·작성자의 미선택을 정확히 구분하는 것이다. 이번 얀데레 피아노 사례를 재현 기준으로 쓰되, 개선은 다른 관계 개념과 조건부 후보에도 적용할 수 있게 설계한다.

## 1. 확인된 원인과 개선 범위

근거는 당시 실행의 [재현 진단 기록](../../runs/20261005-yandere-snow-miku-piano/semantic_data_diagnosis.json)과 [후보팩](../../runs/20261005-yandere-snow-miku-piano/candidate_pack.json)이다. 당시 런타임 커밋은 `cf40a76e4ada095b5a56f3c229c06029d136e1ad`이다. 현재 워킹트리에서도 아래 판정 경로가 존재함을 확인했다. 다른 작업의 수정 파일이 있으므로 실제 구현 시작 때에는 적용 기준 소스와 데이터 해시를 다시 고정해야 한다.

| 확인된 현상 | 원인 | 변경할 부분 |
|---|---|---|
| 얀데레 문맥이 `context_mismatch` | 성인 인물의 실사 캐릭터 연기라는 문맥이 등록 표현과 일치하지 않음 | 문맥 근거 판정과 사유 설명 |
| `surface_affect`가 누락됐다고 판정 | 값은 존재하지만 `affectionate warmth`가 의미 클래스의 표현 목록에 없었음 | 표현 정규화와 미인식 상태 |
| 의도성 항목 때문에 `incomplete` | 공통 필수 7축과 개념별 추가 요구의 조율 부족 | 개념별 필수·보조 조건 |
| 관계 연산자 3개가 누락됐다고 판정 | 연산자는 있지만 구성원·연결 방향이 요구 구조와 다름 | 작성 기록, 역할 연결, 관계 진단 |
| 첼로 후보가 피아노 장면에 노출 | 후보의 설명은 정상이나 장면 전제와 변경 범위 검토가 충분하지 않음 | 조건부 후보의 적용 검토 |

일반 후보 64개와 시각 개념 후보 11개가 노출됐고 최종 선택은 0개였다. 이 수치는 검색 실행의 증거다. 모든 후보가 부적합했다거나, 데이터가 작품에 기여했다는 증거는 아니다.

얀데레의 기존 정의인 ‘같은 상대를 향한 애정 → 경계를 넘는 소유적 행동 → 그 상대에게 보이는 결과’는 유지한다. 특정 표정·도구·직업·손목잡기를 보편적인 필수 형태로 추가하지 않는다. 기존 개별 렌더 개선 문서의 표현 선택도 보편 정의로 승격하지 않는다.

## 2. 우선 수정: 판정 결과가 실제 원인을 말하도록 한다

현재의 요약 상태를 호환 가능한 범위에서 유지하면서 상세 사유를 추가한다. 공개 계약의 상태나 필드가 바뀌면 생성기·뷰·합성 감사기를 함께 갱신하고 해당 계약의 버전을 명시한다.

- **문맥 근거 미인식:** 필요한 문맥 표현을 찾지 못했음. 다른 의미라는 증거와 구분한다.
- **명시적 문맥 충돌:** 다른 의미나 제외 조건이 실제로 확인됨. 충돌한 원문과 조건을 기록한다.
- **항목 없음:** 입력에 해당 축이 없음.
- **값 미인식:** 축과 값은 있지만 의미 클래스에 연결하지 못함.
- **관계 없음:** 해당 연산자가 입력에 없음.
- **관계 구조 불일치:** 연산자는 있으나 구성원·연결 방향이 다름. 기대 구조와 실제 구조를 함께 표시한다.

예를 들어 이번 결과는 ‘애정 표현 누락’이 아니라 ‘`surface_affect` 값은 존재하나 등록 클래스 미인식’으로, ‘`same_target` 누락’이 아니라 ‘`baseline`과 `surface_affect`의 역할 연결 미확인’으로 설명해야 한다. `context_mismatch`를 무조건 ‘사용자가 다른 의미로 정의했다’고 번역하는 현재 설명도 교체한다.

이 단계는 판단을 더 느슨하게 만들지 않는다. 잘못된 탈락 설명과 실제 미충족 조건을 분리하는 수정이다.

## 3. 문맥은 등록 문구와 기존 입력 근거를 함께 사용한다

`visual_profile_context_applicability`에 문맥의 긍정·부정 근거를 반환하는 상세 판정 경로를 추가한다. 기존 튜플 반환을 쓰는 호출부는 호환 래퍼로 유지하거나 함께 이관한다.

1. 사용자 정의·부정·제외·명시적 다른 의미를 먼저 적용한다.
2. 기존 등록 문맥 표현과 함께, 요청 해석 및 동결된 코어에서 확인되는 문맥 근거를 검토한다.
3. 긍정 근거가 충분하면 `applicable`, 명시적 충돌이면 `excluded`, 근거가 부족하면 `unresolved`로 구분한다.

이번 사례에서는 코어의 `clearly adult woman portraying Snow Miku`가 성인 인물의 캐릭터 연기라는 근거다. 판정을 통과시키려고 `adult character`라는 문구를 프롬프트에 덧붙이는 방식 대신, 기존 문구의 의미와 출처를 연결한다. 사람이라는 분류만으로 성인·허구 캐릭터 맥락까지 추정하거나 참조 얼굴에서 성격을 추정하지 않는다.

코드가 확인할 수 있는 것은 필드 존재, 원문 위치, 해시, 선언된 근거 연결이다. 자유문장의 의미를 자동으로 보장한다고 주장하지 않는다. 작성자의 의미 검토가 필요한 연결에는 검토 주체와 근거를 남기고, 해결되지 않은 항목은 필수 조건 활성화의 근거로 쓰지 않는다.

문맥 미인식을 곧바로 적합으로 바꾸지 않는다. 정확한 요청 용어와 충분한 문맥 근거가 확인된 시각 프로필은 기존 요청별 필수 조건 경로를 따르고, 검색으로 발견한 선택 후보는 계속 선택 대상이다. 추상 개념 프로필의 `consistent`도 자동 채택을 뜻하지 않는다.

## 4. 표현 정규화와 필수 항목을 조율한다

### 표현 정규화

첫 수정은 이번에 실제로 누락된 `affectionate warmth`와 의미가 분명한 대응 표현을 `open_warmth`의 작성 데이터에 보강하는 것이다. 동시에 판정 결과에 원래 값, 매칭된 표현, 클래스 ID, 데이터 출처를 남긴다.

일반적인 정규화는 코어 동결 후 수행한다. 원문 값과 근거를 보존한 채 의미 클래스에 연결하고, 미등록 표현이나 모호한 표현은 `unrecognized` 또는 `ambiguous`로 기록한다. 느슨한 부분 문자열이나 임베딩 유사도만으로 클래스를 확정하지 않는다. 부정, 대비, 다중 의미도 함께 검토한다. 예를 들어 ‘애정이 없는 감시’를 애정이나 소유적 애정으로 연결해서는 안 된다.

확장 대상으로 선택한 표현 외의 독립적인 한국어·영어·일본어 문장도 검증에 포함한다. 알려진 별칭을 늘리는 것과 새로운 표현의 의미를 안정적으로 처리하는 것을 별도로 평가한다.

### 필수·보조 항목

공통 필수 7축은 개념별 요구 전체가 아니라 기본 작성 계약이다. 추가 축이 허용되므로 ‘7축 밖의 요구는 모두 오류’라고 처리하지 않는다. 프로필마다 추가 요구가 의미를 구별하는 데 필요한지, 입력 절차에서 어떻게 근거를 제공하는지 검토한다.

얀데레에서는 이번 정의를 성립시키는 애정·동일 상대·경계 침범 행동·보이는 결과를 우선한다. **`affect_leak_intentionality`는 필수 차단 조건에서 보조 설명으로 옮기는 것을 권고한다.** 관찰된 행동만으로 의도적·비의도적 감정 노출을 확정할 필요가 없고, 이 구분이 현재 얀데레 정의의 필수 요소도 아니기 때문이다. 입력에 값이 있다면 보존하되, 모르는 값을 임의로 채우지 않는다.

다른 개념에서 의도성이 실제 구분 조건이면 유지하고 해당 추가 정보의 작성·검토 절차를 명시한다. 데이터 검증에는 축·클래스·증거 역할의 유효성과 각 필수 조건의 충족 경로를 추가한다.

## 5. 관계는 이름보다 역할과 근거를 연결한다

작성 단계의 일반적인 관계 안내를 보강하고, 동결 후에는 기존 축·증거 문구·관계의 연결을 검토한다. 초기 작성 단계에서 후보 프로필을 미리 읽도록 절차를 바꾸지 않는다.

이번 초안에는 다음 근거가 이미 있다.

| 역할 | 초안의 근거 |
|---|---|
| 겉으로 보이는 애정 | `soft, affectionate smile directed at her adult duet partner` |
| 상대의 이탈 계기 | `As he lifts his left hand to leave` |
| 붙잡는 행동 | `she closes her right hand firmly around his left wrist` |
| 행동의 결과 | `his halted forearm stays angled toward the aisle` |

`baseline`을 전역적으로 `surface_affect`의 별칭으로 만들지 않는다. 이번처럼 기준 상태의 근거가 애정 표현을 나타내는 경우에만 역할 연결을 검토한다. ‘계기 → 결과’를 ‘계기 → 행동’으로 자동 교체하거나, 내적 애착과의 대비를 눈에 보이는 결과와의 대비로 자동 인정하지도 않는다.

추가 연결이 필요하면 동결된 원문에 근거가 있는지, 같은 상대를 가리키는지, 요구된 인과·대비가 실제로 성립하는지 확인한다. 확인된 연결은 원래 관계를 보존한 별도 판정 근거로 기록한다. 원문에 없는 행동·결과·관계를 만들어 통과시키지 않는다. 동결된 주장 자체를 바꿔야 하면 기존 재작성 경로로 새 코어와 해시를 만든다.

`same_target`의 구성원 순서가 무관하다는 기존 처리는 유지한다. 구성원 자체의 변경은 순서 변경과 다르게 취급한다. 애정은 A에게 향하고 통제 행동은 B에게 향하는 사례는 계속 불충족이어야 한다.

## 6. 후보의 적용 조건과 작성자의 선택을 분리한다

현재 `photo_candidate_context.py`는 선언된 전제 조건을 보존하고 최종 장면 근거를 검증하는 경로를 갖고 있다. 별도의 키워드 필터를 새로 만드는 대신 이 경로를 활용한다.

- 장면 전제가 필요한 후보의 작성 데이터에 필요한 대상·도구·접촉 관계와 변경 속성을 명시한다. 첼로 연주 후보라면 첼로와 활이 필요한 행동임을 보존한다.
- 검색 결과와 선택 가능한 노출 목록을 구분한다. 피아노 연주가 고정된 요청에서 첼로로 대체하는 후보는 고정 속성과 충돌한다고 표시한다.
- 장면이나 악기를 바꿀 수 있는 요청에서는 조건부 선택 가능성을 남긴다. 초기 장면에 없다는 이유만으로 모든 새 아이디어를 제거하지 않는다.
- 후보 설명 자체의 오류, 장면 전제 미충족, 고정 의미 충돌, 판정 미해결, 적용 가능하지만 미선호, 채택을 서로 다른 검토 결과로 남긴다.

기존 문맥 전제의 any/all 의미와 출처는 유지한다. 조건을 새로 만드는 경우에는 후보의 실제 의미를 근거로 삼고 작성 데이터에 반영한다. 최종 채택 때에는 해당 조건이 완전하게 실현됐는지 합성 감사에서 확인한다.

전부 미채택하는 선택은 계속 허용한다. 다만 ‘적용 가능하지만 기존 초안이 더 적절함’을 ‘의미상 부적합’으로 보고하지 않는다.

- [후보 전제 계약](../../skills/photo-prompt-image-generator/scripts/photo_candidate_context.py), [합성 감사기](../../skills/photo-prompt-image-generator/scripts/audit_composed_prompt.py), [후보 뷰](../../skills/photo-prompt-image-generator/scripts/compose_pack_view.py): 조건과 상세 사유가 중간 단계에서 유실되지 않도록 조율.
- [스킬 절차](../../skills/photo-prompt-image-generator/SKILL.md): 독립 초안 → 코어 동결 → 조회 → 검토·합성의 순서를 유지하면서 일반 역할 작성과 미인식 처리 안내 보강.

작성 데이터가 바뀌면 해당 변경을 소비하는 파생 인덱스를 재생성한다. 기존 벡터는 텍스트·제공자·모델·차원·해시가 일치하는 항목만 재사용한다. 생성된 인덱스를 수동 수정하지 않는다. 과거 후보팩·코어·이미지·진단 기록은 변경하지 않고 새 실행 기록을 만든다.

단계별 기록에는 안정적인 후보 ID와 함께 조회, 노출, 검토, 채택, 프롬프트 반영, 이미지 검증을 남긴다. 동일 후보가 여러 검색 경로에 등장한 경우 중복 합계로 성과를 부풀리지 않는다. 내부 순위 근거를 공개 후보팩에 추가하는 변경은 필요하지 않다.

## 8. 검증과 수용 기준

먼저 당시 동결 입력을 그대로 재실행해 데이터 처리의 차이를 검증한다. 진단용으로 필드를 복사해 `consistent`를 만든 기존 실험은 원인 확인 자료일 뿐, 유효한 전체 코어나 수정 완료의 증거로 재사용하지 않는다.

| 검증 사례 | 기대 결과 |
|---|---|
| 이번 요청·초안의 원문 그대로 | 성인 캐릭터 문맥과 애정 표현이 인식되며, 관계는 실제 근거와 연결 상태대로 평가됨 |
| 별칭 보강에 사용하지 않은 다국어 표현 | 근거 있는 의미 연결 또는 명확한 미인식; 조용한 오분류 없음 |
| 원문에 축은 있으나 모호한 값 | `ambiguous`/`unrecognized`, 축이 없다는 설명 금지 |
| 문맥 근거가 부족한 입력 | `unresolved`, 필수 조건 자동 활성화 금지 |
| 단어 설명·실제 사건 설명·명시적 제외 | 사진용 캐릭터 조건 활성화 없음 |
| 사용자가 다른 의미를 명시한 용어 | 사용자 정의 우선, 기존 프로필 의미 강요 없음 |
| 애정은 있지만 경계 침범이 없음 | 일반적인 헌신과 구별되어 얀데레 관계 충족 판정 없음 |
| 애정 없는 감시·공포 소품만 있는 장면 | 얀데레 관계 충족 판정 없음 |
| 동일 상대 관계의 구성원 순서만 변경 | 동일한 관계로 판정 |
| 애정과 통제의 상대가 다름 | 동일 상대 조건 불충족 |
| 계기·행동·결과 중 실제 근거가 누락 | 누락된 역할 명시; 자동 관계 보충 없음 |
| 피아노가 고정된 요청과 첼로 후보 | 대체 충돌 또는 전제 미충족으로 구분 |
| 악기 변경이 열린 요청 | 조건부 후보 검토 가능, 새 전제의 최종 실현 감사 |
| 모든 선택 후보를 거절하는 합성 | 정상 처리, 실제 검토 이유 보존 |
| 신규 상세 정보가 있는 팩의 뷰·감사 | 원문·근거·출처·해시·후보 ID 유실 없음 |

기존 `test_photo_character_response_concepts.py`, `test_photo_visual_profile_retrieval.py`, `test_photo_visual_obligations.py`, `test_photo_authorial_core_v6.py`와 관련 후보 문맥·합성 감사 시험에 사례를 추가한다. 정상 기준과 부정 사례를 함께 고정하고, 이전에 통과하던 다른 캐릭터 개념의 구별 조건을 보존한다. 관련 검사 통과 후 데이터·팩 계약의 필수 전체 검사를 수행한다.

수용 결과는 다음 세 단계로 보고한다.

1. **의미 판정:** 이번 false negative의 원인이 해소되고, 부정·혼동 사례의 잘못된 필수 활성화가 고정 검증 집합에서 0건이다. 이 수치는 검증 집합 범위의 결과로 한정한다.
2. **합성:** 후보의 의미·전제와 요청의 고정 속성이 보존된다. 필수 조건은 최종 프롬프트에 근거가 있고 선택 후보의 0개 채택도 가능하다.
3. **이미지:** 실제 출력에서 애정·통제·결과가 같은 상대에게 향하는지, 손의 주체와 좌우·접촉·건반과의 간격·이탈 동작이 읽히는지 별도로 검토한다. 이번 14개 픽셀 기준의 남은 실패를 데이터 판정 성공만으로 통과 처리하지 않는다.

이미지 효과를 검증할 때에는 기존 경로와 개선 경로에서 요청·동결 초안·제어값·얼굴 참조를 동일하게 사용하고, 최종 프롬프트 차이와 채택된 조건을 기록한다. 한 경로의 생성 이미지를 다른 경로의 참조로 넣어 비교 조건을 바꾸지 않는다. 변경 전후 각 1장의 출력은 사례 비교로만 취급하고 일반적인 품질 향상을 주장하지 않는다. 변경이 최종 프롬프트에 반영되지 않았다면 이미지 효과가 입증됐다고 보고하지 않는다.

추천 착수 범위는 **P0와 P1을 하나의 변경으로 구현하고 당시 입력의 재실행으로 검증하는 것**이다. 판정 문제를 먼저 해결한 뒤 P2의 후보 전제 보강과 P3의 이미지 검증을 진행하면, 어떤 수정이 어떤 결과를 바꿨는지 추적할 수 있다.

## 스킬 지침 반영 범위

사용자의 후속 지시에 따라 특정 키워드와 무관한 작성·검토 절차를 `SKILL.md`, `references/composition-contract.md`, `references/retrieval-contract.md`에 반영했다. 요청 전체에서 관계의 역할과 근거를 작성하고, 의미 적합성·전제 및 변경 범위·작품 선호를 구분하며, 미인식 표현·정보 누락·관계 구조 차이·명시적 충돌을 정확히 설명하도록 안내한다. 사람 이외의 대상, 다른 언어·바꿔 쓴 문장·복합 요청·독립 키워드가 없는 요청에도 같은 판단 기준을 적용한다.

기존 독립 초안과 동결 경계, 필수 조건, 선택 후보의 권한, 데이터와 출력 계약은 유지한다. 이 반영은 작성·검토 지침 변경이며 현재 판정 코드의 동작을 수정한 결과가 아니다. 위의 P0–P3 구현·검증 항목은 별도 후속 작업으로 남는다.

반영 검증: `skill-creator/scripts/quick_validate.py` 통과, `tests.test_photo_prepack_isolation` 6개 통과, 수정 문서의 링크·공백 검사 통과. 이 검증은 스킬 형식과 기존 격리 조건의 보존을 확인하며, 실제 생성 품질이나 판정 코드의 개선을 입증하는 결과는 아니다.

독립 재검증은 기존 런타임·데이터 커밋 `cf40a76e4ada095b5a56f3c229c06029d136e1ad`에 수정된 지침 3개만 적용한 별도 서브에이전트에서 수행했다. 새 초안을 동결한 뒤 일반 후보 64개와 시각 개념 후보 11개를 조회하고 10개 후보의 상세 내용을 검토했다. 채택은 0개였으며, 적용 가능하지만 덜 유용한 후보와 전제 미충족 후보를 구분하고 표현 미인식·추가 축 요구·관계 구성원 및 끝점 차이를 실제 입력에 따라 설명했다. 이 결과는 지침을 따른 검토 행위의 사례이며 자동 판정 코드가 개선됐다는 증거는 아니다.

원래 얼굴 참조만 사용한 실제 이미지 생성 1회는 성공했다. 엄격한 픽셀 기준 14개 중 7개는 통과하고 7개는 실패했다. 손목 대신 소매·팔뚝에 접촉한 점, 상대의 이탈과 멈춤 및 출입구 쪽 반응이 읽히지 않는 점, 압박을 보여주는 손가락 관절이 보이지 않는 점이 남았다. 최종 프롬프트는 새 초안과 같았고 사용자 수용 판정은 대기 중이다. 이 재검증은 변경 전후 품질 비교가 아니며, 지침 검토와 이미지 충실도를 별도로 기록한 결과다.
