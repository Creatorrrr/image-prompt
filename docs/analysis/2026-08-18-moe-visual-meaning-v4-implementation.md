## 결론

기존 v1 의미 계약은 29개 요소의 본질과 최소 구성요소를 보존했지만, 후보 변형별 외형·부품 연결·카메라·시간·상호작용을 충분히 구분하지 못했다. 이를 수정하기 위해 v1을 변경하지 않고 v2 시각 확장을 추가했다.

- 29개 이미지 검색 근거 레코드
- 29개 시각 의미 계약
- 52개 상호 배타적 시각 변형
- 233개 후보 subtype의 정확히 한 변형 귀속
- 124개 별칭의 `exact` 98개, `variant` 6개, `carrier` 14개, `related` 6개 분류
- 29개 canonical ID와 124개 별칭을 합친 153개 결정적 사전검증 PASS

민감 용어는 정규화 정의와 안전 판단 계보에 그대로 남는다. 런타임 프롬프트에서는 필요한 경우 용어만 생략하고 눈·입·혀·관계 방향·의복 위상·신체 접촉 같은 관찰 가능한 조합을 모두 강제한다. 따라서 명칭을 순화하면서 의미까지 다른 것으로 바꾸는 방식은 허용하지 않는다.

## 구현 구조

```text
immutable meaning v1 + qualitative image evidence v1
                         |
                         v
visual meaning extension v2
  aliases + variants + topology + camera + time + interaction
                         |
                         v
grammar v4 -> candidate pack v6 -> composed prompt v4 -> audit v4
```

1. `build_moe_meaning_contracts_v2.py`가 이미지 근거와 시각 계약을 같은 고정 입력에서 재생성한다.
2. `moe_visual_contract.py`가 29개 순서, 원 의미 해시, 별칭 타입, 233개 subtype의 정확한 1회 커버리지, 모든 v1 구성요소 보존, 런타임 금지 명칭 누출을 검사한다.
3. `compile_moe_grammar_v4.py`가 v3 바이트를 복사하고 시각 계약과 이미지 근거 해시를 결합한다.
4. 런타임은 관련어를 거부하고, 변형 별칭이면 그 변형이 소유한 subtype만 후보로 남긴다.
5. 선택된 후보의 주 표현에 v1 구성요소를 먼저 결합하고, 한 v2 변형의 필수 시각 구문을 이어서 결합한다.
6. 후보와 변형의 출력 모드를 교집합으로 계산한다. 흑화 전후를 단일 프레임으로 강제하는 요청처럼 증명 불가능한 조합은 생성 전에 실패한다.
7. 감사는 로컬 v4로 전체 선택을 재생하고 계약·해시·변형 소유권·구문·매체를 검증한다.

## 실패·에러 케이스 판단

| 관찰된 문제 | 판단 | 처리 |
|---|---|---|
| 표시명과 같은 별칭이 모두 `canonical`로 기록됨 | 런타임 우선순위 결함 | ID만 canonical로 먼저 처리하고, 표시명보다 타입 별칭을 우선하도록 수정 |
| 관련 검색어가 요소를 활성화할 가능성 | 데이터와 로직 모두의 의미 경계 문제 | 데이터에 `related`를 명시하고 런타임에서 fail-closed |
| 변형 별칭을 줘도 다른 의상/변환 계보 후보 선택 가능 | 선택 로직 결함 | 변형 소유 subtype으로 후보 풀 제한 |
| “generic smug face가 아니라” 같은 문장 때문에 confound 실패 | 테스트/감사 모델 결함 | confound는 렉시컬 금지어가 아니라 픽셀 검토 기준으로 유지 |
| 4개 검색 레코드에 안정적 대표 URL이 없음 | 허위 보강하면 안 되는 근거 한계 | 빈 배열과 낮은/중간 신뢰도를 허용하고 질의·반복 특징·한계를 필수 검증 |
| 민감 명칭을 빼면 의미도 순화될 위험 | 데이터와 감사 결함 | v1 정의·안전 계보는 유지하고 v2 외적 구성을 전부 결합, 금지 명칭과 구성 누락을 별도 검사 |
| 감사 PASS를 이미지 성공으로 오해 | 범위 해석 오류 | qualification과 문서에 “프롬프트 사전검증이며 픽셀 증거 아님”을 고정 |

## 검증 결과

- `build_moe_meaning_contracts_v2.py --check`: 29/29 데이터 재현
- `compile_moe_grammar_v4.py --check`: 29 요소, 233 후보, 198 출처 재현
- 집중 unittest: 28개 테스트 PASS
- v4 qualification: 29 canonical + 124 alias = 153/153 PASS
- 활성 별칭: 118/118 PASS
- 관련어: 6/6 거부 PASS
- 기존 v2/v4와 v3/v5 테스트는 그대로 PASS

이 결과는 데이터 무결성, 선택, 프롬프트의 문자적 시각 구속을 증명한다. 실제 렌더 이미지에서 요소가 보이는지, 혼동 사례가 발생하지 않는지, 미감이나 선호도가 높은지는 별도의 이미지 생성과 픽셀 검토가 필요하다.
