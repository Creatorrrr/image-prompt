# 29개 모에요소 의미 계약 v3 개선·구현 계획

작성일: 2026-08-17
대상: `subculture-illustration-image-generator`의 명시적 모에요소 경로

## 1. 목표와 성공 조건

기존 29개 ID와 233개 후보를 유지하면서, 스킬이 각 용어의 실제 의미를 후보 스타일이나 이름만으로 오인하지 않도록 한다. 민감한 용어는 정규화 의미 데이터에는 원뜻과 계보를 보존하고, 실제 이미지 프롬프트에서는 이름 대신 필수 외적·관계적·시간적 구성요소로 표현할 수 있게 한다.

성공 조건은 다음과 같다.

1. 29개 요소마다 정규화 정의, 본질, 비동치 사례, 의미 축, 표현 충실도, 매체 능력과 안전 경계를 가진다.
2. 민감 명칭을 프롬프트에서 빼더라도 정의를 순화하거나 다른 개념으로 대체하지 않는다.
3. 런타임은 선택 후보뿐 아니라 그 후보가 따라야 할 정확한 의미 계약의 바이트와 해시를 함께 묶는다.
4. 모든 필수 구성요소 그룹이 최종 프롬프트에서 문자 그대로 확인되어야 한다.
5. 단일 이미지로 증명할 수 없는 변화·관계·착시는 `sequence_required`, `partial_evidence`, `interaction_required`로 한계를 드러낸다.
6. 원 요청과 정규화 의미를 함께 안전 판단 입력으로 남기며, 명칭 제거를 정책 우회로 사용하지 않는다.
7. v1/v2 문법과 기존 v4 결과는 수정하지 않고 명시적 재현 경로로 남긴다.

렌더 결과의 실제 판독성·미감·선호도는 이 개선의 성공 범위가 아니다. 그것은 별도의 픽셀 검토가 필요하다.

## 2. 기존 구조의 문제

- v2의 `definition_and_history`에는 일부 출처 ID나 조사 메모가 섞여 있어 개념 정의와 출처 추적이 분리되지 않았다.
- 일부 `semantic_subtypes`에는 `researched_variant_*` 같은 자리표시자가 남아 있었다.
- 후보를 골랐다는 사실은 기록했지만, 그 후보가 어떤 정규화 정의와 본질을 지켜야 하는지는 팩에 고정하지 않았다.
- 용어 이름을 직접 쓰지 않을 때 필요한 외적 구성요소와 최소 충족 수가 기계 판독 가능한 형태가 아니었다.
- 정확 표현, 성인 안전 유사형, 단일 이미지의 부분 증거, 시퀀스 필수, 상호작용 필수의 차이가 없었다.
- 민감 명칭을 지우는 일과 의미를 약화하는 일이 구분되지 않아, 과도한 순화 또는 무의식적 정책 우회가 가능했다.

## 3. 데이터 모델

새 의미 원본은 `moe_meaning_contracts_v1.json` 한 곳에 둔다. 각 계약은 다음 필드를 가진다.

| 필드 | 역할 |
|---|---|
| `canonical_definition_ko` | 민감한 내용까지 포함해 실제 개념과 계보를 축약 없이 설명한다. |
| `essential_semantics_ko` | 이 요소를 그 요소답게 만드는 필수 의미 단위다. |
| `non_equivalents_ko` | 자주 혼동하지만 같은 의미가 아닌 대체물을 차단한다. |
| `semantic_axes` | 원인·주체성·관점·강도·재질·구도처럼 선호를 나눌 축이다. |
| `runtime_label_policy` | 이름을 그대로 허용할지, 생략할지, 상표만 중립화할지 정한다. |
| `runtime_forbidden_labels` | 프롬프트와 네거티브 프롬프트에 노출되면 실패할 문자열이다. |
| `semantic_fidelity` | `exact_componentized`, `safe_analogue`, `partial_evidence`, `sequence_required`, `interaction_required` 중 하나다. |
| `component_groups` | 최종 프롬프트가 반드시 포함할 관찰 가능한 대안 묶음과 최소 충족 수다. |
| `false_substitutes_en` | 의미를 흉내 내지만 본질을 만족하지 않는 이미지 대체물이다. |
| `do_not_infer_en` | 한 장면이나 외형만으로 단정하면 안 되는 원인·동의·정체성 등이다. |
| `adult_requirement` | 신체 초점·성적 계보·학교 맥락에 필요한 성인/비성적 경계다. |
| `capability` | 단일 프레임, 시퀀스, 상호작용 매체가 의미를 얼마나 증명할 수 있는지 선언한다. |

이 파일은 다섯 v2 조사 dossier의 SHA-256을 고정한다. 따라서 의미를 고치려면 어떤 조사 바이트를 근거로 했는지가 항상 확인된다.

## 5. 버전과 런타임 흐름

```text
immutable v1 IDs/aliases
          +
immutable v2 dossiers + v2 grammar + compatibility
          |
          | exact source hashes
          v
moe_meaning_contracts_v1.json
          |
          | compile_moe_grammar_v3.py
          v
illustration_moe_grammar_v3.json
          |
          | explicit element selection only
          v
candidate pack v5 -> composed prompt v3 -> semantic audit v3
```

새 작업의 기본은 v3/v5다. `--grammar-version v2`를 명시했을 때만 기존 v2 문법과 v4 팩을 재현한다. v3 컴파일러는 v2 후보를 복사해 정규화 계약을 결합하며, v2 파일 자체는 쓰지 않는다.

런타임 처리 순서는 다음과 같다.

1. 완전한 ID 또는 검토된 전체 별칭으로만 요소를 활성화한다.
2. 로컬 v3 문법과 의미 계약의 해시·29개 순서·원 dossier 해시를 검증한다.
3. 원 요청의 선호 단서로 명시된 요소 내부 후보만 고른다.
4. 후보의 주 표현에 각 의미 계약의 누락된 필수 구성요소를 이름 없이 추가한다.
5. 팩에 전체 의미 계약, 계약 해시, 충실도와 매체 능력을 고정한다.
6. 원 요청 해시와 `original_request_plus_canonical_meaning` 안전 입력 경계를 기록한다.
7. 하나의 사건으로 재구성하고 프롬프트/네거티브 프롬프트에서 금지 명칭을 검사한다.
8. 로컬 자산으로 선택을 다시 실행한 뒤 계약·구성요소·매체·성인 조건을 감사한다.

## 6. 실패 폐쇄 감사 규칙

- 팩 ID를 다시 계산해도 로컬 정규화 계약과 다른 정의는 실패한다.
- `safe_analogue`를 `exact_componentized`로 바꾸거나 그 반대인 경우 실패한다.
- 필수 구성요소 그룹 중 하나라도 최종 프롬프트에 없으면 실패한다.
- `runtime_forbidden_labels`가 프롬프트 또는 네거티브 프롬프트에 나타나면 실패한다.
- 시퀀스 필수 요소를 단일 프레임으로, 상호작용 필수 요소를 정지 이미지로 주장하면 실패한다.
- 성인 명시가 필요한 신체 초점·성적 계보 요소에 `adult` 근거가 없으면 실패한다.
- 기존 base pack의 안전 메타데이터와 네거티브 프롬프트가 바뀌면 실패한다.
- 감사 PASS는 의미·프롬프트 사전검증일 뿐 픽셀 구현 성공으로 승격하지 않는다.
