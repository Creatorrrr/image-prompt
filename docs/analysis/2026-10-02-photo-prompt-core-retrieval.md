# Photo prompt corpus and retrieval cleanup

The independently authored baseline now owns the photographic scene. Candidate data is loaded only after the request envelope, authorial core, creative controls and embodiment review are validated. Basic-prompt authoring receives no slot inventory. The structured subject, setting, event and style fields record the authored scene; they are not candidate-selection templates.

## Changes

- Removed 706 runtime presets, concept recipes, scene-expression assets, selection routes, sampler entrypoints and their retired fixtures. Removed CLI arguments are rejected; there are no adapters or substitute defaults.
- Preserved every authored slot entry across the base corpus and extensions. The current corpus contains 112 slots and 9,432 entries.
- Retrieve only grounded, owned slots from the frozen core, subject/context/facet guards and exclusions. Explicit frozen observations receive focused, property-compatible discovery. All ordinary candidate adoption remains optional, including adopting none.
- Bind the complete candidate inventory to its frozen core and source corpus. Composition audits recompute the inventory, and composed prompts and render requests bind the retrieval hash.
- Rebuilt the slot/character semantic index from existing embedding vectors. No new embedding or image-generation calls were made. Removed obsolete generated index directories.
- Updated related trend-scout contracts and the sibling illustration skill's current photo boundary and validator source binding. Historical run and qualification evidence remains immutable and is not executed as a compatibility path.
