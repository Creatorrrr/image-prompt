# 전체 공통 후보 풀의 슬롯 태그 보강 계획

2026-10-14 수정: **남은 5~8단계는 Codex가 원문을 직접 읽고 의미·태그를 판정한다. Gemini API는 임베딩·텍스트 생성·재심사·캐시 관리를 포함해 호출하지 않는다.** 이 지시는 아래의 이전 실행 방식과 역사 리포트의 재개 안내보다 우선한다. 이번 수정은 계획 변경이며 전수 심사나 운영 데이터 적용을 재개한 결과가 아니다.

2026-10-13 품질 개선 커밋 `b7074e7771eecad191cfa0dc8f2a873413e0bfb3`를 출발점으로 한다. 목표는 후보 본문을 하나씩 유지하면서, 각 후보의 실제 의미·소유자·효과·적용 조건에 맞는 슬롯을 모두 연결하는 것이다. 슬롯별 검색 대상은 계속 공통 풀 전체이며 BM25F와 임베딩을 함께 사용한다. 태그 소속으로 검색 풀을 나누거나 같은 후보에 검색 점수를 여러 번 주지 않는다.

이 문서는 실행 계획이다. 품질 개선에서 잘못된 슬롯 9개는 보정했지만, 아래의 전체 데이터 다중 태그 추가는 아직 수행하지 않았다. 각 단계는 구현·검증·증빙을 완료한 뒤 별도 커밋하고 다음 단계로 진행한다.

2026-10-13 슬롯 체계 감사 후 순서를 수정했다. **슬롯 자체의 정비를 전체 태그 추가보다 먼저 수행한다.** 기존 2단계의 의미 정의를 새로운 0단계로 앞당기고, 2단계에서 조건·의미 판정 계약을 구현한 뒤 3단계에서 기존 슬롯과 연결을 새 체계로 이관한다. 이후 4~8단계에서 전체 후보의 태그를 보강한다.

실행 현황: 참고 대화의 전체 45개 분류에 근거한 슬롯 정비 **0~3단계와 4단계 파일럿을 구현·검증 완료**했다. 4단계에서 609개를 심사하고 누락된 방향·손톱·국소 신체 형태 역할을 추가해 관리 역할은 139개다. 5단계의 선행 원전 보정·조건부 실현 계약은 커밋 `12cd3540d`까지 반영했지만, 전수 심사·전체 태그안 확정과 6~8단계는 남아 있다. 이후 별도 로컬 임베딩 전환 커밋 `39971eaeb`가 반영됐다. [실행 현황](../research-evidence/photo-prompt/slot-taxonomy-revision-20261013/PROGRESS.ko.md)과 [4단계 리포트](../research-evidence/photo-prompt/slot-tag-pilot-20261013/REPORT.ko.md)에 이전 단계의 검증 범위를 기록한다.

## 남은 단계에 공통으로 적용하는 실행 방식

**의미 판정은 Codex가 원문을 직접 읽고 한다.** 2026-10-14 후속 사용자 승인에 따라 `gpt-6.1-sol` 서브에이전트를 적절한 effort로 분업에 사용할 수 있다. 이번 분업은 `high` effort, 중복 없는 고정 ID 범위, 250개 관리 배치를 사용한다. 주 에이전트는 배정·근거 통합·누락/중복/조건 검사·커밋을 맡고 각 서브에이전트는 담당 원문·필수 참조를 직접 읽어 의미와 태그를 판정한다. 주 에이전트가 서브에이전트의 모든 원문을 직접 읽었다고 표시하지 않는다. Gemini·다른 외부 생성 모델·로컬 생성 모델·별도 CLI 심사에 위탁하지 않으며 임베딩 유사도나 규칙만으로 만든 자동 태그를 직접 검토로 기록하지 않는다. Python 보조 도구의 역할은 원문·참조 펼치기, 작업 목록·차이·누락 집계, 정확한 인용·hash·schema·조건·검색 순위 검증과 승인된 변경의 결정적 적용이다.

검토 입력은 canonical 본문 전체와 한국어·영어 의미, 효과, intrinsic 조건, 실현 분기, 구성원·프로필·관계 참조 및 출처다. 먼저 원문에서 소유자와 속성·행위·관계를 해석한 뒤 현재 139개 역할 명세를 대조한다. 필요한 역할을 추가할 수 있지만 정의·이웃 경계·양성/음성 사례·query 계약을 먼저 정비하고 영향 후보를 재검토한다. 기존 슬롯·태그·Gemini 초안은 최초 의미 판정 이후 비교 자료로만 열어 누락·이견을 확인한다.

기존 Gemini 원응답·정규화·재심사·자격화 파일은 역사 증빙으로 보존한다. 기계 검사 통과, `qualified` 파일명, 같은 원문의 반복 응답은 직접 검토 승인 근거가 아니다. 직접 검토 도구는 `review_corpus.py`, `adjudicate_reviews.py`, `qualify_reviews.py`, `qualify_batches.py` 등 외부 심사 모듈을 실행·import하지 않는다. 해당 모듈의 통계·검증 함수가 필요하면 API 의존성 없는 보조 모듈로 분리해 필요한 부분만 검증한다. 원격 prompt cache를 재생성하거나 provider 상태를 조회하지 않는다.

임베딩은 스킬의 설치된 로컬 모델·고정 lock·`embedding-default.json`·활성 manifest 공간을 확인한 뒤 수행한다. 빌더는 `--backend embeddinggemma2-local`을 명시하고 문서·질의·실행 증거가 같은 공간인지 검증한다. 로컬 모델 누락·변조·공간 불일치에는 오류를 내고 멈추며 Gemini fallback, 과거 Gemini 벡터의 활성 혼합, 자동 rollback을 하지 않는다. API 키를 주입하지 않고 네트워크 차단 조건에서도 실제 신규 질의가 추론되는지 검증한다. 모델 재설치·다운로드·임베딩을 이번 계획 수정에서 수행하지 않는다.

직접 검토 대장은 `slot-tag-codex-direct-20261014/` 아래에 기존 증빙과 분리해 작성한다. 후보별 ID·종류, 원본/검토 후 의미 hash, 원본 파일, catalog 및 선택 역할의 spec hash, 참조와 조건, 의미 요약, 역할별 추가/유지/제거, 직접/맥락 구분, 정확한 JSON pointer·긍정 인용, 소유자·속성·효과, 적용할 realization ID, 수정 전후 본문·사유, 혼동 경계, 판정 상태를 기록한다. `reviewer=Codex`, `review_method=codex_direct_source_read`, `independent_human_review=false`와 실제 작성한 배치 증빙을 남긴다. `all_roles_considered` 표기나 원문을 출력한 사실만으로 승인하지 않는다.

서브에이전트 판정은 별도 v2 행의 `review_method=codex_subagent_direct_source_read`로 기록한다. 실제 도구 호출로 배정한 task·model·effort·범위와 작성자 note·원문 packet·판정 파일의 hash를 결합한다. 배정 밖 ID·검토자 불일치·변경된 note·미해결 판정·읽지 않은 참조는 승인으로 집계하지 않는다. 원래 주 에이전트의 v1 판정은 소급해 작성자를 바꾸지 않고 보존한다. 동일 모델 계열의 분업 결과는 독립적인 사람·독립 모델 정확도 평가가 아니다.

관리 배치는 250~500개 ID로 누락을 관리하되 실제 읽기는 본문 길이에 맞춘 소규모로 한다. 짧은 옵션은 약 8~20개, 복합 프로필·묶음은 약 1~5개부터 시작해 전체 원문·필수 참조가 한 번에 읽히도록 줄인다. 잘린 입력·요약문만 읽은 항목·읽지 않은 참조·미판정 행은 승인 상태로 바꾸지 않는다. 대장과 진행 현황을 배치마다 저장해 이후 문맥이 바뀌어도 미완료 ID부터 이어간다.

기존 609개 Codex 파일럿은 별도 모델 초안과 구분한다. 현재 원문·kind·조건·효과·분기·필수 참조·catalog/spec·원문 인용과 승인 이유가 모두 유효한지 확인한 항목만 새 대장으로 이관한다. 바뀐 항목과 비어 있거나 불특정한 owner/property 근거는 직접 다시 읽어 보완한다. 재사용 가능 수를 먼저 가정하지 않으며 과거 파일럿과 이번 직접 검토의 중복 ID는 한 번만 센다.

외부 사실의 진위가 불명확한 전문·문화·과학 항목은 그 불확실성을 숨기지 않는다. 원문이 실제로 선언한 시각·맥락 의미와 검증되지 않은 사실 주장을 분리하고, 필요하면 일차 출처를 확인하거나 표현을 제한·보정한 뒤 재검토한다. 사실 미확인 주석을 달았다는 이유로 잘못된 주장을 승인하지 않는다. 직접 검토는 Codex의 텍스트 의미 판정이며 독립적인 사람·전문가의 심사나 이미지 픽셀 검증으로 표시하지 않는다.

각 관리 배치·단계는 검토/구현 → 해당 범위 검증 → 결과 저장 → 명시한 파일만 커밋 → 다음 배치/단계 순서다. 기존 미커밋 코드와 다른 작업 파일은 별도로 보존하고, 이 작업의 변경을 직접 확인·검증하기 전에는 포함하지 않는다. 지금은 계획만 수정하며 pull·운영 데이터 적용·빌드·publication·커밋·push를 수행하지 않는다. 후속 실행에서 main 통합이 필요하면 원본을 먼저 병합한 뒤 로컬 공간으로 파생물을 재생성하며, 기존의 완료된 pull을 이번에 수행했다고 기록하지 않는다.

## 0단계 — 슬롯 체계 감사와 목표 명세 확정

[슬롯 체계 감사](../research-evidence/photo-prompt/slot-taxonomy-audit-20261013/REPORT.ko.md)는 112개 catalog·12,020개 연결의 metadata와 모든 슬롯의 대표 후보 709개를 대조했다. 설명 112개가 모두 이름의 띄어쓰기이고, 10개는 의미 차원이 비어 있으며, 역할 제안은 넓은 차원 교집합만으로 fit을 판정한다. 현재 체계를 그대로 전체 후보에 확대하지 않는다.

각 역할의 정의, 대상·소유자, 직접/맥락 구분, 적용 전제, 효과 속성 경로, 포함·제외 예시, 이웃 역할 경계를 확정한다. 새 연결의 근거는 후보의 의미 필드·관계·효과·소유자·조건을 가리키고 검토한 의미 hash를 고정한다. BM25F·임베딩 유사도는 발견 보조이며 단어 포함·기존 슬롯·높은 유사도만으로 태그를 확정하지 않는다. 성인 등장만으로 성적 표현을, 가죽·라텍스만으로 fetish_styling을 지정하지 않는다.

감사의 45개 유지·44개 범위 재정의·12개 일반화·5개 맥락 역할·6개 통합/폐지 제안을 기준으로 목표 명세를 만든다. material, body_framing, partner_framing, distance_narrative, quality, frame_anchor_medium의 통합·분해는 후보별 실제 역할과 참조를 대조해 결정한다. prop_state 같은 일반 역할에는 업무·문화·성인 맥락을 조건으로 보존한다. 물리 질감, 이미지 면의 입자, 광학 흔적, 대기 물질을 구별하고 world·서사·장르·정서의 경계를 정한다.

세부 슬롯이라는 이유만으로 eyeliner·lip finish·camera height 같은 독립 속성을 합치지 않는다. lighting/makeup처럼 실제 완결된 복합 구성은 역할로 유지할 수 있다. 탐색용 family는 표시 metadata로 두며 자동 상위 태그·추가 검색 투표·추가 예산을 만들지 않는다. 정책·진단 이름을 일반 검색 슬롯으로 되살리지 않는다. 목표 슬롯 수를 미리 고정하지 않는다.

직접 역할은 해당 속성·관계를 실제로 표현한다. 맥락 역할은 해석·상황의 관계를 표현하며 이를 인물 출신·마음·동의의 관찰 사실이나 이미지 안 글자로 확대하지 않는다. 현재 binding의 role=optional은 채택 정책이므로 이 의미 구분과 혼용하지 않는다. 명세가 불확실한 전문 항목만 관련 원전과 대조한다.

검증: 기존 112개 모두에 유지/개명/분해/통합/맥락 이전의 결정과 전후 대응안이 있고, 목표 역할마다 이웃 혼동 양성·음성 사례와 소유자·속성 계약이 있어야 한다. 각 통합은 조건·부위·인원·참조 보존 방식까지 정의한다. 이번 감사 완료를 목표 명세 확정이나 운영 이관 완료로 표시하지 않는다.

산출물: 확정 목표 taxonomy, 슬롯 대응 설계, 의미·연결·근거 계약과 경계 판정 지침. 이 단계는 설계 문서이며 운영 원본을 바꾸지 않는다. 커밋: 슬롯 체계 정비 설계.

## 1단계 — 전체 원본과 검토 범위를 고정

현재 authored manifest, 전체 canonical ID 목록, 후보·연결·정책·catalog hash, active search manifest와 closure, local runtime generation을 고정한다. 기존 변경 중인 파일과 이 작업 파일의 경계를 먼저 기록한다. 이후 main과 통합할 때도 authored 원본을 먼저 병합하고 파생 인덱스를 다시 만든다.

전수 검토 대장을 만든다. 한 행은 canonical 후보 하나이며 ID·종류·원본 파일·내용 hash·출처·현재 연결·효과·적용 조건·구성원/프로필 참조·검토 상태를 포함한다. 후보 중심 대장과 슬롯별 역참조를 모두 만든다. 예전 트리에서 어떤 슬롯에 있었는지는 참고 출처로만 사용한다.

검증: ID 집합과 종류별 합계가 위 기준과 일치하고 대장이 전체 원본과 1:1로 대응해야 한다. 기존 12,020개 연결과 모든 참조를 대조한다. 이후 어떤 레코드도 top-k 검색에 노출되지 않았다는 이유로 검토 대상에서 빠질 수 없다.

산출물: 전체 inventory, 기준 hash, 검토 대장, 현재 태그 분포·무태그 목록. 커밋: 전수 태깅 기준 고정.

## 2단계 — 조건 분리·의미 계약과 역할 판정기 구현

대량 추가 전에 실행 경로를 정리한다. 현재 `photo_global_retrieval.eligible`은 기존 binding 중 하나라도 조건을 통과하면 후보를 허용한다. 새 태그에 빈 조건을 넣으면 기존 연결에만 있던 필수 제한을 우회할 수 있다. 반대로 특정 역할의 제한을 후보 전체의 필수 조건으로 옮기면 다른 적합한 역할에서도 검색을 막는다. 단순한 조건 복사·합집합·교집합으로 해결하지 않는다.

필수 주체·성인·소유자·행위자 수·물리 전제·금지 조건은 의미상 타당한 범위에서 후보 자체의 계약으로 관리한다. 특정 슬롯에서의 활용에 필요한 조건은 역할별 계약으로 관리한다. 공통 슬롯 기본값을 실제 후보 의미의 증거로 취급하지 않는다. intrinsic effects와 프로필 내부 concept_candidate의 효과, 묶음의 공동 효과도 대조해 단일 소유 범위를 명확히 한다. 비어 있는 효과를 슬롯 이름으로 추정해 채택 가능으로 만들지 않는다.

기존 연결 전부의 조건을 분류하고 참조를 보존한다. 새 계약에 필드가 필요하면 native source/reader/role proposal/validator 계약을 명시적으로 버전 변경해 함께 전환한다. 레거시 트리·옛 seed·이전 계약을 읽는 호환 경로는 추가하지 않는다. 새 조건이 빠진 항목을 무제한 허용하는 fallback도 금지한다.

0단계의 의미 명세를 schema·reader·query specification·역할 제안이 함께 읽게 만든다. fit은 의미 검토 근거, 소유 대상, 실제 속성 경로·관계·적용 전제와 직접/맥락 역할을 확인한다. appearance 교집합만으로 의복 커프를 hair_color로 eligible 처리하지 않고, lighting 교집합만으로 빛무늬를 입사 방향으로 처리하지 않는다. 빈 차원을 자동 허용으로 바꾸지 않는다. 근거 부족은 검토 필요, 명백한 역할 불일치는 부적합으로 구별한다.

영어·한국어 focus는 같은 의미 경계를 표현해야 한다. 현재 caption_context의 한국어 표기처럼 캡션 역할을 일반적인 사진 상황으로 넓히는 번역을 수정한다. 양쪽 언어의 질의 specification과 검증 사례를 함께 갱신한다.

슬롯의 core focus 투영과 활성 선택·open dimension·제시 예산도 확정 계약에 맞춘다. 모든 질의는 계속 전체 공통 positive 풀에서 독립 검색한다. 새 명세·query recipe에 맞지 않는 옛 query context는 재사용하지 않는다. 후보 본문과 임베딩은 기존의 엄격한 동일성 조건을 만족하는 경우만 재사용한다.

검증: 새 중립 태그 하나가 필수 조건을 무력화하지 않아야 한다. 인물 없는 요청, 성인 허용 여부, 비인간 요청, 특정 소재 잠금, 소유자·행위자 수 잠금의 양성·음성 사례를 검증한다. 정상적인 인물·패션 소재, 상품·다큐멘터리 촬영, 다른 역할로 활용하는 경우가 공통 기본값 때문에 막히지 않아야 한다. 현재 품질 개선의 264개 소재 조건 보정도 유지한다. 차원은 같지만 대상·속성이 다른 후보, 직접 사실과 관련 맥락, 필수 효과가 잠긴 요청을 구별하는 판정 회귀를 추가한다. 운영 계약을 바꾼 만큼 원본·인덱스·실행 데이터를 함께 전환하고 검증한다.

산출물: 조건 전수 분류 대장, native 의미·조건 계약, 판정·질의·제시 코드, 회귀 증빙과 검증된 인덱스·실행 데이터. 커밋: 의미와 조건을 검증하는 역할 계약.

## 3단계 — 기존 슬롯·연결을 새 체계로 완전히 이관

0단계의 대응안에 따라 112개 기존 슬롯의 유지·개명·분해·통합·맥락 이전을 적용한다. **기존 12,020개 연결 전부**를 새 역할 정의로 판정한다. source 조건을 빈 값으로 덮거나 이전 태그를 새 이름으로 일괄 치환해서 끝내지 않는다. 같은 의미의 물리 배치를 합쳐도 신체 부위, 추가 참여자, 성인·주체·소유자 조건과 맥락 근거를 유지한다.

통합·분해된 역할에 따라 binding·프로필·묶음·정책·guard_role·core focus·query·budget·검증 fixture의 참조를 갱신한다. 후보 본문은 계속 하나만 소유한다. 시각 후보가 아닌 순수 정책·검사 항목을 다른 계약으로 옮기는 예외는 원본 ID·의미·새 소유 파일·참조·positive 포함 여부를 별도 대장에 남긴다. 제약을 후보 태그로 위장하거나 설명 없이 원본을 삭제하지 않는다.

슬롯 ID와 core의 camera.capture_mode 같은 동명 속성은 의미와 계약이 다를 수 있다. 코드의 문자열 사용처 대장을 읽고 실제 슬롯 소비자만 전환한다. 폐지·개명한 슬롯 ID는 운영 catalog·독립 질의·역할 제시에서 제거하며 운영 alias/fallback을 두지 않는다. 기존 요청 artifact를 새 성공 결과로 다시 쓰지 않고 새 native run으로 검증한다. 이 단계의 변경 내용에 맞게 인덱스·질의·runtime generation을 갱신한 뒤 커밋한다.

검증: 112/112 슬롯과 12,020/12,020 기존 연결에 유지 또는 대체/제거 이유·새 참조·조건 대응이 있어야 한다. 신규 catalog의 중복 의미·누락 역할, 후보 본문 유실/복제, 고아 binding/프로필/묶음, 옛 슬롯 운영 참조가 없어야 한다. 단계별 positive 수가 18,186에서 바뀌는 예외는 사유와 전후 완전 대응을 검증한다. 역할 경계·필수 조건·전체 풀 검색·lazy shard·실제 acquire를 확인한다.

산출물: 정비된 native catalog와 기존 연결, 전후 대응 대장, 소비자 코드·fixture, 실제 검색과 인덱스·실행 검증. 커밋: 슬롯 체계 전환 및 기존 연결 이관.

## 4단계 — 여러 종류와 희소 슬롯을 포함한 파일럿

전체에서 500~800개 정도를 파일럿으로 고른다. 단순 빈도순이 아니라 정비 후 모든 슬롯, 모든 종류, 무태그 프로필·묶음·관계, 다중 속성 옵션, 소유자·방향·색·형태·문화 변형 경계, 성인 맥락, 최초 표본의 넓은 관련 슬롯 판정 30건과 보정한 9건을 포함한다. 통합·분해·맥락 이전한 역할의 전후 경계도 포함한다. 진단 레코드의 제외 판정도 함께 확인한다.

후보를 먼저 읽어 적합한 모든 슬롯을 제안하고, 슬롯 명세로 전체 공통 풀을 BM25F·임베딩 검색해 빠뜨린 역할을 역으로 점검한다. 슬롯별 top-k에 들어온 후보만 검토하는 방식은 사용하지 않는다. 재검토는 후보 의미와 경계를 다시 읽는 과정이며, 같은 규칙의 자동 실행 결과를 독립 심사로 계산하지 않는다.

예를 들어 같은 옷의 표면 구조는 garment_detail·surface_material·texture가 모두 직접 역할일 수 있다. 반면 넓은 패션 맥락에 속한다는 이유만으로 의복 종류·성적 표현·색 태그까지 붙이지 않는다. 묶음과 프로필은 자신이 표현하는 완전한 의미를 기준으로 검토하고 구성원 태그를 기계적으로 전부 합치지 않는다.

검증: 추가·제거·유지 판정과 근거가 일치하고 파일럿의 태그 수를 늘리기 위해 의미를 넓히지 않아야 한다. 조건 우회·중복 투표·hard activation 확대가 없어야 한다. 미합의·모호한 판정은 의미 계약을 고쳐 다시 검토한 후 종료한다.

산출물: 파일럿 전후 대장, 보정한 판정 규칙, 검색·조건·역할 제시 결과. 커밋: 파일럿 태깅과 검증.

5B — 종류·출처·의미 영역별 관리 배치 안에서 Codex가 후보와 필수 참조를 직접 읽는다. 먼저 609개 기존 Codex 파일럿의 유효성을 확인해 재사용/재검토를 분리한 뒤, 전체 고정 ID 대장에서 아직 승인되지 않은 후보를 끝까지 검토한다. 현재 태그를 유지·제거하거나 실제 적합한 모든 역할을 추가한다. 내용이 약하거나 잘못돼 태깅을 확정할 수 없는 후보는 먼저 정확한 필드·문자열·사유로 의미 보정을 작성하고, 보정된 전체 본문·번역·조건·구성 계약을 다시 읽는다. 스크립트는 수정안을 임의로 만들거나 누락 판정을 자동으로 승인하지 않는다.

관계 개념·메커니즘은 실제 서사/관계 역할로 검토하고 구체 동작으로 잘못 바꾸지 않는다. 순수 검사 규칙은 진단으로 분리하되 구체 대상을 표현하는 프로필을 조건 문구가 있다는 이유로 진단으로 옮기지 않는다. 옵션·프로필·묶음은 자신의 완전한 의미로 심사하며 구성원 태그를 합집합하지 않는다. OR 대안은 해당 분기의 효과·구성원·조건만 근거로 하고, 공통/선택 효과를 섞지 않는다. 부정·혼동·라우팅용 문구와 태그/facet만으로 긍정 역할을 만들지 않는다. 의복·머리카락·신체·배경·이미지 면의 소유자, gaze/머리 방향, 소재/성적 맥락, 관찰 가능한 흔적/추정 원인을 구별한다.

판정은 공통 실행 방식의 직접 검토 대장에 기록한다. 애매한 항목은 `needs_source_fix` 또는 `needs_boundary_review`로 남겨 확정 태그로 적용하지 않는다. 보정 제안·보류 상태는 체크포인트로 저장할 수 있지만 해당 배치를 완료했다고 보고하거나 확정 적용 단계로 넘기지 않는다. 후보별 최소 태그 수·전체 태그 증가율 같은 할당량은 두지 않는다.

Native 자격화에서는 사실별 실제 realization ID와 이미 존재해야 하는 대상·부위·맥락을 별도로 직접 심사해 기록한다. `required_carriers: []`도 심사 결과이며 태그·단어·주체 범주에서 자동으로 채우지 않는다. 얼굴·머리카락·손톱 등은 요청과 동결 본문에 결합된 명시적 기존 대상 근거가 있어야 하고, 존재 근거가 잠긴 속성을 바꿀 권한을 주지 않는다. 원문에 이미 선언된 맥락·보존 조건과 실제 변경 효과를 구별하고, 전체 효과·분기·구성 조건을 빠짐없이 대조한다. 같은 소유자의 별칭으로 속성 잠금을 우회하거나 직접 검토된 의미만으로 native 자격화 완료를 표시하지 않는다. 이 보조 계약의 코드·fixture 검증과 전체 후보의 실제 자격화·역검색 완료는 별도로 기록한다.

실제 요청에 이미 선언된 대상 중 하나를 명시적으로 선택하는 공통 경로는 `95b31c4b3`에 구현·검증·커밋했다. 최종 코드의 292회 실행·286개 고유 테스트·498개 하위 검사가 실패·오류·skip 없이 통과했고, 기존 동일 공간의 로컬 벡터 18,180개만 재사용한 빌드와 publication 및 실제 acquire를 확인했다. 새 추론과 Gemini 호출은 0회다. 동일한 실제 소유자로 해석된 한 source/RID의 효과 값·operation·receiver 집합 충돌을 거부하며, 공개 후보팩은 변경하지 않는다. 이 결과는 전체 후보의 의미·태그 승인이나 최종 검색 평가를 대신하지 않는다. 선택한 부위들이 같은 인물에 속해야 하는 등의 동적 source-target 관계 조건은 별도 계약 보완 후 검증하며, 그 조건이 미완성인 후보는 보류를 유지한다.

동시에 [직접 검토 초안 체크포인트](../research-evidence/photo-prompt/slot-tag-codex-direct-20261014/ROOT-MANUAL-DRAFT-CHECKPOINT-01.json)에 서로 겹치지 않는 1,300개 후보의 담당자 원문·기존 5B·자기 binding 읽기와 불변 산출물 hash를 보존했다. 이는 운영 native 승인 1,300건을 뜻하지 않는다. 얼굴·신체 부위의 중립 witness 표기, 동일 효과 값, 실제 적용 대상·별칭의 충돌을 별도 검증하고 보류된 판정은 정확한 이전 행과 사유를 결합한 새 revision으로 심사한다. 전체 18,250개의 최종 명세 직접 판정과 보류 0건이라는 5단계 종료 조건은 유지한다.

검증: 각 배치의 ID·긍정 인용·원본/수정 후 hash·선택 분기·owner/property·효과·조건을 대조하고, 의미 변경은 관련 옵션·프로필·묶음·참조에 전파한다. 운영 원본을 고친 배치는 새 local index closure·runtime publication·실제 acquire까지 검증한 뒤 커밋한다. 대장만 작성한 배치는 운영 데이터를 바꾸지 않는다. 5단계 종료 조건은 직접 검토 승인 집합이 18,250/18,250, 누락·미검토·미해결 보류 0건, Gemini 신규 호출 0건이다.

산출물: 직접 검토 기준 snapshot·입력/검증 보조 도구, 전체 확정 태그안·긍정 인용·소유자·분기 근거 대장, 필요한 source 보정과 native 검증, 배치별 검증·커밋, 실제 직접 검토 coverage.

현재 상태: 선행 보정은 완료했지만 5A~5C의 새 방식 실행은 이 문서 수정만으로 완료되지 않는다. 과거 응답 7,666개와 자격화 파일 5,341개는 역사 초안이고, 최초 리포트의 1,786개는 그보다 이전 시점의 수다. [최초 실행 리포트](../research-evidence/photo-prompt/slot-tag-full-corpus-20261014/REPORT.ko.md)의 Gemini 재개·캐시 생성 안내는 실행하지 않고 이 문서의 직접 검토 절차를 따른다.

## 6단계 — 확정 연결 적용과 무결성 검증

5단계의 직접 검토 승인 대장과 현재 source/catalog hash가 일치하는 추가·제거 관계만 native 원본에 적용한다. Gemini 초안·단순 유사도·규칙 출력에서 관계를 자동 수입하지 않는다. 기존 후보 ID와 계속 유효한 binding ID는 유지한다. 새로운 binding ID는 후보·슬롯 관계와 검토한 계약에 따라 안정적으로 생성하고 재실행해도 같은 관계가 중복되지 않도록 한다. 동일 후보·동일 슬롯의 불필요한 다중 관계는 허용하지 않는다. 조건별 변형이 필요하면 한 관계 안에 명시적인 적용 대안을 기록하며 검색 투표를 추가하지 않는다.

원본 본문은 후보당 하나만 소유한다. 태그별로 후보 복사본을 만들지 않는다. 관계 근거와 출처를 추가하되 예전 출처는 보존한다. 연결을 제거할 때는 묶음·정책·참조가 해당 binding을 사용하는지 먼저 확인하고 의미상 같은 유효 관계로 갱신하거나 관련 구성을 함께 수정한다. 고아 참조를 남기지 않는다.

특히 binding을 구성원 참조로 쓰는 묶음에서 연결을 제거하거나 구성원을 diagnostic으로 바꾸면, 임의의 다른 슬롯 binding으로 치환하지 않는다. 실제 의미가 같은 참조로 갱신하거나 후보 참조와 표시 역할을 분리하는 native 계약을 명시적으로 전환하고 필요한 consumer·validator·fixture를 함께 고친다. 진단 의존성은 시각 효과·positive 투표를 만들지 않게 보존한다. 이관 전후의 구성원·실현 분기·조건·출처 대응을 전수 검증하고 레거시 참조 adapter는 남기지 않는다.

검증: 후보 본문 소유자 유일성, 후보·슬롯 관계 중복 0, dangling reference 0, 관련 원전·효과·소유자 일치, 동일 의미 hash 기반 자격 근거 일치를 확인한다. 기본적으로 18,250개 후보를 보존하며 추가·분리·통합이 필요한 예외는 이유와 모든 참조 대응을 별도 검증한다. 태그 적용 전후의 누락과 중복은 전수로 비교한다.

산출물: native 확정 연결, 전후 대응 ledger와 무결성 결과. 커밋: 전체 검토 태그 적용.

## 7단계 — 인덱스·슬롯별 검색·샤딩·실행 데이터 검증

새 source fingerprint로 인덱스와 실행 데이터의 metadata·guard·payload를 재생성한다. 슬롯 연결 수가 늘어도 positive 문서는 canonical 후보당 하나다. 태그를 lexical 본문에 반복 삽입하거나 태그별 복제 문서를 만들어 점수를 올리지 않는다.

태그·조건 metadata만 바뀐 후보는 full text, recipe, provider/model/revision/dimensions, 모델 패키지·실행 설정, vector integrity가 같은 **현재 로컬 공간의 벡터만** 재사용한다. 본문이 바뀐 후보는 같은 로컬 모델로 다시 임베딩한다. 모델·recipe·공간이 바뀌면 문서 전체와 관련 질의를 재임베딩하고 별도 검증한다. 슬롯 명세를 바꿔 독립 질의가 달라졌다면 해당 질의 context와 실제 로컬 query embedding도 새로 생성한다. 예상·실제 로컬 추론 수, 동일 공간 재사용·실패 내역과 실행 trace를 기록한다. 과거 Gemini query 벡터나 응답을 새 local 검색 증거로 재포장하지 않는다.

모든 슬롯에 대해 독립 BM25F·임베딩 lane·RRF·역할 제시를 확인한다. 영속 태그가 없는 후보와 다른 슬롯 태그만 있던 후보도 적합한 요청에서 발견될 수 있어야 한다. 다중 태그 후보를 여러 개의 검색 문서나 여러 ranking vote로 계산하지 않는다. 역할 부적합·필수 조건 위반은 순위와 별도로 검증한다.

검증: 전체 통계·문서 수·vector 범위·posting·payload closure를 대조하고, 전체 139개 슬롯의 한국어·영어 고정 질의에서 각 lane의 순위를 같은 로컬 벡터 공간의 offline full-scan oracle과 비교한다. 이후 슬롯을 추가했다면 늘어난 최종 catalog 전부로 범위를 확장한다. reader의 lazy loading, 필요한 extent bytes, 64MiB 콘텐츠 cache·64개 vector descriptor 한계, skip certificate, 최악 조건의 bounded full streaming을 검증한다. cold metadata read와 검색·재검산 read를 분리하며 전체 프로세스/RSS·모델 메모리를 reader cache 한도로 표시하지 않는다.

API 키 제거·OS 네트워크 차단 상태에서 캐시에 없는 실제 신규 로컬 질의와 BM25F/embedding/RRF, receipt 발행·재생·구성 감사를 검증한다. 캐시 적중만으로 신규 로컬 추론을 주장하지 않는다. 완전히 검증된 native generation만 활성화하고 실제 acquire 경로에서 새 태그·조건이 제시되는지 확인한다. 실패한 빌드나 일부 태그안으로 자동 활성화하지 않으며, 로컬 실패 때 Gemini로 우회하지 않는다.

산출물: 실제 검색·조건·역할 제시 결과, shard I/O와 oracle 비교, embedding ledger, 검증된 실행 데이터. 커밋: 전체 태그 검색 및 실행 통합.

## 8단계 — 최종 의미 품질 평가와 완료 리포트

기존 1,000개에서 보정·유지·보류 판정의 후속 상태를 확인하고, 별도 seed·ID 목록을 판정 전에 고정한 새로운 무작위 1,000개를 Codex가 직접 재검토한다. 현재 태그·이전 판정·Gemini 초안을 숨기고 원문으로 먼저 판정한 뒤 최종 태그와 대조한다. 기존 표본과 겹친 수와 별도 보충 표본을 구별한다. 전수 심사를 한 같은 Codex의 재검토이므로 독립 사람의 정답, 미사용 holdout 정확도 또는 독립 모델 평가로 표시하지 않는다.

무작위 표본에서 빠질 수 있는 희소 슬롯·관계 종류·진단·문화/과학 변형은 별도 보충 검토한다. 모든 슬롯을 포함한 독립 질의와 양성·음성 경계 사례도 평가한다. 발견한 의미 오류·번역 왜곡·오태그·누락·조건 오류는 원문과 연결을 함께 보정한 뒤 영향 범위를 직접 다시 읽는다.

보고 항목은 직접 검토 coverage와 파일럿 재사용/신규 직접 판정 수, 종류·슬롯별 태그 분포, 단일/다중 연결 수, 오태그·누락 판정, 조건 위반, 중복·참조 무결성, 실제 BM25F/로컬 임베딩/RRF 검색 결과, 읽은 shard/extent·메모리·시간, 로컬 추론·재사용·실패 대장, 수정 지시 이후 Gemini 호출 0건이다. 과거 provider 사용·미확인 응답/비용과 현재 실행을 구분한다. 태그 개수의 증가를 의미 품질 향상으로 간주하지 않는다. 검색 검증과 텍스트 의미 판정, 전문가 확인, 이미지 픽셀 품질은 별도로 보고한다.

현행 native 원본·관계·reader만 운영에서 사용하고 이전 트리나 임시 fallback 경로가 남지 않았는지 확인한다. 파생 파일 정리는 active manifest closure, 참조 fixture, 재현 증빙을 보호한 뒤 정확히 미참조인 파일만 대상으로 한다. 역사 증빙과 다른 작업 파일을 폴더 단위로 삭제하지 않는다.

검증: 위 완료 조건을 모두 만족하고 미검토·보류·미해결 무결성 오류가 없어야 한다. 새 표본과 경계 평가에서 발견한 오태그·조건 오류는 고친 뒤 영향 범위만 다시 검증한다. 생성 이미지나 픽셀 검사는 별도 요청이 있을 때 수행하며, 시행하지 않은 품질을 완료로 표시하지 않는다.

산출물: 전체 완료 대장, 표본·경계 평가, 남은 증거 한계, 최종 리포트와 필요한 정리. 커밋: 전체 슬롯 태그 보강 완료 검증.
