# 전체 공통 후보 풀의 슬롯 태그 보강 계획

2026-10-13 품질 개선 커밋 `b7074e7771eecad191cfa0dc8f2a873413e0bfb3`를 출발점으로 한다. 목표는 후보 본문을 하나씩 유지하면서, 각 후보의 실제 의미·소유자·효과·적용 조건에 맞는 슬롯을 모두 연결하는 것이다. 슬롯별 검색 대상은 계속 공통 풀 전체이며 BM25F와 임베딩을 함께 사용한다. 태그 소속으로 검색 풀을 나누거나 같은 후보에 검색 점수를 여러 번 주지 않는다.

이 문서는 실행 계획이다. 품질 개선에서 잘못된 슬롯 9개는 보정했지만, 아래의 전체 데이터 다중 태그 추가는 아직 수행하지 않았다. 각 단계는 구현·검증·증빙을 완료한 뒤 별도 커밋하고 다음 단계로 진행한다.

어느 단계든 운영 원본·조건·코드가 바뀌면 그 단계 안에서 필요한 인덱스 갱신·closure 검증·실행 데이터 갱신까지 완료한 뒤 커밋한다. 7단계는 전체 슬롯과 성능의 종합 검증이며, 앞 단계에서 원본과 인덱스가 어긋난 상태를 남겨도 된다는 의미가 아니다. 검토 대장만 작성하는 단계는 운영 원본을 바꾸지 않는다.

현재 프로필·묶음·관계·진단 레코드 6,246개에는 영속 슬롯 연결이 없다. 무태그도 검색은 가능하다. 기존 두 슬롯 연결 16개는 중복 원본을 통합하면서 원래 소속을 보존한 결과이며 의미에 맞는 새 다중 태그를 심사한 결과는 아니다.

완료는 다음 조건으로 판정한다.

- 전체 18,250개에 개별 검토 결과가 있고 누락·미검토·보류 항목이 없다. 의미 변경이 필요했던 후보는 먼저 고치고 그 의미를 기준으로 다시 태깅한다.
- 18,186개 positive 레코드는 실제 활용 역할에 맞는 연결을 갖는다. 단일 역할이면 하나를 유지하고, 여러 직접 역할이면 모두 연결한다. 슬롯 수를 맞추기 위해 태그를 붙이지 않는다. 적합한 기존 슬롯이 없으면 catalog의 의미 범위를 검토해 필요한 역할을 정의한다.
- 진단 64개도 전부 검토하되 진단 전용 분류와 제외 근거를 기록한다. 시각 후보 슬롯을 억지로 붙이거나 positive 검색에 넣지 않는다.
- 모든 연결에는 의미상의 근거와 적용 조건이 있다. 오태그 제거와 신규 태그 추가가 함께 끝나고 후보 중복·유실·고아 참조·중복 연결이 없다.
- 새 태그를 붙여도 후보 자체의 필수 적용 조건, requester의 제외·잠금, 성인·주체·소유자 조건을 우회하지 않는다. 태그는 의미 탐색과 제시 역할이며 hard profile의 자동 활성화 근거가 아니다.
- 모든 관리 슬롯이 전체 공통 풀에서 독립된 BM25F·임베딩 검색을 유지하고, 필요한 shard/extent만 읽는 경로와 정확한 순위가 검증된다.

## 1단계 — 전체 원본과 검토 범위를 고정

현재 authored manifest, 전체 canonical ID 목록, 후보·연결·정책·catalog hash, active search manifest와 closure, local runtime generation을 고정한다. 기존 변경 중인 파일과 이 작업 파일의 경계를 먼저 기록한다. 이후 main과 통합할 때도 authored 원본을 먼저 병합하고 파생 인덱스를 다시 만든다.

전수 검토 대장을 만든다. 한 행은 canonical 후보 하나이며 ID·종류·원본 파일·내용 hash·출처·현재 연결·효과·적용 조건·구성원/프로필 참조·검토 상태를 포함한다. 후보 중심 대장과 슬롯별 역참조를 모두 만든다. 예전 트리에서 어떤 슬롯에 있었는지는 참고 출처로만 사용한다.

검증: ID 집합과 종류별 합계가 위 기준과 일치하고 대장이 전체 원본과 1:1로 대응해야 한다. 기존 12,020개 연결과 모든 참조를 대조한다. 이후 어떤 레코드도 top-k 검색에 노출되지 않았다는 이유로 검토 대상에서 빠질 수 없다.

산출물: 전체 inventory, 기준 hash, 검토 대장, 현재 태그 분포·무태그 목록. 커밋: 전수 태깅 기준 고정.

## 2단계 — 슬롯의 실제 의미와 연결 판정 규칙 정의

112개 슬롯 각각에 다음을 정리한다: 무엇을 직접 표현하는가, 누구/무엇의 어떤 속성을 바꾸는가, 포함·제외 사례, 이웃 슬롯과의 경계, 필수 조건과 선택 가능한 변형, 표현 맥락으로만 관련 있는 경우. `prop_direction`과 물건 상태, 빛 방향과 빛 패턴, 피부 장식과 의복, 세계 설정과 미디어 스타일 같은 경계를 명문화한다.

연결은 직접 역할과 맥락상 관련 역할을 구분한다. 직접 역할은 해당 슬롯의 의미를 실제로 표현하는 연결이다. 관련 맥락은 그 슬롯을 해석하는 데 도움을 주지만 해당 속성을 독립적으로 지정하지 않는 연결이다. 관련 맥락을 직접 속성값으로 제시하지 않도록 제시 계약도 정의한다. 현재 binding의 `role=optional`은 채택 정책이므로 이 구분과 혼용하지 않는다.

새 연결의 근거는 후보의 의미 필드·관계·효과·소유자·조건을 가리키고 검토한 의미 hash를 고정한다. BM25F·임베딩 유사도는 발견 보조 자료다. 단어 포함, 기존 슬롯, 높은 유사도만으로 확정하지 않는다. 예를 들어 성인 인물이 있다는 사실만으로 adult_context를, 가죽·라텍스가 있다는 사실만으로 fetish_styling을 붙이지 않는다. 실제 슬롯 의미에 해당하는 상황·표현 맥락이 있어야 한다. 의미 정의가 불확실한 전문 항목은 원전과 대조한다.

기존 데이터의 진단·정책 제어 항목을 검색용 슬롯과 구분한다. 현재 catalog에 없는 제어 이름을 임의의 슬롯으로 만들어 후보 수를 채우지 않는다. 필요한 새로운 역할은 포함·제외 규칙을 갖춘 catalog 항목으로 추가한다.

검증: 모든 관리 슬롯에 판정 규칙이 있고 이웃 슬롯의 혼동 사례를 구별해야 한다. 직접/맥락 연결의 근거와 제시 동작을 검증한다. 관측 가능한 사실과 서사·역사·재료 정체 같은 맥락 주장을 구분하며 맥락을 시각 필수 요소로 확대하지 않는다.

산출물: 슬롯 의미 명세, 연결·근거 계약, 경계 사례와 검토 지침. 커밋: 태깅 의미 계약 정의.

## 3단계 — 후보 자체의 조건과 역할별 조건을 분리

대량 추가 전에 실행 경로를 정리한다. 현재 `photo_global_retrieval.eligible`은 기존 binding 중 하나라도 조건을 통과하면 후보를 허용한다. 새 태그에 빈 조건을 넣으면 기존 연결에만 있던 필수 제한을 우회할 수 있다. 반대로 특정 역할의 제한을 후보 전체의 필수 조건으로 옮기면 다른 적합한 역할에서도 검색을 막는다. 단순한 조건 복사·합집합·교집합으로 해결하지 않는다.

필수 주체·성인·소유자·행위자 수·물리 전제·금지 조건은 의미상 타당한 범위에서 후보 자체의 계약으로 관리한다. 특정 슬롯에서의 활용에 필요한 조건은 역할별 계약으로 관리한다. 공통 슬롯 기본값을 실제 후보 의미의 증거로 취급하지 않는다. intrinsic effects와 프로필 내부 concept_candidate의 효과, 묶음의 공동 효과도 대조해 단일 소유 범위를 명확히 한다. 비어 있는 효과를 슬롯 이름으로 추정해 채택 가능으로 만들지 않는다.

기존 연결 전부의 조건을 분류하고 참조를 보존한다. 새 계약에 필드가 필요하면 native source/reader/role proposal/validator 계약을 명시적으로 버전 변경해 함께 전환한다. 레거시 트리·옛 seed·이전 계약을 읽는 호환 경로는 추가하지 않는다. 새 조건이 빠진 항목을 무제한 허용하는 fallback도 금지한다.

검증: 새 중립 태그 하나가 필수 조건을 무력화하지 않아야 한다. 인물 없는 요청, 성인 허용 여부, 비인간 요청, 특정 소재 잠금, 소유자·행위자 수 잠금의 양성·음성 사례를 검증한다. 정상적인 인물·패션 소재, 상품·다큐멘터리 촬영, 다른 역할로 활용하는 경우가 공통 기본값 때문에 막히지 않아야 한다. 현재 품질 개선의 264개 소재 조건 보정도 유지한다.

산출물: 조건 분리 설계·전수 분류 대장, 필요한 native 계약과 실행 코드, 회귀 증빙. 커밋: 태그 증가에 안전한 적용 조건 계약.

## 4단계 — 여러 종류와 희소 슬롯을 포함한 파일럿

전체에서 500~800개 정도를 파일럿으로 고른다. 단순 빈도순이 아니라 모든 슬롯, 모든 종류, 무태그 프로필·묶음·관계, 다중 속성 옵션, 소유자·방향·색·형태·문화 변형 경계, 성인 맥락, 현재 넓은 관련 슬롯 30개와 보정한 9개를 포함한다. 진단 레코드의 제외 판정도 함께 확인한다.

후보를 먼저 읽어 적합한 모든 슬롯을 제안하고, 슬롯 명세로 전체 공통 풀을 BM25F·임베딩 검색해 빠뜨린 역할을 역으로 점검한다. 슬롯별 top-k에 들어온 후보만 검토하는 방식은 사용하지 않는다. 재검토는 후보 의미와 경계를 다시 읽는 과정이며, 같은 규칙의 자동 실행 결과를 독립 심사로 계산하지 않는다.

예를 들어 같은 옷의 표면 구조는 garment_detail·surface_material·texture가 모두 직접 역할일 수 있다. 반면 넓은 패션 맥락에 속한다는 이유만으로 의복 종류·성적 표현·색 태그까지 붙이지 않는다. 묶음과 프로필은 자신이 표현하는 완전한 의미를 기준으로 검토하고 구성원 태그를 기계적으로 전부 합치지 않는다.

검증: 추가·제거·유지 판정과 근거가 일치하고 파일럿의 태그 수를 늘리기 위해 의미를 넓히지 않아야 한다. 조건 우회·중복 투표·hard activation 확대가 없어야 한다. 미합의·모호한 판정은 의미 계약을 고쳐 다시 검토한 후 종료한다.

산출물: 파일럿 전후 대장, 보정한 판정 규칙, 검색·조건·역할 제시 결과. 커밋: 파일럿 태깅과 검증.

## 5단계 — 전체 데이터의 의미 심사와 태그안 작성

종류·출처·의미 영역별로 나눠 전수 검토한다. 운영상 250~500개 단위로 작업하되 전체 대장의 고정 ID 집합으로 누락을 방지한다. 각 후보의 본문·효과·관계·조건·출처와 필요한 참조 후보를 읽고 현재 태그를 유지·제거하거나 적합한 슬롯을 추가한다. 내용이 약하거나 잘못돼 태깅을 확정할 수 없는 후보는 먼저 의미를 보정한다. 수정 본문은 조건·구성 계약까지 함께 대조한다.

18,250개 모두를 읽는 후보 중심 심사와, 각 슬롯의 누락 가능성을 전체 풀 검색으로 점검하는 슬롯 중심 심사를 병행한다. 관계 개념·메커니즘은 실제 서사/관계 역할로 검토하고 구체 동작으로 잘못 바꾸지 않는다. 진단은 전용 분류·제외 근거를 남긴다. 의미가 같아 보이는 옵션·프로필·묶음도 역할·활성화·증거·구성 계약이 다르면 별도 canonical 레코드를 유지한다.

판정에는 후보 ID, 검토한 의미 hash, 추가/제거 슬롯, 직접/맥락 구분, 근거 필드, 소유자와 효과, 필수·역할 조건, 보정 이유, 검토 상태를 포함한다. 애매한 항목은 확정 태그로 저장하지 않고 해당 배치가 끝나기 전에 해결한다. 태그 수의 목표치나 후보별 최소 두 개 같은 할당량은 두지 않는다.

검증: 배치의 모든 ID가 대장에 대응하고 의미 변경은 관련 옵션·프로필·묶음·조건으로 전파돼야 한다. 배치마다 본문·연결·원전 대조 범위를 기록하고 검증 후 커밋한다. 단계 종료 시 전체 검토 범위가 18,250/18,250이고 미검토·보류가 0건이어야 한다.

산출물: 전체 확정 태그안과 검토 대장, 필요한 의미 보정, 배치별 검증·커밋.

## 6단계 — 확정 연결 적용과 무결성 검증

확정된 추가·제거 관계를 native 원본에 적용한다. 기존 후보 ID와 계속 유효한 binding ID는 유지한다. 새로운 binding ID는 후보·슬롯 관계와 검토한 계약에 따라 안정적으로 생성하고 재실행해도 같은 관계가 중복되지 않도록 한다. 동일 후보·동일 슬롯의 불필요한 다중 관계는 허용하지 않는다. 조건별 변형이 필요하면 한 관계 안에 명시적인 적용 대안을 기록하며 검색 투표를 추가하지 않는다.

원본 본문은 후보당 하나만 소유한다. 태그별로 후보 복사본을 만들지 않는다. 관계 근거와 출처를 추가하되 예전 출처는 보존한다. 연결을 제거할 때는 묶음·정책·참조가 해당 binding을 사용하는지 먼저 확인하고 의미상 같은 유효 관계로 갱신하거나 관련 구성을 함께 수정한다. 고아 참조를 남기지 않는다.

검증: 후보 본문 소유자 유일성, 후보·슬롯 관계 중복 0, dangling reference 0, 관련 원전·효과·소유자 일치, 동일 의미 hash 기반 자격 근거 일치를 확인한다. 기본적으로 18,250개 후보를 보존하며 추가·분리·통합이 필요한 예외는 이유와 모든 참조 대응을 별도 검증한다. 태그 적용 전후의 누락과 중복은 전수로 비교한다.

산출물: native 확정 연결, 전후 대응 ledger와 무결성 결과. 커밋: 전체 검토 태그 적용.

## 7단계 — 인덱스·슬롯별 검색·샤딩·실행 데이터 검증

새 source fingerprint로 인덱스와 실행 데이터의 metadata·guard·payload를 재생성한다. 슬롯 연결 수가 늘어도 positive 문서는 canonical 후보당 하나다. 태그를 lexical 본문에 반복 삽입하거나 태그별 복제 문서를 만들어 점수를 올리지 않는다.

태그·조건 metadata만 바뀐 후보는 full text, recipe, provider/model/dimensions, vector integrity가 같은 기존 벡터를 재사용한다. 의미 본문이 바뀐 후보만 재임베딩한다. 슬롯 명세를 바꿔 독립 질의가 달라졌다면 해당 질의 context와 실제 query embedding도 새로 생성한다. 변경 영향과 예상 호출 수를 먼저 산출하고 실제 호출·재사용·실패 내역을 기록한다.

모든 슬롯에 대해 독립 BM25F·임베딩 lane·RRF·역할 제시를 확인한다. 영속 태그가 없는 후보와 다른 슬롯 태그만 있던 후보도 적합한 요청에서 발견될 수 있어야 한다. 다중 태그 후보를 여러 개의 검색 문서나 여러 ranking vote로 계산하지 않는다. 역할 부적합·필수 조건 위반은 순위와 별도로 검증한다.

검증: 전체 통계·문서 수·vector 범위·posting·payload closure를 대조하고, 고정 질의에서 각 lane의 순위를 offline full-scan oracle과 비교한다. reader의 lazy loading, 필요한 extent bytes, cache·descriptor 한계, skip certificate, 최악 조건의 bounded full streaming을 검증한다. 완전히 검증된 native generation만 활성화하고 실제 acquire 경로에서 새 태그·조건이 제시되는지 확인한다. 실패한 빌드나 일부 태그안으로 자동 활성화하지 않는다.

산출물: 실제 검색·조건·역할 제시 결과, shard I/O와 oracle 비교, embedding ledger, 검증된 실행 데이터. 커밋: 전체 태그 검색 및 실행 통합.

## 8단계 — 최종 의미 품질 평가와 완료 리포트

기존 1,000개에서 보정·유지·보류 판정의 후속 상태를 확인하고, 별도 seed로 새로운 무작위 1,000개를 평가한다. 무작위 표본에서 빠질 수 있는 희소 슬롯·관계 종류·진단·문화/과학 변형은 별도 보충 검토한다. 모든 슬롯을 포함한 독립 질의와 양성·음성 경계 사례도 평가한다. 기존 표본을 학습한 결과를 새 표본의 독립 정확도로 계산하지 않는다.

보고 항목은 전수 검토 coverage, 종류·슬롯별 태그 분포, 단일/다중 연결 수, 오태그·누락 판정, 조건 위반, 중복·참조 무결성, 실제 BM25F/임베딩/RRF 검색 결과, 읽은 shard/extent·메모리·시간, 실제 provider 호출이다. 태그 개수의 증가를 의미 품질 향상으로 간주하지 않는다. 검색 검증과 텍스트 의미 판정, 전문가 확인, 이미지 픽셀 품질은 별도로 보고한다.

현행 native 원본·관계·reader만 운영에서 사용하고 이전 트리나 임시 fallback 경로가 남지 않았는지 확인한다. 파생 파일 정리는 active manifest closure, 참조 fixture, 재현 증빙을 보호한 뒤 정확히 미참조인 파일만 대상으로 한다. 역사 증빙과 다른 작업 파일을 폴더 단위로 삭제하지 않는다.

검증: 위 완료 조건을 모두 만족하고 미검토·보류·미해결 무결성 오류가 없어야 한다. 새 표본과 경계 평가에서 발견한 오태그·조건 오류는 고친 뒤 영향 범위만 다시 검증한다. 생성 이미지나 픽셀 검사는 별도 요청이 있을 때 수행하며, 시행하지 않은 품질을 완료로 표시하지 않는다.

산출물: 전체 완료 대장, 표본·경계 평가, 남은 증거 한계, 최종 리포트와 필요한 정리. 커밋: 전체 슬롯 태그 보강 완료 검증.
