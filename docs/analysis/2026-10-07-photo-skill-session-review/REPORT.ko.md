### P0-1. 이미 제안된 의미 판정 개선을 코드까지 완성

10/5 분석은 문서 반영과 자동 판정 구현을 분명히 구분했다. 현재 코드에서도 그 후속 과제가 남아 있다.

현재 authored vocabulary에 대해 같은 조회 함수를 직접 실행했을 때, surface_affect 값인 “affectionate warmth directed at the same duet partner”는 클래스가 없고 “openly affectionate”는 open_warmth로 연결됐다. 실제 API나 후보팩 생성은 수행하지 않았다. [현재 어휘 점검](/Users/chasoik/Projects/image-prompt/docs/analysis/2026-10-07-photo-skill-session-review/semantic_vocabulary_probe.json)

현재 evaluate_character_response_profile은 필드 자체의 부재와 클래스 미인식을 모두 missing_axes에 넣는다. 관계도 구성원·방향이 다른 경우 missing_relation_operators로 요약한다. 긍정 문맥 표현을 찾지 못한 경우와 명시적 반대 문맥 역시 설명 단계에서 쉽게 혼동된다. [축·관계 판정 코드](/Users/chasoik/Projects/image-prompt/skills/photo-prompt-image-generator/scripts/prompt_generator.py:5598), [문맥 판정 코드](/Users/chasoik/Projects/image-prompt/skills/photo-prompt-image-generator/scripts/prompt_generator.py:6166)

권장 변경:

1. 기존 상위 상태를 유지하더라도 상세 사유에 필드 부재, 값 미인식, 실제 제외 근거, 관계 부재, 관계 구조 차이를 구분한다. 원문 값과 실제·기대 구조를 함께 제시한다.
2. 의미가 확인된 대응 표현을 authored vocabulary에 보강한다. 자유문장을 등록 문구로 덧붙여 통과시키는 대신 원래 값과 출처를 보존한다.
3. 추가 축이 해당 개념의 필수 의미인지 재검토한다. 예를 들어 얀데레의 affect_leak_intentionality는 기존 제안처럼 보조 설명으로 옮길 근거가 있지만, 다른 개념까지 일괄 삭제할 이유는 없다.
4. 클래스 매칭이나 embedding 유사도를 실제 의미 일치의 자동 증명으로 승격하지 않는다. 미인식은 판정의 한계이며 사용자의 명확한 의미를 바꾸는 근거가 아니다.

완료 기준은 같은 동결 입력에 올바른 상세 사유가 반환되고, 다른 상대에게 향하는 행동·부정된 애정·역방향 관계가 계속 구별되는 것이다. 한국어·영어·일본어의 새 바꿔 쓰기와 비인물 관계를 포함한다. 데이터나 공개 필드가 바뀌는 범위만큼 빌더·뷰·감사와 관련 회귀를 함께 검증한다. 기존 [10/5 개선안](/Users/chasoik/Projects/image-prompt/docs/analysis/2026-10-05-photo-semantic-matching-improvement-plan.md)의 미구현 P0~P3를 출발점으로 삼는 것이 가장 효율적이다.

### P0-2. API 경로도 감사된 실행 요청을 직접 소비

현재 API helper는 prompt_en이 있으면 호출할 수 있고 audit_status는 선택적인 기록 정보로 읽는다. 실제 호출 전에 pack·composed audit·runtime request를 검증하는 경로는 없다. 참조 파일을 전달하는 입력도 없으며, call_api의 요청에는 model·prompt·size·n만 들어간다. 가이드에서 요구한 감사와 참조 보존을 호출자의 수작업에 맡기는 구조다. [입력 처리](/Users/chasoik/Projects/image-prompt/skills/photo-prompt-image-generator/scripts/generate_images_via_api.py:114), [호출](/Users/chasoik/Projects/image-prompt/skills/photo-prompt-image-generator/scripts/generate_images_via_api.py:151)

오프라인으로 call_api와 recorder를 대체했을 때 prompt_en만 있는 JSON이 호출 지점에 도달하고 helper가 성공으로 반환했다. 이것은 실제 미감사 이미지가 생성됐다는 증거가 아니라 **보조 스크립트 자체가 해당 조건을 강제하지 않는다는 제어 흐름 증거**다. [점검 결과](/Users/chasoik/Projects/image-prompt/docs/analysis/2026-10-07-photo-skill-session-review/api_adapter_offline_probe.json)

권장 변경:

- 스킬의 API 진입점은 기존 photo-image-render-request/v2, 원본 pack·receipt, composed 객체를 받아 호출 직전에 기존 감사기를 실행한다.
- 감사한 runtime_prompt_en과 실제 전송 문자열을 같게 유지한다. 참조가 필요한 요청은 실제 첨부 여부와 해시·역할을 확인하고, 해당 어댑터가 지원하지 않으면 전송 전에 명확히 실패한다.
- 성공·실패 기록에 같은 요청 연결을 남긴다. 요청한 모델 식별자와 도구가 관측해 준 실제 모델 식별자는 구분하고, 알 수 없는 정보는 unknown으로 둔다.
- 이미지를 받았지만 저장이나 기록이 실패한 경우에는 복구할 파일을 다룬다. 새 생성 호출로 대체하지 않는다. 현재 이 원칙이 구현된 부분은 그대로 유지한다.
- 재시도 횟수와 API fallback은 기존 사용자 권한을 따른다. 새 승인 문구를 요구하거나, 정책 차단 뒤 원문을 자동 완화하는 절차를 추가하지 않는다.

핵심 검증은 호출을 대체한 상태에서 감사 누락·변조·참조 누락이 전송 전에 차단되는지, 정상 요청 바이트와 레저 연결이 유지되는지다. 실제 유료 호출은 이 구현 점검의 필수 조건이 아니다.

### P1-1. 창작 판단은 에이전트가 하고, 연결 작업은 도구가 수행

현재 SKILL 본문은 485줄·약 10,206 whitespace words다. scripts의 Python/JS/문서 텍스트는 약 26,833줄이다. 스키마와 바인딩을 손으로 연결하면서 창작에 집중하기 어렵다는 위험은 문서 크기와 실제 형식 보정 기록에 의해 뒷받침된다. 이 크기 자체가 예술적 약화의 원인이라는 인과 증명은 아니다.

중립적인 단계 실행 도구를 제안한다.

| 단계 | 도구의 책임 | 에이전트의 책임 |
|---|---|---|
| 요청 준비·동결 | raw bytes·span·설정·표준 공백·해시·필수 필드 연결 및 검증 | 의미 해결, 작품 방향, 5~10 관찰 범주, 장면·공간 판단, 증거 문구 |
| 코어 후 조회 | 고정 입력·source generation·receipt로 정확히 한 pack 생성 | 필수 의미 검토와 필요한 후보 상세 선택 |
| 구성 감사 | 기존 계약별 조건, literal evidence, stale 해시, 실행 준비 상태 확인 | 열린 선택의 수정·보존·삭제와 채택 판단 |
| 렌더·기록 | 감사된 입력 전달, 오류 보존, 저장·레저·리뷰 연결 | 실제 이미지 판독, 국소 수정 판단, 사용자 선호 구분 |

새 pre-core 도구는 정확히 허용되는 경로로 명시하고 후보·프로필·이전 출력에 접근하지 않는 독립 모듈로 만들어야 한다. 예제에서 장면을 골라 주거나 사용자 의미를 대신 정하는 템플릿 생성기는 제안하지 않는다. 신체 검토의 supported 이유도 도구가 자동 작성하지 않는다.

즉시 정리할 문서 불일치도 있다. 새 코어의 camera flag 사용은 본문에서 요구하지만 Phase 2 대표 명령에는 없다. 새 작성과 역사 재생을 구분한 실행 예제, 요청된 방향/높이의 조건부 옵션, pack과 receipt 동반 보존을 한곳에 모을 필요가 있다. [camera 지침](/Users/chasoik/Projects/image-prompt/skills/photo-prompt-image-generator/SKILL.md:244), [대표 실행 예제](/Users/chasoik/Projects/image-prompt/skills/photo-prompt-image-generator/SKILL.md:348)

SKILL에는 창작 판단·권한·시점 경계와 짧은 실행 순서를 남기고 반복되는 스키마 설명은 중립 도구의 작성용 shape로 공급한다. 상세 후보 계약과 유지보수 설명은 기존 post-core references를 활용한다. 초기 장면 개발 지침을 post-core 파일로 옮기거나, 초기 단계에 후보 examples를 읽게 해서는 안 된다.

5~10 범주 선택은 9/24 사용자가 직접 요청한 설계이고, 48~1,280단어 범위와 장면 개발 확대도 사용자의 후속 요구다. 이번 개선에서 이를 임의 삭제하거나 짧은 태그 프롬프트로 되돌리지 않는다. 핵심은 같은 의미·장면을 반복 기록하는 연결 노동을 줄이는 것이다.

### P1-2. 세 조건 비교로 스킬의 실제 기여를 분리

현재 가장 중요한 미검증 질문은 “기본안을 잘 쓰는 것과 후보 데이터 조회 중 무엇이 결과를 개선하는가”다. 막차 실험에는 이를 나누는 조건이 없었고, 반복 수정에서는 스킬 버전·설정·작성자가 함께 바뀌었다. 그 상태로 데이터 양이나 이미지 모델 차이를 원인으로 확정하기 어렵다.

다음 비교를 권장한다.

| 조건 | 입력 | 확인하려는 기여 |
|---|---|---|
| A | 사용자의 실제 요청과 같은 참조 범위 | 직접 생성 기준 |
| B | 후보를 보기 전 독립 작성한 기본안 | 스킬의 초기 해석·작가적 방향 |
| C | B와 같은 고정 기본안·설정에서 만든 최종안 | 후보·후기 구성의 추가 기여 |

B와 C는 같은 기본안을 사용한다. 서로 다른 독립 작성자가 만든 초안을 비교하면 후보 효과와 작성 변동이 다시 섞인다. 다중 표본이 필요하면 기본안을 여러 개 독립 작성하되 각각 B/C 쌍을 만든다. 평가자는 조건·키워드 설명을 가린 상태에서 먼저 이미지의 상황과 인상을 읽고, 다음에 원문 충실도를 별도로 판정한다.

평가 결과는 사용자 요구 충실도, 상황의 가독성·감정적 설득력, 전체 사진의 매력·시각적 위계, 실제 사용자 비교 판단으로 구분한다. 작성자가 추가한 손가락 각도나 작은 재질 흔적의 재현 실패는 기록하되 사용자 요구의 실패와 같은 칸에 합치지 않는다. 선택한 계약의 strict gate는 계속 유지하며 사후 기준을 낮추지 않는다.

실험은 현재 소스·제어값·참조·렌더 도구·실제 검색 lane·시도 정책을 고정한다. 과거 rule fallback을 현재 BM25F나 hybrid 경로의 결과로 재명명하지 않는다. 이미지 seed나 실제 모델 ID를 통제·확인할 수 없으면 그 제한을 남긴다. 차단은 픽셀 품질 미채점으로 처리한다.

평범한 일상 사진, 정물·비인물, 요청이 정확한 희소 장면, 같은 상대를 향한 관계, 1인칭 접촉, 다국어 복합 요청을 포함한다. 모든 테스트를 복잡한 관측소·정비·연구실 상황으로 구성하면 일상적인 사진의 매력을 평가하기 어렵다. 초기에는 사례 비교로 보고하고 작은 표본으로 일반적인 품질 우위를 선언하지 않는다. 이번 분석에서는 이 이미지 실험을 실행하지 않았다.

### P1-3. 재시도용 허용 필드 추출과 수리 원인 기록

현재 retry whitelist와 lineage 원칙은 적절하지만 부모 산출물에서 허용 필드만 읽어 내는 작업은 수작업이다. prepare_retry_context 같은 보조 도구가 부모 해시, 보존 차원·속성, 유효 hard obligation, 실제 실패 gate, 허용된 국소 변경만 추출하도록 제안한다. 후보 목록·미채택 아이디어·과거 선택 범주는 출력하지 않는다.

수리 판단은 최소한 다음 원인을 구별해야 한다.

- 원문 의미를 기본안이 잘못 해석한 경우: 의미 해결 및 envelope/core 재구성 경로.
- 에이전트가 고른 연출에 물리적 모순이 있는 경우: 허용 범위에서 공간 관계 수정 후 재감사.
- 일관된 프롬프트를 모델이 다르게 그린 경우: 실패한 부분만 국소 수정 또는 승인된 동일 입력 재시도.
- 작은 구조가 요구된 관측 배율에서 보이지 않는 경우: 해당 계약의 review_scale·visibility 조건을 확인하고 관측 불가 상태를 그대로 보존.
- 출력 정책 차단, 파일 저장 실패, 레저 기록 실패: 각각 별도의 실행 결과. 장면을 완화하거나 다시 생성하는 것으로 임의 대체하지 않음.

손·소품의 주체, 접촉 대상, 같은 상대에게 향하는 행동, capture camera와 장면 속 장치의 구분을 기존 자료에서 짧게 추출하면 수정 중 관계를 잃기 어렵다. 사용자 요청상 프레임 밖이어도 되는 받침·발·가슴·접촉을 검토 증명만을 위해 화면에 끌어들이지 않는다. 새 기본 장면이나 보편적인 얼굴·시선·포즈 gate를 추가하는 방법은 권장하지 않는다.

해시·literal binding은 기록 무결성을 검사한다. 실제 공간 추론과 이미지 판독은 에이전트의 책임으로 남긴다.

### P2. 기존 데이터 검토를 사용자의 의미와 현재 노출에 연결

최신 관리 보고서에는 의미 검토 단서 46건 중 43건이 미검토로 남아 있다. 이는 중복 확정 43건이나 오류 43건이라는 뜻이 아니다. 이미 구현된 audit/build/query/diff와 해시 결합 검토 기록을 사용해 정비하면 된다. 새 양방향 그래프나 일괄 semantic edge 자동 생성은 필요하지 않다. [관리 구현과 남은 범위](/Users/chasoik/Projects/image-prompt/docs/analysis/2026-10-06-photo-data-quality-and-links/IMPLEMENTATION.md)

우선 검토할 항목은 잘못된 사람·행동 전제, 대상·부위·재질 소유의 모호함, 일반 개념을 특정 실현으로 좁힌 하드 의무, 동일 의미의 문맥·언어 경계다. 실제 노출·오채택·최종 문장의 오류와 연결된 항목부터 처리한다. 넓은 분위기 용어에 한 가지 사건·복장·미세 부품을 필수로 부과하지 않는다. 반대로 사용자가 그 좁은 관계를 명시했으면 필요한 증거를 지킨다.

새 데이터 추가도 가능하지만 검증은 등록 수보다 노출·검토·채택·최종 변화·이미지에서 읽힌 의미를 따라야 한다. 0개 채택은 정상 선택일 수 있고, 수백 개 추가가 곧 작품 향상인 것도 아니다. 변경별 집중 검증에서 시작하고 독립 경로에 걸친 변경이나 남은 위험이 있을 때 전체 회귀로 넓힌다. 기존 실패·과거 fixture 의미를 새 성공으로 바꾸지 않는다.

## 5. 적용 순서와 보존할 원칙

추천 순서는 **현재 의미 판정 사유와 API 진입점 보완 → 중립 단계 도구·실행 문서 정리 → 기본안/후보 효과 비교 → 재시도·데이터 정비**다. 첫 두 항목은 비용 없는 코드·텍스트 점검으로 구체적으로 검증할 수 있다. 이미지 비교는 그다음에 별도로 범위를 정해 수행한다.

다음 사항은 유지한다.

- 독립 기본안 동결 전 후보·프로필·과거 출력 접근 금지.
- raw request·설정·사용자 요구와 작성자 선택의 권한 구분.
- 부분 속성 잠금, 후보 0개 채택, 후기 단계의 열린 연출 수정.
- sensual/fetish/surreal/creativity의 현재 값·의미·범위와 최신 adult 문구 조건.
- 이야기·감정·전후관계 개발을 현재 프레임에서 보이는 단서로 실현하는 방향.
- 좁은 runtime negative와 사용자 제외사항의 출처 보존, 플랫폼 enforcement의 별도 취급.
- 현재 불변 런타임 세대·receipt와 이미 구현된 관리용 양방향 조회.
- prompt audit, runtime audit, 실제 픽셀, 사용자 선호의 분리.

이번 검토에서 작성한 파일은 이 분석 폴더의 보고서·목록·근거 JSON이다. 스킬·데이터·테스트 소스는 수정하지 않았고 실제 이미지/API 호출·커밋·푸시도 수행하지 않았다.
